## 1. 平台事实（设计必须遵守）

| 项 | 数值和规则 | 来源 |
|---|---|---|
| CPU | EdRV32，RV32IM，没有浮点；clk_sys 125 MHz，60 帧时每帧约 208 万周期 | SoC 规格 |
| 画面 | GPU 渲染 640 × 360，分 2 条（每条 640 × 180），RESOLVE 到 DDR；DISP 用 `L0_X2` 放大到 1280 × 720；UI 可用 DISP 的 L1 层 | gpu-spec 2.1、2.10 |
| 纹理 | 片上纹理 RAM 只有 **192 KiB**。一帧用到的所有纹理必须同时装得下；格式 I4、I8（调色板 16 组 × 256 项）、RGB565 | gpu-spec 2.6 |
| 四边形 | 屏幕空间矩形，**不缩放、不旋转**，只能翻转；有全局透明度 | gpu-spec 2.8 |
| 旋转和缩放的精灵 | 用两个三角形画 | gpu-spec 2.4–2.5 |
| 对象单元 | 硬件推进（v += a，p += v）、寿命、存活区域、与 8 个目标框碰撞并输出命中列表、绘制；不能做大量对大量的碰撞 | gpu-spec 2.9 |
| 声音 | 48 kHz 立体声 16 位环形缓冲，CPU 混音 | aud-spec |
| 输入 | 键盘（gdd 5c 键位：WASD、J、K、L、U、Q、F、空格、Esc、Enter）和鼠标（只用于菜单）。PC 直接读键鼠；板上由 PC 经网口发送虚拟键盘鼠标指令（`sw/lib/virtual_input.h`，需从 8 键扩展为键盘位图 + 鼠标坐标和按键） | `sw/lib/plat/plat.h` |

## 2. 目录与模块

```
sw/apps/ember_isles/
  docs/      gdd.md、tech.md
  data/      CSV 数据表（gdd 第 10 章）
  assets/    源素材（PNG、模型脚本、乐谱）
  tools/     数据表和素材的转换工具（Python 标准库），输出到 build/
  src/
    core/    定点数学、随机数、实体池、事件、录像回放
    sim/     战斗模拟：属性结算、标签、状态、触发、武器、技能、敌人 AI、碰撞网格、波次、关卡
    meta/    局外成长、存档
    gfx2d/   图块地图、精灵、文字、HUD、粒子（对象单元）
    audio/   合成器、音乐序列、音效、混音
    ui/      菜单、升级三选一、商店、祭坛、图鉴、压测和对比页
    game.c   主循环：输入 → 模拟一帧 → 2D 表现 → 提交 GPU → 音频
```

- **模拟和表现严格分开。** `sim/` 不包含任何 GPU、平台或浮点代码；`gfx2d/` 只读取模拟状态，不修改它。
- **对象单元只用于表现层。** 粒子、飘字、拾取光效可以交给对象单元推进；影响胜负的东西（子弹、敌人、伤害）一律在 `sim/` 中用定点数计算，保证确定性，并且与平台无关。2D 表现可以把模拟里的子弹作为对象表提交，只用来绘制（STEP = 0）。
- 只使用驱动、`sw/lib/plat/` 和 C 标准库，PC 和板上用同一份源码。

## 3. 确定性

- 定点数：位置用 Q16.16，角度用 16 位整数（65536 为一圈），三角函数查表。
- 固定 60 Hz 步长；随机数用带种子的 xorshift，每个子系统各有独立的流。
- 录像：种子加每帧 16 位输入位图（协调者 2026-11-24 决定，取代 8 位）：bit0–3 = W/A/S/D，bit4 = J，bit5 = K，bit6 = L，bit7 = U，bit8 = Q，bit9 = F，bit10 = 空格，bit11 = Esc，bit12 = Enter，bit13–15 保留为 0。鼠标只用于菜单，不进录像。旧 8 位录像随 E3 一并转换或重录。验收方法：同一录像在 PC 和 Spike 上回放，每 60 帧的模拟状态摘要（实体数、玩家生命、波次、关键数值）逐项相同。

## 4. 预算与测量

| 项 | 预算（估算，实测后修订） | 测量方法 |
|---|---|---|
| CPU 模拟 | ≤ 120 万周期/帧 | 把模拟编译成 Spike 程序，回放录像，统计每帧指令数（`instret`）；按 CPI 1.3 换算成周期，CPI 待上板实测修正 |
| CPU 表现和提交 | ≤ 50 万周期/帧 | 同上 |
| 音频合成 | ≤ 15 万周期/帧 | 同上 |
| GPU | ≤ 一帧的 70% | PC 模拟器的 PERF 计数加单元周期模型；以上板实测为准 |
| 纹理 | 每关 ≤ 192 KiB：地图图块、角色、敌人、特效、字体共用一张或几张图集 | 素材工具在转换时统计 |

2D 目标：同屏敌人 1500，模拟子弹 3000，表现粒子 8000。达不到时报告实测值和瓶颈，不加降级逻辑掩盖。

## 5. 素材管线（v2.0）

- **像素画**：真正按网格绘制的原生尺寸像素画，不用 imagegen 原画缩小。角色为正常人体比例，高约 32–40 像素；精致帅气，配色鲜艳（gdd 3.3、用户 2026-11-24）。
  - 角色动作骨架共用，武器是单独图层，挂在每帧的手部锚点上（gdd 5c.1）；动作套：待机、移动、冲刺、受击、死亡、互动、技能施放，加每个武器类别的攻击和蓄力动作。
  - imagegen 只可用于概念草图和配色参考。
- **伤害数字和命中特效**：专门的粗体像素数字（1 像素深色描边），档位和动画见第 7 节。
- **音乐和音效**：可用高质量授权素材（CC0、CC-BY，署名写进 `assets/CREDITS.md`），或达到同等水准的原创；不用商业游戏素材或仿制品。
- 生成物放在 `build/ember_isles/`，按 C 数组或二进制镜像链接进程序。

## 5a. PC 与 FPGA 两种配置

- **C 第一版在 PC 上运行完整设计**，渲染仍走 GPU 模拟器（`tools/gpu/emu`），代码与 FPGA 同一份。
- PC 配置允许超出 FPGA 容量：纹理 RAM 等容量做成模拟器的构建参数，PC 配置放宽，FPGA 配置等于硬件值。运行时统计实际用量（纹理、对象数、每帧 CPU 指令数、GPU 周期），作为 FPGA 裁剪的依据（gdd 10a）。
- 不为 PC 配置写另一套渲染路径。

## 7. 表现质量标准（E2b 起，用户 2026-11-24 试玩反馈后补充）

第一版试玩反馈：画面廉价、PC 版卡顿移动慢、粒子和动画差、音乐难听；参考《元气骑士》一类俯视角像素射击肉鸽的效果，可用网上素材。以下作为之后各阶段的验收标准，每轮都要输出截图和短视频，先由协调者逐项对照，再交用户确认。

| 方面 | 标准 |
|---|---|
| 帧率 | PC 版稳定 60 帧；性能信息显示实际帧率 |
| 美术 | 风格统一的成套像素素材；饱和明快的配色；角色和敌人有清晰描边、阴影，与地面对比明显；地面图块有结构感（石砖、草地、沙滩、岩浆），不用噪点纹理 |
| 动画 | 角色和敌人有待机、行走、攻击、受击、死亡动画（各 4–8 帧）；武器跟随朝向；拾取物浮动 |
| 打击感 | 枪口或施法闪光、命中火花、敌人受击闪白和击退、死亡爆散、屏幕震动和短暂顿帧、伤害数字弹出（暴击放大变色） |
| 特效 | 半透明和叠加发光（火焰、光束、爆炸）、拖尾、地面持续效果的动画；大招有全屏级表现 |
| 规模 | 中后期同屏数百到上千敌人（压测模式显示精灵数和帧率） |
| 声音 | 关卡音乐使用高质量的授权素材，或达到同等水准的原创；音效覆盖射击、命中、爆炸、拾取、升级、受伤 |
| 界面 | 中文；武器、遗物带图标；升级界面为"图标 + 名称 + 说明" |
| 素材授权 | 只用 CC0、CC-BY（署名写进 `assets/CREDITS.md`）、OFL（字体）；不用任何商业游戏的素材或仿制品 |
