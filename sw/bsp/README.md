# Bare-metal BSP

Source the toolchain environment, then run:

```sh
. ~/.local/opt/edrv32/env.sh
make -C sw                         # minimal, ROM startup
make -C sw MEMORY=sram             # preload and enter at SRAM base
make -C sw MEMORY=ddr              # preload and enter at DDR base
make -C sw coremark                # compile-only CoreMark framework in SRAM
```

`PROGRAM` selects `sw/tests/<program>/main.c`, with `coremark` selecting the
CoreMark application. The default minimal program is linked at the reset entry
0, copies initialized data from ROM to SRAM, clears BSS and host symbols, and
returns a status from main. SRAM/DDR programs require the test platform or a
bootloader to enter the ELF entry address. All links set a 16-byte-aligned stack
at the top of their data memory. Every invocation rebuilds the selected program,
so changing MEMORY does not reuse an ELF for a different memory layout.

The three linker scripts import `build/sw/soc_memory.ld`, generated by the
software build from the ROM/SRAM/DDR entries of `soc_address_map.json` (SoC 6.1).
All outputs are under `build/sw/<program>/`: `<program>.elf`, `<program>.dis`,
`<program>.map`, `rom.hex`, `sram.hex`, `ddr.hex`.

`python3 tools/elf2mem.py <elf> <output-directory>` reads little-endian ELF32
PT_LOAD file bytes at physical/load addresses, rather than run-time virtual
addresses. Each hex token is **one byte** for `$readmemh` into a byte array.
`@` addresses are offsets from the named memory's base. BSS/NOLOAD bytes are
not emitted: BSP startup clears them, including tohost/fromhost. A memory with
no file-backed bytes has an empty image; for the default ROM link, initialized
SRAM data resides in ROM in the image and is copied at startup, so `sram.hex`
and `ddr.hex` are empty. The SRAM and DDR link modes populate their own images.

The testbench locates aligned 64-bit ELF symbols `tohost` and `fromhost`.
`edrv32_exit(status)` writes `(status << 1) | 1`: **1 is PASS**, other odd values
encode a nonzero failure status. `edrv32_putchar` uses the HTIF write syscall
request (64, fd 1, buffer, length) and waits for fromhost acknowledgement; a
host console consumer is required when running CoreMark. No hardware register
addresses are invented. SYSCTRL SIM_EXIT is outside this task's tohost scope;
its register offset awaits the SYSCTRL register specification.
