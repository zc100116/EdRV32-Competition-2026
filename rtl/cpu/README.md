# CPU RTL

实现 `docs/spec/cpu-spec.md`；单一 clk_sys 时钟域，Verilog-2001。
CPU 不实现 C 扩展，无 RVC_EN 参数；misa=0x40001100，mepc 低两位清零。

前端按 8 字节组取指，每个响应贡献一条或两条完整 32 位指令。
响应缓冲容量四条，随后写入四条 IB；保留原 no-C 路径的容量和推进条件。
无跨组拼接、RVC 展开、长度预测或 F2 边界恢复。
D 级冷 JAL 重定向在无法发射时保留 IB 头，M/E 重定向清空 IB。

内部记录仍为 179 位，以保持现有观测接口：

|位|含义|
|---|---|
|31:0|PC|
|63:32|32位指令|
|95:64|原始编码|
|96|保留的compressed观测位，恒0|
|97|保留的前端illegal观测位，恒0；非法编码由D译码|
|98|取指错误|
|99|BTB命中|
|100|预测跳转|
|132:101|预测目标|
|141:133|原始gshare索引低9位|
|178:142|RAS检查点：count[2:0]、ptr[1:0]、栈顶[31:0]|

本次按步骤提交：0 删除 C 残留；1 预测器扩容与分布式 RAM；2 V3s。
第0步删去 cpu_rvc、cpu_f2_recover 单元测试，迁移 cpu_core_smoke、cpu_frontend
共用文件至 *_no_c，保留无 C 测试；cpu_redirect_wait 删除重复配置。

检查与测量结果见 `docs/reports/2026-11-02-perf-cpu-v015.md`。
仿真前执行 `. ~/.local/opt/edrv32/env.sh`，全部仿真独占
`flock /tmp/edrv32-sim.lock`，`tools/regress.py` 使用 `-j 1`。

预测器为 BTB 128 项（PC[9:3]、tag PC[31:10]）、gshare 4096 项
（PC[13:2] XOR 12 位非推测 GHR）、RAS 4 项。
`edrv32_ram_cpu_btb` 为 128×58：{tag22,target32,position1,type3}，
一同步写、一异步读，无初始化或复位；有效位由预测器 FF 复位清零。
`edrv32_ram_cpu_direction` 为 4096×2，一同步写、查询/更新各一异步读，
上电全01、复位不清除。两包装行为阵列均名 `memory_r`，读延迟0拍，
写入时钟边沿后读端看到新内容；同沿更新使用沿前旧计数器值。
IB 新增 `push_index_hi_i`/`index_hi_o`（各6位，按槽各3位），
前端 `decode_index_hi_o` 接核心 `d_index_hi_w`；E 用 `e_predict_index_r`
保存完整12位索引，供唯一控制转移训练。取指组合查询时序不变。

V3s 配对按 4.2 六条件检查：两条至多一条只能管线0执行、至多一条控制转移，
无组内 RAW，任一槽 CSR/系统/FENCE 不配对，槽1非法或取指异常不配对。
槽1只能管线0执行时互换，`e_swap_r/m_swap_r/w_swap_r` 表示槽0在管线1。
D记录按槽索引，E/M/W记录与valid按物理管线索引；单发仍进入管线0。
旁路在每一级先检查较老槽、后检查较年轻槽，旁路来源编码仍按物理管线。
寄存器堆同地址双写以槽1为准；trace退休记录重排为程序顺序。

两条管线分别计算条件、目标和误预测，每组只有一个预测器更新端口。
重定向优先级为M>E>D，E组内按槽优先；槽0重定向冲刷槽1，
包括互换后的年轻访存请求。D槽0冷JAL不发射槽1、不计配对失败事件；
D槽1冷JAL允许双发射，停顿时IB保留两条，通过 `keep_pair_i` 指示。
M级分别保留两条管线的异常，按槽选择陷阱PC/原因/mtval；
槽1异常时槽0进入W，中断在槽0边界接受。HPM事件4包含两条管线，
配对失败原因按RAW>结构>类型>缺少槽1排序，事件7为两条管线0专属或双控制。

`cpu_v3s` 单元验证互换WAW、管线1分支/JAL、年轻访存取消和槽1精确异常；
`cpu_ib` 验证独立索引旁带及停顿槽1重定向的双记录保留；
`cpu_predictor` 验证128/4096索引、计数器饱和、RAS和warm reset保留计数器。

互换组中年轻设备访问未发出时，中断仍按槽0接受并取消年轻访问；
设备已 `dc_commit_o` 发出后，`m_device_started_r` 阻止整组再接受中断，
待响应后两槽提交。协调者已确认该边界，随后同步进规格4.5。
槽1分支异常也要等待槽0访存结果，槽0正常响应后提交，或优先报告槽0访存错误。
`cpu_v3s` 另覆盖设备发出前/后的中断、M停顿时槽1冷JAL仅重定向一次并保留
两条记录、年轻分支异常等待年长load，以及双异常优先级。

JALR始终在管线0执行，其D级预测目标减立即数的预计算也按映射后的槽选择；
`cpu_v3s` 用不同立即数的年长ALU和年轻JALR，覆盖冷训练后再次命中的互换组。

较老的管线1分支需要重定向或已有异常时，年轻管线0 DIV不得先启动或拉起全局
停顿；取消判定不依赖DIV等待信号。被冲刷的年轻MUL同样不向乘法器发valid。

槽0冷JAL首次D重定向的周期不配对；若它先前因后端停顿留在IB，目标指令随后
进入IB，则停顿解除后可按通常规则配对，包括与目标load互换。映射不禁止这种组。
