# 卡 93：新首页，以及协作式与 FreeRTOS 调度 A/B 对比（卡 75 比特流）

## 1. 目标

1. 在板上看新首页和设置页：两张场景大卡片、4 个分类页签、设置页。
2. 同一个比特流、同一份应用代码，比较两种调度方式在流畅度、延迟、CPU 开销上的差异，决定演示用哪一种（设计 `docs/design/2026-11-16-showcase-r4-plan.md` 的 D7）：
   - **A**：现有协作式；
   - **B**：FreeRTOS 抢占式。

**主观项每项给 1–5 分（5 分最好），并写一句主要问题。**

建议在卡 92 之后、同一次上板时做。

## 5. 操作步骤

**公平性要求**：A、B 依次运行，期间摄像头位置、画面中的物体、光照、人的位置都不变。每换一个程序，都先复位进入 BIOS，再加载。

**曝光**：两个程序都用同一档。
- 卡 92 已经判断出"短"更好：进入设置页切到"短"；
- 否则保持"标准"。

在 result.md 中注明用的是哪一档。

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 0 | Windows Codex（C） | `git fetch origin`，`git switch -c win/20261116-93-sched-ab origin/zc100116/b3`，记录 HEAD |
| 1 | 用户（U） | 下载卡 75 比特流，复位进入 BIOS，加载 **A**，记录 HELLO |
| 2 | U | **新首页**（只用 A 看）：<br>- 首页 4 个页签各拍一张照片；<br>- 用板上四个按键（下一个、上一个、确认、返回）走一遍：能否遍历全部卡片、进入应用、返回；<br>- 进入设置页拍照，切换镜像和曝光，看是否生效；<br>- 整体观感 1–5 分，说哪里好看、哪里要改（排版、对齐、字号、图标、颜色） |
| 3 | U + C | **对 A 做下面几项**。每项开始和结束时，请 Codex 记下时间：<br>a. **抓取测试** 2 分钟：拖动方块、快速挥手，流畅度 1–5 分；<br>b. **切图形**（慢）玩 1 局，流畅度 1–5 分；<br>c. **人脸贴纸** 1 分钟：左右移动头部；<br>d. **实时识别**：对准固定摆放的 2–3 个物体，2 分钟；<br>e. **芯片信息** → CoreMark 跑 1 次；<br>f. **图形引擎** → benchmark 完整跑 1 次；<br>g. **经典游戏（NES）** 运行 1 分钟 |
| 4 | U | 复位进入 BIOS，加载 **B**，记录 HELLO |
| 5 | U + C | **对 B 重复第 3 步 a–g**，条件相同。另外对比 a、b 两项：B 比 A 更顺、相同还是更差 |
| 6 | U | 全程留意：有没有死机、复位、画面卡住或停住、检测框异常。**B 是第一次上板，出现异常请拍照，并记录当时在哪一步** |
| 7 | C | 整理串口和照片，填写 result.md，推送分支 |

**第 7 步的串口统计**：按程序（A、B）和页面段（抓取、切图形、人脸、实时识别）分别统计。

1. **vision 行**：`fps`、`shown`、`e2e`、`gui`，各给最小、中位数、最大值。
2. **sched 行**：
   - `pace` 各档的占比；
   - `skip` 合计；
   - `gui_wait`、`render`、`rnd`、`sw`、`vsync` 的中位数；
   - `comm`、`app`、`gui` 的占用中位数，以及 `*_max` 的最大值；
   - 各中断次数和时间的中位数；
   - B 另列 `ctxsw`、`kern` 的中位数。
3. **游戏**：`event=end` 行的分数和时长；`draw_fps` 的中位数。
4. **CoreMark**：Iterations/Sec、CoreMark/MHz。
5. **benchmark**：平均 fps，以及 `LVGL split scene="ALL"` 的 render_ms、rnd_ms、sw_ms。
