# 任务卡 20261103-54-showcase-p5-board：演示程序 P5 版上板验收与数据采集

## 1. 目标

在最终版 F CPU125 比特流上验收 showcase P5 版。P5 按卡 53 的失败反馈重新规划，设计记录是 `docs/design/2026-11-03-showcase-p5-replan.md`。

本卡同时采集以下数据：

- 定位 LVGL benchmark 帧率下降的原因；
- 技术文档和演示视频要用的最终数字。

## 2. 输入

- **代码**：`origin/zc100116/b3` 上包含本卡的提交。从这里拉出 `win/20261103-54-showcase-p5-board`，记录 HEAD。
- **比特流**：与卡 53 相同的最终版完整 F（CPU 125 MHz）。在 result.md 中记录它的路径和生成时间。
- **程序**：`src/showcase-p5.elf`，12947900 字节，构建自 b3 64aec2b6（第 2 轮）。连接后，调试工具显示的板端版本应为 `64aec2b6`。
- **对比程序**（D 节）：卡 48 的 `tasks/win/20261103-48-vrn-f-rnd1slim/src/demo_npu.bin`。
- **NPU 模型**：`tasks/win/20261029-09-b3-software/src/npu/`。
- **测试图片**：`EdRV32-test-images/coco-val-160/images` 中取 20 张，文件名记入 result.md。
- **调试工具**：用本 checkout 的 `tools/debug_tool`。先关掉旧进程再重新启动；工具的协议已经改变，旧版本不能用。

同卡 53。本卡不运行 PnR。

## 4. 需要的 IP

## 4a. 第 2 轮（2026-11-03）

第 1 轮的部分结果已在结果分支 0f0c6912 提交。根因见设计记录 `2026-11-03-showcase-p5-replan.md` 第 9 节：
- A1 进入视觉识别后停机：没有上传模型就启动了 NPU；
- benchmark 慢：LVGL 每帧用 CPU 清屏。

第 2 轮的程序做了以下修改：
- **程序内嵌 YOLOv8n 模型**，上电即可识别，不需要先上传。PC 仍然可以上传模型替换；上传期间打开视觉识别或图片识别，会显示"未加载模型"，不停机。
- **清屏改由 RND 完成**。
- **串口按整行输出**，`LVGL split` 行不再和 CPU 行交错。
- **改正 RND/DISP 带宽计数**。

请在同一个结果分支上继续，**从 A1 重新开始**。第 1 轮的日志保留不动，第 2 轮的日志加前缀 `r2_`，例如 `artifacts/uart/r2_A.log`。

## 5. 与卡 53 相比的变化（执行前请告诉用户）

- **虚拟键鼠只走网口，串口虚拟输入已经删除。** 网口未连接时，虚拟设备不可用，工具会显示原因。板载 next、prev、enter、esc 四个键始终可用。
- **同一时刻只运行一个功能**。切换时，前一个功能先停下来，后一个再启动；页面会短暂显示"正在启动 / 正在停止"。
- **视觉识别的"暂停"会同时停止摄像头和推理**，画面停在最后一帧，按"继续"恢复。
- **图片识别改为手动逐张。** 工具中选择文件夹后，用"上一张 / 下一张"逐张发送；板端页面也有"上一张 / 下一张"。自动批量已经删除。
- **图像处理每一项都有独立开关**，关闭时保留参数；有"本项恢复默认"和"全部恢复默认"。
- **控件改为 LVGL 标准控件**：键盘焦点框只在用按键导航时出现，鼠标点过的按钮不会一直高亮。
