# 卡53 P4上板反馈与重新规划要求

## 实测与用户观察

1. **识别性能不达标**：照片 `artifacts/photos/P3_post177ms_3fps.jpg` 显示识别3 fps、NPU每帧41.1 ms、后处理177.1 ms、目标总数0。卡53后处理目标≤35 ms，当前未达标。用户观察后处理一直100多ms、帧率个位数。不能以PC仿真结果代替本板测量。请对比独立demo_npu与showcase的同模型、同输入、同阈值，并分开测量真实执行耗时、等待/调度间隔、输出读取、后处理、绘制和界面刷新，查明统计口径及CPU开销；目前不能断言都是NMS计算慢。
2. **图片交互要求变更**：用户明确不需要自动批量处理。改为选择文件夹建立图片列表，手动“上一张/下一张”，一次只加载、检测一张；显示当前文件名、序号、处理中/已完成状态，返回图片和检测框必须对应当前请求。原卡53的40张自动批量不再作为本轮验收要求。
3. **图像处理交互**：与PC调试工具一致，每项功能先有独立启用开关，再调节阈值/参数；板端页面与工具状态同步。明确禁用时参数保留还是恢复默认、各功能组合与执行顺序，避免操作一项影响其他项。
4. **暂停后其他功能失效**：用户使用图片检测批量后暂停，随后实时识别和图像处理都失效。必须明确暂停画面、停止输入、停止推理、取消传输、退出页面的区别，并设计恢复和切换流程。不能将某一个模式的停止传播到整个系统后无法恢复。
5. **虚拟输入异常**：用户看到仍走串口，延迟大、鼠标乱跳、经常自动点击。采集时工具COM7/115200已连接；串口缓冲有连续 `1B 56 ...` TX报文，证明本轮存在串口虚拟输入，不能标为全程网口输入已通过。工具状态中PEER=false，expectedPeer=192.168.1.2:6000，peer=null；UDP接收socket曾记录192.168.1.10:5000，两者并不等于应用握手当前有效。以实际发送通道、板端接收和应用消费三处证据确认；排查队列积压、坐标、按下/释放、重复事件和页面切换残留，根因未确认。
6. **按钮与视觉**：用户质疑组件是否正确使用、点击高亮不恢复。源码 `sw/apps/showcase/ui/shell.c:ui_button` 调用ui_box，ui_box在theme.c调用lv_obj_create，通用按钮不是lv_button_create；clicked主动lv_group_focus_obj，theme.c为LV_STATE_FOCUSED配置高亮，因此焦点高亮可持续存在。这不等于已证明鼠标释放丢失。请按LVGL组件语义使用按钮、开关、滑条、下拉框等，区分悬停、焦点、按下、选中、禁用；持续焦点不能让用户误认为按钮还按着。用户要求重新规划页面美观性和组件使用。
7. **游戏返回错误**：实测游戏中Esc仍直接退主页面，未按卡53要求退回游戏列表并保持原游戏位置。
