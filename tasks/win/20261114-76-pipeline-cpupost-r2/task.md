# 卡 76：在卡 68 R2 的比特流上联调视觉流水线（CPU 后处理临时版本）

## 1. 目标

视觉流水线首次上板联调：用卡 68 R2 现成的比特流，运行 CPU 后处理版本的 showcase，逐一验收 8 个预设、任意组合编辑和 PC 端联动。

背景：
- 视觉流水线把原来的视觉识别、图片识别、图像处理三页合并为一页。用户用积木链任意组合摄像头/PC 图片 → 处理积木 → HDMI。设计见 `docs/design/2026-11-14-showcase-vision-pipeline.md`。
- 正式版本使用 NPU 硬件后处理，但卡 68 R2 没有这部分硬件。本卡用临时构建 `SHOWCASE_POST=cpu`：类别选择、DFL 和阈值由 CPU 做，其余与正式版本相同。
- 检测跳的耗时和"框滞后"会比正式版本长，这是预期的。正式版本随卡 75 验收。
- 卡 68 R2 之后，b3 只改了 NPU 后处理和扇出复制，媒体和存储子系统没有功能变化，软件与该比特流兼容。

**不需要 PDS 综合或布线**，可以和卡 75 的 PnR 同时进行，只要占用开发板。

## 5. 操作步骤

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 0 | Windows Codex（C） | `git fetch origin`，`git switch -c win/20261114-76-pipeline-cpupost-r2 origin/zc100116/b3`，记录 HEAD。确认 `tasks/win/20261114-76-pipeline-cpupost-r2/src/showcase-pipeline-cpu.elf` 存在。 |
| 1 | 用户（U） | 下载卡 68 R2 的比特流，按 KEY1 复位进入 BIOS，记录 `CLK_SYS_HZ`，应为 125000000。 |
| 2 | U + C | 按卡 68 的方法，经 BIOS 网口加载 `src/showcase-pipeline-cpu.elf`。记录：<br>- `Load result: PASS`；<br>- `showcase first frame`；<br>- 调试工具从 HELLO 取得的板端程序版本，应为 `314908a1`。 |
| 3 | U + C | 首页进入"视觉流水线"。**8 个预设逐一运行，每个 1 分钟**：<br>- 保存串口的 `pipe fps=` 行；<br>- 拍一张照片，包含主画面和右下角的硬件路径表；<br>- 检查画面与预设一致：检测框位置和类别、旋转、放大、滤波效果，无错乱。<br>预设依次为：标准识别、边缘识别、旋转识别、局部放大、整屏旋转、夜视增强、多级滤波、PC 图片。PC 图片预设见第 6 步。 |
| 4 | U + C | **看此级**：在多级滤波预设中选中第 2 个积木（Sobel），执行"看此级"，主画面应切到该级输出。拍照。 |
| 5 | U + C | **用板上按键编辑**：<br>- 在标准识别预设的"检测"后插入"滤波"，改为 Sobel，画面应变为在边缘图上叠框。拍照；<br>- 选中链首的"摄像头"卡片，用"在后面插入"插入"叠加"，使它位于"检测"之前。应出现中文拒绝提示"叠加检测框之前必须先放置检测积木"，链保持不变。拍照。 |
| 6 | U + C | **调试工具**：<br>- 在 PC 端切换一次预设、修改一个积木参数（例如滤波类型），板上画面同步变化；<br>- PC 端能显示链状态和每跳统计；<br>- 切到 PC 图片预设，从调试工具发送 1 张图片：PC 端收到检测结果，HDMI 显示该图片和检测框。截图 PC 端界面。 |
| 7 | U + C | **稳定性**：整屏旋转预设连续运行 5 分钟，保存全部 `pipe fps=` 行，记录死机、复位、画面错乱。 |
| 8 | C | 整理 result.md，推送 `win/20261114-76-pipeline-cpupost-r2`。 |

遇到死机或画面错乱：记录当时的预设、链内容和最后 50 行串口输出，然后按 KEY1 复位、重新加载，继续后面的项目。

- 调试工具与板端同步，PC 图片的检测结果正确回传；
- 整屏旋转 5 分钟无死机、复位、画面错乱；
- 所有数字取自串口或工具原文，找不到的写"未取得"。
