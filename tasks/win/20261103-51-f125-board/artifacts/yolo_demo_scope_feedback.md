# YOLO演示目标范围和检测灵敏度：用户补充意见，待Claude讨论

## 用户原话与现场

“就是我感觉yolo有点太灵敏了，画面时很多不想检测的都有框，这个能否调吗，或者最后演示，选一个模型，包含的类别少一点，比如固定几种动物？几种常见物品？一起记录给claude讨论”

照片：photos/yolo_unwanted_detections.jpg。用户看到摄像头画面中不希望作为演示目标的区域/物体也被绿色检测框覆盖，影响演示观感。没有逐个核验物体、类别和置信度，不能将所有“不想检测”的框直接认定为算法误检，也不凭照片断言具体分数。

## 当前软件事实

- sw/lib/yolo_post.c按5个plane×16个lane处理80个类别；sw/lib/yolo_post.h的class_threshold契约为概率大于0.25的首个INT8阈值。阈值与模型量化表有关，不是直接把显示分数整数写入硬件。
- 已有按类别区分的NMS，IoU阈值0.45（intersection×20>union×9）；最多100个结果。不能写成“尚未实现重叠框处理”。
- 当前推理及后处理接口固定了5040候选、725760字节输出等契约；本次没有修改软件、参数、模型或RTL。

## 建议讨论的两条路线（不是已定实现）

### A：保留当前模型，限制演示输出

1. 提高置信度门限以减少低分候选；可对比当前0.25与例如0.4、0.5的演示效果，同时记录漏检和误检。具体值待实测选定。
2. 增加类别白名单，只显示选定动物或常见物品。用户尚未选定具体类别；候选可以讨论猫/狗/鸟等动物，或瓶子/杯子/书/手机等常见物品，不将候选写成最终需求。
3. 根据实际重复框情况再讨论NMS设置；IoU调整针对重叠抑制，不能解决所有无关类别或错误分类问题。现有NMS按类别区分，跨类别重复需另外评估。
4. 需要考虑给上板界面提供阈值和类别选择入口；当前没有确认可直接通过现有GUI运行时调整，不能告诉用户已有此功能。

白名单能减少不需要的输出框，但仍是原80类网络推理，不能承诺因此降低NPU计算量或提升核心fps。提高门限也可能漏掉真实目标。

### B：使用真正的少类别模型

围绕最终演示场景训练/微调少数类别，例如几种动物或几种常见物品。该路线可能更贴合演示，但不等于只替换权重：需要核对当前NPU支持的网络/算子、输出头的通道布局、描述符、量化、类别表及CPU后处理；当前硬编码80类和输出大小的部分需要配套修改。

需重新生成模型包及参考结果、完成量化前后精度验证与上板自检。减少类别后性能是否改善取决于实际网络和编译结果，不能预先保证。
