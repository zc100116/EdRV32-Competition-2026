# T-HAND-ORIENT：用 FreiHAND、DexYCB 补充手的各种朝向，在 GPU 服务器上微调手势模型（卡 86，Linux 执行）

## 背景

- 卡 83 用 HaGRIDv2 训练了手势模型：14 类 + 21 个关键点，YOLOv8n-pose，HaGRID val 的 Box mAP50 为 99.4%。
- 卡 84 上板发现手背朝镜头时效果很差。原因是 HaGRID 几乎都是"手举在脸旁、手心或侧面朝镜头"的姿势；手背样本只有 stop_inverted、peace_inverted、two_up_inverted 三类。伸手抓取时手背朝镜头、手指朝前的姿势基本没有。
- 本 Task 用两个带 3D 关键点的公开数据集补充各种朝向，并在原来的 14 类上微调：
  - **FreiHAND**：13 万张单手特写，含 3D 点；其中 32,560 张是绿幕原图，配有手的掩码。仅限研究用途。
  - **DexYCB**：8 台相机拍摄的手抓物体，640×480，含 21 点 2D/3D、MANO 参数和手的分割掩码；CC BY-NC 4.0；每个人一个 12 GB 的包。
- 公开数据集只标了关键点、没有手势类别，所以要用 **3D 关键点自动判断手势**。手指弯曲角度、指尖间距等量与手的朝向无关，手背朝镜头时同样可算。
- 用户已同意本次训练，租用的服务器仍在。服务器按小时计费，不要让 GPU 空等，也不要做 Task 以外的探索。

2. **下载**：在服务器的 tmux 中进行，可以用 aria2 多连接。
   - FreiHAND v2：训练集和评估集，从 Freiburg 官网页面上的链接下载。

3. **3D 手势判断** `src/hand3d_gesture.py`：输入 21 个 3D 点，输出 14 类之一，或者"不确定"。
   - 先核对两个数据集的关键点顺序，统一成 HaGRID/MediaPipe 的顺序：0 手腕，1–4 拇指，5–8 食指，9–12 中指，13–16 无名指，17–20 小指。
   - 特征：
     - 每根手指的伸直程度：由各指节骨向量之间的夹角计算；
     - 指尖之间的距离，以及各指尖到拇指尖的距离，都除以手腕到中指根的 3D 距离；
     - 相邻指尖的张开程度；
     - like / dislike 用拇指在图像中朝上还是朝下来区分。
   - 每个类别对应的手型：

     | 类 | 手型 |
     |---|---|
     | palm | 五指伸直、张开 |
     | four | 四指伸直，拇指收起 |
     | fist | 四指完全弯曲，拇指收起或压在手指上 |
     | point | 只有食指伸直 |
     | peace | 食指、中指伸直，其余弯曲 |
     | three | 恰好三指伸直 |
     | call | 拇指、小指伸直，其余弯曲 |
     | thumb_index | 拇指、食指伸直，其余弯曲 |
     | like / dislike | 只有拇指伸直，分别朝上、朝下 |
     | ok | 拇指尖和食指尖相碰，其余三指伸直 |
     | grip | 五个指尖聚到一起 |
     | grabbing | 五指都半弯成爪形，指尖分开，不碰掌心 |

   - 不满足任何一类，或者同时满足多类的，判为"不确定"。不确定的样本不参加训练，**不要标成 no_gesture**。
   - 每个样本另外记录朝向，由 3D 点算出的掌心法线和相机视线的夹角决定，分为手心、手背和侧面三种。只用于评估统计。
3a. **防止污染（协调者补充，必须执行）**：
   - **手框定义与 HaGRID 一致**：
     - 公开数据的手框一律由 21 个点的外接矩形加边距得到，不用掩码的外接矩形。FreiHAND 的掩码含前臂，DexYCB 的掩码含手腕。
     - 边距在 HaGRID train 上统计：取 HaGRID 原框相对关键点外接矩形四边的外扩量，除以关键点外接矩形的长边，四边分别取中位数。
     - 把这四个比例写进 result.md。
   - **被遮挡、被截断的手不用**：
     - 有关键点落在图像外的样本，丢弃；
     - FreiHAND：有关键点落在掩码外的样本丢弃，掩码先膨胀 5 px 再判断。这类样本通常是手指被手里的物体挡住了。
   - **不要手里拿着物体的帧**：DexYCB 只用"伸手接近物体"阶段的帧。
     - 先找出被抓物体（`ycb_grasp_ind`）开始移动的那一帧：相对第 0 帧的平移超过 5 mm；
     - 只用这一帧之前 15 帧以前的帧。
   - **不要画面里有没标注的手**：
     - 用卡 83 的 best.pt（conf 0.25）对 DexYCB 候选帧做检测；
     - 只要有一个检出框与标注手框的 IoU < 0.3，就丢弃整帧，因为这可能是没标注的另一只手。
   - **划分不泄漏**：FreiHAND 不随机划分，按样本编号连续切块，最后 5% 的编号作验证集。
   - **合成质量自检**：用卡 83 的 best.pt 检测 FreiHAND 合成图中手心朝镜头的那部分，统计检出率。如果明显低于 HaGRID val，说明合成有问题，先停下用 `ask` 报告。
   - **统计**：每条过滤规则各丢掉多少样本，写进联系图关口的消息和 result.md。
4. **FreiHAND 合成** `src/freihand_composite.py`：
   - 只用 32,560 张绿幕原图和它们的掩码，按 3a 过滤和划分。
   - 用掩码把手抠出来，贴到 HaGRID 图片上：
     - 训练集贴到 HaGRID train 的图上，验证集贴到 HaGRID val 的图上；
     - 每张图贴 1–2 只手，不能与原有的手框重叠；
     - 原有的 HaGRID 标签全部保留。
   - 随机变换：
     - 缩放到手框长边为图高的 8%–45%；
     - 平面内旋转 ±45°；
     - 水平翻转的概率为 50%；
     - 掩码边缘羽化约 3 px；
     - 轻微的亮度和颜色扰动；
     - 关键点随同一变换一起变换。
   - 只贴手势判断明确的手。抽样一律用 `default_rng(0)`。
5. **DexYCB 转换** `src/dexycb_to_yolo.py`：
   - 每个序列、每台相机，每隔 10 帧取 1 帧；跳过没有手的帧（`joint_2d` 为 −1）；
   - 按 3a 只取接近阶段的帧，去掉有没标注的手的帧；手框按 3a 由关键点得到；
   - 手势由 3D 点判断，"不确定"的帧整帧丢弃；
   - subject-01、02 作训练集，subject-03 作验证集；
   - 训练集抽样到约 2 万张，验证集约 3 千张。
6. **联系图关口**：
   - 按"数据集 × 类别"各随机抽 24 张，画出手框、21 个点、类名和朝向，拼成联系图，复制到本机 `build/hand-orient/sheets/`（不入库）；

   - 协调者会逐张检查联系图：
     - 某个"数据集 × 类别"中判错的超过 1/24，这一组就不用，该类只用 HaGRID 的样本；
     - 整个数据集问题多，就整个不用。
   - 等待期间可以继续做第 7 步的数据组装，但不要开始训练。
7. **训练**：

     - HaGRID train：按类别等比抽样到约 6 万张，用 `default_rng(0)`；stop_inverted、peace_inverted、two_up_inverted 的样本全部保留；
     - FreiHAND 合成图约 3 万张；
     - DexYCB 训练集约 2 万张。
   - 验证集：HaGRID val 全部、FreiHAND 合成验证集、DexYCB subject-03 验证集。
   - 从 `$D/runs/hagrid-v8n-r2/weights/best.pt` 开始训练，结构仍为 YOLOv8n-pose，14 类 + 21×3 关键点。
   - 参数：30 轮、imgsz 640、batch 128、workers 16、`cache=False`、seed 0、deterministic；其余用默认值，不调参。
   - 第 1 轮结束后，用 `ask` 告诉协调者每轮耗时和预计结束时间。这条不需要等待回复，发完继续。
   - 训练期间每 30–60 分钟检查一次；中断时用 `resume=True` 续训。
8. **评估** `src/hand_orient_eval.py`：新旧两个模型（卡 83 的 best.pt 和本次的 best.pt）都要评估。
