# 卡 101：安全帽检测去闪烁、搅拌机误检（卡 75 比特流）

## 1. 目标

复测卡 100 的工地反馈："检测有点不太灵敏，一直在闪烁，右上角的搅拌机能识别成安全帽"。

**主观项每项给 1–5 分（5 分最好），并写一句主要问题。**

本卡的程序包含卡 100 的全部内容。卡 100 中还没测的项目（画笔锁手、抓取甩出、农场流畅度、OK 背包、APK 其他场景），可以直接用本卡程序一起测，结果写进本卡的 result.md。

## 2. 本版内容（相对卡 100）

| 项 | 内容 |
|---|---|
| 去闪烁 | 安全帽页对检测框做跟踪：<br>- 新目标连续 2 帧才显示；<br>- 目标连续丢 4 帧才消失，期间框停在原位；<br>- 类别按最近 5 次检出投票；<br>- 已戴、未戴计数按稳定后的目标统计 |
| 警示去抖 | 有未戴帽的人持续 0.3 s 才显示警示；没有未戴帽的人持续 0.5 s 后消失 |
| 搅拌机误检 | 搅拌机保留在 APK 画面中，由识别侧解决：只对"安全帽"类把置信度门限提到 60%，"未戴帽的头"不变。卡 100 实拍中，搅拌机被认成安全帽 25–58%，真安全帽 81–94% |
| 串口 | 每秒一行的 `helmet` 记录在原始计数 `helmet= head=` 之外，增加稳定后的计数 `helmet_s= head_s=` |

## 4. 环境、IP

PG2L200H-6 FBB676 开发板，PDS 只用于下载比特流；不需要新的 IP。

## 5. 操作步骤

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 0 | Windows Codex（C） | 按第 3 节拉分支，记录 HEAD |
| 1 | 用户（U） | 下载卡 75 比特流，经网口加载 `src/showcase-r5f-hw.elf`，记录 HELLO。每测一项前清空调试工具的串口记录，测完另存一个文件 |
| 2 | U + C | **安全帽检测**（平板打开 APK"工地"第一项）：<br>a. 平板放稳，最好用支架，不要用手拿着；摄像头对着平板，停留 30 s，看框和计数还闪不闪，搅拌机还会不会被框成安全帽；<br>b. 复位状态应为已戴 4、未戴 2，并有警示；<br>c. 点那两名未戴帽的工人，看计数变化和警示消失是否及时；<br>d. 点"演示"跑完一遍，看警示的出现和解除；<br>e. 评分：稳定（不闪）、误检、反应速度、计数准确；录视频 |
| 3 | U + C | （可选）卡 100 中还没测的项目，用本程序测，方法同卡 100 |
| 4 | C | 整理串口和视频，填写 result.md，推送分支 |

**第 4 步的串口统计**：`helmet` 行中原始计数和稳定计数（`helmet`/`helmet_s`、`head`/`head_s`）各自的相邻采样变化次数，以及 `fps`、`e2e` 的中位数。

## 6. 产物

放在 `tasks/win/20261118-101-helmet-stable-board/artifacts/`：
- `uart/<项目>.log`；
- `video/`，单个视频超过 100 MB 时用 Git LFS；
- `notes.md`：用户原话。

## 7. 通过判据

本卡是效果评估卡。第 2 步必须有评分和观察，第 4 步必须有统计。数字取自串口原文，找不到的写"未取得"。
