# 卡 85：抓取测试页上板（卡 68 R2 比特流，CPU 后处理）

## 1. 目标

在卡 68 R2 上试用新的"抓取测试"页：用手捏起屏幕下方的方块和球，拖动后放下。比较四种判断方法的手感和成功率，并分别记录手心朝镜头和手背朝镜头两种情况。结果用来决定决赛交互采用哪种判断方法，并作为手部模型重新训练前的基线。

背景：
- 本页用手势模型输出的 21 个关键点判断抓和放，软件说明见 `docs/reports/2026-11-16-grab-test-sw.md`。
- 屏幕下方有 6 个物体，按 0–5 号从左到右排列：红色方块、橙色方块、黄色方块、绿色球、蓝色球、紫色球。
- 抓住物体后，物体跟着光标走；松开后物体自由下落到地面线上。
- 四种判断方法，用"模式"按钮切换：

  | 模式 | 怎么算"抓" | 光标位置 |
  |---|---|---|
  | A 两指捏 | 拇指尖和食指尖捏到一起 | 两指中间 |
  | B 五指抓 | 五个指尖收拢到一起 | 五个指尖的中心 |
  | C 模型类别 | 模型判断为握拳、抓紧或爪形 | 掌心 |
  | D 指尖夹物体 | 拇指尖和食指尖分别贴在同一个物体的两侧 | 两指中间 |

- 判断阈值可以用"参数 −""参数 +"按钮调整，A、B、D 三种模式有效。每改一次，串口会输出新的值。
- "镜像"按钮默认开启。开启后画面像照镜子一样：手往右移，屏幕上的手也往右移。
- "关键点"按钮默认关闭，打开后显示 21 个点和连线。
- "物体复位"按钮让所有物体回到初始位置。
- 已知情况：卡 84 中，手势模型在手背朝镜头时效果明显变差。本卡要把这个差距测出数字。

**不需要 PDS 综合或布线**，只占用开发板。用户操作约 30 分钟。

## 5. 操作步骤

**串口输出**：

- 每秒一行汇总：
  ```text
  grab fps=… shown=… disp=… npu=… wait=… decode=… kpt=… gui=… e2e=… hands=… mode=A|B|C|D param=… d=… state=open|grab held=-1|0..5 picks=… drops=… mirror=0|1 idle=…%
  ```
- 抓和放的状态一变化，就输出一行：
  ```text
  grab_evt ms=… mode=… state=grab|release d=… obj=-1|0..5 x=… y=…
  ```
  `obj=-1` 表示空手抓，即没有抓到物体。
- 参数每改一次，输出一行：`grab param mode=… value=…`。

**计时**：串口每一行都带当前模式，Codex 可以直接按模式切分，不需要用户报模式。用户只在"手心"和"手背"两组之间口头报一次，由 Codex 记下时间戳，写入 `marks.txt`。

**一次"抓取"的定义**：
1. 把手移到指定物体上；
2. 做出抓的动作；
3. 拖动约 30 cm 到另一个位置；
4. 松开，物体落下。

满足以下全部条件才算**成功**：
- 抓到的是指定的物体；
- 拖动过程中物体没有中途掉下；
- 在想松开的地方松开了。

用户在纸上逐次记下 ✓ 或 ✗；失败时简单写原因，例如"抓不起""中途掉""松不开""抓错物体"。

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 0 | Windows Codex（C） | `git fetch origin`，`git switch -c win/20261116-85-grab-board origin/zc100116/b3`，记录 HEAD。 |
| 1 | 用户（U） | 下载卡 68 R2 的比特流，按 KEY1 复位进入 BIOS，记录 `CLK_SYS_HZ`。 |
| 2 | U + C | 经 BIOS 网口加载 `src/showcase-grab-cpu.elf`，记录 HELLO 中的版本，应为 `1bc57627`。进入"抓取测试"页。 |
| 3 | U | **基本检查**：<br>- 打开"关键点"，确认 21 个点贴在手上，拍一张照片；<br>- 镜像开启时，手往右移，确认屏幕上的手也往右移；<br>- 关闭镜像试一下，再打开。记录你更喜欢哪一种；<br>- 关闭"关键点"，后面的测试都在关闭状态下进行。 |
| 4 | U + C | **四种模式逐个试**：站在约 **0.75 m** 处，镜像开启。每种模式（A → B → C → D）各做两组：<br>a. **手心或侧面朝镜头**，按自然的方式抓：0–5 号物体各抓 1 次，共 6 次；<br>b. **手背朝镜头**：再抓 6 次。<br>每组开始前按一次"物体复位"。每种模式做完后，给手感打 1–5 分，5 分最好。<br>如果某种模式明显太灵敏或太迟钝，可以用"参数 −/+"调整后再试，记下最后用的参数。 |
| 5 | U + C | **拿稳测试**：用第 4 步中最好的那种模式，抓起一个物体，在屏幕上慢慢移动约 10 s 再放下，重复 3 次。记录中途有没有自己掉下来。 |
| 6 | U + C | **距离**：用最好的那种模式，分别在 **0.5、1.0、1.5 m** 处，手心朝镜头各抓 3 次，记录成功次数。 |
| 7 | U + C | **切换**：依次进入"手势识别"约 10 s，再进入"实时识别"约 10 s，最后回到"抓取测试"。确认离开抓取页后画面不再镜像，各页正常，没有卡死。 |
| 8 | U | 测试结束后**不要立刻复位**，先等 10 s。如果中途出现不是人为按下的复位或死机，记录发生的时间和之前 50 行串口输出。 |
| 9 | C | 按下面的方法统计，填写 result.md，推送 `win/20261116-85-grab-board`。 |

**第 9 步的统计方法**：
- **各模式**：从串口统计时间窗内的以下数据：
  - `grab_evt` 中 `state=grab` 的次数，以及其中 `obj=-1`（空手抓）的次数；
  - `state=release` 的次数；
  - `hands ≥ 1` 的行数占比；
  - `fps`、`e2e` 的中位数。
- 把串口统计和用户的逐次记录（✓ / ✗ 和原因）合在一起填表。用户的记录以照片或文字形式附在产物里。

## 7. 通过判据

本卡是测量卡，没有通过与否，以下几项**必须有数据**：
- 每种模式在手心组和手背组的成功次数（每组满分 6 次），以及手感评分；
- 最好的模式、最后使用的参数；
- 拿稳测试和三个距离的结果；
- 镜像开或关的偏好；
- 有没有死机、复位或画面错乱；
- 所有数字取自串口原文或用户记录，找不到的写"未取得"。
