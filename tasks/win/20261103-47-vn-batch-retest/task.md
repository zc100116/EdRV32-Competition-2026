# 任务卡 20261103-47-vn-batch-retest：VN 批量识别卡死修复与图片/视频切换复测（沿用卡 43 VN 比特流）

## 1. 目标

卡 43 的 VN 文件夹识别在第 8 张图片后卡住：上传完成，但没有回传，status 无应答，遥测还在。T-VN-BATCH 查明，板端收图后排空遥测的循环 `demo_monitor_flush` 会一直追赶持续写入的新遥测，可能出现活锁。现已改成只排空进入时已有的记录。调试记录见 `docs/debug/2026-11-03-vn-batch-hang.md`；第 8 张时的具体停点仍属推测，本卡用实板确认。同时验证用户要求的两项工具功能：
- **批量识别可以停止**；
- **图片检测与视频检测可以来回切换**：板端新增 WIN3 命令 ASCII `camera`，恢复摄像头检测，不重载模型。

只换软件，不重新实现。

## 5. 操作步骤

| 步骤 | 执行者 | 内容 |
|---|---|---|
| 0 | Windows Codex（C） | `git fetch origin`，`git switch -c win/20261103-47-vn-batch-retest origin/zc100116/b3`；关闭旧调试工具，从本 checkout 重启。 |
| 1 | 用户（U） | 下载 VN bitstream；调试工具网口加载 `src/demo_vnpu.bin`，上传模型。确认 `EDNM loaded`、视频检测出框（S1）。 |
| 2 | U + C | **批量 ×1**：文件夹识别 images 目录，**至少 40 张**（卡 43 在第 8 张卡住）。记录完成数、失败数和原因、每张往返时间；中途每 10 张发一次 `status`，记录是否应答。保存串口和工具日志。 |
| 3 | U + C | **停止**：再开始一次批量，第 5 张左右按"停止"。记录：停止后在途那一张是否正常返回或超时、队列是否清空、工具是否回到空闲；随后立即单张识别一张，确认可用。 |
| 4 | U + C | **切回视频**：在图片模式下按"切回摄像头/视频检测"。确认串口打印 `YOLO source camera`、HDMI 回到摄像头画面并出框、视频推理次数继续增加，不需要重新上传模型。再做一次单张识别，然后再切回视频，共来回 3 次。 |
| 5 | U + C | **长批量**：batch 160 张（images 目录全部）跑完，或运行 15 min。记录完成/失败数、平均往返、status 应答情况。如果再次卡住：不要复位，先发 `status`；记录串口最后 50 行、工具状态（导出 status json）、遥测 seq 是否连续，然后复位。 |
