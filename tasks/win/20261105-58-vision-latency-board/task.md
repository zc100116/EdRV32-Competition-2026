# 卡 58：视觉识别端到端延迟分段实测（上板，只换 ELF）

## 1. 目标

用正式版比特流跑一个新程序，测出视觉识别端到端延迟中的各段等待，同时补齐卡 54 第 4 轮没有回传的数字。

新程序在卡 54 第 4 轮程序的基础上**只加了时间戳打点**，程序行为没有任何改变。测出的数据作为后续调度改进和后处理硬件化的基准。

设计依据：`docs/design/2026-11-04-vision-latency-eval.md`（本卡所在分支）。

## 2. 输入

- **代码**：分支 `zc100116/task-vision-latency-eval` 上包含本卡的提交。从这里拉出 `win/20261105-58-vision-latency-board`，记录 HEAD。
- **比特流**：正式版 F CPU125 r2，即 `origin/win/20261103-48-vrn-f-rnd1slim` 的 `fpga/bitstreams/EdRV32-F-cpu125m-r2.sbit`，与卡 54 相同。
- **程序**：`src/showcase-lat.elf`，12,940,584 字节，构建自本分支 `cd11e01d`。连接后，调试工具显示的板端版本应为 `cd11e01d`。
- **调试工具**：用本 checkout 的 `tools/debug_tool`，与卡 54 相同。先关掉旧进程，再重新启动。

## 3. 环境

与卡 54 相同。本卡不跑 PnR。可以在卡 56、卡 57 布局布线的空档执行。

## 4. 需要的 IP

无。

## 5. 新增串口字段

`vision ...` 行末尾新增三个字段，单位 ms，精度 0.1，每秒一次：

| 字段 | 含义 |
|---|---|
| `vin_wait` | 所选相机帧的 VIN 完成中断 → NPU 启动 |
| `dispatch` | NPU 完成中断 → 开始复制结果 |
| `take` | 结果发布 → 界面第一次取走结果 |

原有字段（`npu`、`wait`、`decode`、`post_span`、`gui`、`e2e`、`period`、`copy` 等）的含义不变。

## 7. 测试内容

| 编号 | 内容 | 记录 |
|---|---|---|
| L1 | 视觉识别，对着有人和物品的场景运行 60 s，**关闭性能浮窗** | `vision` 行和 `vision_gui` 行原文；照片一张 |
| L2 | 同 L1，**打开性能浮窗**，运行 30 s | 同 L1 |
| L3 | 视觉识别，画面里只有静止物体、不动，运行 30 s，关闭性能浮窗 | 同 L1。用来和 L1 对比界面刷新量对延迟的影响 |
| L4 | LVGL benchmark，关闭性能浮窗。这一项就是卡 54 第 4 轮的 Q3 | 16 行 `LVGL split` 原文和结果表照片 |
| L5 | 体验 | 检测框是否跟手；鼠标是否流畅 |
