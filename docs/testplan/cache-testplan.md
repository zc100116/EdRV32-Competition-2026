## 2. 验证环境

### 2.1 组成（模块级，`verif/block/cache/`）

| 组件 | 要求 |
|---|---|
| core 侧驱动 | 按 cpu-spec 3.2 / 3.3 节产生请求：取指请求（含 `ic_kill_o`）；load/store 请求，以及其后的 `dc_commit_o` 或 `dc_kill_o`；FENCE、FENCE.I 序列。分定向和随机两种模式；随机模式可以控制地址范围（制造组冲突）、读写比例、kill 概率 |
| AXI64 内存模型 | 平坦内存，按 SoC 规格 4.1 节响应；可配置的随机延迟、ARREADY/AWREADY/WREADY/RVALID/BVALID 随机反压、按地址注入 SLVERR |
| 参考模型 | 一个按字节寻址的"架构内存"：每个提交的 store 立即更新它；每个 load 的返回值必须等于它在该时刻的内容。测试结束时执行一次整体 clean，再比较 AXI 内存模型与参考模型，两者必须完全一致 |
| AXI 协议检查器 | VALID 保持、负载稳定；行突发必须 LEN = 3、SIZE = 3、行对齐；单拍访问的 SIZE 和 WSTRB 与访问一致；每个方向同时至多一笔事务；ID 为 0 |
| core 接口检查器 | 响应时序符合 cache-spec 5.1–5.3 节（命中下一周期返回；设备访问只在提交后发出；被 kill 的请求不返回、不改变架构内存） |
| APB 驱动 | 访问 `edrv32_cache_ctrl` 寄存器 |

### 2.2 单元级（RTL worker 编写）

| 对象 | 内容 |
|---|---|
| PMA 译码 | SoC 规格 6.1 节每个区域的边界地址（首地址、末地址、末地址 + 1）分别检查分类结果 |
| LRU | 命中、填充对 LRU 位的更新 |
| `edrv32_cache_ctrl` | 每个寄存器的复位值、读写、RW1C、BUSY 期间写 OP_CMD 无效果、中断输出 |

## 3. 测试项清单

档位：S = smoke，F = full，P = perf。

### 3.1 I$

| 编号 | 规格条款 | 测试内容 | 档位 |
|---|---|---|---|
| IC-01 | 5.1 | 冷启动顺序取指：每行先缺失后命中；命中时每周期返回一个 | S |
| IC-02 | 2.1、5.1 | 三个映射到同一组的行轮流访问，检查 LRU 替换顺序 | S |
| IC-03 | 2.3、5.1 | ROM 取指不装入 cache（再次取同一地址仍然发出 AXI 读） | S |
| IC-04 | 2.3、6 | 取指访问非可执行区域：返回错误，不发出 AXI 事务 | S |
| IC-05 | 5.1 | 缺失期间 `ic_kill_o`：响应被丢弃，该行仍然装入 | F |
| IC-06 | 5.1 | `ic_inv_o` 后全部重新缺失 | S |
| IC-07 | 6 | 填充返回 SLVERR：请求返回错误，该行不装入，下一次访问重新缺失 | F |
| IC-08 | 全部 | 随机取指流（含 kill），AXI 随机延迟和反压，每次返回的数据与内存一致 | F |
| IC-09 | 2.2、5.1 | 预译码：填充返回、填充后命中、ROM 取指、`ic_inv_o` 后重新填充，`ic_resp_predecode_i` 每半字都等于 `edrv32_cpu_predecode` 对对应 32 位指令的输出（指令流覆盖全部 opcode 和非法编码）；I$ 缺失代价比 v0.12 多 1 个周期 | S |

### 3.2 D$

| 编号 | 规格条款 | 测试内容 | 档位 |
|---|---|---|---|
| DC-01 | 5.2 | load 命中下一周期返回；连续 load 每周期一个 | S |
| DC-02 | 5.2 | store 命中后提交，数据写入；字节、半字、字三种宽度和所有对齐位置 | S |
| DC-03 | 5.2 | 写缓冲旁路：store 提交后紧跟同一字的 load（全覆盖和部分覆盖） | S |
| DC-04 | 5.2 | 连续 store 不停顿 | S |
| DC-05 | 5.2 | 缺失替换干净行：只有填充突发 | S |
| DC-06 | 5.2 | 缺失替换脏行：先写回（4 拍，数据正确），再填充 | S |
| DC-07 | 5.2 | store 缺失：写分配，填充后合并 store 数据 | S |
| DC-08 | 5.2 | `dc_kill_o`：被取消的 load 不返回，被取消的 store 不改变内存；正在进行的填充继续完成 | F |
| DC-09 | 5.3 | 设备 load/store：只在提交后发出；store 收到 B 后才返回；WSTRB 和数据落在正确字节 | S |
| DC-10 | 5.3 | 设备访问被 kill：不发出总线事务 | F |
| DC-11 | 2.3 | 对 ROM 的 store 返回访问错误；对未映射地址的 load/store 返回访问错误，且都不发出总线事务 | S |
| DC-12 | 2.3 | DDR 非缓存别名：不装入 cache，每次都发出单拍事务 | F |
| DC-13 | 6 | 填充返回错误：请求返回错误，该行不装入 | F |
| DC-14 | 6 | 设备访问返回错误：请求返回错误 | F |
| DC-15 | 全部 | 随机 load/store 流（组冲突密集、kill 随机、AXI 随机延迟和反压），全程与参考模型一致，结束时整体 clean 后内存一致 | F |
| DC-16 | 5.5、7 | 复位初始化：tag RAM 预置随机内容（含 valid=1、dirty=1）后复位，512 周期内 `dc_req_ready_i` 为 0 且不接受维护请求；完成后任何访问都缺失、没有写回；扫描中途再次复位从头开始 | S |
| DC-17 | 2.2、5.2 | store 命中置脏写入 tag RAM 与同周期查找、填充写 tag 的端口冲突：周期行为与 v0.8 相同（DC-01–DC-07 周期数不变），结果与参考模型一致 | S |

### 3.3 维护操作

| 编号 | 规格条款 | 测试内容 | 档位 |
|---|---|---|---|
| MT-01 | 5.4 | 范围 clean：范围内的脏行被写回、清脏位；范围外的脏行不变；行首、行尾不对齐的范围 | S |
| MT-02 | 5.4 | 范围 invalidate：范围内的行失效，脏数据不写回 | S |
| MT-03 | 5.4 | 范围 clean+invalidate | S |
| MT-04 | 5.4 | 整个 D$ clean | S |
| MT-05 | 5.4 | FENCE.I 序列：`dc_clean_all_o` 完成后 `ic_inv_o`；之后取指能看到 store 写入的新代码（I$ 与 D$ 共用同一个 AXI 内存模型） | S |
| MT-06 | 5.4 | FENCE：写缓冲非空时等到排空 | F |
| MT-07 | 5.4 | 维护期间请求照常被接受，`dc_req_ready` 不随请求地址变化；可缓存请求在维护完成前不访问阵列、不返回响应，完成后结果正确；设备请求（轮询 STATUS）照常完成 | F |
| MT-08 | 5.4 | OP_SIZE = 0 立即完成；BUSY 期间写 OP_CMD 无效果 | F |
| MT-09 | 6 | 写回返回错误：IRQ_STAT.bit1 置位、ERR_ADDR 正确、`irq_o` 按 IRQ_EN 输出；写 1 清除 | S |
| MT-10 | 5.4、7 | 范围维护只访问覆盖到的组：1 行、跨两行、N = 组数 − 1、N = 组数、N > 组数（含跨地址回绕到同组）、起点不对齐；两路同时命中各自的行；结果与参考模型一致，无写回时周期数满足 7 节上限 | S |
| MT-11 | 5.4、7 | 整体 clean 跳过干净组段（按组段脏标志）：无脏行、只有一个脏行（首组段、末组段）、全部组段都有脏行；结果一致，周期数满足 7 节上限 | S |
| MT-13 | 2.2 | 组段脏标志：行变脏时对应组段置 1；范围 clean/invalidate 后标志可保守保持为 1，但不得在组段仍有脏行时为 0；整体 clean 后全部为 0 | S |
| MT-12 | 5.4 | 范围维护与写回交错：范围内多个脏行连续写回，写回期间 AXI 随机反压；维护期间 CPU 轮询 STATUS 与发出可缓存请求两种等待方式结果一致 | F |

## 4. 参考模型

- 数据正确性：2.1 节的架构内存参考模型（每个提交的 store 立即生效，load 返回值必须与之相等）。
- 时序和协议：AXI 协议检查器、core 接口检查器。

---

## 5. 覆盖目标

- cache-spec 每一条条款至少对应一个测试项。
- 功能点（testbench 计数器统计）：

| 功能点 | 要求 |
|---|---|
| 命中 × {load, store}；缺失 × {干净替换（含空路）, 脏替换} × {load, store} | 6 个分箱全部出现 |
| 写缓冲旁路 | 全覆盖、部分覆盖都出现 |
| kill 的时刻 | 命中时、缺失填充中、设备访问等提交时 |
| PMA 分类 | 每一类区域都被访问到 |
| 维护命令 | 4 种命令和 FENCE.I、FENCE 都执行过 |
| AXI 错误 | 填充错误、设备错误、写回错误都出现 |
