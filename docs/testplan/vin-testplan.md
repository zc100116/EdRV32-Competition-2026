## 1. 验证对象和范围

`edrv32_vin` 模块级验证，覆盖规格第 2、4、5、6 节中 CH0、CH1、内存源、两路摄像头前端和 P1 仲裁。CH2（NPU 输入适配）本阶段未实现，只检查 0x300–0x37F 读为 0。PIX 的功能在 `pix-testplan` 中验证；本方案中 PIX 位置用 testbench 内的直通连线（`pix_out_* = pix_in_*`）和一个可插入随机反压的直通级代替。与 mem_xbar、真实 DDR 模型的联合行为和 S1/S2 流量下的实时性在 SoC 级验证。

`dma2d_rd/wr` 自身的事务拆分已在 `dma2d-testplan` 验证，这里只检查 VIN 发给它们的描述符和整体数据结果。

## 2. 验证环境

- 层级：模块级，`verif/block/vin/`，Verilator `--timing`，自检。
- DVP 模型：新增 `verif/models/dvp_camera_model.sv`，每路一个实例，自己的 pclk（频率可配）。参数：有效宽高、行消隐、场消隐（pclk 数）、`vsync` 脉宽；可注入：行长加减若干像素、行数加减、行内多一个字节、帧中途停止。像素内容来自 testbench 给出的图像数组（按规格 2.1 的字节序输出）。
- P1 从设备：testbench 内 AXI256 存储模型（读写），随机 `awready/wready/bvalid/arready` 和 R 返回间隔，可长时间停止响应（制造溢出），可对指定事务注入 SLVERR。复用 `verif/common/edrv32_axi256_checker.sv` 检查协议。
- APB：`verif/common/edrv32_apb_if.sv` 驱动寄存器。
- 参考模型：testbench 内按规格 2.2、2.6 独立计算（第 4 节）。

## 4. 参考模型

testbench 内维护：每路摄像头送出的原始帧 → 按规格 2.2 整形（补齐、截断、INCOMPLETE）→ 按 2.4 锁存规则和 2.6 R5 选槽 → 期望的 Surface 内容和完成状态序列。溢出由 testbench 根据它让 P1 停顿的时段预期（判定"本帧不得报告完成"，不预测溢出发生在哪个像素）。比对时读 AXI 存储模型。不读被测 RTL。

## 5. 覆盖目标

规格 2.1–2.7、2.9、4、5、6 的每一条至少对应一个测试项；必须命中：每种不完整帧形态、RING_N 每个取值与全部占用、两通道同源、通道在等待写响应时接收下一帧（背靠背）、溢出后下一帧恢复、内存源反压、全部错误代码。

## 6. 通过判据和回归档位

全部测试自检 PASS；smoke：VI-01–08、11、14、15（缩小尺寸）；full：全部（含 1280×720）。lint 和风格检查 0 告警。
