# PIX 验证方案

| 项 | 内容 |
|---|---|
| 版本 | v0.1 |
| 日期 | 2026-10-28 |
| 对应规格 | `docs/spec/pix-spec.md` v0.1；SoC 规格 v0.10 4.5、7.1 |

## 1. 验证对象和范围

`edrv32_pix` 模块级验证，覆盖规格第 2、4、5 节。PIX 与 VIN CH0 的连接（VIN + PIX 联合）在 VIN 模块级测试中补充一项 VI-18（见第 7 节待定事项）；与 DDR、DISP 的端到端结果在 SoC 级验证。

## 2. 验证环境

- 层级：模块级，`verif/block/pix/`，Verilator `--timing`，自检。
- 激励：testbench 内像素流源，按 SoC 4.5 发送帧（`sof`、`eol`、`eof`），可插入随机 `valid` 间隙，可在帧中途停止后发送下一帧的 `sof`（规格 2.8）。
- 接收：像素流接收端，可插入随机 `ready` 反压，逐帧收集输出像素。
- APB：`verif/common/edrv32_apb_if.sv`。
- 参考模型：Python 脚本 `verif/block/pix/pix_ref.py`，按规格 2.1–2.5 逐位实现（只用标准库），输入一帧 RGB565 和本帧配置，输出期望帧。testbench 把输入帧和配置写成文件，运行前由 runner 调用参考模型生成期望文件；参考模型不参照被测 RTL。
- 图像：随机像素、纯色、渐变、棋盘格，以及一张从 `verif/models/` 现有测试图转换的自然图像（无则用渐变加噪声合成）。

## 4. 参考模型

`pix_ref.py` 按规格 2.1–2.5 的公式逐像素计算，图像以外的邻点取 0；每帧使用该帧 `sof` 时的配置（testbench 在写配置时记录生效帧号）。不完整帧不产生期望输出。比对时逐像素比较 RGB565，失败时打印帧号、坐标、期望值和实际值。

## 5. 覆盖目标

规格 2.1–2.9、4、5 的每一条至少对应一个测试项；必须命中：每个 OP 在两级各一次、7 × 7 组合、亮度/对比度两端饱和、二值化阈值两端、最小与最大尺寸、帧中改配置、两组 Gamma 切换、不完整帧、帧中 SOFT_RST。

## 6. 通过判据和回归档位

全部测试自检 PASS；smoke：PX-01–04、06、08（小尺寸）、09、10、12、13；full：全部。lint 和风格检查 0 告警。
