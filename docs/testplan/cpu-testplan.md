## 2. 验证环境

### 2.1 参考模型

使用 **Spike**（RISC-V 官方指令级模拟器），配置为 `rv32imc_zicsr_zifencei`（`RVC_EN = 0` 时去掉 c）、只有 M 模式，内存映射与测试环境一致。用 Spike 的提交日志（`--log-commits`）作为期望的退休序列：每条指令的 PC、指令编码、写回的寄存器和值、访存地址和数据。

不自己编写指令级模拟器。

### 2.2 环境一览

| 环境 | 层级 | 组成 | 用途 |
|---|---|---|---|
| U | 单元级 | 单个子模块 + 自检 testbench | 由 RTL worker 编写，见第 3.1 节 |
| B1 | 模块级 | `edrv32_cpu_core` + **cache 接口模型** + 内存模型 + 中断激励 + 退休追踪器 | 主要验证环境，由验证 worker 编写 |
| B2 | 模块级 | `edrv32_cpu_core` + 实际 I$/D$ + AXI64 内存模型 | 集成检查和 CoreMark 周期数 |

### 2.3 B1 环境的组成

| 组件 | 要求 |
|---|---|
| I$ 接口模型 | 按 3.2 节实现。命中时下一周期返回；可配置缺失概率和缺失延迟（随机 5–40 周期）、`ic_req_ready_i` 随机拉低、按地址注入取指错误；正确响应 `ic_kill_o`、`ic_inv_o` |
| D$ 接口模型 | 按 3.3 节实现。可配置缺失概率和延迟、`dc_req_ready_i` 随机拉低；地址落在设备区域时置 `dc_resp_device_i`，并且只在 `dc_commit_o` 后执行；store 进入 1 项写缓冲并实现写缓冲旁路；按地址注入访问错误；正确响应 `dc_kill_o`、`dc_fence_o`、`dc_clean_all_o` |
| 内存模型 | 平坦内存，按 `+MEM_HEX=` 后门加载程序镜像；设备区域放一个可读写的寄存器组和 `tohost` |
| 中断激励 | 按测试配置，在指定周期或指定 PC 附近拉高/拉低 `irq_meip_i`、`irq_msip_i`、`irq_mtip_i`；`mtime_i` 由 testbench 计数产生 |
| 退休追踪器 | 每个周期从 core 内部的 W 级取出退休的指令（最多 2 条，按程序顺序），输出与 Spike 提交日志格式一致的追踪文件；通过层次化引用读取，不增加 RTL 端口 |
| 比对脚本 | `tools/` 下的脚本，逐条比较 RTL 追踪和 Spike 提交日志；第一个不一致处打印双方的 PC、指令、写回值，然后以失败退出 |
| 协议检查器 | 检查 3.2、3.3 节的接口规则，例如 `ic_req_addr_o` 8 字节对齐、设备访问只在提交后发出、被 kill 的请求不再产生提交 |

### 2.4 测试程序来源

| 来源 | 说明 |
|---|---|
| riscv-tests | rv32ui、rv32um、rv32uc、rv32mi 的 p 环境 |
| riscv-arch-test | 3.10.0（最后一个签名式版本）的 I、M、C、Zifencei、privilege 中适用于 M 模式的部分（该版本没有独立的 Zicsr 用例，Zicsr 由 rv32mi 和 C-01 覆盖）；**必须与参考签名比对**，不能只看是否跑完 |
| 定向汇编测试 | `sw/tests/cpu/` 下，按第 3 节的测试项编写 |
| 随机指令流 | `tools/` 下的随机程序生成器，可以控制指令类别比例和相关性密度（见 3.3） |
| CoreMark | `sw/apps/coremark` |

## 4. 覆盖目标

- 规格的每一条条款至少对应一个测试项（第 3 节的"规格条款"列）。
- 功能覆盖用 testbench 中的计数器统计（Verilator 不支持 covergroup），full 回归结束时输出覆盖报告。必须覆盖的功能点：

| 功能点 | 覆盖要求 |
|---|---|
| 配对结果 | 双发射（不互换、互换各自出现），以及 7.1 中的 4 种失败原因，每种都出现 |
| 旁路源 | 6 个旁路源 × 2 个操作数 × 2 个消费者槽位，全部出现 |
| 异常原因 | 槽 0 的每种异常原因（mcause 0–7、11）都出现；槽 1 的 mcause 0、4–7 都出现 |
| 重定向类型 | E 级（方向、目标；槽 0、槽 1 各自出现）、D 级（槽 0、槽 1 各自出现）、M 级系统指令重定向（MRET、FENCE.I）、异常、中断、MRET、FENCE.I，全部出现 |
| 提前地址 | 4.10 条件的每一种排除情况、提前访问失败的每一种原因，全部出现 |
| 停顿类型 | load-use、乘法、除法、CSR、I$ 缺失、D$ 缺失、设备访问，全部出现 |
| 中断到达时刻 | E-03 中列出的 5 种时刻全部出现 |
