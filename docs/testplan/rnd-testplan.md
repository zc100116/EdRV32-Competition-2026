# RND 验证方案

| 项 | 内容 |
|---|---|
| 版本 | v0.4（已确认，2026-10-31） |
| 日期 | 2026-10-31 |
| 对应规格 | `docs/spec/rnd-spec.md` v0.4；SoC 规格 v0.16 4.2、7.1、7.2、7.4 |

## 1. 验证对象和范围

`edrv32_rnd` 模块级验证，覆盖规格第 2、4、5、6、7 节。
- `dma2d_rd/wr` 自身的事务拆分已在 dma2d 验证方案中验证，这里只检查 RND 的整体结果和协议。
- 与 mem_xbar、真实 DDR 模型和其他主设备并发时的带宽，在 SoC 级验证。
- LVGL 绘制单元驱动的正确性在 RN-17 中验证：主机比对加上板自比对，不做 SoC 级仿真（用户 2026-10-29：能在板上观察的功能不做完整 SoC 仿真）。依赖 B3-3 的 LVGL 移植。

## 2. 验证环境

- 层级：模块级，`verif/block/rnd/`，Verilator `--timing`，自检。
- P4 从设备：testbench 内 AXI256 读写存储模型：
  - 随机 `arready/awready/wready`、R 间隔、B 延迟；
  - 可设固定读延迟；
  - 可对指定事务注入 SLVERR。
  - 复用 `verif/common/edrv32_axi256_checker.sv` 检查协议。
- APB：`verif/common/edrv32_apb_if.sv`。
- 参考模型：Python 脚本 `verif/block/rnd/rnd_ref.py`，只用标准库，不参照被测 RTL。
  - 按规格 2.1–2.6 逐位实现：2.2 的 d、mix、Q 表、over 和混合模式，2.3 的覆盖率，2.4 的模糊。
  - 输入：存储模型初值和命令列表；输出：期望的存储内容。
  - 附命令编码函数，只用于产生激励。
- 新 RTL 的单元测试由 RTL 员工编写；模块/SoC 测试由独立验证员工按本方案编写，禁止阅读被测 RTL。仅 V2-INTEG 执行整体联调回归，前序员工只运行自身参考模型或单元级检查。
- 测试图：随机像素、棋盘格、带编号的网格（便于定位坐标错误）、全 0/全 255 的 α 平面。
- 比对：每条测试读出目标缓冲整体和一圈外框（外框预填随机值，检查绘制区域外不变）。失败时打印命令序号、坐标、期望值和实际值。

## 4. 参考模型

- `rnd_ref.py` 逐条执行命令：
  1. 先按规格第 6 节判断是否非法：非法时期望 ERR_CODE 3、存储不变、停止；
  2. 否则按 2.5 求绘制区域，对区域内每个像素按 2.6 求 S_c、sa（或直接值），再按 2.2 写回；
  3. COPY 先读完整个源区域；
  4. BOX_SHADOW、BLUR 只在内存中计算中间结果，不比对临时区内容。
- testbench 读取整个存储模型（目标、外框、源、临时区以外），与参考逐字节比对。
- RN-17 的参考是 LVGL 自带的软件渲染结果，不是 `rnd_ref.py`。
- 扩展方式：保留旧命令的逐位运算顺序，在同一解码器加入0x09–0x0D和参数块读取；只扩展规格第6节的合法OP/源格式/MODE集合，不新增参数检查。
- 几何 oracle 直接在每个子点代入边方程和圆二次式，不复用 RTL 的逐像素差分算法；无AA取中心，AA固定16点，inside并集后计数。附手算的小三角形/共边、线、弧及圆q初值示例，逐项检查EDGE_INCL、signed48符号和分数比较。
- 几何随机参数按 rnd-spec v0.4 2.3 的范围生成（圆 q 与 8E 在 signed36、圆步差在 signed24）；定向覆盖 q、8E 和步差的范围边界（取合法参数可达的最邻近端点，例如步差 −8388608、+8388592），结果仍与 oracle 逐位一致。
- AFFINE oracle 用 Python 整数按绝对x/y直接计算u/v，负数用floor；四tap独立解码/越界置零，严格按预乘、加权舍入、Q表还原、重新着色、圆角、over的顺序。参考不模拟源窗口/替换，避免与RTL同错。
- MASK直接更新alpha；BLIT参数块和阴影挖空复用原C函数。新增每命令手算示例及f/g、alpha、边界定向算术自测；参考员工不得读取RTL。
- 独立验证员工扩展vectors、APB/AXI检查和test.yaml；以同一初始存储生成硬件期望图，比较整个目标及外围、源、命令和参数（只排除规格未定义的临时区）。种子和命令保存在build/rnd，失败打印RN编号、命令/参数地址、坐标、期望/实际和时刻。
- RN-17在锁定LVGL同对象/同时刻分别重画，记录RGBA、任务coverage/几何边界；新增旋转ARGB、弧、widgets帧。分别记录非边缘最大通道差、>1LSB像素比例、几何边缘带内/外直方图；MASK另记alpha差。不得用4×4量化步长替代相对LVGL的误差界。

## 5. 覆盖目标

规格 2.1–2.6、4、5、6、7 的每一条至少对应一个测试项。必须命中：
- over 的 oa = 0、sa = 0、sa = 255、Da = 255 分支；
- 全部 10 种像素格式在允许的命令中各用一次；
- 亚字节和字节级的任意起始偏移；
- 圆角半径被截断；
- 渐变饱和；
- COPY 四个方向的重叠；
- 模糊越界；
- 瓦片翻转；
- 命令之间的读写依赖；
- 每种错误代码；
- ABORT 在途事务；
- RN-21–28各项两种采样/滤波选择、圆头并集、MASK直接写回、参数块读取、32×16残块和32源块冲突；
- AFFINE全部源格式、颜色键/重新着色/四MODE/圆角、越界透明、预乘插值；
- RN-17新增三类帧和profile中的G1–G4认领；未被这些能力覆盖的原不支持条件保持原判定。

## 6. 通过判据和回归档位

- 全部测试自检 PASS；硬件相对整数参考逐字节0差。
- v2 smoke 在原smoke基础上加入 RN-21–28 表中指定代表项；full 加入完整组合和RN-19全部13种命令。原26项和531项只是v0.2基线计数，v2实际向量数由验证员工生成后在报告填写。
- V2-INTEG 统一运行一次完整模块回归及所需smoke/perf；前序员工不运行完整回归。旧RN-18在同一台机器、相同模型/激励下改前改后比较，各场景周期不增加；RN-29记录G1/G4吞吐、DDR读beat和资源参考。
- RN-17原阈值不放宽；新增几何边缘带按规格第8节定义（两几何边界各扩1像素之并集），带内无单点上限，带外≤1 RGB565通道LSB，整帧>1LSB像素仍≤1%。MASK的ARGB目标边缘带外alpha差≤1/255。
- `python3 sw/apps/s3/host/rnd_profile.py`：G1–G4覆盖任务不再因几何、遮罩、bg_cover、rotation/skew/clip_radius或AA变换退回软件。虚线/points等范围外原因不要求消除。`verif/soc/board_render` smoke通过。
- 驱动范围检查（rnd-spec v0.4 5.4）：主机测试对 TRIANGLE、LINE、ARC 各构造一例超出 2.3 范围的任务，确认退回软件；16 场景 profile 的认领任务数与 v0.3 相同。
- 静态验收：rtl/media/rnd、RND技术包装和edrv32_fpga_board_render_top风格/lint 0告警；Yosys对比设计记录估算，最终PDS125MHz与D8另行上板回填。
- smoke：`verif/unit/rnd_*` 单元测试；`verif/block/rnd/smoke`，从现有向量中选 26 项代表用例（列表在 `verif/block/rnd/run.py` 的 `SMOKE_CASES`），每个 RN 项至少一项：RN-01 两种格式、RN-03 两种格式、RN-04–RN-09、RN-10 两种格式（重叠方向 dr）、RN-11 R=8、RN-12 R=8、RN-13–RN-16、RN-20 水平和竖直两项；`verif/unit/rnd_engine/smoke` 只跑 case137/139 两个向量。冷编译超过 60 秒，属于 9.1 的例外，用于改动后的快速回归。
- full：全部功能项（RN-18/29性能测量除外），保留原向量并增加v2项；RN-05、11、12、15的完整组合也在此档。
- perf：RN-18、RN-29。
- lint 和风格检查 0 告警。
- RN-17 容差（用户 2026-10-29 定稿）。差值按 RGB565 的最低位计：两边的像素各自截成 R5/G6/B5 后逐通道相减。
  - 两种渲染器覆盖率都为 255 的像素（全覆盖区），每个通道相差不超过 1 个最低位；
  - 全帧中任一通道相差超过 1 个最低位的像素，不多于全帧的 1%；
  - 边缘像素（任一渲染器覆盖率不为 255，以及 BOX_SHADOW 的模糊区）不设单像素上限，数量由上一条约束，上板时目视检查。
  - 依据：LVGL RGB565 混合把透明度量化为 5 位，rnd-spec 2.2 按 8 位混合，两者普遍相差 1 个最低位；rnd-spec 2.3 按像素中心横截面计算圆角覆盖率，LVGL 用 4 倍采样的二维圆，边缘覆盖率最多相差 79–95/255；BOX_SHADOW 两边的模糊算法也不同。主机实测 11 帧的结果见 `sw/apps/s3/lvgl/RN17_RESULTS.md`：全覆盖区最大差 1 个最低位，超过 1 个最低位的像素最多 0.465%。
