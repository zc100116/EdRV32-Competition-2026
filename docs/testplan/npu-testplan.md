## 1. 验证对象和范围

- 本模块验证：`edrv32_npu` 整体（寄存器块、描述符读取、调度、读写 DMA、行缓存、窗口生成、MAC 阵列、量化、激活表、融合残差加、POOL、UPSAMPLE、后处理类别最大值/两阈值/候选压缩/gather/DFL/候选写出、错误和 ABORT、两个异步桥）；离线编译工具和 Python 参考模型的自检。
- 留给上一层：
  - VIN 中的 NPU 输入适配（随 VIN 验证）；
  - NPU 经 mem_xbar P3 与其他端口共享带宽（SoC 级场景 S1）；
  - PLIC 中断同步（系统子系统已覆盖）；
  - CPU 排序、NMS、letterbox 映射/裁剪和 EDDT，以及候选 DMA/cache 所有权（SoC 软件集成，测试项 PP-SW-01/02）；
  - 检测精度（mAP）。本方案只保证 RTL 与参考模型逐位一致；量化质量沿用旧工程流程（INT8 mAP50 0.623），由离线工具负责。

## 2. 验证环境

### 2.1 层级

| 层级 | 目录 | 对象 | 编写者 |
|---|---|---|---|
| 工具自检 | `tools/npu/` 内的 `test_*.py` | 离线编译工具、参考模型 | 各自的作者 |
| 单元 | `verif/unit/npu_<子模块>/` | 后处理 max/标签/前递、DFL、候选打包，行缓存、窗口生成、MAC 阵列、量化、写回打包、描述符译码、寄存器块、读写 DMA、AXI256 异步桥 | RTL 作者 |
| 数据通路 | `verif/unit/npu_datapath/` | 数据通路子顶层（行缓存到写回打包），由测试直接灌入行数据、权重和量化参数 | 数据通路 RTL 作者 |
| 模块级（NB 环境） | `verif/block/npu/` | `edrv32_npu` 整体 + 下列模型 | 独立验证 worker，不阅读被测 RTL |

### 2.2 NB 环境组件

| 组件 | 说明 |
|---|---|
| 时钟 | clk_npu 默认 180 MHz、clk_mem 125 MHz，后处理设计预算验证可用 200 MHz；plusarg 可改频率比（含 1:1、clk_npu 慢于 clk_mem） |
| APB 驱动 | clk_mem 域 APB4 主设备，访问公共和私有寄存器；复用或扩展 `verif/common/` 中已有的 APB 组件 |
| 存储模型 | 新增 `verif/models/npu_axi256_mem.sv`，见 2.3 |
| AXI256 协议检查器 | 复用 `verif/common/edrv32_axi256_checker.sv`，接 NPU 的 clk_mem 侧主口；主设备侧 RREADY/BREADY 允许拉低（SoC 4.2） |
| APB 检查器 | 复用 `verif/common/edrv32_apb_checker.sv` |
| 镜像装载 | 测试开始时按 plusarg 把离线工具生成的模型镜像、描述符表、输入、参考输出读入存储模型和比对缓冲 |
| 比对 | 描述符全部完成（`IRQ_STAT.DONE`）后，按参考模型给出的输出区列表逐字节比对；失败时打印描述符号、地址、期望值、实际值 |

### 2.3 存储模型 `npu_axi256_mem.sv`

| 项 | 规定 |
|---|---|
| 接口 | AXI256 从设备（SoC 4.2），支持主设备 RREADY 反压 |
| 存储 | 字节级稀疏存储，按 plusarg 装入多个 hex 段 |
| 写可见性 | 一笔写的数据在该笔 B 响应发出时才对之后的读可见；B 响应延迟可配。用于检查写响应栅栏（NB-SQ-01） |
| 三档时序 | `zero`：AR/AW 立即接收，首拍延迟 1，每周期 1 拍；`latency`：首拍延迟 `MEM_LAT` 周期（默认 94，对应 N-E1 板测等效点），每周期 1 拍；`bw`：在 `latency` 基础上把数据拍限制为 `MEM_BW_MBPS`（默认 1400 MB/s，按 clk_mem 换算为每 N 周期 M 拍的令牌） |
| 在途 | 读写各最多 `MEM_OUTST`（默认 8）笔，按到达顺序返回 |
| 错误注入 | plusarg 给出读或写的错误地址区间，命中的事务必须分别覆盖 SLVERR 和 DECERR |
| 统计 | 读拍数、写拍数、首笔请求到最后响应的 clk_mem 周期数，供性能报告使用 |

### 2.4 镜像和参考数据

| 来源 | 产物（`build/npu/<用例>/`） |
|---|---|
| 离线编译工具 `tools/npu/` | `model.hex`（权重、量化记录、激活表、三份后处理查表）、`desc.hex`（描述符表）、`input.hex`（INT8_C4）、`regs.txt`（基址寄存器和 DESC_BASE/COUNT 取值） |
| 参考模型 `tools/npu/ref/` | 每条描述符执行后输出区的内容 `ref_<n>.hex`，最终输出 `ref_out.hex`，比对区列表 `check.txt` |
| 随机用例生成器 `tools/npu/gen_case.py` | 小形状随机层：随机权重、量化参数和输入，经编译工具和参考模型生成上述文件 |

后处理用例必须另有 raw box/cls 输入、寄存器配置、完整候选参考列表及 CPU 最终 EDDT，均放在 `build/npu/<用例>/`。EN=1 且不写 cls 时，参考 cls 必须从离线结果取得，不得从禁写 DDR 空洞读取。模块环境必须能对写回支路连续灌入带标签 beat，并在 DUT 边界记录接收时刻；SoC 软件环境必须包含 CPU、D-cache、BSP cache 操作和 NPU DMA。

整网用例的真实权重和输入图像来源见第 7 节待定事项 1。

### 3.9 后处理方案 (b)（PP）

本节条款编号必须对应 NPU 规格 v0.10。除明确列为 SoC/Windows 的项外，必须在单元或 NB 环境执行；小规模定向项属于 S，全容量与真实帧属于 F，周期/资源测量属于 P。

| 编号 | 规格条款 | 内容 | 激励 | 检查方法 | 档位 |
|---|---|---|---|---|---|
| PP-01 | 2.6、4 | 新寄存器和两阈值边界、零候选完成 | IDLE 配置后复位/SOFT_RST；三个 head 分别给 可表示的 best=TH−1/TH/TH+1、probability=TH−1/TH/TH+1，INT8 阈值 −128/127/128；默认 103/105/103、4194304 与提高阈值各一次 | 必须核对八个寄存器复位均为零、DOORBELL 清 POST_COUNT/POST_DONE、第一关 >= 与第二关严格 >、128 全拒绝；0 候选必须 POST_COUNT=0、POST_DONE=1 且 DONE_COUNT/IRQ 仅完成一次，候选区无写事务 | S |
| PP-02 | 2.6、5.2、5.6 | 同分类别 tie、每格至多一条和两格同时入队 | 在同一/不同 C16 plane 设置相同最大值，含 class 0/15/16/63/64/79；同一 beat 两格分别通过/拒绝 | 必须逐字段比对 oracle，tie 取最小 class_id、anchor 无重复，两格通过必须均入队，入队顺序必须符合输入标签 | S |
| PP-03 | 2.2、4.4、5.6 | plane/row/C32 block/pair/half-tail 标签与 best 前递 | 按真实行/块/分块平面交错灌入 C80，连续访问同一 best 地址；覆盖行尾、首末 pair、第三 C32 半块和 head 切换 | 必须比对每个 anchor 的 max/class/概率，五个 plane 完成前不得输出；plane 0 必须覆盖上一帧 best，半拍选择和前递必须逐字段正确 | S |
| PP-04 | 4.4、5.6 | DFL 边界和完整中间位宽 | 四侧分别使用全相等、单 bin 峰值、−128/127、峰差 255、首/末 bin 峰值及舍入半点；含首末 cell、三种 stride 和超出图像的框 | 必须以 oracle 整数公式逐字段比对 Q8 未裁剪框；检查 den 25 bit、num 28 bit、舍入分子 36 bit 不截断，四侧地址和 32 B beat 的高/低半选择正确 | S |

## 4. 参考模型

- **功能**：`tools/npu/ref/` 中的 Python 模型按规格 2.1–2.4、4.1、4.2 解释描述符表和存储镜像，按描述符顺序执行，产出每条描述符后的存储内容。它只读描述符字段和存储，不调用编译工具的内部函数；派生字段（ROW_SLOT_BEATS、K_COUNT 等）只用于 RTL，参考模型从形状字段计算。
- **后处理 oracle**：必须使用 `tools/npu/yolo_post_ref.py` 的 `decode_candidates`、整数 DFL、排序/NMS 和 EDDT 路径。模块比对必须保留 NMS 前全部候选，以 anchor 关联逐字段比对 xyxy_q8/probability_q24/class_id/anchor，并单独检查硬件按入队次序输出；不得要求硬件输出等于 oracle 按 head/cell 遍历的次序。默认结果必须相同；可调阈值验证必须按相同整数定义扩展 oracle：先 `best>=INT8_THh`，再查表要求 `probability_q24>POST_PROB_TH`，不得用浮点比较替代。
- **独立性**：参考模型和 RTL 由不同的 worker 编写；参考模型的整网结果再与旧工程主机算术逐层比对（TL-04），两者独立实现同一套量化算术。
- **性能参照**：周期数与 N-E2 周期模型比较，偏差写进测量报告，不作为通过判据（规格 8.6）。
