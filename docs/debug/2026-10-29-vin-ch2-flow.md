# VIN CH2 内存源反压与 letterbox 补齐限速

## 1. 现象

SC-05 的内存源 1280×720 同时送 CH0、CH2 时，CH2 上报溢出错误 3，整帧丢弃。
本次依据已确认的 `vin-spec` v0.3（`6537bc8`）实现 Task V-F1。
原始 SoC 证据见 `zc100116/task-soc-verif` 分支的
`docs/debug/2026-10-29-soc-sc05-ch2-overflow.md`；本 Task 未运行 SoC 测试。

## 2. 复现

修改前基线为 `6537bc8`；RTL 提交 `a6d824a`、`a6f6cd4`，
单测和测量脚本提交 `7e36bed`。
工具为 Verilator 5.020、Yosys 0.70+219（5053d0e26）。
单元激励为确定性 RGB565 图案，AXI 接收端按固定周期插入停顿，无随机种子。

```sh
. ~/.local/opt/edrv32/env.sh
python3 tools/regress.py smoke --path verif/unit/vin_ch2 -j 1
```

单元测试旧版的内存源停写用例直接期望溢出；本次改为尊重 ready 的完整帧输入，
分别在顶部补齐、有效行、EOF 后保持写侧停止 20000、12000、12000 个周期，
要求无溢出且逐字节正确。旧 RTL 在第一段停顿中即不满足无溢出要求。

## 3. 观察

新增单元场景中，每张完成的 Surface 都检查 983040 字节、30720 beat：

- 内存源长停顿：首个 W 在 SOF 后 20000 周期，EOF 后 13297 周期写完。
- 摄像头帧首停顿 1500 周期：首个 W 在 SOF 后 1500 周期，补齐及有效数据正确。
  此场景每三个 clk_mem 周期送一个 RGB565 双像素字，首次有效输出晚于顶部补齐。
- 摄像头有效行停顿 12000 周期：只报告一次溢出，不报告完成；随后完整帧复用槽位。

## 4. 根因

基线 `edrv32_vin_ch2.v` 的 `source_ready_o` 恒为 1，顶层忽略该端口。
`edrv32_vin_ch2_data.v` 的上下补齐各 960 beat 连续输出，512 项 FIFO 无法吸收
停写时的全部补齐。旧 v0.2 本来允许内存源帧在 CH2 溢出，v0.3 已改变此契约。

## 5. 修复

### 补齐与摄像头

补齐计数器只在 `padding_ready_i` 为 1 时递减，输出 valid、EOF 同步限速。
`padding_ready_i = count_r < 511`：`count_r` 已包含接受但尚未写 RAM 的 beat，
另留一项给 `u_data.valid_o` 中尚未被父模块计数的输出。无弹出时，count=510
且已有一个输出，可再生成最后一个补齐，随后依次占用第 511、512 项；不会越界。

有效 beat 仍不等待 FIFO。有效 beat 与未结束的顶部补齐相撞时，通过同拍寄存的
`blocked_o` 接入原有 overflow 判定，保证补齐优先、整帧丢弃。摄像头 ready 恒为 1，
2.7 的丢帧状态机、DMA 收尾、槽位回退及错误事件通路保持原样。

### 内存源阈值推导

接收许可寄存为 `source_capacity_r <= count_r < 430`；顶部补齐未结束时也不接收。
当 FIFO 计数上升到 430，寄存许可最多再接收一个双像素字。水平和、行 RAM 读取、
像素寄存三级加这个字，最多有四个待打包像素；和 pack 中已有的最多七像素相加，
最多再成一个 beat。另有一个已在 `valid_o` 中的 beat，总计最多两个在途 beat。

最后一个输入字可启动自主冲刷：640 像素，即额外 80 beat。即使 EOF 恰好遇到
ready 撤销且写侧完全停止，所需容量上界为 `430 + 2 + 80 = 512`。80 beat
冲刷也包括在该预留里，因此不需要给缩放流水线增加逐级暂停；底部补齐随后继续
按上述独立空位条件输出。顶部补齐与内存有效输入串行，不与此预留争用。

顶层只对内存源将 CH2 ready 加入多播握手，并同时限定 CH0/CH1 的输入 valid，
保证暂停时其他内存源通道不会重复消费同一字。摄像头的共享 ready 不引用 CH2。

### 组合深度

`verif/unit/vin_ch2/flow_timing.py` 使用 VIN 正式 filelist，技术 RAM 作黑盒，
`synth -flatten -noabc; abc -lut 4; opt_clean`；在 FF、黑盒、输入边界截断，
递归统计 LUT 输出深度。此结果是组合级数代理，不代表布局布线延迟。

| 对象 | 最长 LUT4 级数 | LUT4 数量 |
|---|---:|---:|
| 修改前 `6537bc8` | 34 | 12247 |
| 本次流控 RTL `a6f6cd4` | 34 | 12259 |
