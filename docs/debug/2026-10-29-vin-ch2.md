# VIN CH2：NPU 输入适配与单行 RAM 调度

## 1. 现象

B2 需要将 VIN 所选源的 1280×720 RGB565 帧转换为 640×384 INT8_C4 Surface。
CH0 经 PIX、CH1 旁路的行为不变；CH2 在 PIX 前分流，独立参与 P1 写仲裁，
任何情况下都不参与源 READY 或 urgent 的产生。

## 2. 复现

实现依据：`vin-spec` v0.2，Task B2-1b；独立模块验证依据 `vin-testplan` v0.3。
RTL 与单元测试提交：`b6b3bb9199a4e5ad7042fbe58f1b6af3f1435925`；
最终验证结果见第 6 节。

工具：Verilator 命令报告版本 5.020（Debian 5.020-1）；
Yosys 0.70+219（5053d0e26）。Linux 端先执行：

## 3. 观察

顶部 12 行共 960 个 256-bit beat。输入第一个偶数行只有 640 拍，不能等到
第一个奇数行的平均像素到达时再尝试串行补齐顶部，否则需要额外的暂存空间。

CH2 使用一个 `edrv32_ram_pix_line`：偶数行保存水平和；奇数行读取水平和，
以平均、量化后的像素替换；下一偶数行读取这些像素，同时写入新的水平和。
因此第一行有效输出安排在输入第 2 行，顶部 padding 有足够的独占输出时间。
最后一行在源 EOF 后从同一 RAM 读出，随后输出底部 960 个 padding beat。

## 4. 根因与量化恒等式

规格量化在整数域可以精确化简，不需要乘法器、除法器或 256 项表。
令 `c=2k` 或 `2k+1`，`0<=k<=127`：

- 偶数时，`(254c+255)/510 = k + (255-2k)/510`，余项在 `[0,1)`。
- 奇数时，`(254c+255)/510 = k + (509-2k)/510`，余项也在 `[0,1)`。

所以对全部 256 个输入，`floor((254c+255)/510) = c >> 1`。
先平均再量化精确等于 `(four_pixel_sum + 2) >> 3`。
RTL 保留 10-bit 四点和及舍入，只取 `[9:3]`；每通道再补一个零高位。
独立 testbench 按原规格两步公式计算参考值，没有使用这一恒等式计算期望值。

## 5. 实现

### 5.1 数据与延迟

输入先经过 RGB565 展开及三路 9-bit 水平和寄存器。行 RAM 同步读取和标签
对齐之后，奇数行计算四点和、舍入和量化，并写回行 RAM；下一偶数行或 EOF
冲刷阶段读取量化像素，经过单像素寄存器、8 像素打包和 whole-beat 输出寄存器，
再进入 FIFO 写入寄存器、FIFO RAM、两槽读头和 `dma2d_wr`。

行 RAM 的读延迟为 1 拍。读回平均像素时，从对应偶数行输入字到打包输出为
3 拍，另需收齐一个 beat 的 8 个像素；首行还包含上述一对源行的缓存调度延迟。
顶部 padding 从 SOF 后一拍开始产生，每拍一 beat。单位测试的 AXI 端首个 padding
数据在 SOF 后 19–20 拍握手，EOF 到最后一个 AXI 数据握手为 1853–1861 拍，
包含测试所加的 AW/W/B 停顿；它们不是不带反压的固定流水延迟。

| 存储 | 实例/容量 | 实际用途 |
|---|---|---|
| 行缓存 | 一个 `edrv32_ram_pix_line`，1024×48 bit（6 KiB） | 地址 0–639；偶数行 27-bit 水平和，奇数行 24-bit 量化像素 |
| CH2 写 FIFO | 一个 `edrv32_ram_vin_wfifo`，512×288 bit | 16 KiB payload，加 2 KiB strb；容量包含已接受、尚未写 RAM 的 beat |
| FIFO 读头 | 两个 288-bit 寄存器 | 提前预留输出位置，寄存捕获使能 |
| P1 B 所有者队列 | 16×2 bit | 三路各最多 4 个 outstanding；按 AW 顺序分发 B |

CH2 复用 CH0/CH1 的 R5 选槽和单个 pending 描述符结构；描述符固定为
`width_bytes=2560`、`height=384`，`OUTSTANDING=4`。缓存满时停止接受该帧的
输出 beat，已接受突发排出后 ABORT 收尾，不报告完成并回退槽指针。
源像素仍被消费，含内存源；选路仅在共享源真正握手时向 CH2 交付一个字。

CH2 配置和状态位于 0x300，新增 IRQ bit9 与 PERF5/8/11，错误码 3/8。
源尺寸错误、非法 SRC、非法 RING_N 拒收；全部槽忙计 SKIP。没有增加配置参数、
额外检查、超时或保护路径。性能事件仍先寄存再独立累加。

### 5.2 Yosys 参考测量

技术 RAM 按黑盒处理；`synth -noabc; abc -lut 6`，分层累加 LUT/FF。
结果仅用于结构比较，不能当作 PDS 资源或 125 MHz 时序收敛结论。

| 对象 | LUT6 | FF | 行 RAM | VIN FIFO RAM |
|---|---:|---:|---:|---:|
| 完整 VIN | 10175 | 8491 | 1 | 4 |
| CH2（含其 DMA） | 1523 | 2049 | 1 | 1 |
| CH2 数据通路 | 269 | 564 | 1 | 0 |
| 三路 P1 仲裁 | 447 | 51 | 0 | 0 |

完整 VIN 的第四个 FIFO RAM 属于已有内存源输入缓冲；三个写通道各一个。
CH2 数据通路水平和寄存器 D 输入最大 3 级 LUT6，四点和/舍入/存储格式选择
最大 6 级；量化取位本身为连线，额外算术级数为 0。

先 `proc; flatten; opt_expr; opt_clean; opt_dff; opt_clean`，不合并等价寄存器，
CH2 自有宽数据使能：两个 FIFO 头各 288 bit，由 `fifo_capture0_r/1_r` 驱动；
打包移位 224 bit，由 `pixel_valid_r` 驱动。没有新增组合控制的宽数据使能。
已有公共 `dma2d_wr` 的 288-bit 保持寄存器组合使能沿用 V-R8 第 8.5 节已确认边界，
本 Task 没有修改公共 DMA。

## 6. 防回归与验证结果

单元测试 `vin_ch2` 逐字节检查四张完整输出帧，每帧 983040 B、30720 beat。
构造 RGB565 2×2 绿色块使平均结果覆盖全部 0–255，因此包含所有量化跳变邻近值；
红蓝独立图案检查展开、取整和通道次序。覆盖全黑、全白、两处 padding 边界、
每行首尾 beat、stride 空洞、源空拍、INCOMPLETE、写响应错误、内存源溢出、
槽号回退、非法尺寸/SRC/RING_N、全部槽忙、ABORT 以及恢复。

既有 `vin_regs` 增加 CH2 寄存器、IRQ bit9 和 PERF5/8/11 检查；
`vin_p1_arb` 扩展为三路各 16 个突发的全长序列，独立核对 W/B 所有者；
`vin_ch` 仅适配仲裁器端口扩展。

最终结果：风格检查 9 个 RTL 文件、0 告警；`edrv32_vin` 的 `-Wall` lint
0 告警。全部 `verif/unit/vin_*` 共 7 个目录，smoke 7/7、full 7/7。
删除末行冲刷的 4 拍等待后，已重新运行 CH2 两档，四张完整帧仍逐字节通过。

- CH0/CH1 通道 RTL 未改；源 READY 与 urgent 仍只由原有两通道决定。
