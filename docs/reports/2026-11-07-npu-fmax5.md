# NPU FMAX5：布线主导路径本地化
基线 `b5be940c`（卡63）；改后为本报告所在提交（`git log -1 -- docs/reports/2026-11-07-npu-fmax5.md`）。
目标 PG2L200H-6 FBB676、clk_npu 5.000 ns、WNS ≥ +0.300 ns；本轮 Linux 验证不产生 PDS 布线结果。
原始时序：`origin/win/20261107-63-npu-timing-probe-r4:tasks/win/20261107-63-npu-timing-probe-r4/artifacts/R4/`。
采用该处 top200、top20_detail、near_positive、high_fanout、preserve_registers；卡63 WNS −0.027 ns、2违例。
以下改后级数/扇出为 RTL 结构预算，须由 PDS 复核，不等于路后测量。

| 路径 | 改前级数/最大扇出 | 改后寄存边界、级数/每份扇出预算 |
|---|---|---|
| bank wr_addr→RAM | 0/96 | bank×segment 保留地址；0/4（一个256位wrapper含4个DRM） |
| wr_valid→RAM | 1/32（共享段使能） | 每segment预译码写使能寄存；0/4，≤16 |
| conv weight_addr/data→wr_slice | 0–1/256 | bank入口数据与逐beat有效寄存；0/8数据，0/32片使能（beat7另驱动3个提交FF）；RAM提交+1拍 |
| rd_segment_output→window weight | 0/256 | 每4通道一份选择寄存，共8组/bank；原有读边界，0–2/32 |
| skew rd_en→RAM | 0–1/15（top20明细） | 最后skew级按segment复制；0/4；bank0直连输入≤32 |
| activation/local_activation→APM | 0/20 | 原skew末级每链复制，前缀共享；0/≤5个同一APM引脚（符号扩展），中间源≤4 |
| lane_weight→APM | 0/≤4个APM引脚（含符号扩展） | 原有输入边界两份权重寄存；0/≤2，不增加MAC延迟 |
| a3_pixel→a4_activation | 1/128 | 每像素四份32位选择控制；1/32 |
| schedule_row→自身/weight_base/cmd_base | 6–7/74 | 三个行坐标与输出行同步递增；并行slot匹配/OR选择，预算≤4级；坐标位≤8 |
| stop→residual_wr_data | 2/262 | residual负载逐拍采样，valid单独控制；该CE路径消除；top stop按conv/read_dma两份保留 |

只复制已列出的路径类别；MAC仅复制skew末级，避免整条skew复制；数据寄存器不复位。
副本统一使用 `(* keep = "true", syn_preserve = 1 *)`；额外寄存位约6,031（RTL估算：MAC 5,120、weight_store 861、window 6、conv 43、top 1），APM/DRM实例增量0。
写beat7提交从+1→+2拍，conv block_finish从3→4；协调者批准单元scoreboard/首次末行读顺延，读延迟仍2+k。
调度器、激活/权重读、MAC无新增流水边界或行间气泡；512 MAC/拍和外部契约不变。
