# CPU v0.17 后端

环境：Linux，Verilator 5，GCC 15.2，SIM_MODE；RTL 基线 798530a8，规格更新至 884482a9。
本报告分节与对应 RTL 同提交；PDS/器件 PG2L200H-6 的 150 MHz 实测留待卡 59。

## 第 1 步：寄存重定向、mul4、旁路

- E/D 判定与训练完整寄存；M 陷阱/系统前端重定向也寄存，core 当拍冲刷；新增 stage/PC 追踪。
- E 重定向取消年轻 E 请求、kill 同组年轻 M 访存；M 年轻指令不能提交。
- APM 输出直接进入本地 64 位寄存器；W2 写回/退休；W2 经 RF 写读预合并，W 仍有真实旁路。
- 旁路先确定来源及管线映射，再用独热 AND/OR 选数据；E 数据不经过槽互换 mux；分支操作数独立副本。
- D$ 先合并非 lookup 响应，再做最后一级路选择；前端停顿用寄存副本。
- 级数仅结构估计：E→预测器/IB 13/12→两段各≤7；APM→选择 6→0；ALU 环 9–10→约7。
- D$ tag→响应旧约4→约4；到操作数的跨模块映射仍须 PDS 校准，不能把估计当时序签核。
- 单元 cpu_mul、cpu_core_smoke_no_c、cache_dcache PASS；风格 0 告警；子系统 `-Wall` lint 结果见 build/step1-lint.log。
- B1 smoke：8 PASS / 32 FAIL（build/step1-b1.log）；协调者确认等待 N-VERIF 更新后在 N-INT 重跑。
- b-01/e-01/p-01：旧 debug 比较 W 而非 W2；b-03：D 代价改3且旧检查采样活动 D 目标；b-07：现规范允许同组年轻 load 请求、随后 kill。
- b-08：旧同拍 D 槽观察；b-09：旧冷 JAL 配对原因检查；p-04：mul 延迟实测4，旧值3；p-03：W2 RF 编码0，旧覆盖要求5。
- b-02/e-07/m-01/m-04/p-02/p-08、9 个 ISA：程序完成，旧 tohost 结束提前，追踪仅缺最后 store。
- random 8 项：旧检查禁止寄存冲刷撤销 E 请求；其中 low-dep-00 为 stalled-request checker，其余为 request-valid checker。
- R-05 CRC PASS，窗口 1,955,141 周期、2,479,576 指令、5.114721 CoreMark/MHz；比方案A参考 1,956,461 少1,320（0.0675%）。
- 窗口 HPM 1..16：921055,637466,396620,505036,261519,151847,160911,46522,165205,0,0,94522,278,22,0,46212。
- 复现：`. ~/.local/opt/edrv32/env.sh`；所有仿真命令前加 `flock /tmp/edrv32-sim.lock`。
- 单元：`python3 tools/regress.py smoke --path verif/unit/<上述目录> -j 1`；B1：`python3 tools/regress.py smoke --path verif/block/cpu -j 1`；R-05：`python3 tools/cpu/b2_run.py r05`。
- lint：在 rtl/filelists 下 `verilator --lint-only -Wall +define+SIM_MODE --top-module edrv32_cpu_subsys -f cpu_subsys.f`；风格：`python3 tools/check/verilog_style.py <改动RTL>`。
