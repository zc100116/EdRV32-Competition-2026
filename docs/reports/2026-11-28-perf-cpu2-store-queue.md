# CPU v2 LSU store 队列容量扫描（C11）

- 模型提交：`3b45c10bd`；输入与 M01 相同：`build/cpu-v2/isa/zba/{coremark,vision,render}/{coremark.elf,spike.log}`（输入提交 `1a26a7924`，GCC 15.2.0）。
- 工具：PyPy 7.3.17 / Python 3.10.14 回放，CPython 3.12.3 单测；trace 周期估算，器件、速度等级和频率约束不适用。
- 配置同 M01：单发射精简 / 双发射满配 combo4-zba，NONE、异步 RF、IcacheProbe(1)、寄存前端余量、C07 DIV；完成窗口固定 8/16，释放后次拍可用信用。
- 扫描显式启用 `store_queue_model=True`，容量 `store_queue_entries=0/2/4`（0=∞）；默认仍为 False/0，保留原行为。可缓存 store 准备即 done，退休标记提交，随后每拍至多排空一个 beat；设备保持队头授权。
- ID 预留登记容量，双 beat 占两项；同字 load 在 LSU 等全部冲突 beat 排空后走普通访问，early 结果作废；独立 ALU 可继续。D$ 按 hit-only 写缓冲下一拍写阵列，FENCE 等队列/写缓冲空。
- Δ=相对同宽同负载的∞队列周期；CoreMark/MHz=1e7/周期。等待次数统计 ROI 退休且曾同字等待的 load，等待拍统计 ROI 的 LSU 同字阻塞拍，非全核停顿拍。
