# CPU 时序第二轮（2026-11-06）

## 0. 级数校准
输入 RTL：卡59 `b1e9d08b`，卡60 `1281d669`；PDS 2022.2-SP6.1，PG2L200H-6，150 MHz，slow setup。
Linux：Yosys 0.70+219 / 5053d0e26，XC7 LUT/MUXF/CARRY4 代理；顶层 `edrv32_cpu_subsys`，IP 使用 `ip_stubs.v`。
`cpu_levels.py` 输出每个起点/捕获引脚对的最大级数及该最长路径最大负载数；保留寄存器名称、副本，支持名称正则。
LUT、MUXF、CARRY4 各1级，INV为0；异步 LUTRAM 保留读地址依赖，存储输出另作起点，黑盒内部级数不计；CLR/PRE 不作 setup 终点。
按 PDS 清单的完整起终点匹配明细，再映射 RTL Q 别名；`[bit]_N`、`_r_N_copy[bit]` 为 PDS 物理副本命名。
共91条：卡59 47条、卡60 44条，全部与 `timing_setup_fail_all.txt` 同名同级数；P10 缺样已由协调者批准。

采样覆盖上界换算：P5/P7 为工具+1，P6 为工具+2，其余为工具+0；仅覆盖这些样本，没有统一精确偏移。
映射实例：卡59 P1 首条 PDS 13级（3 COUT、1 L5、7 L6、2 Y），工具18级全部为 LUT；PDS 比较器为 `N6.slt_{3,7,11}/COUT` → `slt_15/L5`。
同条 PDS 将控制逻辑放入 `e_redirect_old_r/opit_0_L5Q_perm/L6`、`m_wait_dc_r/opit_0_L6Q_perm/L6`、`dc_expect_r/opit_0_inv_L6Q_perm/L6`；XC7 对应路径由独立 LUT 构成。
卡59 P4 首条 PDS 12级含4 COUT、2 L5，工具25级含8 CARRY4、1 MUXF7、16 LUT；PDS 最大时延路径与工具最大级数路径选择不同，不能逐项相减认作同一条物理路径。
拟合：`slack150=a+b·L+c·log2(F)`；`slack135=slack150+0.740741 ns`；F仅取数据路径最大扇出，排除时钟树、async recovery/removal。

FF/DRM交点向下取整为150 MHz各3级，135 MHz各10/6级；这些是均值拟合值，不是硬预算。最小残差为FF −1.850、LUTRAM −1.007、DRM −1.291 ns；本数据不能给出各类均可用的硬预算。
复现（先 source `~/.local/opt/edrv32/env.sh`，仓库根目录）：
```sh
python3 -m tools.synth.cpu_levels build/cpu-levels/59 --commit b1e9d08b --start e_branch_b_r --end e_operand_a_r
python3 -m tools.synth.cpu_levels build/cpu-levels/60 --commit 1281d669 --start e_redirect_r --end 'u_predictor\.ras_data_r'
python3 -m tools.synth.cpu_calibrate build/cpu-levels
```
原始路径由工具以 `git show origin/win/<卡任务>:tasks/win/<卡任务>/artifacts/R1或R2/...` 提取；逐条结果 `build/cpu-levels/calibration.tsv`，拟合 `fit.json`，级数 `59,60/pairs.tsv`；使用 `--netlist .../xc7.json` 可免综合重新过滤。
