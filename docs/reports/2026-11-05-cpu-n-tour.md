## JAL 根因与回归

首轮 B1 为 44 PASS / 3 FAIL：B-12 激励被 gshare 学会；两个随机测试在寄存 D 重定向周期缺失 JAL。逐拍日志 build/cpu-n-tour/debug/random.log 的 cycle374 显示 d_issue=1、d_swap=1：单发射却选了年轻 load，IB 弹出 JAL。
修复让 d_swap 遵守 d_issue 的同一寄存重定向单发射条件；不修改规格。cpu_v3s scenario21 用旧 load 请求背压，在捕获 D 重定向时释放，使未发射 JAL 与仅管线0可执行的 load 同时在 IB。
修复前 6413d119 的 core/frontend/IB/predictor 快照在 scenario21 报 FAIL retained slot0 JAL swapped with unissued load；日志 build/cpu-n-tour/v017-negative/run.log。修复后 scenario21 及全部21场景通过（v3s-final.log）；定向回归补充提交 `a13373a4`。
## 复现及原始数据

先 `. ~/.local/opt/edrv32/env.sh`；以下所有 Verilator 构建/仿真命令前均加 `flock /tmp/edrv32-sim.lock`，构建并行数为 1。
- `python3 tools/regress.py smoke --path verif/unit/<cpu_predictor|cpu_frontend_no_c|cpu_v3s> -j 1`（各目录分别执行）。
- `python3 tools/regress.py smoke --path verif/block/cpu -j 1`；三个失败项补跑使用 tools/cpu/run_b1.py 对应 case.json。
- `python3 tools/cpu/b2_run.py r01` 至 `r04`；`python3 tools/cpu/b2_run.py r05 --check-cycles`；`python3 tools/cpu/b2_early_stats.py`。
- `python3 tools/cpu/check_retained_jal.py` 复现旧 RTL 失败；`python3 tools/cpu/eval/run_tournament_eval.py build/cpu-n-tour/input/coremark` 单次模型结果为 model.json。
- `python3 tools/check/verilog_style.py rtl/`；在 rtl/filelists 下执行 `verilator --lint-only -Wall +define+SIM_MODE --top-module edrv32_cpu_core -f cpu.f`。
日志均在 build/cpu-n-tour/：predictor.log、frontend.log、b12-final.log、random-*-final.log、b1-final.log、r0[1-5]-final.log、stats-final.log、negative-final.log、v3s-final.log、style.log、lint.log。
## 资源与交接

估算新增 LUTRAM：(3×256×10 + 3×1024×2 + 2×4096×2)/64 = 472 个 64-bit 单元；逻辑表状态为 12,800 bit。局部历史/方向各 3 读副本，选择器 2 读副本、各 4 bank。
F2 纠正路径估计 6–7 LUT 级：bank 选择 1、局部/全局及位置选择最多 2、纠正判定 1、PC 优先级/数据选择 2–3；顺序地址进位链并行预计算，不串在方向判定之后。资源及实际级数最终以 PDS 为准。
用户生成 IP：ip_lutram_cpu_local_history（256×10，初值0，3实例）、ip_lutram_cpu_tournament（1024×2，初值01，11实例）；初始化 .dat 生成命令见对应 fpga/ip/*.md。
新增包装已由协调者在 9a60b0cb 加入 rtl/filelists/cpu.f，无待添加项：edrv32_ram_cpu_local_history.v、edrv32_ram_cpu_local_direction.v、edrv32_ram_cpu_chooser.v。
