# CPU v0.21 / NPU 180 MHz 整片集成

输入：`5f2b9837` + 本提交的软件/测试修改；CPU/cache 与冻结点 `9fa3f649` 无差异。
工具：本机 Verilator 5.020、xPack GCC 15.2.0、host GCC 13.3.0、Python 3.12.3；RTL 仿真无器件/速度等级。
目标时钟 sys/npu=125/180 MHz；本次为功能仿真，实际时钟见下表，目标频率时序/上板留 Windows 整片卡。
软件频率常量、EDTM、忙碌率、板级耗时示例及 UI 全部改 180 MHz；未增加开关。
SoC/整片 CPU 命名端口连接通过严格 lint；整片 PDS 导入递归包含全部 CPU v0.21 源文件及五个 predictor RAM 包装，无遗漏。
四个 LUTRAM：BTB 无需初始化；direction/local_history/tournament 为 HEX，分别 1024×`5`、256×`000`、1024×`1`；三个 `.dat` 不在仓库，协调者确认按说明在 Windows IP 目录生成，具体路径写入整片卡；禁止沿用 tournament 的 NONE/0。

CoreMark：GCC15 tuned，RV32IM+Zicsr、10 迭代，`-O3 -funroll-all-loops -finline-limit=600 -falign-functions=4 -falign-jumps=4 -falign-loops=4`；对照 R-05 1,807,726 周期 / 5.531812（约 5.53），少 9,079 周期（−0.502%），CM/MHz +0.505%；环境及 ELF 布局不同，非逐周期等价对照；归一化周期测量，不满足官方 10 秒时长。
首轮 board_npu 构建缺 ultralytics 子模块，补齐后构建 PASS；未更改依赖或生成器。
旧 soc_connect 假设媒体槽 1–9 全连通，与现行 RESERVED 槽不符，首轮 SIM_EXIT=0x185；协调者要求改选 board_render，未改旧测试。
旧 board_b1 启动由协调者要求停止：共享 `verif/models/ip_pll_sys.sv` 固定 100 MHz，与现行 125 MHz 不符，依赖它的旧板级测试 UART 波特率会失真，留待清理；board_render/npu 自带强制 UART 分频与接收波特率配对。
SC01 日志检查器原期望 I$/D$ 8192 字节；经协调者授权改为现行 32768，仅重放既有日志，不重跑 RTL。
