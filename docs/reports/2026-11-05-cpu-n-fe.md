# CPU v0.17 前端零周期时序候选

- RTL：`e7fe212e`（前端/预测器 `438252c2`）；基线：`798530a8`（v0.16）；范围仅 frontend / predictor / icache，未改 IB、core 或 RAM/IP 接口。
- 结论：保持周期和端口的卡 59 候选，**尚未证明满足 7/4 级与扇出 ≤16 的全部预算**。
- 协调者答复：保留原周期、原端口，交卡 59；不授权本任务修改 IB 或增加 I$ 后流水级。
- 修改：并行预计算有/无响应的队列余量，直接用 IB 占用判断空位，移除晚到响应后的加减链。
- 修改：顺序/保持/重定向 PC 候选与预测并行，末级选择预测目标；F2 数量直接用布尔式。
- 修改：BTB tag 分为两个 11 位比较、I$ 每 way 分为两个 9 位比较；RAS 的组内 PC+4、组末 PC+8 并行；I$ 响应资格在发起边沿寄存。
- 扇出措施：I$ 地址 PC 副本、每 8 位流记录的读指针/计数副本使用 `syn_preserve`，查询 PC 使用 `syn_maxfan=16`。
- Yosys 会合并这些同值副本；其代理网表不能证明 PDS 的副本扇出，卡 59 必须检查实际负载；F1 测量副本保留了 PC 别名。

## 级数参考与残余

工具：Yosys 0.70+219 / git 5053d0e26，XC7 LUT6/MUX/CARRY 代理；BTB/PHT 异步 RAM 行为替换，I$ DRM 黑盒。
没有执行 PDS；目标仍为 PG2L200H、CPU+L1 150 MHz，最终以卡 59 的 PDS 器件/速度等级及路径为准。
下表为实际映射单元级数，**不是 PDS 级数**；包含 LUTRAM 地址到输出的一层，CARRY4 每块各计一层。

| 起点 → 终点 | 修改前 | 修改后 |
|---|---:|---:|
| F1 PC[8] → F1 PC[0]（预测环） | 8 | 8 |
| F1 PC[8] → F2 hit | 7 | 7 |
| ic_resp_valid_i → F1 PC | 7 | 5 |
| ic_resp_valid_i → RAS 数据/控制 | 9 | 5 |
| ic_resp_valid_i → IB entries | 7 | 6 |
| 任意前端/顶层输入 → IB entries | 8 | 6 |
| I$ tag DRM → ic_resp_valid_o | 5 | 5 |
| I$ tag DRM → ic_resp_data_o（半字选择之前） | 5 | 5 |
| I$ tag DRM → ic_req_ready_o | 5 | 5 |
| I$ tag DRM → F1 / IB / RAS（串接上界估计） | 12 / 12 / 14 | 10 / 11 / 10 |
| I$ tag DRM → 前端半字数据选择（串接上界估计） | 6 | 6 |

串接上界仅将两个模块的最大值相加，不等同于一条实际可达路径；半字选择在 I$ 数据输出之后增加一层 mux。
残余：I$ tag 至响应/数据/ready 自身仍为 5 级；F1 预测环代理仍为 8 级；响应到 F1/IB/RAS 的 5/6/5 级**均未计入 I$ tag DRM → resp 的比较、命中逻辑**，不能视作满足 DRM 总预算 4 级。
顺序 PC 加法路径原始最大级数 12→11；规格把整条 32 位进位链计 2 级，不能直接以该原始最大值判断预算。

## 下一轮 IB 接口建议（未实现）

将 frontend→IB 的 `push_count_i[1:0]` 改为 `push_valid_i[1:0]`：bit0 表示第一条有效，bit1 表示第二条有效，合法码 00/01/11。
frontend 直接提供已有的 `push_one_w` / `push_two_w`，省去数量编码后在 IB 内重解码；IB 按早到写指针预选两条数据，晚到 valid 只控制写使能。
IB 指针和占用的 +0/+1/+2 候选并行计算，再由 valid 选择；保留同拍入队/出队及重定向语义，周期代价 0。
估计响应到 IB 阵列控制可省 **1–2 个 LUT 级**（6→4–5），须在实现后测量；这本身仍不保证包含 tag 比较后的 DRM 总预算达到 4。
