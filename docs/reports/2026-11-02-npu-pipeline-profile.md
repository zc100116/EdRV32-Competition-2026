# NPU 流水线空等与广播走线测量（T-NPU-PROF）

测量 RTL commit：`ff797e79dbf2a02cedf56bdc4d2468272184aa04`（最后 NPU RTL `d5b7a2c0`）；监视器/解析器随本文提交。规格已 v0.7，但本次 RTL 仍为 b3 的 16 量化 lane / 32 量化 APM，**不是 Q6 实测**。
环境：Verilator 5.020、Python 3.12.3，NPU 150 MHz / mem 125 MHz；PG2L200H-6 为目标器件，未运行 PDS、未测资源映射或 WNS。YOLOv8n 640×384、68 描述符，输入 COCO `000000000009.jpg`；zero 实际首返 1 mem 拍，latency/bw 首返 94 mem 拍，B_DELAY=1；bw 为 R/W 共享 1400 MB/s、64 B token 桶，其余档不节流。
复现：`git submodule update --init third_party/ultralytics`，`. ~/.local/opt/edrv32/env.sh`，`flock /tmp/edrv32-sim.lock python3 tools/regress.py perf --path verif/block/npu/prof -j 1`；解析可单独运行 `python3 tools/npu/pipeline_profile.py build/npu/prof`（仅标准库）。
原始日志：`build/npu/prof/{zero,latency,bw}_{baseline,profile}.log`；全量 3×68 条 start→done、MAC/效率、分类、边界/通道损失、读写字节见 `build/npu/prof/descriptors.csv`，整网见 `totals.csv`；回归日志 `build/regress/perf/block/npu/prof/verilator/run.log`；逐条几何/CSV/字节复核日志 `build/npu/prof/validation.log`。
验收：1 PASS / 0 FAIL；六次检测头均与 Python 参考逐字节一致（每次 725,760 B），三档全部 PERF[0..15] baseline/profile 一致，互斥和=PERF0、MAC 和=PERF1；真实 MAC 与独立空间几何计算一致，CSV 序号均为 0..67；lint/新增 SV 风格 0 告警，`git diff --check` 通过。 对比 `2026-10-31-npu-opt1.md`：PERF0 三档均少 1 拍（本次 6,010,287 / 6,251,054 / 6,955,047），MAC 拍数不变；不把旧 commit 的 1 拍差异当作监视器影响。

互斥规则：每个 `busy_w` 上升沿按 `cur_desc_r` 归属（含取描述符/栅栏，最后 COMPLETE 归 d67），先 MAC，再 FETCH/DECODE(D)、FENCE(F)、非卷积 RUN(N)，再 A1 停顿原因延后 6 拍以对齐 PERF1 的 M1。A1 原因顺序为结果额度 C→残差 R→量化日历 Q；当前/下一窗口上下文均空时，模型未 ready→M0/Mn，否则行未 ready→I0/In；首次 A1 发射前为“首”，之后为“后”。 M0 优先包含模型/首批输入同时未就绪的拍，I0=0 不表示输入无延迟；这些是明确优先级的观测归因，不能直接等同于消除某条件后的收益。latency 原始 PERF4/5/6=1,589,315/380,744/738,408，均可与 MAC 重叠；真实互斥输入/模型/栅栏仅 10,310/268,482/585。
其余尾部：all_submitted 且 window idle 后，MAC/ACC/量化/残差加仍有在途计 Tp，否则计 Tw（结果/W 流排空）；剩余计 S（配置、命令准备/行块切换、首批流水填充和 COMPLETE）。start→done 为算子 start 至 local_done 含两端，不含 D/F；N 含 done 采样拍，比 PERF7 多 5 拍。
真实 MAC 按 A1 有效空间像素计：普通/D2 每像素 256，首层每像素 16×3=48；不计边界补零和填充通道。整网真实 2,549,399,088；满空间核但去通道填充为 2,622,873,600，故边界损失 73,474,512 MAC，通道填充损失 115,015,680 MAC（全在首层）。
效率 η=真实 MAC/(有效拍×512)：整网 93.115%；首层 C3→物理 C8、Cout16→物理 C32，非边界上限 3/8×16/32=18.75%，实测 18.698%；其余通道均 C16 对齐。半块 D2 把两组 C8 折入 32 条链，K 减半，**不再另扣 50%**。真实 MAC/PERF0/512 三档为 82.846% / 79.655% / 71.593%。

载荷估算：CSV 逐描述符 B=read_bytes+write_bytes，整网读/写=16,399,104/9,888,000 B，与 PERF2/3×32 一致；BW floor=max(0,(B−64)×150/1400) 拍（64B token 桶），只消除 C 的估算上限=Σmin(C,max(0,busy−floor))=257,713.57；不含其余类别同时优化，非可兑现性能预测。

广播结构为 RTL 静态连接分析，尚无各源物理坐标/布线长度；DP=`u_conv.u_datapath`。宽向量不等于每位高扇出，特别是权重每字节只有一个 APM、SIMD 两个 b 输入。

可选权重组织：8个 bank 改为各存4条链×8项（仍每bank256b），每bank只接4条链，全部bank同拍读，在APM旁按k做数据错位；仅改变片内写地址/转置与读组织，DDR规格§4.3和装载字节顺序均可保持。估额外 FF=32×8×Σ(k=0..7)−12×Σk=7,168−336=6,832；DRM仍8×3×4=96（Δ0），固定连线/寄存移位无新增数据mux，LUT估Δ≈0（控制小改未综合）。
物理风险/排序：先由Q6把APM290→266（给定下半片280，跨区数量下界 max(0,APM−280) 从10→0，并非布局通过保证），再评估局部bank；后者不省PERF0、增加约6.8K FF，须同时考虑D2 c↔c+16和4组激活位置，可能把权重跨度换成激活/折叠跨度，必须PDS实测后决定。
结论供协调者设计记录/用户选项：流水空等优先评估POOL采样，再评估共享读仲裁/描述符预取；20DRM模型暂存和残差加深需用收益上限权衡拥塞代价；行块/层尾不是本次主要损失。权重/激活连接结论适用于Q6，所有拍数为本次b3，尤其C/R/Q/量化尾部需Q6后重测。
