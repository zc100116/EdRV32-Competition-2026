# 整片 RTL 瘦身：为 NPU 硬件后处理和后续提频腾出布线余量

## 1. 背景和问题

- 卡 68 R2 整片在 PnR 第 176 轮才布通，CLMA 87% / CLMS 86%。
- 卡 69 只在 NPU 枢纽加了 2,727 FF，布线就不收敛（`docs/reports/2026-11-10-route-soc-card69.md`）。
- 卡 70 加入硬件后处理后，整片 ADS 资源比卡 68 多 LUT 1,921 / FF 3,828 / DRM 12。第 7–9 轮未布通数相对卡 68 为 ×1.037→×1.066，比卡 69（×1.007→×1.017）偏离更快，判断不收敛。
- 用户 2026-11-13 要求对整个 SoC 的 RTL 做瘦身评估。

## 2. 约束

- 稀缺资源是 CLM 站点；DRM 剩 117 个（卡 70 已用 298/415），APM 剩约 367 个。
- CPU v0.21 和 cache 已冻结。
- 功能删减、性能指标和存储介质条款的修改都要用户确认（CLAUDE.md 1.5、11.8）。

## 3. 评估结果（全部为结构估算，未经 PDS 复测）

### 3.2 B 组：只改实现，不改功能和规格

| 编号 | 位置 / 改法 | 省 LUT / FF | 新增 DRM / APM | 主要风险 |
|---|---|---|---|---|
| N4 | NPU accum 去 R5 数据寄存 | 0 / 1,216–1,280 | 0 / 0 | 加法反馈路径时序，NPU 枢纽 |
| N5 | NPU residual_add 去 512 位旁路副本 | 0 / 512 | 0 / 0 | 算术前选择，NPU 枢纽 |
| M2 | RND COPY 两侧字节对齐合并为一次 | 900–1,800 / 0–64 | 0 / 0 | 首尾、重叠、反向行序，时序中高 |
| M3 | PIX 每个 kernel 的 min/max 归约树合用 | 200–400 / 280–320 | 0 / 0 | 比较方向网扇出 |
| M6 | GEO 边界 4 路移位累加改 APM | 100–200 / 96–192 | 0 / 4 | APM 切分 |
| M5 | RND draw 目标载荷和 alpha tag 延时链改 DRM | −40–0 / 600–700 | 2 / 0 | 停顿对齐 |

| N6 | NPU result_quant 合并两段桶移位 | 0 / 196 | 0 / 0 | 级数超预算风险 |

### 3.3 C 组：删减诊断或功能（S 类，由用户决定）

| 编号 | 内容 | 省 LUT / FF | 失去的能力 |
|---|---|---|---|
| M1 | 删 VIN 预留写通道 CH1 | 1,000–1,200 / 1,650–1,800（释放 4 DRM） | 双路拼接；软件从未启用 |
| SYS-02 | xbar 去 WAIT_SUM/MAX、URG_CNT 统计 | 700–1,100 / 800–1,120 | 监控 UI 的等待统计 |
| M7 | 删 PIX/GEO/DISP 无程序读取的 PERF | 350–600 / 800–1,150 | 诊断计数 |
| SYS-04 | ETH 只保留 PERF0/1/2/10 | 200–350 / 224 | eth_diag 计数 |
| N8 | NPU PERF2–7 | 150–220 / 280–320 | 读写等待等性能观测 |
| N7 | 后处理按 180 MHz 重排流水 | 0–80 / 250–500 | 后处理 200 MHz 预算 |

不推荐：
- PIX 去掉第二级（M8）：UI 正在使用两级组合；
- 后处理两棵 max 树改一棵（N12）：违反每拍一个 beat 的吞吐要求；
- CPU 的 F 类项（HPM、tournament、IB 预译码）。

### 3.4 已确认无可省之处

- RND 现有全部命令和格式；PIX 两级的全部运算；VIN 的 CH2 和内存源；
- DDR 适配器；跨时钟域 FIFO（16 个）和 APB 桥；
- ROM、SRAM、UART、I2C、CLINT、PLIC；
- 后处理的 best RAM、5040 项队列、查表、串行 DFL。

## 4. 决策（用户 2026-11-13）

- **A 组第一步不做**。浅存储当初改为分布式 RAM（`2026-10-31-drm-lutram.md`），是因为 DRM 位置固定，宽总线会被拉到 DRM 列上形成长线。NPU 结果、量化参数、残差三块位于 NPU 枢纽，改回 DRM 风险大于收益。如果第一步之后整片仍不收敛，第二步只试 mem xbar W RAM（SYS-01）。
- **第一步**：
  - B 组 N4、N5、M2、M3；
  - C 组删除无程序读取的性能计数器：NPU PERF2–7、PIX PERF1–3、GEO PERF1–5、DISP PERF2–6。规格已修改：npu v0.11、pix v0.2、geo v0.2、disp v0.4，b3 `1d2c4591`。
  - 估算省 LUT 1.6–3.0K、FF 3.1–3.7K，不增加 DRM。
  - 上板对比 NPU PERF0、RND 跑分、PIX 实时帧率。
- **保留**：
  - VIN CH1：它是把摄像头原图写入 DDR 的通道，是以 DDR 串联各引擎的可编程数据流的入口；
  - xbar 等待统计：调试工具在显示；
  - ETH 计数器。

## 5. 影响

- 规格：
  - `docs/spec/npu-spec.md` §5.2：量化参数、残差读缓冲、结果缓冲的存储介质改为 DRM；
  - `docs/spec/mem-subsys-spec.md` §7：W 缓冲的存储介质改为 DRM；
  - 两处 §7 资源表相应修改。
- RTL：`rtl/npu/`（writeback、quant_param_store、residual_buffer、accum、residual_add）、`rtl/mem/edrv32_mem_xbar.v`、`rtl/media/rnd/`（copy）、`rtl/media/pix/`（kernel）；`rtl/tech/` 新包装；`fpga/ip/` 新建创建说明。
- 测试：NPU 单元和模块测试、NET-02；mem xbar 单元和模块测试；RND COPY 全部偏移、重叠和 ABORT；PIX 各运算组合；SoC smoke。
- 之后用卡 70 的工程重跑 PnR（卡 70b）。

- N4 评估后回退：保留 R4/R5/ACC 共 3 级，参数准备仍在 R4 输出；末归约项 A1→WB2 双平面 50 拍、单平面 42 拍，MAC II=1、量化每像素对 16/8 拍不变；参考 LUT 增长及 ACC 多一层选择不利于整片打包和时序。
