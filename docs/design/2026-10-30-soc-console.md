## 1. 背景和问题

用户 2026-10-30 在 B3V 上运行 `demo_vision` 后反馈两件事。

**网口视频和 DDR 监控没能验证。** 程序里有这两项功能，但调试工具上没有一条能直接走通的操作路径：
- 需要先在“网口”页监听 6000，再发一个 WIN3 短包建立对端；
- 视频在“网口/视频”相关页面看，DDR 监控在“DDR”页看；
- 场景命令在“场景”页发。
- 每一步分散在不同页面，页面上也看不出卡在哪一步：无连接、未建立对端、没有视频帧、没有监控包。

**项目专用功能分散。** 烧录、场景、YOLO、视频、DDR 分别占一个左栏页签，各自打开串口或 UDP 接收。用户要求：
- 把这些集中成一个 SoC 中控台：中间统一显示板子回传的视频和图片，四周放控制、传输、监测；
- 与通用串口功能（连接、命令、规则、控制台）分开。

## 2. 约束

- **复用现有核心模块，不重写协议**：`core/program.py`、`scene.py`、`video.py`、`telemetry.py`、`yolo.py`、`ethernet.py`，以及 `tools/board/uart_tool.py` 的 `BiosTransfer`。
- **会话唯一**：
  - 串口仍是引擎里的同一个会话；
  - UDP 本地 6000 端口只由一个对象绑定，按应用头分发给视频、监控、YOLO 回传和文件接收。
- **GUI、CLI、REST API 共用会话**：现有 API 风格不变，新增的状态也能经 API 读取。
- **按工程显示可用功能**：
  - B3V 没有 NPU、RND，目标检测和模型发送不显示或明确标为不支持；
  - B3R 只有渲染程序，没有摄像头，也没有网口。
- CLAUDE.md 第 12 节：不加心跳重试、自动重连、备用路径；出错就在状态区写明原因。
- 3.6 节已经规定前端和视觉设计交给 Codex。本记录只定结构、会话和功能边界。

## 3. 可选方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A. 新增一个“中控台”页签，内部整合 | 左栏新增一个页签，打开后占满中栏和右栏；原有项目页签移除，功能并入中控台 | 一处操作，会话唯一，现有通用功能不动 | 要重排 GUI，并把各页的状态合并 |
| B. 保留各页签，只加一个联调向导 | 现有页面不动，新增一页按步骤引导 | 改动小 | 没有解决分散和重复占用的问题，不符合用户要求 |
| C. 独立的新程序 | 另写一个只做中控台的程序 | 边界清楚 | 与调试工具重复维护串口、API；用户要开两个程序 |

## 4. 决策（推荐 A，待用户确认）

### 4.1 页面结构

```
┌───────────── 顶栏：工程选择 [B3V|B3VN|B3R|B3F] · 板子阶段（未连接/BIOS/应用）· 网口状态灯 ─────────────┐
│ 左：程序与传输          │            中：统一显示区               │ 右：场景控制             │
│ · 程序烧录/加载（SRAM   │  视频 / 静态图片 / 检测叠加三种显示，    │ · 场景（目标检测/图像处理）│
│   .bin、DDR .elf），    │  同一块画布切换；                      │ · PIX 5 档、GEO 3 档     │
│   阶段、进度、结果      │  显示帧号、帧率、来源（板端视频/回传图） │ · 输出 hdmi/eth/both     │
│ · 图片发送（WIN0/1）    │                                       │ · fps、采样率            │
│ · 模型发送（WIN2，      │                                       │ · status 摘要            │
│   B3VN/B3F）            │                                       │                         │
├────────────────────────┴───────────────────────────────────────┴─────────────────────────┤
│ 底：DDR 监控（各端口带宽堆叠、利用率、等待、实时性计数、CSV 导出） · 日志（串口、传输结果、回传状态）│
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

### 4.2 会话和状态

- **板级会话对象**持有：
  - 串口引擎引用；
  - 唯一的 UDP 6000 接收端；
  - 当前工程；
  - 板子阶段：未连接 / BIOS / 应用，由串口行判断：`BIOS menu:` 判为 BIOS，`Demo:` 等启动行判为应用。
- **网口状态**按顺序显示四步，每步显示是否完成和最近一次的时间：
  1. 已监听 6000；
  2. 已发送 WIN3 短包（对端建立请求）；
  3. 板端 `status` 中的 peer IP/端口与本机一致（从串口解析）；
  4. 收到视频块 / 收到 EDTM 监控包，分别计数。
  - 中控台提供一键“建立网口连接”：监听、发 WIN3 短包、发 `status`，然后按上面四步显示结果。
- **烧录**直接调用 `BiosTransfer`。B3-13 修改后，板子已在 BIOS 时可以直接开始。

### 4.3 工程能力表

| 功能 | B3V | B3VN | B3R | B3F |
|---|---|---|---|---|
| 程序烧录/加载 | ✓ | ✓ | ✓ | ✓ |
| 图像处理场景、PIX/GEO | ✓ | ✓ | — | ✓ |
| 目标检测场景、模型发送、YOLO 图像检查 | — | ✓ | — | ✓ |
| 网口视频、DDR 监控 | ✓ | ✓ | — | ✓ |

不适用的功能灰显，并写明原因，例如“B3V 没有 NPU”。

### 4.4 移除与保留

- **保留**：连接、命令、规则、控制台、数据面板，以及通用的网口文件收发。
- **并入中控台后移除**：原“烧录”“DDR”“场景”“YOLO”页签和独立视频窗口。REST/CLI 的现有接口保留，不改名。

## 5. 影响

- **代码**：`tools/debug_tool/gui/` 新增中控台页面；`core/` 新增板级会话对象，现有模块改为经它取得串口和 UDP。
- **测试**：`tools/debug_tool/tests/` 增加：
  - 会话唯一性（同时打开视频和监控只绑定一次 6000）；
  - 阶段判断；
  - 网口四步状态；
  - 工程能力表。
- **文档**：调试工具 README 改为以中控台为主的操作说明，含 B3V/B3VN/B3F 各一份“从上电到看到视频和 DDR 数据”的步骤。卡 09 的网口和 DDR 部分改为引用这份步骤。
- 规格不受影响。
