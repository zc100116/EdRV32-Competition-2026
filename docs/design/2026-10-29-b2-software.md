| 项 | 内容 |

| 状态 | 已决定（用户确认 2026-10-29） |

## 1. 背景和问题

用户 2026-10-29 要求：B2 上板就用完整 SoC（含 NPU、ETH），把图像处理和 YOLO 识别的程序都规划好；加上 NPU 后要实时监控 DDR 带宽，经网口传到 PC，在调试工具里可视化。已确认的前提：

- clk_mem 保持 125 MHz（DDR 用户时钟）；`edrv32_soc_top` 一次写全，RND 未开发不接。
- 监控数据经网口 UDP 传输；mem_xbar 每端口统计拆成读、写两组（mem-subsys v0.4）。
- VIN CH2 按工具链量化 `round(c × 127 / 255)`（vin-spec v0.2）。
- GPIO 位分配固定（SoC 3.5）：KEY1–4 bit0–3，LED0–4 bit4–8，摄像头 bit12–15。

本记录确定板上程序的组成、DDR 内存布局、YOLO 数据流、监控记录格式和调试工具新增功能。

## 2. 约束

| 约束 | 来源 |
|---|---|
| SRAM 64 KiB（程序、栈、BSS），Boot ROM 的 BIOS 只能烧录 SRAM | SoC 6.1、7.5 |
| CPU rv32im，无浮点；clk_sys 100 MHz | cpu-spec v0.14 |
| CPU 不搬运大块数据；引擎经 DDR Surface 交接 | SoC 2.3 |
| 后处理（DFL 解码、NMS）由 CPU 完成，与 NPU 跨帧并行 | SoC 8.9 |
| 寄存器访问只用生成的头文件；cache 维护只用 BSP 接口 | CLAUDE.md 9.3 |
| ETH 接收 4 个窗口，发送按描述符切 1024 B 包，应用头 `WIN/FLAGS/OFFSET` | eth-spec 2.3–2.6 |
| NPU 镜像：模型 3,242,752 B、WORK 5,867,520 B、C4 输入 983,040 B、OUTPUT 725,760 B | `tools/npu/README.md` |
| S1 持续 DDR 流量规划 ≤ 1.5 GB/s，S2 ≤ 0.75 GB/s | SoC 9.1 |

## 3. 方案

### 3.1 板上程序

| 程序 | 位置 | 内容 |
|---|---|---|
| Boot ROM + BIOS | ROM（已有） | 启动信息、KEY1 进入 BIOS 烧录 SRAM |
| 监控程序 `sw/apps/monitor` | SRAM（已有） | CoreMark、外设测试、系统信息 |
| 演示程序 `sw/apps/demo`（新） | SRAM，由 BIOS 烧录或作为 SRAM 初始化内容 | 场景 S2 图像处理、S1 目标检测、网口加载、DDR 监控上报 |

演示程序代码估计 40 KiB 以内（驱动约 15 KiB、OV5640 寄存器表约 3 KiB、后处理约 6 KiB、字库 1.5 KiB、监控和网口约 4 KiB、菜单约 3 KiB，**估算**）；大块数据全部放在 DDR。若实测超过 SRAM，再讨论 BIOS 增加"烧录 DDR 程序"一项，本次不做。

### 3.2 驱动与公共软件（`sw/drivers/`、`sw/lib/`）

- **寄存器头生成**：各引擎寄存器表（VIN、PIX、GEO、DISP、NPU、ETH、MEM_XBAR、PERF_MON）写成 JSON 描述，由 `tools/gen/` 生成 C 头文件（偏移、位域），满足 CLAUDE.md 9.3。
- 引擎驱动：VIN（通道、环形槽、内存源）、PIX（点运算、3×3 配置、Gamma 表）、GEO（描述符）、DISP（Surface 提交、VBlank 释放）、NPU（MODEL/WORK/INPUT/OUTPUT/DESC 基址、启动、完成中断）、ETH（MAC/IP、窗口、发送描述符、MDIO 与 PHY 复位）、MEM_XBAR 统计、PERF_MON。
- OV5640：I2C0 SCCB 初始化表（720p30 RGB565 DVP），两路摄像头分别经 I2C0 两对引脚，`pwdn`/`rst_n` 由 GPIO bit12–15 控制。寄存器表从厂商双目摄像头例程（`doc/fpga/pago_200/2_Demo/5_1 双目摄像头例程`）和旧工程 `legacy/sw/hal/drivers/cam.c` 核对后移植。
- 字库：8×16 ASCII 点阵，CPU 在 RGB565 Surface 上画框、填充标签底色、写类别名和置信度。

### 3.3 DDR 内存布局（软件分配，物理地址）

| 区 | 基址 | 大小 | 用途 |
|---|---|---|---|
| NPU 描述符 | 0x0008_0000 | 64 KiB | `tools/npu/compile_yolo.py` 默认 `DESC_BASE` |
| NPU 模型 | 0x0010_0000 | 4 MiB | 权重、量化记录、LUT（默认 `MODEL_BASE`） |
| NPU WORK | 0x0100_0000 | 8 MiB | 中间特征图（默认 `WORK_BASE`） |
| NPU 输入环（VIN CH2） | 0x0400_0000 | 3 × 1 MiB | CH2 Surface 环 3 槽，每槽 983,040 B；第 0 槽同 `INPUT_BASE` |
| NPU OUTPUT 双缓冲 | 0x0500_0000 | 2 × 1 MiB | 6 个 box/class 输出；NPU 写一份时 CPU 后处理另一份 |
| 底图环（VIN CH0） | 0x0600_0000 | 4 × 2 MiB | 1280×720 RGB565，每槽 1,843,200 B |
| GEO 输出 | 0x0700_0000 | 2 × 2 MiB | GEO 结果 Surface |
| L1 检测框双缓冲（B3 起） | 0x0740_0000 | 2 × 4 MiB | 1280×720 ARGB8888，各层 SWITCH1 后复用 |
| L1 绘制资源（B3 起） | 0x07C0_0000 | 4 MiB | 全透明 COPY 源、RND 命令列表、DDR 字体；地址常数在 `sw/apps/demo/demo.h` |
| 网口窗口 0、1 | 0x0800_0000 | 2 × 2 MiB | PC 发来的测试图像（双缓冲，VIN 内存源读取） |
| 网口窗口 2 | 0x0900_0000 | 16 MiB | PC 发来的 NPU 镜像（描述符 + 模型），CPU 校验字节数后复制到上面两区 |
| 网口窗口 3 | 0x0A00_0000 | 64 KiB | PC 发给 CPU 的短命令 |
| 发送缓冲 | 0x0A10_0000 | 4 MiB | 监控记录环、检测结果、回传的 CH2 输入/NPU 输出 |
| DDR 应用程序（B3 起） | 0x1000_0000 | 64 MiB | BIOS 加载到 DDR 运行的程序（LVGL、游戏），代码、数据、字体图片、显示缓冲和栈都在本区；链接脚本 `sw/bsp/ld/ddr_app.ld`（`MEMORY=ddr_app`） |

NPU 的基址由编译器默认值决定；编译器若改默认值，本表随之修改。所有区 4 KiB 对齐，CPU 访问走非缓存别名（0xC000_0000 + 物理地址）或在交接前后按 SoC 7.4 做 cache 维护。

### 3.4 场景与数据流

**S2 图像处理**（与 SoC 1.2 图像通路阶段相同，DISP 直接扫描）：摄像头 → VIN CH0 + PIX → 底图环 → DISP；可选 GEO（底图 → GEO 输出 → DISP）。UART 菜单或 KEY2–4 切换 PIX 运算（旁路、亮度/对比度、Gamma、高斯、Sobel 等）和 GEO 变换（旋转、缩放）。

**S1 目标检测**：

1. 每帧摄像头数据同时进入 CH0（底图，PIX 旁路）和 CH2（NPU 输入），两者 frame_id 相同（vin-spec 5.4）。
2. CPU 收到 CH2_FRAME 中断，若 NPU 空闲，就把该槽设为 `INPUT_BASE` 启动 NPU，并用 SLOT_BUSY 锁住 CH2 槽和同 frame_id 的 CH0 槽；NPU 忙时跳过这一帧（检测帧率低于摄像头帧率时自然丢帧）。
3. NPU 完成中断后，CPU 对该份 OUTPUT 做后处理，同时 NPU 已可开始下一帧（跨帧并行）。
4. 后处理：每个锚点先用整数比较筛选类别分数（阈值预先换算到 INT8 输出域，不算 sigmoid），只对过阈值的锚点做 DFL（16 bin 定点 softmax，查表求 exp）和框解码，再按类别做 NMS（IoU 用整数面积比较）。阈值默认置信度 0.25、IoU 0.45，最多 100 个框。**估算**：5040 个锚点 × 80 类的比较约 1–2 M 周期（10–20 ms @ 100 MHz）。
5. CPU 在锁住的 CH0 槽上画框和标签，提交给 DISP，VBlank 释放后解除 SLOT_BUSY。显示延迟约 1–2 帧。

RND 未开发前由 CPU 画框；RND 完成后改为 RND 绘制和图层合成（SoC 1.2 的最终形态）。

**YOLO 正确性检查**（网口图像，不依赖摄像头）：

1. 调试工具把一幅 1280×720 RGB565 图像发到窗口 0。
2. CPU 用 VIN 内存源读出，经 CH0 显示、经 CH2 生成 NPU 输入，NPU 推理、CPU 后处理。
3. CPU 经网口回传三样东西：CH2 输入（983,040 B）、NPU OUTPUT（725,760 B）、检测结果列表。
4. 调试工具用 `tools/npu/ref/npu_ref.py` 对回传的 CH2 输入跑参考模型，逐字节比对 OUTPUT；再用同一套后处理的 Python 参考比对检测结果；同时用 `input_pack.py` 对原图生成的输入与 CH2 输入比较，显示差异个数。

**网口加载**：调试工具把 `compile_yolo.py` 生成的描述符和模型发到窗口 2（末包 NOTIFY）；CPU 比对 `WIN2_BYTES` 后复制到 NPU 区。每次上电加载一次，约 3.3 MB，**估算**约 0.1 s。

### 3.4a 输出选择：HDMI / 网口 / 同时（用户 2026-10-29 要求）

最终输出帧（S2 为 PIX/GEO 结果，S1 为已画框的底图）是 DDR 中的一张 Surface。输出方式三档，串口菜单和调试工具都可切换：

| 档 | DISP | ETH |
|---|---|---|
| HDMI | 扫描该 Surface | 不发视频 |
| 网口 | 停止扫描（`CTRL.ENABLE = 0`，省去 P0 的读流量） | 发送该 Surface |
| 同时 | 扫描 | 发送 |

- 网口视频每帧两条发送描述符：32 B 帧头（`OFFSET` 0）+ 像素（Surface 原地，`LEN` 1,843,200，`OFFSET` 32，末包 NOTIFY）。CPU 不复制像素。S1 中该帧的检测结果（3.5a 的 EDDT）在帧头之前经 WIN 2 发出，PC 按 frame_id 对应。
- 帧头：`{magic "EDVF", version u16 = 1, format u16 = 1（RGB565）, width u16, height u16, stride u32, frame_id u32, mtime u64, scene u32}`，小端，共 32 B。
- 帧率：设为摄像头帧率的整数分之一，1–60 fps。720p30 约 55 MB/s（网口单向上限 116.6 MB/s 的 47%）；720p60 约 111 MB/s（95%），作为极限测试档，预期出现丢包。
- 一帧的 Surface 在 DISP 释放（VBlank 换帧）和 ETH 发送完成（`DONE_COUNT` 前进）之前保持 SLOT_BUSY；ETH 上一帧还没发完时，本帧不发（计入"网口跳帧"）。
- 网口视频的读流量在 P6，与 ETH 接收、PERF_MON 共用 `RATE[P6]`（复位约 5%，约 200 MB/s）；60 fps 档同时还有大量接收时由软件调高 `RATE[P6]`。



**采样**：CLINT 定时器 100 Hz（10 ms，[待定] 可在菜单中改为 10–1000 Hz）。中断中写 MEM_XBAR `STAT_CTRL` = SNAPSHOT|CLEAR（同一拍先锁存后清零，窗口无缝衔接），读出快照寄存器，连同软件事件组成一条记录写进发送缓冲环；每攒满 16 条（160 ms）或场景切换时由 ETH 发送一次（WIN = 3）。每条记录 `WINDOW_CYC` 给出精确的窗口长度，中断延迟不影响带宽换算。

**记录格式 v1**（小端，固定 320 B，**草案**）：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | `magic` | `"EDTM"` |
| 4 | `version`、`type` | u16 = 1；u16 = 1（周期记录） |
| 8 | `seq` | u32，记录序号（PC 据此发现丢包） |
| 12 | `scene` | u32，0 空闲、1 S1、2 S2 |
| 16 | `mtime` | u64，窗口结束时的 CLINT `mtime` |
| 24 | `window_cyc` | u32，MEM_XBAR `WINDOW_CYC` |
| 28 | `ds_busy`、`dir_switch` | 2 × u32 |
| 36 | `port[7]` | 每端口 7 × u32：`rd_txn`、`rd_beat`、`wr_txn`、`wr_beat`、`wait_sum`、`wait_max`、`urg_cnt`（P0–P6） |
| 232 | `vin` | 4 × u32：CH0/CH2 完成帧数、CH0/CH2 溢出丢帧数（PERF3、5、6、8 的增量） |
| 248 | `disp` | 2 × u32：读空次数、提交帧数 |
| 256 | `npu` | 4 × u32：完成推理次数、最近一次推理的 clk_npu 周期数、最近一次后处理的 clk_sys 周期数、最近一次检测框数 |
| 272 | `eth` | 2 × u32：本窗口收、发字节数 |
| 280 | `cpu` | u32：本窗口内 CPU 空闲（WFI）周期数 |
| 284 | `clk_sys_hz` | u32，SYSCTRL `CLK_SYS_HZ`（`mtime` 每个 clk_sys 周期加 1，SoC 6.1） |
| 288 | `clk_npu_hz` | u32，演示程序编译时常数（npu-spec：150 MHz），用于换算 NPU 周期 |
| 292 | `vid_skip` | u32：本窗口内网口跳帧数（3.4a：ETH 上一帧未发完而不发的帧） |
| 296 | 预留 | 填 0，凑到 320 B |

带宽换算：`MB/s = beat × 32 B × 125 MHz / window_cyc / 10^6`。DDR 利用率 = `ds_busy / window_cyc`。

**PERF_MON 延迟探针**（可选，默认关闭）：在调试工具里开启后，CPU 让 PERF_MON 以低速率做顺序读，每秒读一次 16 格读延迟直方图并发一条 `type = 2` 的记录。它占用 P6 的带宽（P6 限速 5%），开启时界面上标明。

**延迟直方图记录（type = 2，320 B）**：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0–23 | 同 type 1 | `magic`、`version` = 1、`type` = 2、`seq`（与 type 1 共用序号）、`scene`、`mtime` |
| 24 | `hist_width` | u32，PERF_MON `HIST_WIDTH`（clk_mem 周期） |
| 28 | `read_cnt` | u32，PERF_MON `READ_CNT` |
| 32 | `lat_min`、`lat_max`、`lat_sum` | 3 × u32，PERF_MON `LAT_MIN/MAX/SUM`（clk_mem 周期） |
| 44 | `hist[16]` | 16 × u32，PERF_MON `HIST[0..15]`：第 k 格为延迟 `[k·W, (k+1)·W)` 周期，第 15 格收纳 ≥ 15·W（mem-subsys-spec 2.3） |
| 108 | `clk_sys_hz` | u32 |
| 112 | 预留 | 填 0，凑到 320 B |

### 3.5a 网口线协议（板子 ↔ PC）

两个方向都用 eth-spec 2.3 应用头，`OFFSET` 一律为该数据块内的字节偏移；PC 端按 `WIN` 区分数据块。

| 方向 | WIN | 数据块 | 内容 |
|---|---|---|---|
| PC → 板 | 0、1 | 测试图像 | 1280×720 RGB565，行距 2560 B 连续存放，低 16 位为左像素（SoC 4.5）；末包 NOTIFY |
| PC → 板 | 2 | NPU 镜像 | 偏移 0：32 B 头 `{magic "EDNM", version u32 = 1, desc_count, desc_bytes, model_bytes, work_base, input_base, output_base}`（u32，小端；后 3 项为编译器 `regs.txt` 的值，CPU 与 3.3 的布局核对，不一致时报错不运行）；偏移 0x1000：描述符（`mem_desc.hex` 内容）；偏移 0x10_0000：模型（`mem_model.hex` 内容）。CPU 收到 NOTIFY 后核对 `WIN2_BYTES = 32 + desc_bytes + model_bytes`，把两段复制到 `DESC_BASE`、`MODEL_BASE` |
| PC → 板 | 3 | 短命令 | 预留给以后的网口命令；B2 的场景控制走串口菜单 |
| 板 → PC | 0 | CH2 输入回传（网口图像检查时）/ 视频帧（输出选择含网口时） | 检查：983,040 B，NPU 输入槽原样；视频：3.4a 的帧头 + 像素。两种用途不同时出现，PC 按自己发起的操作区分 |
| 板 → PC | 1 | NPU 输出回传 | 725,760 B，OUTPUT 区原样（布局见 `tools/npu/README.md`） |
| 板 → PC | 2 | 检测结果 | 16 B 头 `{magic "EDDT", version u16 = 1, count u16, frame_id u32, reserved u32}` + count × 12 B `{x0, y0, x1, y1: i16，1280×720 显示坐标；class: u16（COCO 0–79）；score: u16，千分比 0–1000}` |
| 板 → PC | 3 | 监控记录 | 3.5 的 type 1 / type 2 记录，每包若干条首尾相接，`OFFSET` 为批内字节偏移 |

一次网口图像检查，板子按 WIN 0、1、2 的顺序回传，最后一个块（WIN 2）的末包带 NOTIFY，PC 据此认为三块收齐。

### 3.6 调试工具新增功能（`tools/debug_tool/`）

| 页面 | 功能 |
|---|---|
| DDR 监控 | 接收 WIN 3 记录；各端口读、写带宽堆叠面积图（滚动 60 s），4.0 GB/s 理论值和 2.6 GB/s 规划有效值两条参考线；DDR 利用率；各端口平均/最长等待；实时性计数（DISP 读空、VIN 溢出、紧急授权，非 0 标红）；NPU 推理耗时、后处理耗时、检测帧率；场景切换标记；丢包计数；可导出 CSV；可选延迟直方图 |
| YOLO | 选择 `compile_yolo.py` 输出目录并发送镜像（显示 `WIN2_BYTES` 校验结果）；选择图片 → 缩放到 1280×720 RGB565 发送；显示板上检测框（叠加在原图上）；对回传的 CH2 输入和 NPU 输出运行参考模型并显示逐字节比对结果 |
| 场景控制 | 经串口菜单命令切换 S1/S2、PIX 运算、GEO 变换，设置采样率 |
| 视频 | 接收 WIN 0 视频帧（RGB565 直接交给 Qt 显示），按 frame_id 拼帧、缺包的帧丢弃；显示帧率、丢帧数、网口跳帧数；可叠加 WIN 2 检测框；输出选择（HDMI / 网口 / 同时）和网口帧率设置 |

## 4. 决策

按第 3 节方案执行（用户 2026-10-29 确认）。3.5 的 type 2 记录、`clk_sys_hz`/`clk_npu_hz` 字段和 3.5a 网口线协议是 B2-5a 问答中补充的细节（同日）。3.4a 输出选择和网口视频由用户同日追加（720p，帧率可选到 60 fps）。标为估算和草案的数字（程序大小、后处理周期、监控记录格式 v1、采样率 100 Hz）在 B2-3、B2-4 实现中实测后回填本记录。

## 5. 影响

- 规格：无新增（记录格式和 DDR 布局属于软件约定，写进 `sw/apps/demo/README.md` 和调试工具文档；若改为由硬件产生采样，另行讨论）。
