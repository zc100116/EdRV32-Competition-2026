## 1. 背景和问题

旧工程中摄像头（OV5640 DVP 采集、SCCB 初始化）和 HDMI（720p60 时序、TMDS 编码与串化）已在板上调通，新 SoC 中原则上照搬，只改接口、命名和时钟域以符合新规格。

像素处理和几何处理的问题在于功能编排没有梳理清楚：

- 旧 PIX 的顺序固定为"点运算 → 一个共享 3×3 窗口 → 输出"，一帧只能做一种空间运算，无法叠加（例如先高斯再 Sobel、先腐蚀再膨胀）。
- GEO 是 DDR 到 DDR 的独立引擎，和 PIX 之间只通过 DDR Surface 交接，谁先谁后、何时启用没有规定。
- 摄像头画面、处理结果、UI、检测框如何合成到显示输出，SoC 规格 8.8 留给了 RND/DISP 模块规格，至今未定。
- 演示场景 S2（图像处理）只写了"摄像头 → PIX → DDR →（可选）GEO → DDR → 图层合成"，没有规定效果组合、显示形式和帧延迟。

本记录逐项讨论这些问题，结论确认后修订 SoC 规格并写 VIN、PIX、GEO、DISP 的模块规格。

## 2. 约束

- 720p30 默认，60 fps 可选；摄像头写通道和 DISP 扫描是硬实时，任何负载下不得溢出或读空（SoC 8.5、8.8）。
- DDR 有效带宽规划值 2.6 GB/s，场景持续流量不超过 0.75 × B_eff；S1 中 NPU 占大头（SoC 9.1）。
- mem_xbar 7 个端口已分配：P0 DISP、P1 VIN、P2 CPU、P3 NPU、P4 RND、P5 GEO、P6 ETH+PERF。新增 DDR 访问者只能共用已有端口。
- 资源：NPU 占 148–156 DRM、288 APM；其余模块共用剩余约 260 DRM、450 APM。
- 旧 PIX 每拍 2 像素 @125 MHz；旧 GEO 算术发射上限 62.5 Mpixel/s（720p30 需要 27.6 Mpixel/s）。

## 4. 决策

### Q1 像素处理效果的叠加：在线固定级联（用户 2026-10-27 确认）

| 方案 | 说明 | 结论 |
|---|---|---|
| A 在线固定级联 | 摄像头流经 PIX 一次完成：点运算 1（亮度、对比度、Gamma 查表）→ 3×3 第一级 → 3×3 第二级 → 点运算 2（灰度、二值化、反色）→ DDR；每级可旁路 | 采用 |
| B 在线 + 内存多遍 | PIX 还能从 DDR 读回 Surface 再处理；需与 GEO 共用 P5，每遍多约 110 MB/s 和 1 帧延迟 | 不采用 |
| C 可编程顺序 | 各级之间加交叉选择，软件排列顺序；面积和验证组合多 | 不采用 |

- 可组合效果举例：高斯 + Sobel（去噪后取边缘）、腐蚀 + 膨胀（开运算）、膨胀 + 腐蚀（闭运算）、均值 + 锐化。
- DDR 流量与只写原图相同（720p30 约 55 MB/s）。
- 延迟（估算，按 720p 每帧约 750 行）：每个 3×3 级 1 行，点运算几个周期；两级合计约 2 行 ≈ 0.09 ms（30 fps，行周期约 44 µs）、0.045 ms（60 fps）。处理结果整帧写入 DDR 后才被显示，帧级延迟至少 1 帧（33 ms），级联延迟可以忽略。
- 帧尾补零输出最后 2 行约 10 µs（2 像素/拍 @125 MHz），在摄像头帧间消隐（约 30 行 ≈ 1.3 ms）内完成。
- 代价：比旧工程多一套 3×3 窗口（约 3 块 DRM 的行缓存），顺序固定。
- 由于 PIX 只处理摄像头实时流，S2 中 PIX 必然在 GEO 之前。

### Q2 GEO：DDR 到 DDR 命令式引擎，CPU 每帧启动（用户 2026-10-27 确认）

| 方案 | 说明 | 结论 |
|---|---|---|
| A DDR→DDR，CPU 每帧启动 | VIN 写完一帧发中断，CPU 写门铃让 GEO 处理该帧；GEO 可处理任意 Surface；支持任意角度旋转、缩放、平移 | 采用 |
| B DDR→DDR，硬件自动衔接 | VIN 帧完成直接触发 GEO；省每帧一次中断，但多一套模块间握手和缓冲所有权逻辑，只能处理 VIN 的帧 | 不采用 |
| C 流式 GEO | 接在 PIX 流后用片上条带缓冲变换；无额外延迟和流量，但不能大角度旋转 | 不采用 |

- 数据流：CAM → PIX → DDR[A] →（CPU 门铃）GEO → DDR[B] → 图层合成；不启用 GEO 时 DDR[A] 直接给图层合成。
- 启用 GEO 的代价：+1 帧延迟，+约 110 MB/s（720p30 RGB565 读写各 55 MB/s）。CPU 每秒 30 次中断。
- 与 SoC 规格 8.7（命令式，一个描述符完成一帧）一致。

### Q3、Q4 图层合成与 S2 显示形式：推迟到 RND 阶段（用户 2026-10-27）

图层合成是渲染器（RND）的职责，本阶段的基础图像通路不做合成：DISP 直接扫描一张视频 Surface（VIN/PIX 或 GEO 的输出），S2 本阶段为全屏显示处理结果。合成方式（DISP 扫描时叠加或 RND 离线合成）和 S2 的显示形式在 RND 阶段讨论；DISP 本阶段不为图层预留端口或结构（CLAUDE.md 第 1 节第 3 条）。

### Q5 摄像头初始化：软件经 I2C0，沿用旧寄存器表（用户 2026-10-27 确认）

- 旧工程验证过的寄存器表 `legacy/rtl/vision/camera/ov5640_720p.hex`（248 项 `{地址[15:0], 数据[7:0]}`，其后为 ROM 填充）和上电/复位时序原样移植为软件驱动（`sw/drivers/`），内容不改；经系统子系统已有的 I2C0（端口 0 接 cam0、端口 1 接 cam1）写入。
- 与 SoC 规格 8.5（摄像头由软件经 I2C 配置）和 sys-subsys 2.8 一致；60 fps 模式为另一张表，由软件切换。
- 风险：I2C0 尚未在板上驱动过摄像头。先用 `verif/models/sccb_model.sv` 仿真逐项核对写入序列，再上板。
- 传感器 PWDN/RESET 由 GPIO0 驱动（SoC 规格第 3 节端口表、8.3）。

### Q6 帧缓冲：三缓冲环 + CPU 交接（用户 2026-10-27 确认）

- VIN CH0 写 3 张 Surface 组成的环；每写完一帧（最后一个写响应返回后）发中断，状态寄存器给出帧号和槽号。
- CPU 把最新完整帧交给 DISP（写 DISP 的下一 Surface 寄存器，VBlank 生效，SoC 8.8）或交给 GEO（门铃）；GEO 输出写自己的 3 张环，CPU 再交给 DISP。
- 3 张保证 VIN 正在写的槽不会是 DISP 正在扫描或 GEO 正在读的槽（VIN 写槽 = 最新完成槽 + 1；GEO 处理一帧不超过 33 ms，早于 VIN 绕回到该槽）。
- 与 SoC 规格 7.3 R5 一致（N 块环形缓冲，2 ≤ N ≤ 4，本方案 N = 3）：软件可把 DISP 正在扫描或 GEO 正在读的槽标为占用，VIN 跳过占用槽；全部占用时丢弃本帧并计数。正常情况下 CPU 交接 + VBlank 切换（≤ 16.7 ms）短于一个摄像头帧（33 ms），不需要占用标记；软件延迟超过一帧时用占用标记避免撕裂。
- 延迟估算（30 fps，从摄像头开始输出一帧到 HDMI 扫完）：不经 GEO 约 50–67 ms（1.5–2 帧）；经 GEO 约 83–100 ms。
- 显存：720p RGB565 每张 1.8 MB，VIN 与 GEO 两个环共约 11 MB。
- 不采用双缓冲（显示未切换时 VIN 只能丢帧或撕裂）和硬件自动交接（VIN–DISP 多一条硬件接口，启用 GEO 时仍需软件）。

## 5. 影响

SoC 规格修订（经用户确认后改）：
- 8.5 VIN：不需修改（7.2 帧完成状态、7.3 R5 环形缓冲、2.x GPIO0 驱动 PWDN/RESET 已覆盖 Q5、Q6）。
- 8.6 PIX：功能改为固定级联"点运算 1（亮度、对比度、Gamma 查表）→ 3×3 第一级 → 3×3 第二级 → 点运算 2（灰度、二值化、反色）"，每级可旁路。
- 8.8 DISP：本阶段单层扫描一张 Surface；图层合成留到 RND 阶段（与 RND 一起定）。
- 1.2 S2：本阶段全屏显示处理结果。

新增模块规格和配套文档：`docs/spec/vin-spec.md`、`pix-spec.md`、`geo-spec.md`、`disp-spec.md`，以及对应的验证方案和实施方案；软件驱动 `sw/drivers/` 中的 OV5640 初始化。摄像头采集前端、HDMI 时序和 TMDS 按旧工程移植。
