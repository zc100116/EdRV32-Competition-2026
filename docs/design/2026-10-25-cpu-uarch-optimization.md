# CPU 微结构优化方向（C-E4 之后）

| 项 | 内容 |
|---|---|
| 状态 | 讨论中 |
| 日期 | 2026-10-25 |
| 依据 | [C-I3 B2 测量](../reports/2026-10-25-perf-cpu-b2.md)、[C-E4 轨迹模型评估](../reports/2026-10-25-perf-cpu-uarch-eval.md)（分支 `zc100116/task-cpu-uarch-eval` d5c75e3） |
| 影响规格 | `cpu-spec.md` v0.9 §4.2（配对规则）、§4.4（预测器）、§7.1 |

## 1. 背景和问题

C-I3 在 RTL（cpu-spec v0.9，B2 配置，`READ_LATENCY=2`）上测得 CoreMark/MHz：O2 3.585，tuned 4.307；IPC 约 1.03（O2）。HPM 显示周期主要损失在：

| 现象（RVC=1，O2，计时窗口 2,789,093 周期） | 计数 | 占周期 |
|---|---:|---:|
| 单发射：第二条类型不支持（管线 1 只做 ALU） | 662,406 | 23.7% |
| 单发射：配对 RAW | 448,007 | 16.1% |
| 单发射：结构冲突 | 105,040 | 3.8% |
| load-use 停顿 | 279,911 | 10.0% |
| 前端断流（IB 空） | 171,522 | 6.1% |
| 误预测/重定向次数 | 80,058 | 约 13% 的控制转移 |
| I$/D$ 缺失 | 122 / 24 | 可忽略 |

各事件可重叠，不能相加。最大的单项是"类型不支持"。C-E4 用与 RTL 校准的周期模型（四组配置总周期误差 −0.03% 至 −0.94%）评估了五个方向。

## 2. 约束

- 目标频率 150 MHz（clk_sys，[待定]，C-W2 综合后定）。任何改动的收益要按 `CoreMark/MHz × Fmax` 计算，IPC 提升被频率下降抵消就没有意义。
- 每拍最多解码、发射、退休两条；保持程序顺序退休和精确异常。
- v0.8 已为消除组合环路删去槽 1 异常、简化 kill 语义（C-R4）；新改动不能把这些复杂度带回来。
- 面积预算：PG2L200H 资源充裕，CPU 不是 LUT 瓶颈；DRM 需与 cache、SRAM、NPU 统筹。

## 3. 可选方案

速度比 = V0 周期 / 变体周期，四列依次为 RVC1/O2、RVC0/O2、RVC1/tuned、RVC0/tuned（C-E4 模型实测，I$/D$ 全命中）。硬件代价为**估算**，依据是对 cpu-spec v0.9 结构的逐项推算，未综合。

| 方案 | 内容 | 速度比 | 硬件代价（估算） | 时序和复杂度风险 |
|---|---|---|---|---|
| V1 发射交换 | 较老一条是 ALU、较年轻一条是管线 1 不能执行的类型时，交换管线后同发 | 1.043 / 1.044 / 1.040 / 1.036 | D→E 两套指令包的交叉选择器（约 2 × 100 位 2:1 选择），W 级按年龄位提交；约 200–400 LUT | 中高：管线 0 上的指令可能比管线 1 年轻，异常、分支冲刷、kill 都要按年龄判断（较老的管线 1 指令必须照常提交）。这正是 v0.8 为消除组合环路而简化掉的路径；选择器位于 D 级配对判定之后，可能进入关键路径 |
| V2 管线 1 支持分支和 JAL | 槽 1 可以是条件分支或 JAL（不含 JALR） | 1.053 / 1.052 / 1.057 / 1.064 | 管线 1 增加 32 位比较器和目标加法器（约 100 LUT）；E 级两个重定向源按年龄选择；模型允许一对中两条都是分支，需要 gshare/GHR 每拍更新两次（双写口或两位历史移位）；约 300–500 LUT | 中：E 级重定向选择是已知的长路径，多一个源会加长它。只允许一对中最多一条分支可以省去双更新口，但该子方案未建模 |
| V3 = V1 + V2 | | 1.061 / 1.061 / 1.076 / 1.080 | V1 + V2 | 两者之和 |
| V4a 16 字节取指 + IB 8 | 每拍取 16 字节，每 16 字节组一个 BTB 项 | 0.991 / 0.983 / 0.999 / 1.006 | I$ 数据读口 64→128 位，IB 加倍 | — 无收益：每组只能预测一个跳转，BTB 冲突增多，误预测反而增加 |
| V4b 16 字节取指，双半组 BTB 查询 | 同上，但两个 8 字节半组各查一次 BTB（双读口） | 0.998 / 0.998 / 0.996 / 0.999 | 比 V4a 多一个 BTB 读口 | — 无收益：前端断流只占 6%，解码宽度仍为 2，取得更多没有用 |
| V5 预测器加大 | BTB 64、gshare 1024（RAS 仍为 4） | 1.022 / 1.015 / 1.021 / 1.024 | BTB 每项约 60 位（tag 23 + 目标 30 + 位置/类型），64 项约 3.8 Kbit，可放 1 块 DRM 或分布式 RAM；gshare 1024 × 2 位 = 2 Kbit 分布式 RAM；增量约 100–200 LUT 或 1 块 DRM | 低：结构不变，只是索引宽一位；F1 查询路径基本不变 |
| V3 + V5 | | 1.085 / 1.078 / 1.096 / 1.102 | V1 + V2 + V5 | 同 V3 |

由此推算的 CoreMark/MHz（按 C-I3 的 RVC=1 实测乘以模型速度比，**估算**）：

| 配置 | O2 | tuned |
|---|---:|---:|
| 当前 v0.9 | 3.585 | 4.307 |
| + V5 | 约 3.66 | 约 4.40 |
| + V2 + V5 | 约 3.86（估算 V2、V5 收益相乘） | 约 4.65 |
| + V3 + V5 | 约 3.89 | 约 4.72 |

V2 与 V5 相乘是估算，模型没有单独跑 V2+V5 组合。

### 3.1 模型的局限

- I$/D$ 全命中；tuned 配置的真实 I$ 缺失使模型前端断流少 6–11%，对变体之间的相对比较影响小。
- 只有 CoreMark 一个负载；视觉应用的控制代码（驱动、调度）分支更多，V2、V5 的收益预计不低于 CoreMark，但未测。
- 不包含频率影响。

### 3.2 C-E5 补充数据

[C-E5 报告](../reports/2026-10-25-perf-cpu-pipeline-analysis.md)（b0353bb）：

- V2s（一对最多一条控制转移）速度比 1.042–1.045，比允许两条分支的 V2 少约 1–2 个百分点；V2s+V5 为 1.059–1.069。
- V0 互斥损耗栈（RVC1/O2，占 2×周期的比例）：配对类型 11.8%、load-use 10.0%、配对 RAW 8.0%、E 重定向气泡 6.9%、其他结果延迟（主要是乘法）6.7%、D 重定向气泡 1.8%、配对结构 1.9%、错误路径发射 0.6%、前端断流接近 0。
- V2s+V5 上的理想化上限（RVC1，O2 / tuned）：取消组内 RAW +15.8% / +5.7%，load 延迟 1 +11.7% / +10.4%，槽 1 全类型 +10.4% / +11.4%，完美预测 +7.6% / +10.4%，乘法延迟 1 +7.2% / +1.9%，完美前端 <1.5%。
- 敏感性（V2s+V5，RVC1/O2）：load 结果延迟 2→3 损失 14.6%；乘法延迟 3→2 +3.7%、3→4 −3.5%；E 重定向代价每 ±1 拍约 ∓1.9%（tuned 约 ∓2.8%）；D 重定向代价每拍约 0.4%。
- 推论：加宽前端没有价值（与 V4 结论一致）；剩余最大的两项是组内 RAW 和 load-use，后段 ALU（C-E7）正好针对这两项；load 结果延迟必须保持 2，综合时若 D$ 路径不满足时序，应优先用其他手段而不是加 load 延迟。

### 3.3 C-E7 后段 ALU 与 C-E8 乱序模型

依据 [C-E7 报告](../reports/2026-10-25-perf-cpu-late-alu.md)（da0f078）和 [C-E8 报告](../reports/2026-10-25-perf-cpu-ooo-model.md)（ed7dea6）。速度比相对 V0，四列依次为 RVC1/O2、RVC0/O2、RVC1/tuned、RVC0/tuned；顺序变体均以 V2s 为基础。

| 方案 | 速度比（相对 V0） | 主要硬件增量（定性） |
|---|---|---|
| V2s+V5 | 1.066 / 1.059 / 1.064 / 1.069 | 管线 1 分支单元；BTB 64、gshare 1024 |
| L1+V5：仅管线 1 后段 ALU | 1.071 / 1.064 / 1.075 / 1.078 | +1 ALU |
| L2+V5：两条管线后段 ALU | 1.099 / 1.092 / 1.089 / 1.088 | +2 ALU、后段旁路 |
| L2s+V5：L2 + store 数据晚旁路 | 1.117 / 1.110 / 1.094 / 1.095 | L2 + store 数据旁路 |
| **L2b+V5：L2 + 后段分支** | **1.193 / 1.176 / 1.156 / 1.162** | L2 + M 级分支判定（该类误预测代价 +1 拍）、M/E 同拍训练用一项待写缓冲保持单写口 |
| 乱序默认（ROB32/IQ16、误预测 7、每拍选 2） | 1.275 / 1.238 / 1.108 / 1.135 | 重命名、物理寄存器堆、统一 IQ、ROB、LSQ、恢复 |
| 乱序，误预测 5 | 1.320 / 1.278 / 1.160 / 1.179 | 同上，前端快速恢复（未实现的抽象） |
| 乱序，误预测 9 | 1.201 / 1.168 / 1.032 / 1.062 | 同上 |

- L2b 的大部分收益来自"load → 条件分支"相关（链表遍历、比较）：分支推迟到 M 判定即可消除 load-use 停顿；后段指令占退休数 24%。L2b+V5 的 M/E 同拍训练冲突 2.5–6.1 万次，由待写缓冲吸收，不停顿。
- 乱序模型的窗口在 ROB32/IQ16 已饱和（ROB64/IQ32 仅再快 0.6%），每拍选 3 条只再快约 2%。
- 对比：O2 下乱序默认点比 L2b+V5 高约 7%（1.275 vs 1.193）；tuned 下 L2b+V5 反而高约 4%（1.156 vs 1.108）。乱序对误预测代价敏感，代价 9 时 tuned 几乎没有收益。
- 换算 CoreMark/MHz（按 C-I3 RVC=1 实测乘速度比，估算）：L2b+V5 约 4.28（O2）/ 4.98（tuned）；乱序默认约 4.57（O2）/ 4.77（tuned）。
- 乱序模型的新结构没有 RTL 可校准，错误路径访存不占 LSU 使其略偏乐观；两者都未计入频率差异。乱序核的 Fmax 和面积预计明显差于顺序核（调研：NaxRiscv 13.3k LUT）。

## 4. 决策

用户已确认（2026-10-25 / 2026-10-26）：

- **不做乱序**（2026-10-26）：把顺序双发射做到极致；L2b+V5 为当前基准，剩余优化由 C-E9 评估后一并定稿。


- **V2 暂时采纳受限形式**：管线 1 支持条件分支和 JAL，一对中最多一条控制转移；是否放开到两条，视后续实际情况再定。受限形式的收益由 C-E5 补测。

其余待用户确认。协调者推荐：

1. **V4（加宽取指）放弃**：两种做法都没有收益。
2. **V5 采纳**：+1.5%–2.4%，代价最小，时序风险低。
3. **V2 采纳**：单项收益最大（+5%–6%），复杂度集中在管线 1 和 E 级重定向选择。
4. **V1 暂不采纳**：+3.6%–4.4%，但需要按年龄处理异常和冲刷，等于重新引入 v0.8 删掉的复杂度；V2 落地并完成 C-W2 综合后，如果 E/W 级仍有时序余量再评估。

## 5. 影响

采纳后需要修改：

- `cpu-spec.md` §4.2（槽 1 允许条件分支和 JAL；是否允许一对两条分支）、§4.4（BTB 64 项索引 `PC[8:3]`、gshare 1024 项 10 位 GHR）、§7.1 性能指标；
- `cpu-testplan.md`：槽 1 分支的配对、重定向优先级、预测器更新测试项；
- RTL：`rtl/cpu/` 发射、E 级分支单元、预测器；全量 full 回归和 B2 性能复测；
- 删除 C-E4 模型中不再需要的变体参数（模型本身是工具，保留）。
