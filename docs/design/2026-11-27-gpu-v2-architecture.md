# GPU v2：面向 OpenGL ES 1.1 Common 的架构研究

## 1. 背景和问题

本记录推荐：**默认双分量 FP32 顶点微引擎、固定裁剪/投影、一次几何处理后按
64×64 块分发、共享纹理采样器分两遍、固定像素合成器**。四分量 FP32 作为满配，
不作为 PG2L200H 上默认档。首先验证 setup 的串行共享和局部存储，再增加功能。
现有定点 MVP 加一盏方向光不能直接宣称为 ES 1.1 Common；8 灯、完整光照、
投影纹理 q、用户裁剪、状态/API 语义的成本远超过增加几个像素比较器。

## 2. 约束

- API 为 OpenGL ES 1.1 **Common**，不是 Common-Lite；不做 ES2/可编程像素。
  桌面 immediate mode 属于兼容层；IP 的独立作品集价值优先于竞赛负载。
- clk_gpu 按 200MHz 切拍，150MHz 为保底预算；频率、资源和可布线性最终均由 PDS
  验证。CPU F 配置单精度 FMA 本体8拍，II1；2R源捕获另1拍，不能当8拍一条无依赖指令。
- APM 为有符号25×18、48位后加器，CPI/CPO支持移位级联。24×24正尾数拆
  24×16和24×8：**2 APM，4拍完整积**，不是一颗“FP32 DSP”；FMA的对齐、
  规格化、舍入在CLM。链头MODEZ=0；后级差16用shift16；内部X/Y/MULT/P/CPO
  寄存不重复记外部FF。沿用 apm-cascade 文档原语规则，不假定通用DSP48特性。
- 资源向量统一记 **R=(总LUT, FF, APM, DRM36K, LUTRAM)**；本文所有表中
  `K(R)=ceil(max(LUT/4,FF/8)/0.70)`，为CLM规划代理，不是物理CLMA/CLMS预测。
  新设计约±40%不确定性；不能把表中“分配额”当成综合测量。
- 仅新增此记录和 `tools/gpu/study/`。脚本标准库、串行C编译/执行，无RTL、规格、sw修改；
  不增加保护、校验、门禁或静默降级。GL要求的API错误是未来驱动契约，本轮不实现。

## 3. 可选方案

### 3.1 ES 1.1 差距清单和最小限制

核对主源：[Khronos ES1.1.12完整规格](https://registry.khronos.org/OpenGL/specs/es/1.1/es_full_spec_1.1.pdf)
（2008-04-24，§2–6、附录C；本轮从官方 GitHub registry 同内容PDF提取文本）。
以下“已有”只指v0.6已有机制，不代表已通过ES一致性；一项可同时包含硬件与驱动工作。

| ES必需项 / 最小限制 | v0.6对照与归属 | 原因 / 推荐处理 |
|---|---|---|

| float/fixed及合法BYTE/SHORT等数组类型，当前color/normal/多纹理坐标；客户端数组与VBO（§2.7–2.9） | **驱动实现** | 类型转换、stride、enable、offset、buffer对象、DrawArrays/Elements；不要求专用VBO硬件 |
| POINTS/LINES/LINE_STRIP/LINE_LOOP/TRIANGLES/STRIP/FAN | 三角形**已有**；其余**驱动实现+硬件补** | 索引装配、strip奇偶和provoking vertex由驱动；点线覆盖见3.6 |
| modelview栈≥16；projection≥2；每纹理matrix栈≥2 | **驱动实现+硬件补** | 栈/乘矩阵/逆转置CPU维护；顶点执行MV、P、法线及两套纹理矩阵，不能只保留合成MVP |
| 法线逆转置、NORMALIZE、RESCALE_NORMAL | **硬件补** | 微码/rsqrt；颜色材料追踪由驱动，不可用物体空间固定方向光替代 |
| 灯≥8：方向/位置、衰减、spot、ambient/diffuse/specular、emission、shininess0..128、双面、COLOR_MATERIAL | **硬件补+驱动实现** | 当前只有一盏物体空间方向光+ambient，未有完整材质、眼空间或镜面 |
| 6个齐次view clip平面，用户裁剪面≥1 | **硬件补** | 当前W近裁+XY保护带5面，没有标准−w≤z≤w与用户平面；用户方程在调用时按MV变换 |
| viewport、DepthRange、FrontFace/CullFace、SCISSOR | 部分**已有**；**硬件补+驱动实现** | GL下左原点→当前上左原点；NDC深度−1..1映射0..1；front/back/both；viewport范围需覆盖提供的表面 |
| SUBPIXEL_BITS≥4；共享边只覆盖一次 | **已有** | s12.4/top-left机制可复用；超大坐标先裁剪，不能饱和出假边；整数平移不变性另验证 |
| smooth/flat颜色 | smooth **已有**；flat **驱动实现** | 按图元原始最后顶点固定颜色，须在裁剪/扇分之前保存，不能用裁后第3点 |
| 点大小、线宽，aliased和smooth范围至少[1,1] | **硬件补** | 只承诺宽1也须实现width1抗锯齿覆盖；不能把SMOOTH简单忽略；点大小数组/衰减必需 |
| ≥2纹理单元（最多32）；每单元enable/matrix/env/coords独立 | **硬件补+驱动实现** | 一个物理采样器可分时实现两个逻辑单元，无需两份过滤器 |
| 2D POT纹理，MAX_TEXTURE_SIZE≥64；从1×1起完整mip链，border0；空图像 | 部分**已有**；**硬件补+驱动实现** | 当前8..256需放开1/2/4；推荐max256（小档64），更大纹理不是ES1.1必需 |
| REPEAT/CLAMP_TO_EDGE；MIN六模式、MAG两模式 | 环绕/三种过滤部分**已有**；**硬件补** | MIN与MAG独立、level选择/两级nearest混合、magnification切换点需按§3.7.7/8补齐 |
| A/L/LA/RGB/RGBA；UNSIGNED_BYTE与565/4444/5551上传 | RGB565 **已有**；**驱动实现+硬件补** | A8/L8/LA88/4444/5551本地解码；RGB8/RGBA8可确定性转内部16位，但推荐RGBA8缓存保持质量 |
| Tex(Sub)Image/CopyTex(Sub)Image；texture对象；GENERATE_MIPMAP | **驱动实现+硬件补** | CPU转换/box mip、分配；Copy/Read触发tile物化，目标需load/store，不能仅写出当前条带 |
| OES_compressed_paletted_texture必需，10格式 | I4/I8近似**已有**；**驱动实现** | palette4/8 × RGB8/RGBA8/565/4444/5551；上传解压到确定内部格式，现有565+A4不能无损表示所有输入 |
| MODULATE/REPLACE/DECAL/BLEND/ADD/COMBINE，RGB/alpha scale1/2/4，DOT3等 | MODULATE部分**已有**；**硬件补** | 详3.5；按base format保留alpha/颜色，不能把所有输入都当RGBA相乘 |
| 纹理(s,t,r,q)，2D使用s/q,t/q，矩阵后q可变化 | **硬件补** | 不是两套u,v的简单复制：每套各有透视分母；r虽不取样仍参与纹理矩阵 |
| Fog LINEAR/EXP/EXP2 | **硬件补+顶点微码** | §3.8允许顶点计算f后插值、距离用abs(ze)；不是任意把颜色变暗，fog须在纹理之后混合 |
| AlphaFunc全部8函数；最终alpha=0仍可能写深度/模板 | **硬件补** | 删除无条件透明discard语义；alpha测试在模板之前 |
| 深度8函数、写掩码、clear/depth range | LEQUAL/ALWAYS **已有**；**硬件补** | 其余6种与disable时不写深度须补齐 |
| 模板8函数、KEEP/ZERO/REPLACE/INCR/DECR/INVERT、读写mask | **已有+驱动实现** | INCR/DECR饱和；wrapping不是本轮必需；clear必须遵守mask/scissor |
| BlendFunc全部合法组合：含DST_ALPHA/1−DST_ALPHA/SRC_ALPHA_SATURATE | 部分**已有**；**硬件补** | 无目标alpha时Da=1；当前常量alpha/MinMax等超集不能代替漏掉的必需因子 |
| RGBA逐通道写掩码；16种color logic op；DITHER | **硬件补+驱动实现** | logic开启时跳过blend，按目标存储位运算；允许恒等dither但需保存/查询enable（初始开） |
| PolygonOffset(factor,units) | **硬件补** | setup求max(abs(dz/dx),abs(dz/dy))，加m·factor+r·units，r对应深度分辨率 |
| ReadPixels RGBA/UB及OES_read_format查询 | **驱动实现+硬件补** | pack alignment1/2/4/8；tile flush后RGB565展开RGBA8，alpha=255；native读格式565可报告 |
| color/depth/stencil位数 | RGB565/D16/S8 **已有** | §4与表6.23不规定D16/S8最低位数，甚至可无D/S；推荐提供16/8，不误称24位深度为最低要求 |
| multisample相关state/query | **驱动实现** | SAMPLE_BUFFERS=0/SAMPLES=0合法；保留API状态，按无MSAA语义运行，后处理AA不能冒充MSAA |
| OES_point_size_array/OES_point_sprite/OES_read_format | **硬件补+驱动实现** | 附录C.2列为必需扩展；point sprite不是可省掉的桌面扩展 |
| Get*/Is*/Gen/Delete/Bind、默认状态、GL错误、Flush/Finish、hint、字符串 | **驱动实现** | 有限对象表按分配结果报告OOM；错误规则按ES；不在GPU内部添加新保护流程 |
| glBegin/glEnd、QUADS、display list、TexGen、桌面glOrtho等 | **兼容层实现** | 不属ES1.1；收集当前属性→顶点数组；桌面额外状态不能偷偷加入ES核心 |
| secondary color / 独立specular色 / 显式FogCoord | **兼容层实现（可选硬件支持）** | **不是ES1.1 Common核心必需**。ES镜面已加进主色；任务要求仍在3.4估算其扩展成本 |

不能因“本场景不用”而删除必需API；小档减少吞吐/公布范围，不减少8灯、2纹理、
1用户面。FBO、draw_texture、matrix_palette、anisotropic、NPOT和stipple不在本轮核心目标。

### 3.2 顶点方案：周期、精度和资源

工作负载定义：D=方向灯、diffuse+ambient、NORMALIZE、MV/P、2纹理矩阵、投影；
G=位置灯+距离衰减+spot+specular，单面。双面约再增加一次灯求值，不能用D代表完整ES。
下表无裁剪交点、无DDR停顿；共享顶点缓存命中按3.3另扣。周期指稳态每顶点服务间隔，
不是首结果延迟；吞吐为MHz/周期，单位Mvertex/s。

| b FP32 SIMD4 | 96 / 320 | 1.563 / .469 | 464 / 1696 | (14500,10000,12,4,2200) / 5179 | (+5373,−10568,−52,+3,+282) |

200MHz吞吐为上表×4/3；CPU列须使用CPU实际频率，不能默认与GPU同频。
CPU的新增F/8另占(3709,873,2,0,320)，K1325（FPU记录结构估算，含RF/队列）；
若CPU本来已带F则这是共享资源，不重复收费，GPU和CPU差值仍分开记。
旧geometry的9127/20568/64/1/1918**已经包含**project2835/9084/26/1/665、
clip2713/4773/12/0/264、transform1193/2594/24/0/208与外壳；不能把子项再加一次。

周期输入/公式：a为共享4乘法固定矩阵/灯流水：D=32+16L；G=80+112L，
包含normalize/spot/pow迭代，但未列RTL排程，置信度低。D1不是现有II2：增加MV、
法线、第二纹理矩阵及复用使服务间隔不同。若要求继续II2需复制灯与矩阵路径，
不能沿用此资源额。b采用 `C_D=(64+32L)×4/W`，`C_G=(288+176L)×4/W`：
4分量排程中base64预算分为MV/P8、normal/normalize16、两纹理矩阵8、viewport8、
属性转换8、RF/RAW气泡16；每方向灯32含dot/clamp8、颜色积加12、调度12。
G的base额外224为normal/距离准备/SFU与调度，每灯176为距离/衰减48、spot/pow64、
specular32、颜色32。是可复算的静态槽预算，**未编译微码，不能宣称精确实测周期**。

CPU公式D=960+384L、G=2240+1856L：标量运算数量基于同一向量内核拆4分量，
加载/存储/整数指针256槽，余为发射、分支和依赖等待；FMA8与源捕获/转发导致
单顶点dot有依赖，独立顶点软件流水可缩短等待但不会提供4路发射。编译trace和CPU
完整cache争用尚待测，±2倍敏感度比把8拍机械乘所有FMA更有意义。1000三角形帧
3000顶点D1需4.032M CPU周期=26.88ms@150MHz，未计游戏，故c只推荐启动参考/低顶点UI。

**a的数值问题**：原定点仅加灯数不满足Common范围。要接受float、维持小量相对精度，
需每向量指数/块浮点输入、约64位尾数累加与宽中间积；表中额外8.9kLUT/40APM为
该扩展分配额，不是简单“复制7盏灯”。固定数据流在D场景吞吐很好，但全状态组合
验证和位宽证明工作量大；没有低于SIMD的资源证据，暂不推荐。仅保留旧范围可做
自定义API小核，不能挂Common名称。

**b的ISA草图**：64位微指令含opcode8、dst5、src0/1/2各5、三个8bit swizzle、
三个neg/abs各2bit、写掩码4、条件2bit，正好64bit。LOAD_CONST重解释源字段存7bit索引，
立即数/长分支用附加字。指令为MOV、ADD、MUL、FMA、MIN/MAX、DP3/DP4（宏展开）、
RCP、RSQ、LOG2/EXP2（用于一般pow）、CMP/SELECT、定次数LOOP、LOAD_ATTR/CONST、
STORE_VERTEX/END。不开一般内存load/store或像素程序。支持对有限数按FP32工作，
不需要CPU IEEE异常标志体系；算术单位保留24位有效尾数、正确指数，不能称P18为FP32。
4分量对应同一顶点xyzw；默认2分量分两次、小档1分量分四次。4个顶点context轮转
隐藏FMA8拍；仅静态微码依赖排程，未额外预算乱序记分牌。RCP/RSQ种子+Newton，
LOG/EXP分段表，SFU预算约1.5kLUT/1kFF/4APM/1DRM，已在geometry总额内。
CPU L(24)=2749/Q(24)=819提供单lane逻辑量级上界参考；GPU去CSR/DIV/SQRT后
2lane约5k逻辑，加控制/RF/SFU/clip形成8.5k总额。省面积来自复用和局部存储，
不是“FP32比定点天然更省”。

RF采用32个vec4/context、4context，逻辑2KiB；3R1W LUTRAM复制为6KiB，
128深度×128位×3读
约768 LUTRAM，uniform和输入/输出表计入1400总额。结果直达局部RF，跨单元只发
vertex槽号；属性按字段存DRM，禁止把16属性各级完整打拍。程序建议512×64=32Kbit，
占1DRM；其他2DRM用于clip工作集/属性。寄存口实际推断/CLMA打包为PDS风险。

**裁剪位置**：保留固定“距离分类+有序多边形队列+交点”控制，算术复用局部FP32
乘加/倒数；不保留旧s40×s43全并行12APM与75拍project总线。7面（6view+1user）
逐面处理，三角形最多10个多边形顶点，缓存16槽；clip/fan次序和共享边一致性须验证。
无裁剪先outcode，典型均在体内；穿越时估算每交点160×4/W周期（16属性、一次rcp及
多分量插值）。额外交点J则 `Cframe += 160J×4/W`，并按扇形扩展bin数。
全微码裁剪省约(600,500,0,0,128)，K215，但所有顶点占微引擎、循环/队列压力大；
全固定FP裁剪另加约(2500,3000,12,1,400)，K893，保持吞吐但违背默认面积优先。
默认折中不是保证极端裁剪的II2；v2若要求旧几何II2应另立高吞吐档。

### 3.3 几何到条带/块：工作量、DDR与驱动

令T为源三角形、V为独立变换顶点、S条带数、F为tile引用数/T，输入顶点64B、
输出屏幕顶点80B（16属性×4B、屏幕xy8B、tag/padding8B）、索引引用8B。
输入64B可打包position4、normal3、RGBA8、两套vec4纹理坐标；旧16B顶点不是ES全属性大小。

| 组织 | 顶点工作 | 几何/列表DDR（不含纹理和RT） | 片上额外与性能 | 驱动 |
|---|---|---|---|---|
| 当前每条全重放 | S·3T（无索引cache） | S·3T·64 + S·命令字节 | 沿用目标129DRM；无bin硬件额 | 每条保存状态、重放；texture upload不可重复计算为每帧一次 |
| 一次顶点、按180行条带bin | V；无cache时3T | 64V输入+80V输出写+80V输出读（引用局部cache前）+16F T | 新bin/cache R(1800,1600,0,8,500)，K643；64顶点cache按80B/项约2DRM | 保持源顺序、状态包ID，2条的F通常1..2 |
| 一次顶点、64²tile bin | 同上 | 冷读最坏每引用3×80，`64V +80V +240FT +16FT`；有cache时以实际读miss代替 | 默认64² RT5DRM，60块；setup按FT次，tile清/写出60次 | 不能按纹理重排透明/模板操作；tile列表内严格源命令顺序 |
| 一次顶点、CPU bin | 同上 | 与GPU bin相同 | GPU bin逻辑可省约800LUT/600FF/128LR，K286；CPU包围盒每三角形20..80周期估算 | CPU必须等GPU几何完成/读回边界，DDR与同步使其适合作为首个研究实现 |

一次几何不等于一定省DDR：S=2时旧读384T B；无cache的tile方案可超过它。
收益核心是保住昂贵光照只做一次，DDR换片上资源。V应由DrawElements索引和小cache
实测决定；GLBegin展平后通常V=3T，不能先假定顶点共享率50%。

脚本从现有stress构造的1000三角形求包围盒：条带引用1000，64²引用1634，F=1.634；
该场景两条各有不同图元，不应再声称重放同一1000三角形两次。若所有场景共用一份
列表，640×360旧重放2V，新V；1280×720旧8V，新V。全屏三角形包围盒在60块中
引用60次，bin不是无代价；可用精确三角形tile覆盖减少引用，默认预算只做bbox。

RT按 `ceil(w·h·bpp/36864)` 算逻辑下界，另计宽度/端口打包：
640×180×40bit=125块下界、现有实测129；64²×40=5块；32²×40=2块；
64²×64（RGBA8+D24S8）=8块。默认从129减到5，省124DRM；双缓冲tile则10块，
本预算单tile、渲染和store串行，未偷用双缓冲吞吐。完整颜色Surface RGB565
每帧460800B=27.648MB/s@60；RGBA8为55.296MB/s。若每tile需保留旧D/S，
40bit目标一进一出2.304MB/frame=138.24MB/s（含颜色），远高于只写颜色的数字。

64像素宽一行RGB565=128B；64bit总线16beat、256bit总线4beat，都能完整burst。
32²行64B分别8/2beat。64bit/256bit效率差主要在跨行地址/命令开销和短引用，
不是64²本身导致浪费。单独8B引用在256bit若一条一事务只有25%有效，合并64B
或512B邻接列表可恢复满载；64bit本地读8B天然合适，仍有仲裁开销。
计划DDR每拍有效 `总线字节×η`，η默认.55，敏感度.30..80；256bit是片上接口，
不能把它等同物理DDR带宽。tiles遇到ReadPixels/CopyTex/Finish、修改参与绘制的
buffer/texture时按ES命令序物化；clear、blending、mask、保留D/S都必须跨提交正确。

### 3.4 三角形建立和属性插值

当前7个平面Z/q/uq/vq/RGB。核心2D项目纹理需要Z、q_w、s0/w、t0/w、q0/w、
s1/w、t1/w、q1/w、RGBA、fog_f，共**13**个标量；常见q0=q1=1时与q_w共用，
降到11个。任务中secondary RGB作为桌面扩展另3个，最坏16标量；r0/r1只在顶点矩阵
和裁剪传输中保留，因此clip记录18标量而非18个像素平面。两套纹理一般需要两个
倒数分母；q0=q1=1才能共用一个。雾用f时不再插值眼空间距离；alpha也不能省。

| 方案（默认16属性能力，常见11活跃） | setup / raster R，K | 插值/性能 | 精度和代价 |
|---|---|---|---|
| 平行扩展当前P-A | setup(16000,36000,54,1,4000)，K6429；raster(10000,24000,0,0,2200)，K4286 | 2pixel/cycle；setup属性池原II8→至少16..24 | 原7→16的raster有效数据位254→约600；不能只把控制逻辑线性放大，更不能说增加9属性免费 |
| 边函数λ + APM属性池 | setup(3500,4200,12,2,900)，K1250；raster+插值(6500,7200,32,0,1500)，K2322 | 每属性用a2+λ0(a0−a2)+λ1(a1−a2)，2乘；16属性×2pixel需64个24×24乘积=128APM才可全并行II1；32APM池约.5pixel/cycle | Q24 λ在细长三角形/大属性抵消有误差；只把边函数变λ不能消除乘法带宽 |
| 局部块浮点setup（推荐研究） | setup(4300,5400,32,2,1100)，K1536；raster(3300,4300,0,0,700)，K1179 | 共享4乘池按属性循环，16拍/三角形；像素加法2lane/拍 | P-A本来就是块浮点；新意是tile局部原点、串行setup和字段RAM，不是换名即可省FF |

上述setup和raster是各自**完整替换额**，不是在旧10k/5k上再相加。属性在DRM/LUTRAM
按槽存，最多16个属性逐个建立，元数据只传slot/tag；每属性的σ/γx/γy和指数不沿
85拍全流水广播。上限16拍是计划调度，在面积/倒数/属性读写冲突尚未排定时取16..32
敏感度。1000三角形×F1.634×32=52288拍仍远低于像素工作，不需要旧II8的复杂全流水。
若保持原三角形II8且属性数增倍，省下的算术必须补回来；这不是无损原始峰值优化。

精度分两层：Common§2.1.1的单次算术约1e-5和数值范围；§3的屏幕子像素≥4bit、
插值公式/共享边/平移不变性。ES没有“整帧UV≤1/256纹素”或“必须D24”的统一规定。
24bit尾数满足单操作量级；最终长链误差仍要验证。颜色可按§3.5.1屏幕线性近似，
深度必须屏幕线性；纹理一般不可仿射近似。P18内部单次相对舍入约2^-18，
接近而非自动证明Common要求，倒数、乘法与取消误差必须共同检查。

沿用Python模型误差方法：共同覆盖像素上UV纹素、Z u16、RGBA u8分别max/RMS，
覆盖XOR另记，2×2 helper算LOD/mip分歧，过滤后RGB与最终DDR分开。既有P-A报告
在146源+4屏幕三角形、786556共同像素中与v0.5逐位相同，只证明该语料，不证明ES。
本轮 `v2_model.py` 实际调用当前PixelArithmetic；52屏幕三角形×2纹理分母，
每3像素抽样57988点，每套与双精度解析式比较：

| 候选 | UV max/RMS（纹素） | Z max/RMS（u16） | RGB max/RMS（u8） |
|---|---|---|---|
| 当前P-A/P18 | .046555 / .002149 | 2.23171 / .456285 | .503580 / .103131 |
| Q24 λ+24bit有效乘加 | .002046 / .000054 | .005844 / .001571 | .000019 / .000003 |
| 24bit共享指数S/gx/gy | .028785 / .000376 | .647629 / .346632 | .001091 / .000075 |

后两项没有最终Z/RGB输出量化，因此颜色数字不能与P-A的整数输出直接判优；用于
比较插值内部误差。重心模型先逐乘积24bit舍入、再以双精度累加并作24bit最终舍入，
没有模拟逐条FP32加法的中间舍入，是乐观候选；硬件排程确定后须替换该累加模型。所有方案共享精确edge覆盖，XOR0是构造条件，不能当独立覆盖验证。
第二套修改每顶点纹理q为1/2/4并翻转UV；没有新增硬件/完整ES多纹理模拟器。
本轮**未测**新增属性的完整clip、alpha/雾/secondary、LOD/过滤误差、tile边界不变性，
因此推荐保留P-A宽度42/32与24bit候选对照，不能因24bit样本好看就定稿缩宽。
64²局部域使累计误差上界从L=1024到约128：每系数舍入误差界
`(|δS|+|dx δgx|+|dy δgy|)·2^e`，非全局直接截断；细长/面积1和抵消例不可删。

1pixel/拍，env池需要复制，不能沿用此面积。

第二套一般q的透视、属性池、完整纹理cache和点线覆盖不全在这个数字内。

纹理容量是另一个风险：当前192KiB两半各96KiB，单张256² RGB565完整mip约174.8kB（170.7KiB），
已经不能装进一个半区，两张更不可能一起常驻。双纹理若每fragment两遍期间整张装卸会
使DDR需求不可接受。推荐逻辑texture对象放DDR，默认64KiB/四bank只读cache，
共享两个地址空间/格式标签；cache tag/miss/合并填充控制含在bin_cache分配额中，
data计texture_ram16DRM；不以“上传失败换低纹理”作兜底。cache正确性是新增关键风险。
小档可明确MAX_TEXTURE_SIZE=64，32KiB缓存；若先做常驻版本，只能用于受限试验，
不能忽略合法大纹理绑定导致的工作量。缓存命中率未经测量，3.8给10%/50%miss敏感度。

### 3.8 性能模型：640×360、60fps

可复现输入来自 `tools/gpu/emu/stress.py` 和 scene API，实跑单线程C模拟器公共API，
读取PERF1..4；不是主机帧耗时换算为GPU周期。脚本实得：3000顶点、1000建立三角形、
2000个16²quad、717910通过像素（3.11593屏幕），4000对象槽推进、384B纹理装入、
2次SET_TEX、736B命令。384B包含小级padding，不能用256B原图代替。现有
`emu/REPORT.md`的20.539ms串行/10.961ms三线程是PC功能模型速度，只说明可测试性。
PERF4是通过测试像素，不含失败片元，**是采样需求下界**；本场景不是GLQuake实测。
不引用无版本/地图/分辨率的Quake“每帧多少三角形”传闻，使用此仓库实值并给放大输入。

模型的基础geometry仅计3D顶点，像素则已经包含quad。默认关闭硬件quad时，
2000quad展开为8000独立顶点、4000tri；屏幕直送微码16cycle/顶点，加setup16cycle/tri，
另需8000×(输入64+输出写读160)=1.792MB几何DDR（未计额外tile重复）。按同一64bit/.55
预算，共加599273cycle≈4.00ms@150，默认D1全场景约**17.06ms@150、12.79ms@200**。
因此默认150MHz不能对这份含UI场景保守承诺60fps；压缩屏幕记录/批量直送可再研究。
满配保留原quad不加这些顶点成本，小档单lane约再加4.85ms@150。脚本另输出with_ui列，
不把UI展开成本藏进原来3000顶点。CPU生成这些记录的成本仍需trace测量。

公式：`G=3000·Cvertex`；`P=717910/rate`，双bilinear默认rate1、小档.5；
`Setup=1634·16`；`B=3000·(64+2·80)+2·1634·8+460800+717910·16·miss`，
miss=.10时2,307,600B/frame=138.456MB/s@60；16B是假定每fragment两纹理各4个16bit
tap的冷字节请求，line过取/tri/32bit/mip会再变。此B把变换输出读视为理想cache一次，
无cache上侧用3.3的240FT替换。`DDRcycle=B/(8·.55)`；256bit接口理想周期为此1/4，
仍须物理DDR上限。`lower=max(G,P,Setup,DDRcycle)`；保守串行预算
`upper=G+P+Setup+DDRcycle+115200`，最后项是clear/store管理；两者都是模型，
前者假定各引擎完美重叠，后者没有队列/命令排空额外停顿，不是严格数学实测上下界。

架构目标。若实际超过上限，先重排串行setup、cache和宽上下文，回到设计讨论；
本轮不写任何运行门禁。PDS须同时取得CLMA/CLMS、局部拥塞、200/150MHz slack；
不能用K一个数批准满配上板。DRM大幅下降是tile存储变化的结果；不用同样比例
虚减APM/FF，texture cache控制预算尤其可能偏小。

新增资源的可核对锚点：双lane FP32算术逻辑至少约2×2749=5498LUT（CPU FPU
文档S核心公式含DIV/SQRT及控制，因此仅作保守代理）；加RF/微码控制/裁剪投影，
geometry默认8.5kLUT是紧预算。setup从全深流水变共享池，减少的FF来自存储组织和
三角形间隔16拍，**不属于“不降低原始吞吐”的v1优化**。texture减少来自去palette与
双逻辑单元共享采样器，而不是格式增加后自然变小。所有v2 nominal数值需逐模块
综合校准，不满足时不把“估计”改写成“已达到”。

### 3.11 驱动和桌面兼容层

裸机分层建议：

1. ES入口与状态：维护默认值、矩阵栈16/2/每纹理2、8灯/材质、数组/VBO、2套纹理
   状态；Get/Is从影子状态返回，dirty状态以不可变包进入命令列表；调用返回/同步行为
   按ES，不每次状态修改立即排空GPU。float/fixed API在边界转换，光位在调用时变到眼空间。
2. Draw编译：装配索引/strip/fan、保留provoking vertex、CPU可选去重；冻结顶点输入和
   纹理版本；选择微码variant（灯数/双面/fog/tex矩阵），发几何与bin任务。
   不是生成任意用户shader，不需要完整GLSL编译器。
3. 执行层：有序state ID、DDR顶点/三角形表、按tile的序号递增列表；texture对象常驻DDR，
   cache按物理纹理页读取；每tile CLEAR/LOAD→绘制→STORE。透明排序仍由应用决定，
   binning保持原draw顺序，不为了batch跨透明draw重排。
4. 上传转换：处理PACK/UNPACK对齐、RGB/RGBA8与packed格式、10种paletted、POT小级padding、
   mip自动生成、subimage与CopyTex；在引用已排队纹理被修改时保持旧draw看到旧数据。
5. BSP提交层：沿现有BSP cache维护/DMA一致性和APB/AXI协议，DOORBELL/完成中断/Surface
   翻页；Finish等待完成，ReadPixels物化所需tile并转换，Flush只推进队列而非强制逐API等待。

自写ES驱动估算8..15k C LOC；状态/对象/矩阵/队列约32..96KiB常驻，代码150..350KiB，
frame几何缓冲另外按 `80V+8FT+state_bytes` 分配；V=3000/F1.634约247KiB（不含输入/
纹理/完整D/S），不是驱动总内存固定几十KiB。上述为功能分解估算，没有编译链接测量。

桌面层优先自写GLQuake用到的最小GL1.x子集：Begin/End顶点收集、QUADS转tri、
display list记录、double→float函数别名、TexGen在CPU/顶点微码中算；完整游戏实际入口
需通过PC trace枚举后定，不能只实现Begin/End便宣布所有GL1.x游戏可运行。
估算2..5k C LOC、代码40..120KiB；4096顶点×48B=192KiB收集区；display list和纹理
随关卡增长，估算另1..4MiB，需实跑确认。该层不自动支持桌面显式FogCoord/secondary，
若游戏使用，需启用扩展属性或定义其兼容范围，不能忽略调用。

[gl4es官方README](https://github.com/ptitSeb/gl4es)确认可用ES1.1后端，
[官方构建选项](https://github.com/ptitSeb/gl4es/blob/master/CMakeLists.txt)提供
NOX11/NOEGL/NO_GBM/STATICLIB/NO_LOADER/NO_INIT_CONSTRUCTOR；可静态绑定，自行创建上下文，
不要求裸机带X11。实际仍需分配器、libm、字符串/stdio、时间与初始化适配，并移除动态
装载/环境变量依赖；不能因NOEGL就认为没有平台适配工作。README列出GLES1.1后端对
双面/独立specular/SecondaryColor/FogCoord的限制，因此不把gl4es视为ES驱动合规证明。

本轮官方gl4es `8b1a3da5d2331d0f88b70be25963182d46eed857` tarball统计：
`src/` 下161个.c/.h文件、73142行、2,933,015源字节（包含生成代码，不是链接体积）；
估算裁剪静态固件0.5..2MiB，运行库基础64..256KiB，renderlist另按顶点/显示列表增长。
完整移植体量明显超过2..5kLOC自写子集，但兼容范围更大；推荐PC先用gl4es做行为探索，
裸机首版用trace限定的自写层。统计复现命令见study README，不把源码字节当运行RAM。

## 4. 决策

### 4.1 推荐与三档边界

推荐默认b2、局部块浮点共享setup、双lane光栅、共享双纹理、64²tile、64KiB texture
cache、RGB565/D16/S8，默认关闭对象/quad/后处理AA。API始终支持8灯/2纹理/1用户面，
满灯spot性能允许下降；**功能合规与60fps工作负载承诺分别描述**。

| 档 | 资源R / GPU K | 时钟预算 | 性能预算与用途 |
|---|---|---|---|
| 小 | (36241,35473,117,24,7187) / 12944 | 200设计/150保底，单lane | 640×360 D1双纹理串行21.69ms@150，功能展示/低重绘，不承诺60fps |
| 默认 | (42891,41523,155,36,8387) / 15319 | 同上，双lane；上限44kLUT/56kFF/160APM/48DRM | stress D1约13.06ms@150，UI展开后约17.06ms@150、12.79ms@200；PDS和cache未验证前只是目标 |
| 满配 | (57355,62621,180,59,10211) / 20484 | 同上，四分量顶点；RGBA8/D24S8，可选对象/quad/AA | stress D8约15.62ms@150；原模型以565纹理/目标计算，RGBA8带宽需另×2分项，不承诺相同帧时 |

满配只对较大FPGA/独立IP建议；在当前整片上不能满足“明显低于round11”约束，因此
不会推荐把它直接合到当前板级。默认target数值须按PDS收敛，不以额外FF流水换时序
把已经省出的CLM全部用回去。200MHz目标级数尤其需重新检查FP32，而非引用CPU8拍。

对容量/带宽/计算的敏感度：10%→50%纹理miss让B从2.308MB到6.902MB/frame，
64bit/.55 DDR预算从3.50ms到10.46ms@150；默认D1串行从13.06到20.02ms，失去60。
三线性双纹理rate.5使像素预算增加4.79ms；每fragment两个复杂COMBINE取rate.25，
像素本身19.14ms@150。若10k tri/frame且无共享顶点命中，默认D1几何38.4ms@150，
显著超标；若15k unique vertices则19.2ms。要扩大游戏规模应先做索引后变换缓存、
state batch与实际纹理工作集采样，而不是先放4lane。每套独立texq/高clip率都会压缩余量。

### 7.2 状态生成的顶点微码与排程

`m5_vertex.py`按状态生成指令级可执行IR，不是驱动C实现或最终64bit机器码编码器。

定次数LOOP有可执行语义及定向用例；灯数已知的光照变体直接展开，没有假设额外的
动态常量索引ISA。JSON保存物理指令、opcode数量、常量数和两路FMA10静态发射表。

### 7.3 数值误差和ES精度解释

依据官方[ES1.1.12 §2.1.1、§2.12.1、§3.8](https://registry.khronos.org/OpenGL/specs/es/1.1/es_full_spec_1.1.pdf)：
约1e-5是单次浮点运算的精度要求，不是整个光照或抵消后结果的统一相对阈值。
FP32具备所需最大幅值范围；本轮不构成全范围证明、API一致性或CTS结果。
每一步FP32经struct舍入，FMA调用主机libc fmaf保证单次融合舍入；独立参考用双精度
矩阵/normalize/光照/幂/雾解析式，不调用微码执行器。输入uniform先量化为FP32，
因此表反映GPU计算误差，不包括CPU矩阵逆、MVP合并和材质常量预计算的误差。

种子20261127，每变体128组状态/顶点，其中G的32组定向强制spot通过和可见高光，
双面交替前/后法线，避免大多数spot被拒绝或颜色饱和掩盖误差。矩阵为近单位随机矩阵，
位置xyz在±4、w在.5～2；非整数指数.25～127.75。下表为各输出分量的绝对max/RMS和
非零参考值的相对max；近零结果不人为设分母下限。完整逐输出分类在JSON。

### 7.4 共享 setup：调度、定宽和资源

`m5_setup.py`的候选为4个49×33有符号乘法池，II1/延迟6；两个带指数对齐的加法器
延迟2，两个normalize/舍入器延迟2，一个输入属性行/周期和一个打包记录写/周期。
同一三角形最多4属性活动，每槽两个92bit异步LUTRAM bank，配对分子/梯度可同时写，
单槽不同阶段复用地址；窄深度导致LUTRAM物理宽度浪费，不能只按1432/64估面积。
ASAP假设这些字段bank异步读、计算结果返回时写入，源捕获包含在运算延迟内。
不是16属性×85级完整记录流水。
宽乘法按M-4的4拍APM乘积加2拍外部部分积合并计6拍，不能把49×33仍当24×24。
ASAP静态DAG输出每个操作的发射拍。每属性读取后占两个normalize端口，
完成三个顶点尾数的规格化/指数对齐，
最终三个输出系数也分别占用端口，不能把一条打包记录等同一次移位。
每属性4次梯度分子乘法、2次乘逆面积、2次局部原点乘法，共8次；每三角形面积2次、两次Newton共4次，共 `8A+6` 次乘法。
除乘法外，差分、对齐、规格化、读取、打包及RAM写都消耗有界端口。

|---|---:|---:|---:|
| 11 | 94 | 24 | 165 |
| 16 | 134 | 34 | 213 |

当前模型按一个三角形处理完再接下一个，未假定无限图元在途或跨图元隐藏inverse；
16属性的34拍乘法下界已超过32，165/213还包括有限属性槽和依赖。原16～32拍不是
本精度/池数下的有效预算。可用更强的跨属性软件流水优化165/213，但必须重新排程
并计算更多活动记录和端口；本轮不将可能优化后的拍数当已得到的结果。

算术先对顶点做整数坐标差分，避免直接相减超大全局坐标积。属性按signed48工作
尾数/独立指数对齐，属性差49位，49×33完整积和差最多82位后规格化；逆面积为
32位种子+两次定点Newton。梯度、局部原点计算每次乘/加均舍入到48位，加法保留
3个对齐保护位。最终S/gx/gy使用同一个signed24或signed32尾数指数，指数记录10位。

模型逐次断言系数及累加器有符号宽度。输出不饱和内部平面，Z/RGBA只在与P-A相同
读出位置量化/钳位；UV按Q8读出。采用完整乘积并不代表所有中间字段全程用无限整数。

语料39个三角形：面积行列式=1（Q4坐标）与几何面积=1像素²各一个、近共线、

### 8.2 (a) 跨三角形重叠：吞吐和时延分开

`m5_setup.py` 抽出原 DAG 和语料生成函数，原 schedule 默认行为不变，入口实际
断言仍为 165/213。新 `m6_setup.py` 用同一 DAG，按关键路径优先、老三角形优先
列表调度；每三角形仍最多 4 活动属性，设置 1/2/4/8 个在途三角形，按序退休。
操作返回后才能发依赖，不使用无限上下文。乘法/加法/规格化/读/写延迟仍为
6/2/2/1/1。每配置运行 512 个三角形，取中间 256 个退休的平均间隔，排除首尾。
这是有限资源下的**稳态平均模型**，不是逐三角形固定 II 或最优模调度证明。

每三角形工作量：`M=8A+6`、`ADD=6A+3`、`NORM=14A+1`、输入/输出各 A 行。
原两个规格化端口的下界为 `(14A+1)/2=77.5/112.5`，比乘法的 23.5/33.5 更紧。
所以“乘法下界 24/34”不能直接替换完整 setup 吞吐，但 165/213 也不能叫流水 II。

|---|---:|---:|
| 4 | 77.518 / 112.486 | 24.067 / 33.976 |

原端口是 2 ADD、2 NORM、1 输入属性行、1 输出打包行/拍；扩端口是 4 ADD、
8 NORM，RAM 行吞吐仍为 1R+1W。4 在途需要 16 个活动属性槽，8 在途需要 32 槽。
4 池/4 在途首个三角形 158/212 拍（列表次序使单个时延也略改善）；11 属性退休
间隔实际有 62..93 拍的波动，16 属性 105..118，不能声称每 78/113 拍严格输出。
1 在途新列表次序为 158/212；2 在途 4 池平均约 90/123；更多池不解除 NORM 瓶颈。
帧估算使用向上取整的 **78/113 平均服务预算**，另计首批填充；不是最坏时延界。

RAM 组织和端口条件必须随吞吐一起看：

- 每在途三角形 3 个输入顶点属性 bank，各 16×58 bit；一次属性读同时取 3 bank。
  原 4 活动属性每槽两个 92 bit scratch bank，4/8 在途分别 32/64 个 bank。
  保守按每 context 复制 M-5 的浅 LUTRAM 分配额，未把端口复制当作免费容量。
- 原端口在满负载拍最多需要 8 个乘法源、4 个加法源、2 个规格化源，共 14 个
  独立字段读，结果最多 8 个字段返回写；扩端口最多 32 字段读、20 字段写。
  这些是分散在字段 bank 的端口，绝不是一个“双口 DRM”可以承担的 14R/8W。
  模型限制算术口和行口，不模拟具体 scratch 地址冲突；给出的平均间隔以能完成
  静态字段分配和操作数捕获为条件，真实端口仲裁增加的气泡尚未取得。
- 48 位系数每属性 154 bit，输出用 3 个并行 DRM bank，每 bank 单写、单读，
  可保存 4×16 属性的在途记录，另有空间容纳小记录缓存；DDR 提交仍须按源序号。
  行写口 154 bit/拍不等于 DDR 能连续接收 20B/拍，DDR 服务时间单独计入 8.7。

### 8.3 (b) 每源三角形一次 setup，再重定位

源记录锚点为顶点包围盒最小 x/y 所在的 64 像素网格点。只在这个锚点建立一次
`(S,gx,gy,e)`，三系数同一 signed48 指数 e（signed10），之后所有 tile 保持 gx/gy/e。
对任意 tile 原点 `(ox,oy)`（相对锚点的像素偏移）：

`S′ = S + ox·gx + oy·gy`，`P(x,y)=S′+(x-tx)gx+(y-ty)gy`。

ox/oy 为 64 的倍数。640×360 有 10×6 个 tile；锚点在合法裁后屏幕域时，
x tile 偏移 4 bit、y 偏移 3 bit。七个条件移位项与 S 共八项，用七个 60 bit
加法器组成三级树，II1/属性，延迟 3，估算 `7×60` 进位 LUT + `7×60` 选择 LUT
+200 控制 LUT，`7×60+154` FF；比 M-5 输出多 48 FF，合计新增 1040 LUT/622 FF。
这是整数移位/加法，不消耗 APM。有效域之外的超大整体平移探针使用同样相对锚点，
不把巨大绝对坐标拿去乘。模型对 S′ 和像素累加逐次检查 signed60，系数检查 signed48。

沿 tile 网格递推也能实现：`S(x+64,y)=S(x,y)+(gx<<6)`，换行增加 gy<<6。
只要用相同指数、60 bit 整数累加而不重舍入，路径与直接树严格相等；每属性每步
一个加法器即可。它要求保持每源三角形前一网格位置或预先连续生成其引用，和
raster 按 tile/透明顺序读 bin 的次序不一致，因此本轮选直接树，不在帧预算中假设
递推状态永远命中。若在 bin 阶段预存每 tile 的 S′，还需每引用每属性 8B，不能免费。

**记录和 DDR：**每属性 154 bit，按 20B 存储；64B 头部为三个整数 edge 平面
（各 32/32/64 bit）、锚点/状态/索引。总记录 `B=align32(64+20A)`，
11/16 属性分别 **288/384 B**，bin 引用仍为 16B 的源 ID/顺序信息。
若集中写源表、每个引用读取一次平面，额外流量 `B·T·(1+F)`；不是每引用重新
写源记录。F=1/1.634/4/8 时，11 属性分别 576/758.592/1440/2592 B/源三角形，
16 属性为 768/1011.456/1920/3456。若把平面复制进每个 bin 项，写和读均乘 F，
变成 `2BFT`；大 F 时更差，不推荐。缓存命中可减少读取，但本轮按零命中估算。

和每 tile 从三个 80B 顶点重做的 setup 读流量 `240FT` 相比，源表方案需要
`240T+B(1+F)T`；11 属性 F1.634 时多 606.432B/源，换取不重复计算。
8.7 对 M-5 原 DDR 公式保守地直接增加 758.592B/源，因为原公式本来只计一次
240T 顶点重读，并未计 240FT；没有再重复扣一个未经测量的顶点 cache 收益。

片上存全部记录的容量下界（36K=4608B，尚未计宽度/端口浪费）：

|---|---:|---:|

### 8.5 SFU：小表、共享种子和 II4 的实际代价

M-5 的 86080 bit 表只是容量下界 3 DRM，不是包含可用端口的完整配置。
本轮比较以下选择，所有函数的逐样本求值都没有调用 libm；libm 仅生成常驻表/参考值。

| 选择 | 表有效bit / 物理存储候选 | 算术与精度代价 |
|---|---|---|
| M-5 原表 | 86080 / 至少3DRM，setup另32768bit LUTROM | RCP1024/RSQ1024，LOG193双表，EXP256，三阶多项式 |
| 原表与setup共RCP | 86080 / 至少3DRM | setup从同一FP32倒数尾数转Q31；省原setup512LR，不减少SFU容量下界 |
| 小表+五阶，推荐 | **9280 / 1DRM**，setup共表 | RCP64两次Newton，RSQ64两次Newton，LOG49双表，EXP64；更多算术/更长延迟 |
| 同一小表用分布式ROM | 9280 / 0DRM，约512LR分配额 | 输出逐位相同；多读口/宽度填充和选择树增加LUT，默认已超LUT，故不选 |

小表的 RCP/RSQ 共享64行×64bit，LOG/INV 为49行×64bit，EXP64行×32bit，
按64bit对齐共177行=11328bit，能放一块512×72 DRM。SFU端一次读LOG+INV，
另一个独立读端口供 setup 取RCP；不用复制 ROM，也不让 setup 请求抢 SFU 发射槽。
setup 由 FP32 seed 的隐含位/指数转换 Q31，再做原来的两次定点 Newton，8.4 已实跑。
用每个表的有效 bit 直接相加不能省掉打包/端口说明。

小表 LOG 仍缩到 [.75,1.5)，中心含1；最近中心残差最大约1/96，五阶 log 余项
量级不超过 `r^6/(6(1−|r|)ln2)`，约 3.1e-13；EXP 的残差小于 ln2/64，
五阶余项约 `exp(r)r^6/720 < 2.3e-15`。实际误差仍由 FP32 舍入支配。
RSQ64只做一次 Newton 的 M-5语料最大相对误差约1.98e-4，不满足单运算候选目标，
所以本推荐明确保留两次，不以省时为由暗中减一次。

**200MHz 结构评估（估算）：**两条可发射任意 MUL/FMA 的 FP32 算术流水，
每条尾数24×24需要 **2 APM**，遵守 apm-cascade 的 head MODEZ=0、后级shift16、
X/Y/MULT/P/CPO全寄存。24×16与24×8两项经原生级联得到完整48bit积，4拍；
CLM处理指数对齐、加数、规格化/舍入，不能把4拍完整积误称4拍FP32 FMA。
给每条核心10拍：捕获/指数1，APM乘积4，49bit加法1，LZ树1，规格化移位1，
舍入进位1，打包1；加数对齐的两级移位与乘积流水并行。每级目标5ns，
APM链寄存和单独切开的LZ/移位使结构上有希望达到200MHz，但49bit加法、舍入进位、
ROM输出扇出及标签选择仍须PDS，本轮不能回答“已经放得进”。若需FMA12，必须重排。

单条流水不足以 II4：RSQ每请求6个算术操作，需1.5操作/拍。两条流水的
模4预留表（相对请求拍，engine）为：
`(4,0),(14,0),(24,1),(34,1),(45,0),(55,0),(65,1),(75,1)`。
八项的 `(engine,phase)` 各不相同，前后请求每4拍到达时，即使任意混合opcode也
不会抢同一槽；相邻相关步骤间隔至少10拍。RCP/RSQ/LOG/EXP分别占4/6/8/7项：
LOG额外计入 exponent+table 的加法，EXP计入残差乘ln2，未把它们当成免费运算。
4拍前端含指数拆分、中心差分和ROM读取，最后2拍缩放/打包，故新SFU延迟为
**RCP46、RSQ67、LOG87、EXP77**。512次混合请求的预留冲突断言通过；
这是 II4 的算术预约证明，不是 RTL/物理时序证明。最长需约22个请求在途，
前端保留32项×4×32bit，四个输入字段bank各复制两份供两条核心读；
八个预约位置各有32×32bit结果bank，每bank只有该位置一个写入者。
分配额为 `(4×2+8)×32=512LR`；指数/状态另以标签保存。
每条内部算术结果最多供下一预约槽使用，长期操作数回scratch，不做87级宽记录流水。

SFU估算 `R=(3284,1864,4,1,512)`：LUT为2×1200算术对齐/规格化+500控制
+384新增scratch端口复制额，原128LR已含在M-4分配额，
FF为2×6×64数据对齐+512 tag+384捕获状态+200控制。APM内部FF不再重复计数。
它替换M-4所含(1500,1000,4,1)分配额，geometry增加1784LUT/864FF/384LR；
未把多读口RAM仅按逻辑bit容量计算。此分配额仍有±40%不确定性。

同一 M-5 随机序列/定向输入的单函数模型结果：

|---|---:|---:|---:|
| RCP | 20000 | 5.964e-8 | 2.524e-7 |
| RSQ两次 | 20000 | 1.376e-7 | 1.225e-7 |

约1.03e-5不构成单凭这个数字即可判定的违规。误差传播可直接解释：
`δpow/pow ≈ ln2·(y·δLOG + δMUL) + δEXP`，指数最多127.75会放大LOG误差。
独立序列最坏样本的 `|δLOG|≈1.022e-7`、`|δMUL|≈3.252e-6` 给出约1e-5。
这是数值层面的可接受依据，不是Khronos合规结论；若另要求整条pow严格≤1e-5，
需要扩展中间精度或补偿LOG/MUL，属于额外精度契约，不能只加clamp或换一套通过样本。

若必须512字，则可选循环，把新增ISA契约交协调者另行确认，不在本任务修改规格。

浅宽阵列的**物理**公式为 `banks×ceil(width/72)×ceil(depth/512)`（本节选
SDP一写一读、同步读1拍），不能用总bit/36864向上取整。仓库已有
`fpga/ip/ip_ram_gpu_target_tail.md` 的512×72 SDP配置；本候选去掉额外输出寄存，
按阵列1拍读建模，实际IP选项仍须PDS确认。若用真双口，每口保守按36bit切分，
公式改为 `banks×ceil(width/36)×ceil(depth/1024)`，**不把72bit SDP当两个72bit
任意读写口**。这是真双口宽度的规划假设，尚无本任务生成IP证据。

setup输入实际11136bit，3块110592bit，利用率10.1%；scratch按所选16深度为
47104bit，64块2359296bit，利用率2.0%。即使深度减半也不省一块，原逻辑寿命
1432bit/context更不能拿来直接除36K。SFU16×32×32=16384bit，16块589824bit，
利用率2.8%。大量浪费容量，换的是CLMS站点和局部布线；**不是高效存储容量**。
若scratch必须真双口92bit，32×3=96块，较SDP多32；输入3×2=6块，比SDP多3。
连同SFU/RF真双口替代，DRM须按模式另算，不能继续用123这个数。

**排程与资源增量（估算）：**

| 变更 | ΔLUT | ΔLR | ΔDRM | Δ外部FF | 吞吐/时延条件 |
|---|---:|---:|---:|---:|---|
| setup输入+scratch | −3512=−3640+128 | −3640 | +67 | +3246=174+2944+128 | 读地址先发一拍，数据/操作标签捕获；保留4在途和算术口数 |
| SFU16个bank | −256=−512+256 | −512 | +16 | +576=512+64 | +256L含双核心各3×32旁路及64控制；预取与原算术级重叠 |
| RF备选 | −320=−768+384+64 | −768 | +6 | +448 | 提前读3口，384bit选择器旁路同拍写回，64控制；只在备选表记账 |

setup模型把所有乘/加/规格化/输入读的依赖延迟各加1，算术II仍1，不减少操作数。
512三角形、取中间256退休样本，11属性首包 **158→205**，平均间隔
**77.518→77.498**，波动62..93→61..89；16属性212→266，
112.486→112.494，105..118→101..120。因此继续用78/113平均预算，首包改205/266。
这只证明依赖延迟增加后四context仍可填满两个NORM口，**没有证明物理字段bank
无冲突**；M-6基线也没有该证明。两个同时写同一bank的字段必须原本就拆bank；若
后续落实发现额外复制，须重算，不能悄悄仲裁后沿用吞吐。

SFU预约相邻相关操作相隔10拍，直接把DRM一拍加在算术10拍后会破坏依赖。
方案在预约前1拍取已完成字段，当前拍产生的上一结果通过上述3操作数旁路送入，
输入复本/结果bank仍各自单写。RF同理，微码ROM提前译码发地址。旁路是正常数据
路径，非异常兜底；本轮只给结构与面积，不宣称已经证明其200MHz时序。
如果这条路径不能切拍保持原延迟，需重跑微码排程，不能无条件复用帧表。
推荐64bit方案不迁RF，避免给主结论再引入RF时序假设。

### 9.3 GPU流数据通路：256、128、64bit

只缩DDR流：读DMA、unpack入口、list/bin装包、cache line填充、写回DMA和AXI
桥的数据FIFO。texture命中bank/采样口、两lane像素算术、FP32/平面精度不收窄。
288B记录在256/128/64bit分别9/18/36拍装包；64B cache line分别2/4/8拍。
这是突发局部延迟增加，不是全GPU每片元改成4拍；源setup每78拍、DDR有效每拍
4.4B，记录DDR服务本来就比64bit流慢。miss填充不得占用命中采样bank的端口。

资源估算把每模块M-6额分成固定控制与下表的W256可缩部分：
`Δvariable=floor(variable256×(1−W/256))`；没有把全部模块等比砍半。
LR缩额包含在LUT缩额内；真实浅RAM宽度/深度映射可能非线性，仍需综合。

| 部分 | 可缩LUT/FF/LR输入 | 相对路径长度ℓ | 缩窄边界 |
|---|---|---:|---|
| read_dma | 800/800/256 | 4 | 返回数据/选路，地址和在途表不缩 |
| write_dma | 1100/800/128 | 4 | 数据/字节掩码，AW/B控制不缩 |
| unpack | 320/768/64 | 2 | 流入口，字段运算宽度不缩 |
| AXI桥R/W | 291/256/256 | 8 | 数据跨域，AR/AW/B不缩 |
| texture fill | 256/512/0 | 3 | 仅cache填充流 |
| list/bin | 256/512/128 | 3 | 仅装包/回填流，8 DRM容量不缩 |
| resolve输出 | 128/256/64 | 2 | 写出流 |

转换器+窄侧控制固定加 **384 LUT/768 FF**，归入bridges，不额外再计DMA。
模型按两条256bit短连接、每条长度1留在xbar旁，布线代理
`P(W)=26W+2×256`（W256原始为26×256）；不是实际毫米、扇出或拥塞测量。

| 流宽 | 净省LUT/FF/LR | P位·相对长度 | 对原P | 原始/55%有效MB/s@180MHz |
|---|---|---:|---:|---:|
| 256 | 0/0/0 | 6656 | 100% | 5760/3168 |
| 128 | 1191/1184/448 | 3840 | 57.7% | 2880/1584 |
| 64 | 1979/2160/672 | 2176 | 32.7% | 1440/792 |

**推荐把宽度转换放在GPU的mem_xbar端口边界、mem时钟域，窄侧再跨域**，把
256bit限制在xbar附近；mem_xbar仍看原256bit事务。读将一拍拆4/2拍，写聚合4/2拍，
保留字节掩码、last和响应对应，burst按字节地址而非窄侧beat数生成。不要在每个GPU
消费者分别留256bit长线再转换，那不能取得表中P收益。GPU本地仲裁共享窄流，跨帧
读写依照原命令次序的依赖分配服务；并不改变SoC仲裁规则或新增保底带宽承诺。
这是未来GPU适配器方案，不修改现有CDC原语/端口规格。

带宽必须用更新后的字节数：无UI为 **3.066MB/帧@10% miss**，50%变
**7.661MB/帧**；含UI分别7.226/11.821MB。60Hz对应184/460/434/**709MB/s**。
按9.4规划帧周期实际性能档需求为10%时123..520MB/s、50%时250..600MB/s
（含UI和四种灯光；@180MHz）。因此64bit有效792MB/s仍有约1.12倍60Hz最重
字节需求余量、约1.32倍规划周期需求余量；128bit分别2.23/2.64倍。
64bit与M-6假定的64bit DDR服务率相同，DDR本就给不出超过该流的长期数据；128bit
增加片内突发余量但不提高这个DDR上限。50% miss时纹理瞬时16×.5=8B/片元，
64bit一拍已满，没有空拍余量；此时DDR的4.4B/拍先限制持续片元率，帧模型已计入
全部DDR服务时间，不能宣称50% miss仍是整帧1片元/拍。

150MHz下有效DDR为660MB/s，含UI+50% miss的60Hz字节目标已超过它；180/200MHz
也只是GPU单独服务预算，SoC其他主设备竞争会减少可用份额。64bit推荐以本节
DDR模型为条件；若未来需要同时读写各自接近792MB/s或扩大场景，不应沿用本结论。
128bit保留为局部突发敏感的比较候选，不以超44k的名义值冒称资源达标。

### 9.4 几何N+1与像素N：存储、提交和同步语义

跨帧边界放在**完成几何/bin列表后、开始tile读取前**。几何侧独占顶点/clip/setup/
bin写入，像素侧独占tile光栅/perspective/texture/pixel/target，不复制任何算术lane。
两个帧槽独立持有bin头尾/列表、源平面、已重定位平面、变换后顶点、draw-state快照
和完成序号；N像素只读槽A时N+1几何只写槽B，槽A要到最后tile读完才可回收。
跨帧只需两套描述符，单帧内部setup四context保持不变。bin_cache已有8 DRM用作
几何写合并，像素只读已经封存的DDR列表；若未来需要另一套像素bin缓存，应另算，
本轮采用现有read_dma顺序流，不直接把单份可写cache同时服务两个epoch。

按T=1000、R=1634、V=3000、80B变换后顶点、288B平面记录，64×64 tile时640×360
共有10×6=60 tile；下面是**显式DDR容量估算**，不含clip扩增和应用纹理：

| 每帧槽对象 | 公式 | 字节 |
|---|---|---:|
| bin列表 | 16R（容量保留完整16B；8.7的16R流量已含其读写口径，不再重加） | 26144 |
| bin头/尾 | 60×8 | 480 |
| 源+重定位平面 | 288(T+R) | 758592 |
| 变换后顶点 | 80V | 240000 |
| 合计 | 上述相加 | 1025216 |
| 双槽 | 2×1025216 | 2050432 |

每槽按4KiB对齐为1028096B，双槽2056192B（约1.961MiB）。含UI则T=5000、
R=5634、V=11000，每槽4033216B，对齐4034560B，双槽8069120B（约7.695MiB）。
这是在M-6已写DDR的对象上加第二套**容量**，不为双缓冲再乘2计每帧流量。
16属性平面改384B，每槽额外96(T+R)=252864B；clip产生新顶点/三角形时按实际
扩增数量重新代入，不能把以上固定容量称最坏界。draw-state快照大小随draw数变化，
另加 `2×draw_count×state_record_bytes`；M-6未定义该格式，本节不编造固定容量。
显示front/back颜色缓冲沿用已有方案；ReadPixels若引用尚未显示的目标，生命周期
也必须独立于bin槽，而不是把显示缓冲偷偷挤进上述2MiB。

新增片上额 **200 LUT/512 FF/0 APM/1 DRM/0 LR**：两套256bit描述符、ready/retired
控制及仲裁；一块128×64 SDP存帧/draw状态索引，不存整份纹理/平面，不复制tile RAM。
像素要取的shader状态、纹理地址、视口/剪裁/混合状态在bin提交时形成不可变快照；
驱动不能在N+1配置时覆盖N的全局寄存器供像素继续读。这是后续规格/API工作，
不是本轮已实现的API行为。

- 提交/SwapBuffers按帧序号排队，几何完成只表示槽ready；帧完成要等最后target写
  与DDR写响应结束，最后才能报告render completion/复用槽。初帧仍支付几何+像素，
  重叠改善稳态帧间隔，不把首次延迟说成max。
- `ReadPixels`等待它之前的目标写完成，并完成已有cache一致性操作后读回；对其后
  无关帧可继续几何。`Finish`等待此前全部相关工作，`Flush`只发出命令，不表示退休。
- 纹理更新/删除/重用必须等所有此前采样该存储的像素退休；最简单候选是驱动在
  修改同一存储前等待其最后使用帧。可由应用另配纹理存储保持重叠，本轮不要求
  驱动隐式复制纹理。顶点缓冲被几何读完即可释放；变换后顶点由帧槽持有到退休。
- 渲染到纹理、读回再提交、同一目标的有依赖绘制遵守原GL顺序：只重叠不依赖前帧
  像素结果的几何；依赖点等待前帧完成。UI和3D保持同一目标内的绘制顺序，不能
  为追求跨帧重叠把UI移动到错误帧。

帧时间重算采用两个层级，避免把8.7的四项max直接称为可实现帧时间。
令 `G=VC+source_setup+relocation`，`P=fragment/rate+115200`，
`D=bytes/(8×.55)`；同步读setup首包205/266，稳态仍78/113。
**下界**为 `max(G,P,D)`；**本轮规划模型**只记跨帧计算重叠、不给DDR与计算重叠
收益，`period=max(G,P)+D`，首帧/每次被同步打断则按`G+P+D`。
这是带明确保守收费项的规划值，不是任意反压/共享DDR下严格上界或周期精确仿真。
共享DDR只算一次D，不能给两帧各自一条独立DDR后取max。若要逼近下界，还需
片段预取、读写仲裁和真实DDR请求模型，当前表不承诺该收益。

### 10.2 原生vec4、常量读口和上下文排程

原生DP3/DP4一次发射一组4个FP32乘法及平衡加法树，DP3第四项补零；MUL/ADD/FMA
一次发射4个分量。四lane各用两个APM实现24×24尾数乘积，按apm-cascade的24×16、
24×8拆分，不能把一个FP32乘法当一颗APM。DP树另列三个FP32加法器，不与正在流水中
的vec4 FMA争用加法级，也不把跨lane共用规格化器作为零成本收益。
矩阵仍用列式vec4 MUL+3 FMA（法线MUL+2 FMA），与四条行DP4相比无需额外PACK；
DP4在clip等变体中真实执行，DP3替换原先串行MUL/FMA点积。

仅换原生DP仍有逐顶点LOAD_CONST和长RSQ等待，不能直接宣称30拍。必要配套是
**draw期间不可变常量直接作为指令源**，从每顶点程序删除LOAD_CONST发射槽；有两套
128bit常量读bank，常量地址与RF地址提前一拍捕获。每拍最多两份不同常量，三份可变
源仍来自3R1W RF。常量绑定和CPU折叠方向光ambient沿用M-5，未从误差参考中删除光照。
常量上传、draw切换与CPU编译时间不在稳态顶点间隔内，频繁状态切换仍需另测。

RF每上下文32×128bit，三个1R1W副本，12上下文即384×128；512×72 SDP组织需
`3×2×ceil(12×32/512)=6 DRM`。两份常量bank共4 DRM。原768 LR RF被替换，
不能只增加context而不增加存储/读口。程序采用64bit指令体+每context 8bit静态等待，
12context为160bit行，1024深按1024×36分割为5 DRM，比M-6的3 DRM多2。
其余SFU scratch仍按M-7的16个独立bank收费，没有按总bit容量虚构多端口RAM。

排程采用SSA依赖/关键路径列表顺序、16指令前视、32个动态活跃寄存器上限，随后全部context按同一
指令顺序轮转；没有硬件乱序假设。SFU的II4间隙是固有服务工作，不能误作可通过推迟
SFU消除的RAW气泡：先发RSQ，再用MVP和纹理装载遮住返回等待。算术延迟输入为
vec4 MUL/ADD/FMA 12拍、DP 13拍（乘法结果旁路到两级独立加法树）、普通操作3拍，
SFU为M-6的46/67/87/77再加同步取数1拍；延迟和端口实现仍是结构预算。
SFU不同操作共享II4预约；每条写RF的返回拍都预约唯一写口，包括LOAD_ATTR、
DP、ALU和SFU，不能把不同延迟造成的同拍写回忽略；静态等待避开冲突。

### 10.3 点积舍入、ES精度与资源比较

比较两种真实运算顺序：staged为四个FP32乘积逐个舍入，再做两级FP32平衡加法树；
fused保留完整乘积/和，最后只舍入一次。后者在模型中用整数对齐和round-to-nearest-even
直接产生FP32，避免双精度求和再转FP32在舍入中点产生二次舍入。
M-5的14变体×128组同一语料和独立双精度公式全部重跑，仍有32组可见spot/specular
定向输入，物理寄存器程序与SSA逐输出相等；额外对5种吞吐程序各16输入验证常量前移
和重排的逐位一致性。定向抵消例：`a=(1+2^-23,1,0)`，
`b=(1−2^-23,−1,0)`，精确DP3为−2^-46，staged为0，fused为−2^-46。

本节沿用[ES1.1.12 §2.1.1](https://registry.khronos.org/OpenGL/specs/es/1.1/es_full_spec_1.1.pdf#page=16)
的解释：约1e-5针对单次浮点运算，位置/法线/其他浮点值的最大幅值至少2^32，颜色/纹理
至少2^10；FP32支持这些范围。平衡DP是乘、加组成的表达式，抵消后的整条点积/光照
相对误差可以放大，不能把1e-5直接作复合表达式通过阈值。以下只报告误差，不加门禁；
也未声称完整范围、NaN/非正规数RTL语义或CTS已经验证。

staged DP树费用为`3×656=1968 LUT、3×184=552 FF`，乘法/APM复用四lane，

有限范围的完整积从2^-298到接近2^256，精确固定点容器约557bit（含符号和四项求和余量）。
一个直接融合实现的**结构面积估算**为四路557bit、10级对齐网络，加三个557bit加法器，
再做557bit规格化：按两个同选择mux/LUT，
`4×557×10/2 + 3×557 + 557×10/2 + 300 = 15896 LUT`；流水外部FF按
`4×557+2×557+557+128=4027`计，APM仍8。这是可实现的宽累加参考方案，并非
最优融合器面积下界。与staged树相比约多13928 LUT/3475 FF，主GPU约66994 LUT，
超过57k，因此本轮推荐逐级规格化。可用指数选择和guard/sticky压缩的融合树面积、
取消中间规格化后的时序收益是[待定]，不能以未经验证的64bit截断当作已达同等精度。

### 10.4 setup：扩口压缩与属性专用流水

(a)保留M-6全部算术和舍入位置，按节点类型拆规格化口：输入尾数和最终pack的输入
最多48bit，只需`48×6+48=336 LUT`移位/输出预算；分子、梯度、局部乘积与和仍用
82bit路径622 LUT。**只压缩移位网络，不减少48bit有效系数，也不截断抵消前的完整积**。
3个宽口、3个窄口、3ADD、4乘法池、9在途已够11属性30拍；共享ADD与NORM对齐器
会碰到同拍发射，本轮不记未经预约证明的共享节省。

全82bit的8 NORM/4ADD/8在途是对照。模型保留M-6的4个活动属性槽/三角形，
每个乘、加、规格化、输入读都加一拍同步取数，延迟7/3/3/2/1。每组512三角形，
取中间256退休的平均间隔，首包单列；并非每个三角形都有固定≤30拍间隔。
宽/窄规格化工作量为`8A+1`和`6A`，4池乘法工作量`8A+6`。
3宽口在11属性的下界为89/3=29.667拍，解释推荐结果为何逼近30。
3宽/3窄/3ADD、8在途为30.380拍而失败；加至9在途为29.714。
4宽/3窄/3ADD、8在途为28.282拍但多622 LUT；4宽/2窄/4ADD为32.941拍而失败。

资源公式（估算）：
`LUT=4×164+3×656+3×622+3×336+400+450+1040+128=7516`。
前三项分别是乘积合并/加法/宽规格化；400指数控制、450控制地址、1040重定位、128 RAM
选路。FF为`4×486+6×184+3×164+(3×58+72×92+128)+622+9×289=13689`，
APM为`4×6=24`。scratch有9×4×2=72个独立92bit bank，SDP72每bank两DRM；
另有3输入/3输出DRM，总150。最大36个活动属性与36槽相符；不是把72bank合为双口RAM。

(b)建立边函数公共几何量和一次面积倒数，属性各阶段专用：4次分子乘法、2次乘倒数、
2次局部S乘法分别有独立流水口，14个规格化阶段和6个ADD不再争用池。面积的2次乘法
和两轮Newton的4次乘法仍按每三角形一次，给独立front-end，未逐属性重复倒数。
它计算的是gx/gy/S源平面，再按M-6重定位；没有把乘法移到每个片元或降低像素吞吐。
为缩短scratch寿命，面积倒数返回后才启动属性读；16三角形在途、每拍一属性行。
模型活动属性峰值57，分配64槽（128个92bit bank），不把其误计为32槽。

每条49×33完整积用6 APM，按apm-cascade的有符号25×18与移位后加规则处理：
X分24/24/最高符号块，Y分低16/高17（最高块带符号），每段X对应一条两APM移位链。
三条链并行，链内右移16、保留低16位，延迟2+2=4拍，再用两级82bit CLM树合并三段X
结果，得到M-6的6拍乘法池；本模型另加同步取数1拍。每池164 LUT与486外部FF正是
合并树/残数/标签预算，未把APM后加器能力外推为任意82bit硬加法。
链头MODEZ=0、内部X/Y/MULT/P/CPO寄存和低位残数规则均沿用apm-cascade。

### 10.6 帧时间、放大场景、quad开关

与M-7完全相同的规划口径：`G=V×Cvertex+first+(T−1)×ceil(IIsetup)+11R+3`，
`P=F+115200`，`B=224V+16R+460800+16F×miss+288(T+R)`，`D=B/4.4`。
跨帧稳态`max(G,P)+D`，首帧/同步打断为`G+P+D`，乐观下界`max(G,P,D)`；
JSON保留三者。按150000/200000拍/ms换算，只计跨帧计算重叠，DDR服务全部收费一次。

基准`T/V/R/F=1000/3000/1634/717910`、2000个UI quad，保留原M-7双纹理
16B冷tap/fragment、64bit×55% DDR。5k/10k场景同时给两种放大：fixed保持F不变，
只将T/V/R放大5/10倍（几何密度增加）；scaled再将F放大5/10倍（过绘增加），
分辨率、清屏115200及2000quad数不变。R按`ceil(1.634T)`，没有假定索引共享。

quad关闭时UI加8000个屏幕直送顶点×16拍、4000源三角形与4000引用，并增加对应
224B顶点/288B平面/16B bin流量；这是M-7保留的UI参考成本，未用MVP周期替代直送。
quad开启则用M-4的完整963 LUT/1921 FF快速通道，不占FP32/setup服务。
按stress的16×16矩形位置计算64²tile引用，共**2970**；额外G为2000+2970拍，
B为`16×2000+32×2970=127040B`（描述符输入一次、每引用描述符读与bin费用）。
因此本节没有沿用M-7满配“UI快速通道完全零费用”的乐观项。
该通道仅用于既有单位比例nearest屏幕quad，其他ES绘制仍走三角形；tile提交必须保留
3D/UI原绘制顺序。新增bin分派和字段地址是否可纳入既有控制额，是原型待核对项。

更紧凑融合DP树；真实采样trace的容量曲线；quad的tile分派/状态顺序；64bit共享DDR
仲裁与实际持续带宽；150/200MHz时序和整片CLMA/CLMS路由。这里列出的模型条件没有
变成运行时检查、兜底、哈希或门禁。后续由协调者决定是否更新规格并派RTL原型工作。

## 11. M-9：DDR 流量瓶颈——分块与条带重放

### 11.1 结论、范围与复现

**推荐下一步研究“64B 无损字段打包顶点、取消 DDR 平面表、逐 tile 重建 setup”的
W256 分块方案；不推荐直接回退全命令条带重放。** 在 M-8 原 setup 下，150MHz 的
几何稳态上限为独立三角形 **1.681Mtri/s**、索引网格 **3.089Mtri/s**（1.5GB/s，
冷 tile 顶点读取）。这比原分块的1.030/1.487Mtri/s高，但仍没有无条件5Mtri/s方案。
关键修正是 **29.75拍是每顶点，不是每三角形**：3个独立顶点至少89.25拍，单个
M-8顶点引擎无论DDR多快都只有1.681Mtri/s。下面全部是模型结果/结构估算，未改
规格、RTL、sw，也没有新增运行检查、降级路径或性能保证。

若限于`V≈T`且 tile 顶点重用有效，可用M-8专用属性setup换得**有条件的5.042Mtri/s**：
W256、约65.9k LUT/66.3k FF/211 APM/331 DRM，整片389.5/415 DRM。它超过M-8的
57k LUT/56k FF/160 APM名义额；只能称扩大资源档的可行模型，不能称原预算内达标。
其1.5GB/s结果还要求几何读取≤300B/T；真实cache trace尚未取得。若要求任意独立
三角形、包含纹理和像素的持续5Mtri/s，本轮所有方案均做不到。

输入commit：`7cbeaddf92a96019f553754fd9070290dda46517`（含M-8提交`3c0eb8855`）；
工具取本节同一提交。复现只需一个轻量Python进程，不需仿真主机：

### 11.2 流量分项与模型边界

记`T`为源三角形，`v=V/T`为有效变换顶点比，独立三角形v=3；索引网格v=1是
DrawElements和cache有效的输入假设，不是顶点数量自动等于cache miss数。
`R=fT，f=1.634`沿用M-4 stress bbox引用；裁剪放大系数取1，完整11属性/D1双纹理、
640×360、RGB565+D16S8共40bit片上目标。大图元可有f=60，不能用本表承诺其速率。
三索引取uint16即6B/T；DrawArrays为0，超过16bit索引的驱动分批成本未计。
命令/常量每draw一次：总流量另加`S_cmd`，条带为`S×S_cmd`，本表与M-8一样忽略小
命令流；频繁draw/状态切换时不能忽略它。

| 数据 | DDR字节和收取单位 | 本轮处理 |
|---|---|---|
| 原始完整顶点 | 64B/输入顶点 | 含position/normal/color/两套纹理输入；不得当成旧16B顶点 |
| 原始位置 | 16B/输入顶点 | hybrid第一次仅读position，后续完整64B再次读，重叠部分照收 |
| M-8变换后顶点 | 写80B、读80B/顶点 | 原基线是理想一次重读，实际逐tile冷读可能更高 |
| compact顶点 | 写64B/变换顶点；读64B/实际miss | 8B屏幕xy+11×4B属性+12B锚点/索引/状态；无FP16截断 |
| hybrid位置记录 | 写16B/顶点，读16B×3/引用 | xy/z/clip及索引元数据的布局估算 |
| 原bin引用 | 写8B+读8B=16B/引用 | 基线 |
| compact bin引用 | 写4B+读4B=8B/引用 | 连续数组的32bit源ID；draw/state范围在段头，原顺序由追加顺序表达 |
| 平面记录 | 写288B/T，读288B/引用 | M-8；tile/hybrid/条带完全不写此表 |
| 最终颜色 | 2B/屏幕像素/帧 | 全屏460800B，非每fragment重复DDR写 |
| 保留目标颜色+D/S | 读5B+写5B/屏幕像素/物化区间 | 40bit目标共2.304MB/全屏区间；替换仅颜色写回项 |
| 纹理 | `16×miss`B/fragment | M-8双纹理冷tap口径，miss=.10/.50对应1.6/8B |
| ReadPixels等读回 | 每返回像素另加打包后的字节 | 读回、CopyTex和保留D/S未包含于普通清帧表 |

bin的4B字段是研究布局，不隐藏每引用状态：按draw分段、段头状态快照按`S_cmd`另收。
若必须逐引用存64bit地址/状态，恢复16B/ref，每源多13.072B。所有小记录须聚合burst，
不能将W256下4B独立事务当成100%有效；效率输入η=.55包含平均事务浪费，真实打包待定。

令`λ`为每源三角形的tile顶点读取miss数。冷读`λ=3f=4.902`；合成理想重用
`λ=fv`，仅作为敏感度，实际由顶点跨tile分布、索引顺序和cache容量决定。
compact方案的几何流量为`b=128v+64λ+8f+i`B/T；hybrid为
`b=32v+48f+64λ+8f+i`；条带S条为`b=S(64v+i)`。mesh的i=6，独立三角形i=0。
原基线`b=224v+16f+288(1+f)`，v=3时1456.736B/T，5M需7.284GB/s。
没有把tile冷读错写成“整个场景每顶点只读一次”，也没有为多个方案重复收取同一平面表。

GPU可用带宽B=1.0/1.5/1.8GB/s；SoC规划`0.75×2.6=1.95GB/s`不变，GPU份额已
扣除其他主设备，不能再把DISP从GPU份额重复扣一次。外部共享读写流有效能力
`Bport=fclk×W/8×.55`，真正服务率`Be=min(B,Bport)`。150/200MHz下W64为
.660/.880GB/s，W128为1.320/1.760，W256为2.640/3.520；W128在150MHz无法兑现
1.5或1.8GB/s。主表统一W256，W128相对资源少1191 LUT/1184 FF/448 LR，W64少
1979 LUT/2160 FF/672 LR（按M-7原数据加回），不把位宽变宽误作物理DDR变快。

独立顶点引擎与setup可重叠时的**几何持续上限**为
`Q=min(fclk/Cv_work, fclk/Csetup_work, Be/b)`，不含像素/纹理，不等于帧完成速率。
普通tile：`Cv_work=29.75v，Csetup_work=29.713725f`；fast用11f拍setup。
条带：两项分别乘S；hybrid：`Cv_work=7.166667v+29.75λ`，位置与完整顶点共用
一个引擎，不能将两项各自取max。位置周期来自M-8的原生vec4/12context位置程序。

### 11.3 三类方案及资源

(a) **分块+压缩。** FP32位置+RGBA8+FP16纹理可将记录压到32B左右，但RGBA8只能用于
已按目标精度量化的颜色，不能把裁剪/透视前的任意颜色先截断。FP16纹理最大有限值
65504，且1附近相对间隔约1e-3；投影纹理q、抵消、插值精度不能沿用M-8结论。
若冒险取32B且保持同一计算，冷读mesh流量为271.936B/T，fast可有条件达到5M；
但本轮没有精度证据，不能将它作为满足ES语义的推荐。故推荐先做字段/填充无损压缩到64B，保留11属性FP32；两纹理q、fog、前后面颜色
组合究竟是否能落在此布局，须对照微码输出冻结，16属性仍应回到80B重新计费。
这不是已完成的格式或精度验证。

平面无损去padding最多从288降到`ceil((64×8+11×154)/8)=276B`，不足以改变瓶颈。
即使一次setup直接生成记录并省掉中间顶点表，B=1.5GB/s、5M要求总量≤300B/T；
mesh的平面记录上限为`(300−64−6−8f)/(1+f)=82.357B`，独立三角形仅36.039B。
128B有损平面也要mesh约420.224B/T，仍达不到5M；48bit源系数/指数不能无依据改成
16/24bit并沿用M-6边界精度。因此主方案**不存平面，每引用从顶点重新构建源锚点平面，
再按M-6原锚点重定位**，不逐tile独立舍入梯度，保留连续性语义的设计意图。
普通setup上限降到5.048/f=3.089Mtri/s；fast专用流水上限13.636/f=8.345Mtri/s。

输入索引cache与tile顶点cache各64项、64B记录，各按两个独立bank收费，共4 DRM；
另给512 LUT/512 FF/128 LR标签/查找/地址控制的**分配额估算**，未实测命中率。
cache索引必须包含draw状态/输出身份，cache miss引发重算会增加v；主表v=1并不保证
任意10k网格都只变换10k个顶点。片上整帧平面不选：10k×288B容量下界625 DRM。

(b) **条带立即模式重放。** 每条重放整份列表、重新变换全部顶点、setup全部三角形；
条带外图元不能免费跳过光照。保留纹理cache跨条带并不保证miss不变。几何不需DDR
中间表，透明/模板/RMW顺序在单条内保持，命令/状态/资源须为可重放快照。

40bit两条已放得下，**不必为回条带先砍setup**。可退回M-7 setup70 DRM，节省

### 11.4 帧时间口径、敏感度与ES/驱动语义

上表帧时间全部是**模型规划ms**，每格150/200MHz，GPU带宽固定1.5GB/s，
T=1k/5k/10k、F=717910固定、miss=.10、清屏115200拍、全屏只写颜色460800B，
不额外加入2000quad几何。沿用M-8的“no UI”语料口径：F已含原fixture UI像素，
不能称纯3D实测。普通/fast tile的
`G=T(Cv_work+Csetup_work+11f)+first`，条带去掉11f；首包普通199/fast114拍，
条带每条收199拍。`P=F+115200`，`D=(Tb+460800+16Fmiss)/Be`秒；
规划值`max(G,P)/fclk+D`，首帧/同步打断串行值`(G+P)/fclk+D`，乐观下界
`max(G/fclk,P/fclk,D)`都在JSON。前者只将跨阶段计算重叠，DDR服务保守全部加收，
**故帧表与几何roofline并不互为倒数，也不是周期准确的流水仿真**。
条带没有跨帧几何缓冲，本表max项只假设同条带的geometry/pixel流重叠；逐条提交，
遇到重放/排空不能重叠时应取JSON的串行值。新流水/目标读写的具体调度仍待原型。

B=1.0/1.8GB/s时，主表每行任意帧只需在1.5GB/s时间上加
`Bframe×(1/Be_new−1/1.5e9)×1000`ms，W256两频均不限流；完整数值在JSON。
例如tile、v=1、10k：Bframe=6.217456MB，150MHz的10.565ms变成12.637/9.874ms；
200MHz的8.960ms变成11.033/8.269ms。50%纹理miss较10%每固定像素帧多4.594624MB，
在1.5GB/s多3.063ms，两频相同；条带cache被逐条挤出的附加miss应在此基础上另收。
同比过绘令`F=717910×T/1000`，JSON单列5k/10k；像素变成主要瓶颈，不能把固定F表
用于线性增加覆盖的场景。例如tile、mesh、5k/10k在1.5GB/s为30.370/59.666ms@150、
24.196/47.508ms@200。200MHz仅频率换算，带宽B不随频率增加。

即使fast-ideal的几何上限达到5.042Mtri/s，也没有“本fixture整帧5M”结论：
10k固定F时每T另有46.08B颜色、114.866B纹理，合计412.594B/T，DDR上限3.635Mtri/s；
片元服务连清屏为83.311拍/T，150MHz仅1.800Mtri/s。大覆盖/高miss场景应报告像素/
纹理瓶颈。反之小覆盖、热cache、少状态切换的mesh才可能接近纯几何roofline。

| 语义/驱动要求 | 分块/fast | 条带 | 位置先行 |
|---|---|---|---|
| blend/logic-op/stencil顺序 | tile内严格原draw/图元顺序，禁按材质重排；bin段头持有状态 | 每条按原顺序重放，条带内像素不重排 | 同分块，两阶段共用同一状态版本 |
| 共享边/插值 | 重建相同源锚点/系数，再整数重定位；compact格式需数值验证 | 同一顶点/setup规则，条带裁剪仅限覆盖 | 两次位置变换须同数值规则，不能bin与最终覆盖不一致 |
| ReadPixels/CopyTex/Finish | 先物化此前命令影响的tile，读回按pack规则执行 | 先完成相关条带，跨条带请求须合并物化；不能仅返回当前条带 | 同分块 |
| 部分clear/保留D/S/掩码 | 每物化区间load/store正确旧值，按10B/像素计费 | 后续批次重开条带也需load/store；不能每次清空 | 同分块 |
| 纹理/VBO/数组/状态修改 | 批次结束前保存版本或先完成旧引用；客户端数组需快照/复制 | 重放期间保持命令、矩阵、纹理、数组等稳定；上传/副作用只执行一次 | 两阶段结束前保持全部输入稳定 |
| cache身份与DrawElements | 复用键含输入索引及draw输出状态；共享率用trace测量 | 每条重新执行，不能把跨条输出免费保留全帧 | cache作用于每tile完整顶点；位置可重用不等于光照可重用 |

这些是延迟/重放实现ES1.1行为的设计要求，不是本轮新增驱动功能。现有规格行为不变；
本任务未重新引用未提供内容的外部API文档，语义依据沿用本记录3.1/3.3/9.4的既有分析。
ReadPixels等强制区间缩短、保留目标、纹理更新、裁剪放大、16属性/8灯及API提交开销
都可能使结果低于表值，不能以普通清帧无同步的数字覆盖所有ES1.1用法。

### 11.5 推荐、对M-4/M-7/M-8的修正与待定项

1. **原资源档的省资源推荐：tile/W256/64B顶点/原setup，不存平面。** 冷读mesh
   在1.0/1.5/1.8GB/s约2.170/3.089/3.089Mtri/s，独立三角形1.407/1.681/1.681；
   核心瓶颈已从DDR转到每引用setup或每源顶点。与条带两条的2.521/.840相比，
   其吞吐更高，且GPU219 DRM比334少115块。若带宽很紧且只关心低密度固定像素，
   条带两条省流量/少量逻辑，帧表可能更快，作为明确负载选择，不能称通用吞吐最优。
2. **5M mesh的有条件最省已列候选：fast-ideal/W256。** 原setup3.089上限不够；
   使用M-8已建模的11拍专用setup，且cache miss满足
   `128+6+8f+64λ≤300`，即`λ≤2.3895`，输入cache维持v≈1，才有预算空间。
   理想λ=1.634时5M几何流量1.258GB/s，余.242GB/s给目标/纹理；W128在150MHz
   有效1.32GB/s仅余.062GB/s，故选W256。冷λ=4.902时fast也仅3.255Mtri/s。
   这需要扩大LUT/FF/APM资源额和实测trace，不作本轮已达标保证；没有可靠命中率时
   采用上一项3.089模型上限。独立三角形若要5M，至少三倍顶点吞吐，已超本任务
   “几何计算不再修改”的假设，不用cache口号掩盖该限制。
3. **M-4修正：** 分块省DRM结论仍成立，但“只算一次顶点”不自动等于省DDR。
   先前优先用DDR换计算的权重应改为取消中间平面流；几何快后条带虽可装下，
   重算完整顶点依然昂贵。f和共享率应是负载输入，不能固定当器件特性。
4. **M-7修正：** W64只适用于此前约660MB/s的服务假设，不能承接本轮1.5GB/s；
   本节已将省掉的资源按原表全部加回W256。仅扩大接口不会消除DDR物理预算；
   所有共享流量按读+写合计限额，不允许将各DMA各自按1.5GB/s相加。
5. **M-8修正：** 5M是D1顶点/s和源setup/s两个独立指标，不能叫5M独立三角形/s。
   原19ms等帧结果在其W64、保守服务相加口径下成立，但不能据此证明计算或接口
   已足够新DDR目标。每源一次setup的288B表在f1.634时是主要流量之一；取消它
   要重新按f次setup收费。新目标的帧结果以本节表和明确像素/带宽条件为准。
