## 1. 背景和问题

卡 53 用 b3 d54b69f4 的 showcase-p4.elf 上板，验收没有通过。用户的反馈：

- 识别 3 fps，NPU 每帧 41.1 ms，后处理 177.1 ms（目标 ≤ 35 ms）；
- 虚拟输入仍然走串口，延迟大，鼠标乱跳，还会自动点击；
- 游戏中按 Esc 直接退回首页；
- 批量图片识别暂停后，实时识别和图像处理都失效了；
- 图像处理页没有逐项启用开关；
- 按钮高亮不消失，控件用法不对，页面不美观。

用户要求先重新规划，再下发实现卡和测试卡。规划要覆盖：

- 应用的生命周期，以及硬件资源归谁所有；
- 任务调度和预算；
- PC 工具与板端的状态同步；
- 图片改为手动逐张识别；
- 测量识别耗时，并拆分到各个阶段；
- LVGL 控件和输入。

## 2. 根因分析

下表的"依据"列中，"代码"表示已经在 d54b69f4 源码上确认，"推测"表示需要卡 54 实测验证。

| # | 现象 | 根因 | 依据 |
|---|---|---|---|
| R1 | 后处理 177 ms。画面里 0 个目标时也是这么慢，说明慢的不是 NMS | `vision.c` 用**不经过 cache 的地址**读 NPU 输出（注释写着"no full-buffer invalidation step"）。YOLOv8n 解码要扫 8400 个 anchor × 80 类，加上框的分布，约 69 万次逐字节的 DDR 读。独立的 demo_npu 先 `engine_dma_invalidate`，再按 cache 读（`demo_npu/inference.c:78`）。估算：177 ms × 125 MHz ≈ 2.2×10⁷ 周期，除以 6.9×10⁵ 次读，约 32 周期/次，与一次不经 cache 的 DDR 读的延迟相符 | 代码 + 估算 |
| R2 | 虚拟输入走串口 | 工具只通过串口上的 `ETH peer IP/port` 两行来确认 PEER（`session.py:100`）。板端只在 PEER **变化**时打印这两行，CPU 报告期间还把打印预算设为 0（`network.c`）。工具重连以后，板端的 PEER 没有变，所以不会再打印，工具也就一直等不到。结果是：工具每 2 s 发一次连接请求（日志中共 495 次），始终是 PEER=false，虚拟输入一直走串口，每 20 ms 发一帧。网口本身是通的：遥测和视频都在持续回传 | 代码 + 日志 |
| R3 | 鼠标乱跳、自动点击 | 主要嫌疑是串口回退路径：串口帧与网口状态帧混用；LVGL 的键盘设备把"任意键按住"都当作按下（`read_keys`）；页面切换后，按住的状态被下一个页面接收 | 推测 |
| R4 | 游戏中 Esc 回到首页 | 一次按键被处理了两次：<br>1. NES 收到 Esc 的按下沿，调用 `app_return`，主循环执行 `ui_game_open=false; ui_open(5)`，此时已经回到游戏列表；<br>2. GUI 恢复后，LVGL 的键盘设备读到 Esc 仍然按着，又生成一次 `LV_KEY_ESC`；`ui_back()` 看到 `ui_game_open` 已经是 false，于是执行 `ui_open(0)`，回到首页 | 代码 |
| R5 | 暂停后其他功能失效 | 三个视觉应用共用一个 `v` 状态，靠 `paused / waiting / reconfigure / camera_source / capture / job / image_pending` 七个标志组合出状态。`batch_stop` 只改了 `waiting` 和计数，工具仍在继续发图；而且没有"取消完成"的确认。卡 53 没有复现出具体的失败路径；结构上的原因是没有状态机，停止和恢复的条件散落在各处 | 代码（具体路径待复现） |
| R6 | 图片往返时间被量化到整秒 | 工具日志中，"回传完整"总是落在每秒的 .43 附近，与上传什么时候结束无关。疑似工具 GUI 每 1 s 刷新一次状态，由这次刷新来判断完成、发下一张 | 推测（日志） |
| R7 | 高亮不消失 | 通用按钮是 `lv_obj_create` 做的；点击时会主动 `lv_group_focus_obj`，而主题给 `LV_STATE_FOCUSED` 配了高亮，所以鼠标点过的按钮会一直亮着 | 代码 |

## 3. 新的运行结构

### 3.1 应用与资源所有权

板端始终运行的**服务**：

- 通信服务：网口收发、EDSC 协议、遥测；
- 输入服务：虚拟输入和板上按键；
- GUI：LVGL、L1 层；
- 性能浮窗。

**媒体应用**同一时刻只能有一个处于活动状态：实时识别、图片识别、图像处理、图形测试（RND 和 LVGL benchmark）、游戏、CoreMark。

| 资源 | 所有者 | 释放时机 |
|---|---|---|
| VIN CH0（摄像头） | 实时识别、图像处理 | 应用 STOPPING 时关闭通道，等 VIN IDLE |
| VIN CH2（内存输入） | 图片识别 | 同上 |
| NPU | 实时识别、图片识别 | 等当前帧的 DONE；不中途打断 |
| PIX、GEO | 图像处理 | 等 IDLE |
| RND | GUI（作为 LVGL 后端）；图形测试运行时归测试 | 测试结束后交还 GUI |
| DISP L0 | 当前媒体应用；没有媒体应用时关闭 | 由 REL_BASE 确认释放 |
| DISP L1 | GUI；游戏运行时缩到浮窗区域 | — |
| ETH TX | 只有通信服务能发；应用通过队列提交 | — |
| ETH RX 窗口 0 / 2 / 3 | 窗口 0：当前大块传输；窗口 2：输入；窗口 3：消息 | 取消大块传输时，复位窗口 0 |
| DDR 缓冲 | 按 `ddr_map.h` 固定分区。每个分区只属于一类应用 | — |

视觉状态 `v` 拆成两部分：三个应用共用的"视觉管线"，以及每个应用各自的会话状态。原来的标志组合改成 3.2 节的状态机。

### 3.2 生命周期

每个媒体应用都实现下面这一组状态，由一个统一的应用管理器驱动：

```
IDLE ──start──▶ STARTING ──资源就绪──▶ RUNNING ──pause──▶ PAUSED
                                         ▲                  │
                                         └──────resume──────┘
RUNNING / PAUSED ──stop──▶ STOPPING ──所有资源 IDLE──▶ IDLE
任意状态 ──可恢复错误──▶ FAILED（页面显示原因；可以"重试"，重试后回到 STARTING）
```

| 操作 | 含义 |
|---|---|
| 暂停画面 | 冻结 L0 和检测框，同时停止采集和推理（第 6 节 Q2） |
| 停止 | 取消正在进行的传输，等引擎空闲，释放资源，回到 IDLE |
| 退出页面 | 先停止，再由管理器返回上一级页面 |
| 切换应用 | 旧应用 STOPPING 完成后，新应用才能 STARTING。不允许两者交叠 |

错误分两类：

- 规格定义的硬件错误（VIN、PIX、GEO、NPU 的错误标志）仍然按 CLAUDE.md §12 处理：打印错误并停机；
- 协议和用户操作错误（长度不符、空间不足、取消）只让当前请求失败，回复错误码，应用保持可用。

### 3.3 调度和预算

- 优先级：通信服务 > 输入服务 > 媒体应用 > GUI。媒体应用每次执行的步骤不超过 2 ms；后处理、伽马表计算、模型加载都切成小片执行。
- GUI 每 16.7 ms 至少得到一次执行机会。输入从网口到达，到 LVGL 读到，最长 16.7 ms（沿用卡 53 的目标）。
- 后处理改为：先对 NPU 输出区做 invalidate，再按 cache 读。目标是解码、排序、NMS 合计 ≤ 35 ms。修完后实测仍然超标时，再考虑把解码搬到 NPU 输出格式上（另行讨论）。

### 3.4 识别耗时的拆分测量

实时识别和图片识别每一帧都记录下面这些时间点（mtime），每秒通过串口输出一行汇总，性能浮窗显示其中的关键几项：

1. VIN 帧完成；
2. NPU 启动；
3. NPU DONE 中断；
4. 应用发现 DONE，即开始后处理；
5. 解码结束；
6. 排序结束；
7. NMS 结束；
8. 检测框交给 GUI；
9. GUI 完成这一帧的刷新。

同时记录每个任务的 CPU 忙时比例，以及 DDR 端口带宽。卡 54 在同一个模型、同一张输入图、同一个门槛下，对比 demo_npu 和 showcase 的这些数据，确认帧率的差距分别来自哪一段。

### 3.5 PC 工具与板端的协议

基本原则：**模式以板端为准**，工具只显示板端回报的状态。

1. **连接**：工具在窗口 3 发连接请求，板端通过网口回复 `HELLO`（EDSC 新类型），内容是程序版本、当前应用和会话状态。工具收到 `HELLO` 才算 PEER 建立，不再依赖串口文字。连接断开或超时，工具界面要明确显示，虚拟设备随之失效。不回退到串口（第 6 节 Q1）。
2. **命令应答**：每个命令都带 `seq`，板端回复三种消息：
   - `ACCEPTED`：已收到；
   - `DONE`：执行完成，或者 `CANCELLED`（取消完成）；
   - `ERROR`：带原因码。

   工具在收到 `DONE` 或 `ERROR` 之前，不发同类的下一个命令。
3. **状态广播**：板端在状态变化时，以及每 1 s，发一次 `STATE`，内容是：当前应用、会话状态、图像处理的全部参数、检测门槛和类别。工具的界面完全按 `STATE` 刷新。
4. **图片识别改为手动逐张**：
   - 工具选择文件夹后建立图片列表，用"上一张 / 下一张"逐张发送；
   - 每张图带一个请求号；板端回传的检测结果也带同一个请求号，工具只接受与当前请求号一致的结果；
   - 工具显示文件名、序号/总数、发送中 / 识别中 / 完成 / 失败；
   - 取消自动批量。
5. **完成判定靠事件，不靠定时刷新**：工具在收到网口消息时立即处理完成事件，不等 GUI 的 1 s 刷新（R6）。

### 3.6 图像处理

- 每项功能都有独立的启用开关，参数放在开关下面：
  - 亮度/对比度
  - 伽马
  - 第一级滤波 S1
  - 第二级滤波 S2
  - 灰度
  - 二值化（阈值）
  - 反色
  - 旋转
  - 缩放
  - 平移
  - 镜像
- 执行顺序按硬件固定：PIX 按 pix-spec 1 的流水线顺序（点运算 1 → S1 → S2 → 点运算 2），然后是 GEO。界面按这个顺序排列，并且画出流向。
- 关闭一项只是把这一级旁路掉，不影响其他项，参数保留（第 6 节 Q3）。
- 板端页面和工具都按 `STATE` 显示同一组参数。任何一边改动，另一边在下一次 `STATE` 时同步。

### 3.7 输入

- **单一所有者**：同一时刻，输入只交给 GUI，或者只交给当前媒体应用（游戏、benchmark）。
- **所有权切换时屏蔽按住的键**：切换时还按着的键和鼠标键先屏蔽，等它们松开以后，新的所有者才能收到。这样一次按键不会被两边各处理一次，R4 就修好了。网口断开或切换页面时，补发所有键和鼠标键的释放。
- **Esc 逐级返回**，每次只退一级：设置弹层 → 页面内的子模式 → 页面 → 上一级列表 → 首页。游戏退出后回到游戏列表，焦点停在原来那个游戏上。
- **只传状态，不传增量**：网口发的是完整状态快照，板端只用最新的一帧，不积压。鼠标位置用绝对坐标，滚轮用累计值。

### 3.8 LVGL 控件与外观

- 控件按语义使用：
  - 按钮用 `lv_button`；
  - 开关用 `lv_switch`；
  - 参数用 `lv_slider`，旁边显示数值；
  - 选择用 `lv_dropdown`；
  - 类别用 `lv_checkbox`。
- 五种状态的样式要分开：悬停（只对鼠标）、键盘焦点（只用 `LV_STATE_FOCUS_KEY`）、按下、选中、禁用。用鼠标点过的控件不留焦点框。
- 页面外观：沿用卡 49 用户选定的 B 风格（浅色），重新排布图像处理页和图片页。P5-UI 在 PC 模拟器上给出全部页面的截图，供用户评审；截图放在 `outputs/`，不进仓库。

## 8. 冻结接口（P5-SPEC，2026-11-03）

本节取代 `2026-11-03-showcase-ui.md` 的两部分：

- 4.5.4 中的 CAMERA 消息；
- 4.6.4a 中"PEER 由串口文字确认""回退到串口"的规定。

4.5.4 的其余部分仍然有效，包括：

- 窗口分配、EDSC 头；
- BULK_BEGIN / READY / DONE、ECHO；
- EDNM、EDG2 格式。

所有多字节字段都是小端。

### 8.1 应用和会话

| 值 | `app` | 页面 | 占用的资源 |
|---|---|---|---|
| 0 | 无 | 首页、调试页等 | — |
| 1 | 实时识别 | 视觉识别 | VIN CH0、NPU、L0 |
| 2 | 图片识别 | 图片识别 | VIN CH2、NPU、L0、窗口 0 |
| 3 | 图像处理 | 图像处理 | VIN CH0、PIX、GEO、L0 |
| 4 | 图形测试 | 图形引擎 | RND（测试运行时） |
| 5 | 游戏 | 游戏（运行中） | L0、L1 浮窗、输入 |
| 6 | CoreMark | 芯片信息（运行中） | CPU |

| 值 | `state` | 含义 |
|---|---|---|
| 0 | IDLE | 没有运行；`app` 是 0，或者游戏、CoreMark 已经结束 |
| 1 | STARTING | 正在配置资源 |
| 2 | RUNNING | 运行中 |
| 3 | PAUSED | 只用于实时识别和图像处理：采集和推理已停，L0 冻结在最后一帧 |
| 4 | STOPPING | 正在等引擎空闲、释放资源 |
| 5 | FAILED | 可恢复的错误；`error` 给出原因，可以重试 |

`error`（u8）：

| 值 | 含义 |
|---|---|
| 0 | 无 |
| 1 | 长度不符 |
| 2 | 格式错误 |
| 3 | 空间不足 |
| 4 | 硬件不支持（本 FPGA 版本没有对应引擎） |
| 5 | 状态不符（例如不在图片识别时发图片） |
| 6 | 已取消 |

`DONE` 的 `status` 也使用这一组值。

规则：

- 打开一个页面，就请求打开该页面的应用；离开这个页面，就请求 `app` = 0。
- 应用管理器先让当前应用 STOPPING，到 IDLE 以后再启动新的应用。
- 游戏和 CoreMark 结束以后，状态变为 IDLE，`app` 保持不变。UI 据此回到游戏列表或芯片信息页。

### 8.2 EDSC 消息

| type | 方向 | payload | 说明 |
|---|---|---|---|
| 窗口 3 收到 1 字节 0 | PC → 板 | — | 连接请求。板端记录 PEER，用 HELLO 回复 |
| 0x01 BULK_BEGIN | PC → 板 | 同 4.5.4 | 规则同 4.5.4。另外，`kind` = 2（图片）只在 `app` = 2 且状态为 RUNNING 时接受，否则回复 DONE(status 5) |
| 0x81 READY / 0x82 DONE | 板 → PC | 同 4.5.4 | 图片的 DONE 在 EDDT 发送完成后发出（与现在相同）。取消时回复 DONE(status 6) |
| 0x03 ECHO / 0x83 | 双向 | 同 4.5.4 | — |
| 0x04 APP | PC → 板 | `app`(u8) + `action`(u8：0 打开，1 暂停，2 继续，3 重试) + `arg`(u16：游戏序号，其他为 0) | 先回复 ACK(1)。到达目标状态后回复 ACK(2)：打开 → RUNNING，`app` = 0 → IDLE，暂停 → PAUSED，继续 → RUNNING。失败回复 ACK(3, error)。板端 UI 同时切换到对应页面 |
| 0x05 IMAGE_INFO | PC → 板 | `index`(u16，从 1 开始) + `total`(u16) + `name_len`(u16) + 2 字节 0 + `name`（UTF-8，≤ 256 B，只含文件名） | 在每张图片的 BULK_BEGIN 之前发送。板端在图片识别页显示文件名和"序号/总数"。回复 ACK(2) |
| 0x06 PROCESS | PC → 板 | 8.3 的处理参数块（24 B） | 整组替换。板端在下一帧生效后回复 ACK(2)。参数超出范围时回复 ACK(3, 2)，不做任何修改 |
| 0x07 DETECT | PC → 板 | `threshold`(u8，25…90，单位 %) + 3 字节 0 + `classes`(3 × u32，第 i 位表示 COCO 类 i) | 整组替换。回复 ACK(2) |
| 0x08 CANCEL | PC → 板 | 无 | 取消当前的大块传输或图片识别：窗口 0 复位；已经开始的识别照常算完（不打断 NPU），但不发 EDDT 结果。回复 DONE(kind, 6) 和 ACK(2)；当时没有进行中的传输，就只回 ACK(2) |
| 0x84 HELLO | 板 → PC | `proto`(u16 = 3) + 2 字节 0 + `build`(16 B ASCII，提交号，不足补 0) + STATE payload | 回复连接请求。PC 收到 HELLO 才建立 PEER |
| 0x85 STATE | 板 → PC | 8.4 | 状态变化时发送，此外每 1 s 发送一次 |
| 0x86 ACK | 板 → PC | `type`(u16，所应答命令的 type) + `phase`(u8：1 已收到，2 完成，3 错误) + `error`(u8) | `seq` 等于所应答命令的 `seq` |
| 0x87 IMAGE_STEP | 板 → PC | `direction`(i8：−1 上一张，+1 下一张) + 3 字节 0 | 用户在板端图片识别页按"上一张 / 下一张"时发出。PC 按自己的图片列表发送对应的图片。板端只在 `image_status` 为等待、完成或失败时发出（接收中和识别中，板端的翻页按钮为禁用状态）。PC 在当前图片还在进行时收到 IMAGE_STEP，就丢弃它并在日志中写明，不排队 |

- 删除 0x02 CAMERA：实时识别改用 APP(1, 打开)。
- PC 在收到同一命令的 ACK(2) 或 ACK(3) 之前，不发同类型的下一条命令。例外是 PROCESS 和 DETECT：PC 可以只保留最新的一组参数，等上一条完成后再发。
- **EDDT**（4.5.4 沿用的检测结果格式）：偏移 12 的 u32 原为保留字段，现在是 `request`，即这张图片 BULK_BEGIN 的 `seq`。PC 只接受 `request` 等于当前请求的结果。

### 8.3 图像处理参数块（24 B）

| 偏移 | 字段 | 类型 | 范围 / 含义 |
|---|---|---|---|
| 0 | `enabled` | u32 | 各项启用位（见下） |
| 4 | `brightness` | i16 | −256…255 |
| 6 | `contrast` | u16 | Q8，0…512（0…2.0） |
| 8 | `gamma_tenths` | u16 | 3…30 |
| 10 | `stage1` | u8 | 1…6：均值、高斯、锐化、Sobel、腐蚀、膨胀（旁路由启用位表示） |
| 11 | `stage2` | u8 | 同上 |
| 12 | `threshold` | u8 | 0…255 |
| 13 | `view` | u8 | 0 显示处理结果，1 显示原图 |
| 14 | `angle` | i16 | −180…180，单位度 |
| 16 | `scale_percent` | u16 | 50…400（geo-spec 2.3：缩小不超过 2 倍） |
| 18 | `translate_x` | i16 | −1280…1280 |
| 20 | `translate_y` | i16 | −720…720 |
| 22 | — | u16 | 0 |

启用位按处理顺序排列：

| 位 | 功能 | 位 | 功能 |
|---|---|---|---|
| 0 | 亮度/对比度 | 6 | 反色 |
| 1 | 伽马 | 7 | 旋转 |
| 2 | 第一级滤波 S1 | 8 | 缩放 |
| 3 | 第二级滤波 S2 | 9 | 平移 |
| 4 | 灰度 | 10 | 水平镜像 |
| 5 | 二值化 | 11 | 垂直镜像 |

规则：

- 位 0–6 在 PIX 中执行，顺序见 pix-spec 1；位 7–11 在 GEO 中执行。
- 某一位为 0 时，对应的硬件级旁路，参数保留不变。
- 默认值：
  - 全部不启用；
  - `brightness` 0，`contrast` 256，`gamma_tenths` 10；
  - `stage1`、`stage2` 都是 2（高斯）；
  - `threshold` 128，`view` 0；
  - `angle` 0，`scale_percent` 100，平移 0。

### 8.5 连接和虚拟输入

- **建立和断开连接**：
  - PC 每 2 s 发一次连接请求，直到收到 HELLO。
  - 连接建立后，3 s 没有收到 STATE 就判定断开。断开后，PC 禁用虚拟设备，显示"网口未连接，虚拟设备不可用"，并且重新开始每 2 s 发连接请求。
- **虚拟输入帧**：
  - 窗口 2 的 8 B 帧格式不变。
  - PC 在状态变化时发送，此外每 100 ms 发一次。
  - 板端连续 300 ms 没有收到虚拟输入帧，就把虚拟键盘和鼠标按键全部视为松开。
  - 板端和工具都删除串口虚拟输入（第 6 节 Q1）。
- **输入所有权**：
  - 输入同一时刻只交给 GUI，或者交给当前应用（游戏、benchmark 运行中）。
  - 所有权切换时还按着的键（板载、虚拟键盘、鼠标键）先屏蔽，等它们松开后才对新的所有者生效。
- **板载按键**：next、prev、enter、esc 始终可用，映射到 LVGL 的 NEXT、PREV、ENTER、ESC。
- **串口日志**：板端启动行，以及 `ETH peer IP/port` 两行，仍然作为日志输出，工具不再依赖它们。

### 8.6 识别耗时埋点

实时识别处于 RUNNING 时，每秒在串口输出一行（单位 ms，保留一位小数；百分比为整数）：

```
vision fps=<n> npu=<a> wait=<b> decode=<c> sort=<d> nms=<e> post_span=<f> gui=<g> e2e=<h> cpu_comm=<p>% cpu_app=<q>% cpu_gui=<r>%
```

| 字段 | 定义 |
|---|---|
| npu | NPU 启动 → DONE 中断 |
| wait | DONE 中断 → 后处理第一次执行 |
| decode / sort / nms | 后处理三个阶段各自的 CPU 时间之和 |
| post_span | 后处理从开始到结束的实际时间，包括让出 CPU 的时间 |
| gui | 检测框交给 GUI → 含这些框的那一帧刷新完成 |
| e2e | 输入帧的 VIN 完成 → 含框的那一帧刷新完成 |

每项都是最近 1 s 的平均值。视觉识别页显示其中四项：识别帧率、NPU、后处理（decode + sort + nms）、端到端延迟。
