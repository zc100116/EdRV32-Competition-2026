## 约束

- 现行 npu-spec v0.9 的范围、§1、§9.8 仍排除硬件后处理；以下接口均待用户确认，不据此直接写 RTL。不改 spec/testplan/sw/tools，不访问仿真 VM。
- 保留 5040 anchor（3840+960+240）、每格一候选、类别相同最大值取最小 class_id；CPU 按 probability_q24 降序、anchor 升序排序，按类 IoU 严格 >0.45，最多 100 检测框；不引入 64 上限。
- 新逻辑按 clk_npu 200 MHz、5 ns 设计；FF→FF 组合逻辑 ≤6 级、DRM 输出到 FF ≤3 级，扇出 >32 的控制/复位/标签网络按区域复制寄存器。现行整片运行频率仍是 180 MHz。

## 可选方案

| box 保存方案 | 存储与吞吐（均为估算） | 尾延迟与代价（均为估算） |
|---|---|---|
| raw box 写 DDR，网络结束后候选 gather（推荐） | 保留 5040×64=322560 B 写回；后处理共 14–18 DRM，分解见下文 | 37 候选典型预算 0.10–0.30 ms；5040 候选约 9–13 ms；DONE 包含此尾巴 |
| 所有 box 先 DFL，片上缓存距离 | 最大 head 3840×4×12 bit=23040 B；两 bank、每 bank 1920×24，按 32×1024 有效模式取整约 8 DRM，仅指距离缓存；还需 LUT、筛选状态、FIFO | 同一串行 DFL 单元全帧 5040×320/200M≈8.06 ms，与候选数无关；box 局部突发不能满速吸收，需反压，或额外并行单元/缓存 |

- 第二方案的最后 DFL 若随 box 写出完成，cls 后尾巴仅为候选写出和 B 响应；但代价移到网络执行期间，37 候选也计算全部 5040 格。不能用整网 35 ms 推断局部 box 流没有停顿；最后时刻仍须等待 DFL/输出排空才 DONE。
- raw 方案少读典型稀疏框，避免在已拥塞计算区域放高吞吐 DFL 阵列；接受极端密集场景的长尾。第二方案尚无满速设计，不能沿用第一方案的 2–4 APM/面积预算声称无反压。

## 决策

### 1. 检测头识别和离线表

- 建议保持描述符 64 B，启用原预留字 13：`[1:0] POST_KIND`（0 普通、1 box C64、2 cls C80），`[3:2] HEAD_ID`（0/1/2）；其余位及字 15 写 0。字 14 为 `POST_LUT_OFFSET`，相对 MODEL_BASE、32 B 对齐；普通描述符字 13/14 为 0。
- `tools/npu/fixed_plan.py`、`compile_yolo.py`、`format.py` 从 `D{h}.box.out/cls.out` 生成标签，不靠运行时猜 OUTPUT 地址范围。head 0/1/2 固定为 80×48/40×24/20×12、stride 8/16/32、全局 anchor 起点 0/3840/4800。
- 每 head 表 2048 B：偏移 0..1023 为 256×u32 exp_q20，1024..2047 为 256×u32 probability_q24；沿用 `yolo_tables` 的离线舍入。硬件有效宽分别 21/25 bit（概率 1 对应 2^24）。box 描述符开始时装表，保留三份供尾处理；cls 引用相同偏移，不重复装载。
- box 描述符锁存该 head 的 OUT_OFFSET/OUT_PLANE_STRIDE；cls 使用自身形状/跨距。形状、配对顺序、六个标签及地址互不重叠由编译器保证；不增加硬件一致性检查。

### 2. 写回接点和 200 MHz 流水预算

- 接在 `edrv32_npu_writeback` 已完成量化/激活/残差的结果 RAM 读出口，由 `conv_write` 携带 head、row、C32 block、plane、pair 标签后分流到后处理/原 write_dma；每拍接受一个 256 bit beat，即两个 anchor×16 类。实际流按行/C32 块/分块平面交错，不假设整幅 plane 0 后才 plane 1。
- 拟定 12 拍流水：P1 输入/标签；P2–P5 两棵 16 路带 class_id 的 max 树（每拍一层比较选择）；P6 best RAM 读地址；P7 DRM 输出寄存；P8 合并旧 best；P9 写回 best/发概率查表；P10 概率 DRM 输出寄存；P11 两阈值；P12 压缩入队。读改写同地址用流水前递，plane 0 直接初始化，避免清整块 RAM。
- best 按两个像素分 bank，每格存 signed best 8 bit + class 7 bit，最大 head 7680 B，bank/深度取整估算 4 DRM；比较相等保留更小 class。五个 C16 plane 完成才产生至多两个候选；概率表双端口每拍服务两格。
- 压缩队列固定 5040×32 bit，条目为 anchor[12:0]、class[6:0]、raw best[7:0]、4 位零；按入队序号奇偶双 bank，每 bank 2520×32、取整共估算 6 DRM，支持一拍入两个。存满合法全帧，无需用 DDR FIFO 反压分类流。
- 后处理支路 II=1；类别 403200/32=12600 拍，估算纯接收时间 63 µs@200M，可隐入写回。raw box/调试 cls 的 DDR 原有停顿仍会反压；表装载增加描述符启动等待，尾部 gather 占用 NPU。ready/credit 在本地寄存，不把跨模块组合 ready 链接回量化路径。
- DFL 复用一条串行运算链：峰值寄存→差值→exp DRM→输出寄存→bin×weight（APM 寄存）→分开的 num/den 累加；除法用分段减法/选择的逐位迭代，无单拍完整除法。坐标加减和 stride 移位分拍；所有段遵守上述逻辑级预算。12 拍是延迟，不是允许单拍 12 级逻辑。

### 3. gather、DFL 和 DONE

- 全部描述符写响应完成且分类流水排空后，逐条读压缩队列，以 anchor 找 head/cell；每侧地址为 `OUTPUT_BASE+box_offset+side×plane_stride+cell×16`，对齐到 32 B，选对应半拍的 16 bins。四侧各一拍 AXI256 读取，实际流量 128C B（有效数据 64C B），不另加邻格缓存。
- 每侧 16 拍峰值、16 拍 exp/求和、约 40 拍除法，四侧 288 拍；加流水冲刷、地址、坐标/打包，开发预算估算 320 拍/候选（不含 DDR 停顿）。`den` 用 25 bit、`num` 用 28 bit、舍入分子用 36 bit，完整计算 `(num×256+floor(den/2))/den`，不截中间值。
- 输出未裁剪 signed Q8 xyxy：`((cell_axis×256+128) ± distance_q8)×stride`，左/上取减、右/下取加；零点在差值中抵消。CPU 继续在未裁剪框上 NMS，之后 letterbox 映射/裁剪；跨 head 分数统一查各自 probability_q24，不能比较 raw INT8。
- 估算：37 候选运算 11840/200M=59.2 µs，读 4736 B、写 888 B；5040 候选运算 1612800/200M=8.064 ms，读 645120 B、写 120960 B。假设 1.4 GB/s 有效服务、每次 gather 另计 0.05–0.20 µs 首拍/仲裁，串行保守相加为约 0.10–0.30 ms / 9–13 ms；BE 竞争可继续拉长，均非上限承诺。
- `BUSY` 覆盖整网和尾处理；候选最后 B 响应后才发布 POST_COUNT、置 POST_DONE、递增 DONE_COUNT 并置现有 IRQ_STAT.DONE。无单独 IRQ/计算完成事件；两帧不在该 NPU 内重叠。180 MHz 下将上述尾预算按 200/180 粗略缩放（DDR 时间不随频率等比变化），估算以 35 ms 核心时间不变时变为典型约 35.11–35.33 ms、全过约 45–49.4 ms，待板测。

### 4. 输出和寄存器草案

- 候选记录小端 24 B，与 `yolo_candidate` 内存布局一致：+0..15 四个 i32 xyxy_q8，+16 u32 probability_q24，+20 u16 class_id，+22 u16 anchor；按流中入队次序输出，CPU 排序决定最终顺序。
- 软件给 POST_BASE（4 KiB 对齐），容量固定为 5040×24=120960 B，不设可缩小容量寄存器；POST_COUNT 为最终有效条数，记录连续打包成 32 B AXI beat，最后 beat 未用字节写零。软件独占整个区，不与模型/raw box/work 重叠；不加地址或容量运行时检查。

| 偏移 | 名称/访问/复位 | 建议语义 |
|---|---|---|
| 0x114 | POST_CTRL / RW / 0 | bit0 EN，bit1 RAW_CLS_WRITE；EN=0 维持 raw 输出、无后处理；EN=1 时 raw box 始终写、cls 按 bit1 选择 |
| 0x118 | POST_BASE / RW / 0 | 候选输出物理基址；容量固定如上 |
| 0x11C/120/124 | POST_INT8_TH0/1/2 / RW / 0 | 低 9 bit 有符号阈值 −128..128，`best>=THh`；128 表示全拒绝，软件启动前写表中默认 103/105/103 |
| 0x128 | POST_PROB_TH / RW / 0 | u32 Q24，第二关 `probability_q24>TH`；建议正常写 4194304（0.25）；阈值提高时同步由概率表推导各 head INT8 前筛，不能误删 |
| 0x12C | POST_COUNT / RO / 0 | DOORBELL 清零，成功完成发布 0..5040 |
| 0x130 | POST_STATUS / RO / 0 | bit0 POST_DONE，DOORBELL 清零，仅成功后处理完成置位；EN=0 保持 0 |

- 新 RW 寄存器只允许 IDLE 配置，BUSY 写行为沿用未定义；SOFT_RST 回复表中复位值。ABORT/ERROR 排空已发 AXI，POST_DONE 保持 0、计数无效、不增加 DONE_COUNT；软件不消费部分候选。
- 现代码的 INT8 阈值已等价实现严格概率 >0.25；`post.c` 本身没有额外可调概率比较，展示过滤是后续软件行为。上述显式 Q24 第二关为本草案新增接口，默认结果须与 oracle 相同；UI 默认 0.50/白名单继续在 CPU 展示阶段，不能提前删原始候选。
- 错误只复用现有 ERR_CODE=1/2（含装表/gather/候选写响应错误）、3（非法 OP）、4（既有容量限制）；尾处理出错 CUR_DESC 保持最后描述符。不新增超时、队列溢出、标签/形状检查或静默截断；全帧队列容量由固定网络契约保证。
- 推荐正常禁写 403200 B raw cls，仅 RAW_CLS_WRITE=1 用于逐字段调试；EN=0 供原始算子验证。OUTPUT 布局偏移不变，禁写区域内容未定义，不能因地址空洞读旧帧；省类别写并不能按带宽比例推算核心加速。

## 规格改动草案

- **npu-spec 元数据/§1**：“范围含检测头类别最大值、阈值、候选压缩和 DFL；排序、NMS、展示坐标转换由 CPU 完成。”保留 180 MHz 运行频率，新数据通路按 200 MHz 预算设计。
- **§2 新增后处理、§2.4/2.5**：“POST_CTRL.EN=1 时按检测头标签执行上述 (b) 流程；每格最多一候选，最多5040条，输出未裁剪 Q8 框及 Q24 概率；全部算子和后处理写响应完成后才 DONE。”离线工具必须生成配对标签/表/合法地址与阈值，不由硬件重复校验。
- **§4/4.1/4.2**：加入上表寄存器及 IDLE/复位语义；用字13/14替换部分预留，写入 POST_KIND/HEAD_ID/POST_LUT_OFFSET；规定每 head 2048 B 表、24 B 小端记录及固定输出容量，OUTPUT_BASE 保留 raw box/debug cls 用途。
- **§5.2/5.4/5.5**：增加 best/5040压缩队列/表的逻辑容量，200 MHz 路径预算；规定写回每拍一beat的接收能力、标签契约、前递和尾处理栅栏；ABORT 覆盖装表/gather/候选写，不产生有效后处理完成。
- **§6**：“后处理 DMA 的 SLVERR/DECERR 复用 ERR_CODE 1/2；错误帧候选无效，POST_DONE 不置位。”不扩大其他硬件检查项。
- **§7/8/9.8/10**：区分核心推理与含尾处理 DONE 时间，资源增量暂记估算、实测后定稿；添加上述候选/DFL/完成/全容量验证条款；§9.8 改为“加入方案(b)，排序/NMS留软件”；变更记录指向本文，版本由协调者确认。
