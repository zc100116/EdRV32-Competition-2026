## 1. 背景和问题

卡 46 是第一版 showcase 首次上板，用户反馈如下：

| 问题 | 根因 |
|---|---|
| 启动器不美观 | 没有界面设计，直接写坐标；只有 5 张同样的卡片 |
| 中文显示方框 | LVGL 自带的 `source_han_sans_sc_16_cjk` 只有 1464 个字，界面实际用到的 100 个非 ASCII 字符中缺 48 个 |
| 看不到帧率 | 性能监视器在 `lv_conf.h` 中关闭；benchmark 汇总的 fps 计数没有接上 |
| 组件示例偏黄、图层示例有竖线 | 待查 |

更根本的问题有两个：
1. **改一次界面就要上板一次**，周期以小时计；
2. **视觉识别等核心演示仍是独立程序**，demo_vnpu、demo_npu 都不在 showcase 中。

目标是做成一个面向评审的完整演示系统，并用 PC 模拟器迭代界面，确认后再编译成 ELF 上板。

## 2. 约束

**显示**
- 1280×720 @ 60 Hz。
- LVGL 9.6 以 DIRECT 模式双缓冲渲染 RGB565。
- DISP 有两层：L0 为 RGB565，带卷轴；L1 为 ARGB8888，非预乘。

**RND 硬件能做的**（精简 v1）
- FILL：纯色或线性渐变，可带圆角；
- BORDER：圆角边框；
- GLYPH：A1–A8 字形；
- BLIT：RGB565 / ARGB8888 / I8 位图，可最近邻缩放、翻转、重新着色、整体透明度；
- COPY：同格式矩形搬运。

**只能由 CPU 软件画的**：阴影、弧线、直线、三角形、旋转、模糊、蒙版、透明度图层。

**卡 46 实测代价**（B3R，clk_sys 100 MHz）：

| 场景 | 每帧耗时 |
|---|---|
| 全部场景平均 | 37 ms（RND 6 ms、软件绘制 11 ms、其他 CPU 开销约 20 ms） |
| 整屏文字 | 115 ms |
| 旋转图片 | 160 ms |
| 阴影（软件） | 每帧约 10 ms |

单帧超过 16.7 ms 时，帧率从 60 掉到 30 这一档。

**输入**
- 板上 4 个按键：左、右、确认、返回。
- 网口或串口虚拟键盘、鼠标。
- **每个页面都必须能只用 4 个按键操作。**

**其他**
- 硬件配置有三种：VRN（没有 PIX/GEO）、F（全部模块）、B3R（只有 RND）。启动时探测硬件，缺少所需模块的应用置灰，这套机制已有。
- 商业 NES ROM 不入库。

## 3. 界面设计原则（按硬件特点）

1. **风格**：扁平、深色，用一个强调色。
   - 卡片用硬件圆角矩形和 1–2 px 边框；
   - 背景可以用硬件线性渐变；
   - 不用阴影、模糊、透明度图层，不在运行时旋转。
2. **主题**：不用 LVGL 默认主题，因为它带阴影和按压过渡动画。改用自定义主题和共享的静态样式，减少每帧的样式计算。
3. **字体**：用脚本扫描界面源码中的全部文字，自动生成 Noto Sans SC 子集字体（4 bpp、不压缩）。
   - 字号 14 / 16 / 20 / 28 / 40；
   - 大数字单独用一套数字字体；
   - 合并 LVGL 符号图标。
   - 新增文字后重新生成，从根上避免缺字。
4. **图片**：图标用 I8 调色板或 ARGB8888，由 BLIT 绘制，选中时用 RECOLOR 变色；缩略图用 BLIT 缩放。
5. **动画**：
   - 页面切换直接切换，不做滑动或淡入淡出；
   - 焦点变化只改边框和底色；
   - 动态元素只出现在小区域内（进度条、数字、小图表）；
   - 统计数据 2 Hz 刷新，曲线 1 Hz 刷新。
6. **性能预算**（上板验收）：
   - 静止页面的 GUI CPU 占用约为 0；
   - 页面切换 < 100 ms；
   - 统计刷新时单帧 < 10 ms；
   - 状态栏一直显示 GUI 帧率和 CPU 占用。

### 4.2 全局布局与交互

- **布局**：顶部状态栏 48 px（EdRV32、当前页面名、运行时间、CPU 占用、网口状态、GUI 帧率），底部按键提示栏 40 px（随页面变化），中间内容区 1280×632。
- **按键**：每个页面是一个焦点组，按线性顺序排列。
  - ← / →：前一个 / 后一个焦点；
  - 确认：激活焦点项；
  - 返回：退出当前子视图；不在子视图时回到首页（首页不响应返回）；
  - 鼠标点击与"焦点 + 确认"等价。
  - 焦点只改变边框和底色，没有动画。
- **数值刷新**：数字和计数条每秒 2 次；曲线每秒 1 次；只重画变化的小区域。
- **置灰**：缺少所需硬件的应用卡片置灰，写"当前硬件无此模块"，不能进入。

#### 4.5.2 CPU 调度

沿用协作式调度器（2026-11-02 设计记录 4.1），规则如下：

| 任务 | 优先级 | 内容 | 单次 step 上限 |
|---|---|---|---|
| 通信服务 | 0 | UART/网口接收、虚拟输入、4.5.4 协议消息、EDTM 遥测 | 1 ms |
| 当前应用 | 1 | 应用逻辑；长计算（YOLO 后处理、游戏包解析等）切成小片，每片做完返回 | 5 ms |
| 图形界面 | 2 | `lv_timer_handler()`；有动画时最多 30 fps，静止时不唤醒 | 一帧渲染时间 |

- 加速器（NPU、RND、DISP、VIN、PIX、GEO、ETH）全部中断驱动，中断里只置事件，不做计算。
- 只有三种情况允许独占 CPU，进入前先在界面上给出提示：
  1. NES 运行时独占显示，每次 step 运行一帧；
  2. CoreMark 跑分运行到结束，界面显示"正在跑分"，跑完恢复；
  3. LVGL benchmark 场景序列。
- 调度器为每个任务记录**最长单次 step 时间**，系统监控页显示、串口日志输出。验收时检查是否满足上表上限。

#### 4.5.3 输入设备

- **板上按键**：KEY1–4 → ← → 确认 返回（沿用）。
- **虚拟键盘**：调试工具的虚拟输入帧（8 字节）。按键位沿用 `sw/lib/virtual_input.h`：方向键、ENTER、ESC 映射到 LVGL 键盘输入设备，NES 中映射到手柄。
- **虚拟鼠标**：帧中的 x、y（绝对坐标，0–1279 / 0–719）和 mouse 位 → LVGL 指针输入设备；画一个小箭头光标（LVGL 光标对象，有鼠标输入时显示，5 s 无移动后隐藏）。
- **虚拟编码器（滚轮）**：虚拟输入帧的**第 8 字节**（目前固定为 0）定义为滚轮累计计数，`uint8_t` 回绕，向下为正。板端取与上一帧的差值（按 `int8_t` 解释）作为 LVGL 编码器的 `enc_diff`，帧丢失时不会少计步数。mouse 字节 **bit2 = 中键**，作为编码器按下。编码器滚动等同 ← →，在焦点组内移动；按下等同确认。
- 串口虚拟输入（ESC V + 8 字节）格式相同，同样带滚轮字节。

#### 4.5.4 showcase 网口协议（板端与调试工具共同遵守）

接收窗口分配：

| 窗口 | 用途 | 基址 / 大小 |
|---|---|---|
| 0 | 大块数据（模型、图片、游戏），由 BULK_BEGIN 配置 | 按类型配置，见下 |
| 1 | 不使用 | — |
| 2 | 虚拟输入帧（沿用） | `0x0a010000` / 8 B |
| 3 | 消息（PC → 板） | `0x0a011000` / 1024 B |

**消息格式**（UDP 应用头之后，小端）：`magic "EDSC"`(4) + `type`(u16) + `len`(u16) + `seq`(u32) + `payload[len]`。

- PC 发到窗口 3，偏移 0，NOTIFY = 1。板端处理完后重新配置窗口 3，清零字节计数。
- 板端回复使用相同格式，用发送描述符发出，应用头窗口号 = 3。

| type | 方向 | payload | 说明 |
|---|---|---|---|
| 0x01 BULK_BEGIN | PC → 板 | `kind`(u8：1 模型，2 图片，3 游戏) + 3 字节 0 + `total`(u32) | 板端把窗口 0 配置到该类型的 DDR 区域，大小 = total，然后回复 READY；区域不够时回复 DONE(status = 3) |
| 0x81 READY | 板 → PC | `kind`(u8) + 3 字节 0 | PC 收到后把数据发到窗口 0，偏移从 0 开始，最后一包 NOTIFY = 1 |
| 0x82 DONE | 板 → PC | `kind`(u8) + `status`(u8：0 成功，1 长度不符，2 格式错误，3 空间不足) + 2 字节 0 + `index`(u32) | 窗口 0 的 NOTIFY 到达后，比对字节数并处理。`index`：游戏为新游戏在列表中的序号，图片为帧号 |
| 0x02 CAMERA | PC → 板 | 无 | 视觉识别切回摄像头（取代旧的 ASCII `camera`） |
| 0x03 ECHO | PC → 板 | 任意数据，≤ 1000 B | 回环测试，板端立即回复 0x83 ECHO_REPLY，`seq` 和 payload 原样返回 |

- **模型**沿用 EDNM 格式；**图片**沿用 1280×720 RGB565；识别结果沿用现有的检测框和张量回传格式（调试工具 `yolo.py`）。
- **游戏**为下面的 EDG2 记录。
- 一次只进行一个大块传输：PC 收到 DONE 之后才能发下一个 BULK_BEGIN。

#### 4.5.5 游戏记录 EDG2 和嵌入游戏包

- **EDG2 记录**（小端）：
  - 头：`magic "EDG2"`、`version`(u16 = 2)、`reserved`(u16)、`total`(u32，含头的整条记录长度)、`name_w`、`name_h`(u16)、`name_off`(u32)、`cover_w`、`cover_h`(u16)、`cover_off`(u32，0 表示没有封面)、`rom_off`、`rom_len`(u32)、`utf8_name[64]`；
  - 名字位图：A8；
  - 封面：RGB565，≤ 120×160；
  - ROM：原样。
  - 各段偏移相对记录起点，4 字节对齐。
- **生成**：名字位图用 Noto Sans SC（`third_party/lvgl/tests/src/test_files/fonts/noto/NotoSansSC-Regular.ttf`）20 px 渲染，宽度不超过 180 px；用 PySide6（已在 `tools/requirements.txt` 中）。封面缩放沿用 4.4 的规则。
  - 共享模块 `tools/sw/game_record.py`，调试工具上传和 Linux 构建都用它。
- **嵌入游戏包**：`magic "EDGP"`、`version`(u16 = 2)、`count`(u16)、`count` 个 u32 记录偏移，后接各条 EDG2 记录。
  - showcase 构建时由 `games.txt` 生成游戏包，链接进 ELF 的 `.game_pack` 段，取代旧的 v1 游戏包和 Windows 端打包流程。
- **上传的游戏**放在 DDR 的上传区（8 MB），依次追加，复位后清空。
- **板上显示**：名字位图作为 A8 图片重新着色显示，由 RND GLYPH 绘制；封面由 RND BLIT 绘制。

#### 4.5.6 视觉类页面的显示

- 摄像头画面、上传的图片、图像处理的输出都是 DDR 中 1280×720 的 RGB565 帧，在页面中作为 LVGL 图片对象，由 RND BLIT 缩放到 960×540 显示。检测框是 LVGL 对象，每次推理结果到达后更新。
- 帧缓冲的所有权沿用 VIN 槽位的占用标记：显示或推理正在使用的槽不被覆盖。

#### 4.5.7 代码布局（减少 I$ 缺失）

依据：I$/D$ 各 32 KiB、2 路、32 B 行（cache-spec 2.1）。卡 46 实测 LVGL 运行时 I$ 缺失每千条指令 6–13 次，前端空等周期占 20–30%。

1. 全部代码用 `-ffunction-sections -fdata-sections` 编译。showcase 链接脚本按任务分组放置：
   - 片上 SRAM：调度器、陷入/中断入口、各中断处理、`memcpy`/`memset`、虚拟输入、`platform` 热路径；
   - DDR 中，依次连续放置：NES 模拟核心（nofrendo CPU/PPU/APU 和 mapper）、LVGL 绘制与刷新热路径、`ui/` 页面；其余代码放在最后。
2. **热点测量**：通信服务支持串口命令 `prof <秒数>`。用 CLINT 定时中断按 10 kHz 采样 `mepc`，按 32 B 行统计，结束后串口输出前 256 行的地址和次数。主机脚本 `tools/sw/prof_map.py` 用 ELF 符号表换算成函数热度表。
3. 根据热度表生成链接顺序文件（`sw/apps/showcase/layout/*.txt`，入库），在每组内按热度排列。
4. 效果用 HPM 的 I$ 缺失次数和 benchmark 每帧时间做布局前后对比，写进测量报告。

#### 4.5.9 开发中冻结的接口（2026-11-03，回答 worker 提问）

- `board/vision_hooks.h`：`uint32_t vision_bulk_done(unsigned kind, uint32_t base, uint32_t bytes)` 返回 DONE 的 status（0 成功、2 格式错误；kind 1/2 的 index 填 0）；`void vision_camera(void)`；`void vision_frame_presented(void)`，由 BOARD 在 LVGL 显示的 RENDER_READY 事件中调用；`extern const struct app vision_app_camera, vision_app_image, vision_app_process`，按 app.h 约定实现。
- 帧槽位释放：`ui_data_vision` / `ui_data_process` 返回的图片所在槽位必须保持占用，直到有更新的图片返回给页面，并且此后至少调用过一次 `vision_frame_presented`。
- `ui_data_process(unsigned mode)` 带模式参数；图像处理页像视觉页一样周期刷新。
- 图片识别应用的 needs 为 NPU|ETH，CH2 由 CPU 按行切片计算，不依赖 VIN。
- DDR 区域（DDR 偏移，沿用 demo.h）：模型 BULK 0x09000000 / 16 MiB；图片 BULK 0x08000000 / 2 MiB；游戏上传区 0x0b000000 / 8 MiB；vision 工作区与 demo.h 相同；BOARD 自己的缓冲放在程序 bss 中。常量集中在 `board/ddr_map.h`。
- 模型 BULK 数据保留 EDNM 的稀疏偏移（头 0、描述符 0x1000、模型 0x100000，间隙补零），total = 0x100000 + 模型长度。

## 5. 模拟器方案

### 5.1 代码划分

| 目录 | 内容 |
|---|---|
| `sw/apps/showcase/ui/` | 各页面，只调用 LVGL 和数据接口，不访问寄存器 |
| `sw/apps/showcase/board/` | 板上实现：platform、RND 绘制单元、DISP、NES 移植、NPU 流水、数据接口的硬件实现 |
| `sw/apps/showcase/sim/` | 模拟器实现：`main`（LVGL Windows 驱动，模拟器模式 1280×720）、数据接口的模拟实现 |

- **数据接口 `ui_data.h`**：硬件存在掩码、各任务 CPU 占用、帧率、网口状态、DDR 带宽、检测结果、benchmark 结果、游戏列表等。板上读驱动；模拟器按固定脚本生成随时间变化的数据。
- **由硬件直接显示的内容**（摄像头视频、NES 画面、DISP 图层）：模拟器在同一区域显示示例图片或占位图。
- **lv_conf**：板上和模拟器共用同一份配置，只有绘制单元和驱动不同（板上为 RND + 软件，模拟器只有软件）。模拟器也用 RGB565，颜色层次与板上一致。

### 5.2 构建和交付

1. **Linux 无界面构建**：把每个页面渲染成 PNG 截图，供 worker 和协调者评审。
2. **Windows 程序**：在 Linux 上用 Zig（`zig cc -target x86_64-windows-gnu`，装在用户目录）交叉编译出单个 exe，放进 Windows 任务卡的 `src/`。用户双击运行，不需要安装编译环境。
   - 键盘映射：← → Enter Esc 对应 4 个按键；鼠标可直接点击。
3. **板上**：同一套 `ui/` 代码，加上 `board/`，由 `sw/Makefile` 构建出 ELF。
