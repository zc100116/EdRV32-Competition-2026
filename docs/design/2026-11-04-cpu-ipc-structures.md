# CPU IPC 结构周期模型评估（2026-11-04）

## 背景和问题

T-CPU-IPC2：把“每次省一拍”的机会估算替换为逐周期模型；输入提交 `8a27feb7`，模型代码与本记录同一提交。
V3s、无C、BTB128、gshare4096、RAS4、PC>>2；全命中、相同预热前缀与退休窗口，复用三个已有基线，不重跑。CoreMark / 视觉 / LVGL：2,479,576 / 1,901,338 / 527,757 条，基线1,877,663 / 1,850,040 / 505,611周期；正式板上4.354/MHz。

## 约束

只改周期模型、定向测试与本记录；不改RTL/spec/sw、不访问VM；所有完整模型通过共享flock，最多同时2个，各配置一次。下列为模型估算、不是RTL/PDS实测；表内收益=`Cbase/C配置−1`，CoreMark/MHz=`10,000,000/C`，三个负载的含义及输入生成沿用[Fmax记录](2026-11-04-cpu-fmax-ipc.md)§7。

## 决策

优先保留k=1提前地址和寄存LCB的局部硬件探针：两者分别覆盖稳定基址load与load后比较；先测各自时序，组合收益按本表，不叠加单项百分比。
受限串联在三个负载均有收益，任意ALU额外收益很小，选受限版本；加tournament的组合最高达6.2211/MHz，A代价下5.9649/MHz，但须另证E级频率和第二级纠正气泡。
放弃当前配对循环缓存的IPC目标（三负载均负收益）与64项循环预测器的通用目标（LVGL退化）；指定两种融合在视觉零机会，通用模板组合可保留但需付双结果写回代价；本配置TAGE综合收益低于tournament，暂不优先。
时序预算沿用前记录§1：`Hff=1.141ns,Hdrm=2.524ns,q=0.742ns`；150/160MHz为6.667/6.250ns，局部扇出≤16/8且route≤0.500ns仅是目标，均需真实探针验证。

## 影响

本次只增加默认关闭的实验参数；基线调度、load/MUL延迟、控制恢复不变。HPM发射槽仍按融合单元计，架构指令数按两条计。
若实施，需另行修改CPU/cache规格和RTL，并验证异常/中断的双退休边界、晚分支清除优先级、预测恢复和真实存储端口；本记录不构成RTL授权。
