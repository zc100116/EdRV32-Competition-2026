## 1. 2D 怎样变成 3D 的特例

| 2D 的东西 | 在 3D 管线中 |
|---|---|
| 精灵 | 屏幕空间的矩形贴图（四边形）：不做变换、不做透视、不测深度（或用固定深度） |
| 图块地图背景 | 一屏约 40×23 个 16×16 的图块四边形，约 920 个；或者一个全屏四边形，用图块地图当纹理寻址。不需要专门的图块硬件 |
| 颜色键、Alpha、调色板 | 像素运算级的通用功能，2D 和 3D 共用 |
| 硬件精灵表 | 变成“图元列表”：三角形和四边形放在同一张表里 |

为了保住 2D 的精灵吞吐，四边形走**快速通道**：轴对齐的矩形不用边函数，直接按行展开。估算上限仍是约 3 万个 16×16 精灵（见 2D 文档第 3 节）。

## 2. 管线

```
CPU：游戏逻辑 → 写图元列表、顶点缓冲、矩阵 → START
  ① 取命令和顶点（DMA，从 DDR 读）
  ② 几何（硬件几何单元，R7）：顶点变换（定点 4×4 矩阵）→ 裁剪 → 透视除法 → 视口映射
  ③ 三角形建立：边方程、各属性（纹理坐标、深度、颜色）的增量
  ④ 光栅化：按 4 像素一组扫描，边函数判断覆盖；四边形走快速通道
  ⑤ 纹理：片上纹理 RAM，最近邻取样（像素风格），调色板查表
  ⑥ 像素运算：深度测试、颜色键、Alpha 混合
  ⑦ 片上帧缓存（640×360 RGB565，100 块 DRM）+ 片上深度缓存（16 位，100 块 DRM）
  ⑧ 整帧写出到 DDR → DISP 翻页、放大 2 倍输出
```

## 3. 像素风格 3D 的取舍（后续逐项确认）

| 项 | 可选 | 说明 |
|---|---|---|
| 纹理坐标插值 | 逐像素透视校正 | 已定（R9） |
| 取样 | 只做最近邻 | 已定（R12） |
| 着色 | 顶点光照 + 颜色插值 | 已定（R10） |
| 深度缓存 | 16 位片上 | 倾向采用 |
| 扩吞吐 | 多个渲染单元按横向条带并行 | 按 PDS 数据决定 |

## 4. 待确认的决定（一次一项）

| 编号 | 问题 | 我的推荐 |
|---|---|---|
| R7 | 顶点变换由谁做 | **已定：渲染器内的硬件几何单元**（定点 4×4 矩阵、裁剪、透视除法、视口映射；用户 2026-11-23） |
| R3a | 每个渲染单元每拍 4 像素，多单元并行在后面按数据定 | 采用 |
| R4 | SoC 规划 | **已定：在决赛版 SoC 上增减**：保留 CPU、cache、存储子系统、系统外设、ETH、DISP（加 2 倍放大）；新 GPU 替换 RND；去掉 GEO、PIX、YOLO NPU、VIN（用户 2026-11-23） |
| R8 | 声音 | **已定：只做放音**。ES8156 放音模块插 J25 转接板 PMOD-D（引脚见 `2026-11-23-audio-pmod-pins.md`）；FPGA 做 I2S 主机（12.288 MHz）；DMA 从 DDR 读音频数据；混音由 CPU 软件完成；不做录音（用户 2026-11-23） |
| R5 | 硬件对象运动和碰撞 | **已定：做**。图元表中的简单对象带速度、加速度、寿命字段，GPU 读表时更新位置、到期失效；检测子弹与玩家碰撞框（可加少量敌人框）的矩形重叠，输出命中列表。追踪类子弹由 CPU 改速度，推进和碰撞仍由硬件完成（用户 2026-11-23） |
| R9 | 纹理坐标插值 | **已定：逐像素透视校正**：插值 u/w、v/w、1/w，每个像素用倒数单元（查表 + 一次牛顿迭代）求 w；每拍 4 像素配 4 个倒数单元（用户 2026-11-23） |
| R10 | 着色与光照 | **已定：顶点光照 + 颜色插值**：几何单元每个顶点算 1 个方向光 + 环境光；光栅化插值顶点颜色；像素颜色 = 纹理 × 插值颜色。平面着色是它的特例（每面法线相同）；受击闪色、雾、昼夜也用顶点颜色实现（用户 2026-11-23） |
| R11 | 纹理存放 | **已定：片上常驻纹理 RAM**（约 256 KB，容量规格阶段定），DMA 从 DDR 按关卡/区域装入，分两半可边用边装；取纹理固定延迟、流水线不停顿。纹理读取做成独立接口，以后可升级为 cache（用户 2026-11-23） |
| R12 | 纹理格式与取样 | **已定**：4 位、8 位调色板色和 RGB565 直接色；调色板项为 RGB565 + 4 位透明度（0 = 透明，代替颜色键），片上 16 组 × 256 色；只做最近邻取样；纹理宽高为 2 的幂（8–256），坐标环绕（用户 2026-11-23） |
| R13 | 像素运算与扩展功能 | **已定，第一版一起实现并验证**（用户 2026-11-23）：①深度 16 位，比较“小于等于/总是通过”，按图元开关深度写入；②调色板透明度为 0 的像素丢弃；③通用混合方程（因子 0、1、源 α、1−源 α、目标色等；运算加、减、取小、取大）；④渲染目标偏移 + 裁剪矩形（条带渲染，可原生 720p）；⑤双线性过滤，按图元开关，开启时每拍 1 像素（修订 R12，默认仍最近邻）；⑥8 位模板缓冲；⑦后处理抗锯齿（写出阶段，类 FXAA）；⑧Mipmap 与三线性过滤。不做：4 倍多重采样（RAM 超过器件总量）、逐像素光照和法线贴图 |
| R6 | 演示内容 | **已定：三部分**（用户 2026-11-23）：①原创 2D 弹幕挑战，HUD 显示精灵数和帧率，对比千影 2300；②原创低多边形 3D 小场景，可走动，用到透视贴图、光照、深度、模板阴影；③功能演示页，R13 的 8 项功能逐个开关对比。具体玩法后续逐条确认，不擅自添加 |

## 5. 非像素风格场景的扩展性（2026-11-23 用户要求考虑）

本节数字都是估算。DRM 每块 36 Kb（4,608 B），共 415 块。

| 功能 | 用途 | 代价 | 建议 |
|---|---|---|---|
| 通用混合方程：结果 = 源 × 因子 ± 目标 × 因子，因子可选 0、1、源 α、1 − 源 α、目标色等；运算可选加、减、取小、取大 | 正片叠底、减淡、阴影贴花、各种特效 | 复用 Alpha 的乘法器，只多选择器 | **现在做**，取代固定的三种模式 |
| 渲染目标偏移 + 裁剪矩形 | 把 1280×720 切成 4 条 1280×180，每条用现有的 460 KB 片上缓存渲染一遍，几何每条重算一次，就能原生输出 720p；裁剪矩形也用于分屏、小地图、UI 区域 | 一组偏移和裁剪寄存器，加上比较器 | **现在做**。这样分辨率不再被片上 RAM 卡死，以后多个渲染单元按条带并行也用同一机制 |
| 双线性过滤 | 写实或平滑风格的贴图 | 纹理 RAM 按 (u, v) 奇偶分成 4 个存储体，一拍取 4 个纹素，不增加 RAM；开启时降为每拍 1 像素；另需权重乘法器，约 12 个 | **现在做，按图元开关**（修订 R12：默认仍是最近邻） |
| 8 位模板缓冲 | 阴影体、镜面和传送门、描边、遮罩 | 640×360 × 1 B ≈ 225 KB，约 50 块 DRM | **做**（R13） |
| 后处理抗锯齿（类 FXAA） | 消除三角形边缘锯齿 | 在把整帧写出到 DDR 时，用 3 行缓冲做边缘检测和混合，约 3 块 DRM | **做**（R13） |
| 4 倍多重采样抗锯齿 | 高质量抗锯齿 | 颜色和深度都要 ×4，约 800 块 DRM，超过器件总量 | 不做 |
| Mipmap 与三线性过滤 | 远处纹理不闪烁 | 每个像素按梯度和 w 计算细节级别；各级纹理放在同一块纹理 RAM 中，多占 1/3 容量；三线性每像素取 8 个纹素，降速运行 | **做**（R13） |
| 逐像素光照、法线贴图 | 写实光照 | 每个像素要做法线插值和点积，乘法器数量成倍增加 | 不做 |

## 6. 片上 RAM（DRM）预算（估算）

决赛版中保留的模块（`docs/reports/2026-11-13-resource-slim-sys.md`，PDS 实测）：CPU 27、存储子系统 4、ETH 3、系统子系统 20、DISP 扫描 FIFO 8，合计约 62 块；DDR3 控制器 IP 另计。

| GPU 部分 | DRM |
|---|---|
| 帧缓存 640×360 RGB565 | 100 |
| 深度 16 位 | 100 |
| 模板 8 位 | 50 |
| 纹理 RAM 256 KB（含 mipmap 各级） | 57 |
| 调色板（16 组 × 256 色 × 20 位，4 像素并行读需 2 份） | 约 6 |
| 后处理抗锯齿行缓冲、对象表和命中列表缓冲、音频 FIFO | 约 8 |
| 合计 | 约 321 |

总量 415 块，扣掉保留模块的约 62 块，GPU 可用约 350 块，余量约 30 块，偏紧。如果不够，可以用条带机制调节：640×360 分成 2 条 640×180 渲染，帧缓存、深度、模板减半，省约 125 块，代价是几何计算多算一遍。最终数字以 PDS 综合为准。
