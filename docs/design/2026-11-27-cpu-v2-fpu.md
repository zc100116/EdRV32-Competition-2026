# CPU v2 可配置浮点单元设计与周期模型

## 背景和问题

C2-F 研究独立 CPU IP 的三种构建：无 FPU、F、F+D。目标应用为自研 CPU/GPU
上的 GLQuake 类 OpenGL 程序和一般浮点计算。本记录是设计建议，不修改现有
`cpu-spec.md` v0.23 中“不实现 F/D”的规定，不含 RTL。

输入基线提交 `f63071ea077abec8eff013b194ec3d27dde2885d`；本记录与同次提交的
`tools/cpu/eval/fpu_*.py`、`workloads/fp/` 一起复现。编译/Spike 指令数和 ELF
大小是软件执行测量；所有周期、加速比、资源和流水级数是**模型/结构估算**，
不是 RTL 仿真、综合或 PDS 时序结果。

## 约束

- PG2L200H，整片目标至少 150 MHz，周期 6.667 ns；CLM、尤其 FF 紧张。
- 默认每级至多 3 级 LUT 加一段不超过 36 位的进位链；APM 输出先寄存，不能把
  原语内部时序预算和普通 LUT 预算混为一谈。整数核实测预算由 C2-I 补充。
- APM 为有符号 25×18，48 位后加器，输入/乘积/后加内部寄存。
  依据 `fpga/ip/apm_gpu_cascade.md`、`2026-11-27-gpu-apm-cascade.md` 和本机
  `~/.local/share/edrv32/pango/GTP_APM_E2.v`；不把厂商文件入库。
- 2026-11-27 协调者确认 C2-I V5 接口：所有 FP、转换及 FP 访存走槽 0，
  槽 1 可配独立整数 ALU；独立 FRF，默认 2R1W、FMA 两拍读数，满配 3R1W；
  整数 RF 不增端口；FP load 与运算共享 FP 写回；共用 LSU；顺序提交、提交时
  更新 fflags；长操作不停止无关整数执行；冲刷取消较年轻操作。
- 下文延迟从槽 0 接收操作数起算，到消费者可用结果；默认 FMA 再加 1 拍读 rs3。
  无 FPU 的成本在表中表示相对 C2-I 基础核的零增量，不能解释为整个 CPU 为零。

### ISA 范围与软件契约

采用 RISC-V F/D 2.2，RV32，不附加 Zfh、Zfa、Zfinx 或 RV64 指令。
参考 [F 官方定义](https://docs.riscv.org/reference/isa/v20260120/unpriv/f-st-ext.html)
及 [D 官方定义](https://docs.riscv.org/reference/isa/v20260120/unpriv/d-st-ext.html)。

|范围|设计中包含的行为|
|---|---|
|状态|f0–f31，F 为 FLEN=32，F+D 为 64；fcsr=frm[7:5]+fflags[4:0]；NV/DZ/OF/UF/NX 粘滞累计；CSR 读改写按指令顺序|
|舍入|RNE、RTZ、RDN、RUP、RMM；rm=111 采样已提交 frm；静态 rm 同样支持；精确操作不凭空置 NX|
|特殊值|硬件处理输入/输出 subnormal，渐进下溢，舍入后检测 tininess；±0、±∞；算术 NaN 结果规范化为 S 0x7fc00000 / D 0x7ff8000000000000；sNaN 的 NV 按指令定义|
|FMA|FMADD/FMSUB/FNMADD/FNMSUB 的 S/D，完整乘积与加数相加后只舍入一次；不能用 FMUL+FADD 替代；0×∞ 即使加数为 qNaN 仍置 NV|
|算术|FADD、FSUB、FMUL、FDIV、FSQRT，S 与启用 D 时的 D|
|最值/比较|FMIN/FMAX 按 2.2 的 minimumNumber/maximumNumber；单 NaN 返回数值、sNaN 置 NV；−0 小于 +0；FEQ 仅 sNaN 置 NV，FLT/FLE 遇任意 NaN 置 NV，结果写整数 RF|
|分类/符号|FCLASS 十类；FSGNJ/FSGNJN/FSGNJX，不做算术舍入、无浮点异常；保留转移/符号指令规定的 NaN payload|
|转换|FCVT.W[U].S、FCVT.S.W[U]；D 配置加 FCVT.W[U].D、FCVT.D.W[U]、FCVT.S.D、FCVT.D.S；越界/NaN 的整数结果和 NV/NX 按 ISA；不包含 RV64 的 L/LU 转换|
|位搬移|FMV.X.W / FMV.W.X 保留低 32 位编码；RV32 D 没有 FMV.X.D / FMV.D.X，不额外发明指令|
|访存|FLW/FSW；D 加 FLD/FSD；FLW/窄结果写入高 32 位全 1；FLD/FSD 原样搬移 64 位；32 位 LSU 拆成低地址字、再高地址字两个 beat|
|NaN-boxing|D 配置的窄非搬移运算（含比较、分类、符号注入）检查高 32 位全 1，否则视作 canonical NaN；窄结果上部填 1；FSW、FMV.X.W 的位搬移保留低位，不能误套算术 boxing 检查|
|配置与特权|无 FPU 时不暴露 F/D/浮点 CSR；F 配置不暴露 D；mstatus.FS=Off 的非法访问和 FS Dirty、上下文保存由整数核/特权集成负责；浮点数值异常只置 flags，不陷入|

rm/frm 保留编码的处理、复位 FS 状态以及 FLD/FSD 的自然对齐要求要由协调者写入
未来规格；建议保留舍入编码触发非法指令，访存沿用 CPU 的自然对齐异常。
这是待确认建议，不在此记录中新增架构规定。FLD 两字全部返回后才提交结果；
FSD 两 beat 是一条指令，不能在中途退休/响应中断。32 位总线不承诺 64 位
访存原子性；第二 beat 访问故障的可见副作用遵从总线/CPU 的访存异常契约。

## 可选方案

### 1. 以 FMA 为中心还是完全分离

|方案/模型名|S ADD / MUL / FMA 延迟（3R）|S 启动间隔|F 配置逻辑 LUT / FF 估算|取舍|
|---|---|---|---:|---|
|全部统一 `unified`|14 / 14 / 14|1；默认 2R FMA 为 2|2549 / 1002|控制简单，但普通加法的相关链付出完整乘法延迟|
|共享尾端、短路前端 `bypass`|8 / 10 / 14|1；默认 2R FMA 为 2；共用尾端预约|2749 / 1098|推荐；ADD 跳过乘法，MUL 跳过宽加法，仍共用规格化与舍入|
|独立 ADD + MUL/FMA `split`|8 / 10 / 14|各 1；单槽 0 和 1W 仍限制总吞吐|3665 / 1448|避免不同长度操作的尾端冲突，但多一套加法规格化/舍入|
|共享完整 FP64 `wide`|30 / 30 / 30（S、D 相同）|1；默认 FMA 两拍读|5701 / 4416，12 APM|适合大量 D；S 相关链明显变长，F-only 构建也浪费面积|
|F 快通路 + D 扩展（上述前三种的 D 路径）|D 算术 30；FMA 默认 31|D 开发初值 4，S 保持上述值|F+D 8450 / 5514，14 APM|推荐可选 D；独立 D 算术尾端不拉长 S 延迟|

表中 unified 按 bypass 去掉约 200 LUT、96 FF 的短路选择/标签估算；
split 按增加 `floor(L(24)/3)=916` LUT、`floor(Q(24)/3)=350` FF 的
独立加法尾端估算。这两个比例/常数是结构比较的输入假设，尚无综合测量。

FADD 等价于 `a×1+b`、FMUL 等价于 `a×b+0` 的**数值思路**，不能直接把它们
作为普通 FMA 送入异常判定，例如 FMUL 的零符号、NaN、Infinity、静态舍入仍按
各自指令决定。内部按原指令保留特殊值标签。

`bypass` 的吞吐 1 是无尾端冲突时的上限。不同延迟结果预约共享四级尾端的
入口槽位，冲突时延后发射；结果端再排队使用 1W。`split` 只解除 ADD 与
MUL/FMA 的尾端冲突，不能从单槽 0 同时发射两条 FP。D II=4 是初版保守调度值，
不是 APM 链的固有限制，也不宣称降低下列全流水资源估算；模型另提供
`parallel_d`（D II=1）量化放宽后的收益，最终由 PDS 和混合精度测试确定。

### 2. 24×24 与 53×53 的 APM 分块

正尾数在 X 端按 24 位切块，Y 端按 16 位切块，各块补零进入有符号端口。
`a=Σai·2^(24i)`，`b=Σbj·2^(16j)`，每项权位 `e=24i+16j`。
按 e 排序，链头 `C0=a0b0`，后继 `Ck=ai·bj+(C{k−1} >> Δe)`；
把前一 C 的低 Δe 位延迟后拼接到结果，不用 CLM 加法树。

|精度|X 块 / Y 块|项的权位次序|APM 数|输入到完整乘积|II|
|---|---|---|---:|---:|---:|
|S，p=24|24 / 16+8|0,16|2|4|1|
|D，p=53|24+24+5 / 16+16+16+5|0,16,24,32,40,48,48,56,64,72,80,96|12|14|1|

D 的 e=48 按 a2b0（5×16）、a0b3（24×5）排序，两项之间需要 **Δe=0**，不能误接 shift8。厂商模型 `MODEZ[2:0]=011`
直接选择 CPI，配置 MODEZ=3；后续需要新增固定直通级联包装，本次不写 RTL。
其他差值仅为 8/16，使用已有模式；头部 MODEZ=0。48 位后加器必须保存未舍入
部分积；单项小于 2^40，重复权位求和亦小于 2^47，不发生有符号溢出。
符号在外部单独处理。最终得到完整 48 / 106 位积。

N 项全寄存链延迟 N+2；第 k 项操作数错开 k 拍。保守保留全部 CLM 延迟寄存：
`FFalign=Σ k(wxk+wyk)+Σ Δek(N−1−k)`。
S 为 32+16=48 FF，D 为 1708+576=2284 FF。这里不把 APM 内部寄存误计为 CLM。
`fpu_resources.py` 用固定种子和极值验证 2006 个无符号完整乘积，包括 Δe=0；
这是整数分块模型验证，尚不是 CPU 浮点 RTL 与厂商原语逐拍等价验证。

### 3. 150 MHz 的流水级预算

所有下列拍数是设计估算。长 carry 按低位到高位切拍，低位结果等高位完成，
不加 multicycle 例外。77/164 位是 `W=3p+5` 的保守 FMA 对齐窗口；远小加数
合并 sticky，消去情形必须保存所有会影响舍入的位，不能过早把低积压成 sticky。

|S 路径阶段|工作|局部深度目标|
|---|---|---|
|E1|分类、指数展开、subnormal 前导零树|树分组，≤3 LUT；指数运算 ≤13 位|
|E2–E3|三操作数按 LZC 规格化；指数调整|5 层 barrel 分 2+3 层，不把树与整桶移位串同级|
|E4–E7|2 APM 完整乘积；并行计算 C 对齐|APM 输入/乘积/级联寄存；对齐 7 层分 3+3+1|
|E8–E10|77 位有效加减，低 36、高 36、剩余 5 位；并行 LZA 分组与归约|每拍最多 36 位 carry；LZA 不串在最终 carry 后|
|E11–E13|LZA 预测校正、左规格化或渐进下溢右移；产生最终 G/R/S|barrel 分 3+3+1；LZA 最多一位校正并入最后选择|
|E14|按 rm 舍入、指数溢出/flags、封包|24 位舍入 carry；特殊值结果预先产生|

ADD 不要求先归一化 subnormal：隐藏位按指数零/非零解码，E1 比较有效指数，
E2–E3 对齐，E4 做 ≤28 位加减/LZA 并行，E5–E7 规格化/下溢，E8 舍入。
MUL 经 E1–E3 输入归一化、E4–E7 乘积、E8–E9 最高位选择/下溢移位、E10 舍入。
MUL 和 ADD 的尾端按四级资源预约，未使用的层只传递标签，不多生成精度。
精确消去、所有输入 subnormal 均在这些硬件阶段内处理，不采用软件陷入或 FTZ。

D 路径预算：输入分类/LZC/归一化 5 拍，乘积 14 拍，164 位加减分
`36+36+36+36+20` 共 5 拍，规格化 3 拍，53 位舍入分 2 拍，封包 1 拍，合计 30。
D normalization 的 8 层 barrel 分 3+3+2；宽舍入的进位需保存到下一拍，不能
把 53 位 carry 当作一级 ≤36 位 carry。各级需在 PDS 上检查真正 carry/route；
仅凭此表不能认定已经达到 150 MHz。APM 链必须沿连续站点放置并检查拥塞。

### 4. 除法/开方

|方案|S DIV / SQRT 延迟估算|D DIV / SQRT 延迟估算|占用及资源|
|---|---:|---:|---|
|独立 radix-4 SRT/开方 digit recurrence|22 / 22|66 / 66|每精度一个共享 DIV/SQRT 迭代器；S 每拍两位，D 两拍完成一轮；不占 FMA|
|复用扩精度 FMA 的 Newton|94 / 122|254 / 344|依赖链占满对应精度 FMA；需要种子 ROM、额外内部精度、精确 residual 和末位校正|

SRT 延迟公式：`ceil((p+3)/2)×c+overhead`，S p=24,c=1,overhead=8，
D p=53,c=2,overhead=10。p+3 包括商/根的 GRS 与最终余数判定；DIV/SQRT 共用
余数加减和 digit selection，开方还更新部分根。余数约 p+4 位，S carry ≤28；
D ≤57 位拆两拍，不能套用 S 的每拍一轮得到虚假的 38 拍。22/66 包含准备、
最后余数修正、舍入；极值也按固定最坏延迟建模，特殊值提前完成的收益未计。

Newton 估算假定 8 位种子：S 做 2 轮、D 做 3 轮。
倒数每轮约 2 个 FMA，商与精确 residual 再 2 个，故 S `6×14+10=94`、
D `8×30+14=254`；倒数平方根每轮约 3 个，再 2 个最终运算，
S `8×14+10=122`、D `11×30+14=344`。以上不计 FMA 两拍读 RF，因为内部迭代
使用反馈寄存；不是用标准舍入的 S/D 指令直接迭代就能保证正确舍入。
内部至少 p+3 位并用精确余数决定末位，困难舍入边界也必须硬件完成。
S 的内部 14 拍是乐观开发预算：反馈操作数已归一化，省去两拍输入规格化，
用于补偿 27×27 四项 APM 链比原 S 两项链多出的两拍；若做不到，Newton
延迟还会更大。本模型没有把扩精度乘法错误地当成两颗 APM。

Newton 种子可放一个 DRM（两张 256×12 表共 6144 bit）；S p+3=27 的乘法需
4 APM 而非原 2 APM；D p+3=56 仍需 12 APM，额外精度也增加移位/舍入逻辑。
其面积并非“删除除法器就零成本”。推荐独立 SRT，资源结构估算用
`6(p+4)` LUT、`3(p+4)` FF 表示选择/余数/部分根，包含在后文公式中。

### 5. F+D 的复用选择

- 独立 F 快通路加 D 扩展：14 APM，S 延迟不变；D 的前后处理、106 位积、
  164 位对齐/加减是主要增量。共享槽 0、FRF、转换入口和完成写口。
- 只留一条完整 D 通路（12 APM）：S 数据嵌入宽通路，删去重复 F 规格化和加法；
  `wide` 估算节省 2749 LUT、1098 FF，但 S 算术变成 30 拍。
- 复用 S 的 2 APM，逐项计算 D 的 12 个部分积：单乘积资源下界至少 6 次发射，
  各权位仍需要 106 位累加和残数保存；不能声称“6 拍得到 D FMA”。若单项等待
  3 拍并按完整依赖序累加，光乘法就约 36 拍，连同前后处理约 52 拍以上，
  II 约 36 以上。它省 12 APM，未必省 CLM，且阻占 S；不作为推荐性能方案。

## 决策

推荐三种构建：不含 FPU；F（默认面向图形）；F+D（一般计算可选）。推荐架构为
**FMA 核心、ADD/MUL 短路、共享 S 尾端、独立 SRT、D 独立宽扩展**。
默认 2R1W，FMA 两拍读数；保留 3R1W 为作品集 IP 的可选物理配置建议。
这些是供协调者确认的设计建议，尚未进入规格，不自行添加 RTL 参数。

### 1. FRF、记分牌与精确提交接口

|接口组|需求/候选字段|与整数核的关系|
|---|---|---|
|发射|valid/ready、opcode、fmt、rm、rs1/2/3、rd、源/目的域、操作数、顺序 tag|只接槽 0；ready 由单元占用、RF 读相位、尾端预约和队列空间决定|
|FRF|默认两个独立 5 位读地址+FLEN 数据，一写地址/数据/使能|复制两份 32×FLEN 分布式 RAM，写广播；3R 配置复制三份|
|FMA 第二拍|rs3 地址、锁存的前两源、tag|2R 的第 1 拍读 rs1/rs2，第 2 拍读 rs3；该拍不再接受下一 FP，允许无关整数执行|
|整数源/结果|FCVT/FMV 的 x 源数据；转换/比较/FCLASS 的 x 结果、rd、tag|共用槽 0 的整数读口/写回域；FRF 的 fN 与 xN 不应共享记分牌索引|
|完成|valid/ready、tag、rd/domain、FLEN 数据、5 flags、完成状态|FP load、短运算、FMA、DIV/SQRT 仲裁一个 FP 完成写口；按年龄预约/排队|
|提交|tag、commit、flags OR/CSR 操作、目的写使能|每拍至多一个 FRF 写；与一个无冲突整数提交可并行；fflags 只在该指令退休时更新|
|访存|地址、size、store data、load data、beat、tag、正常 LSU fault|地址来自整数 RF/AGU；FSW/FSD 数据来自 FRF；与整数共用一 LSU，D 两 beat|
|取消|冲刷边界 tag、取消/有效状态|结果只在有效 tag 下提交；清掉年轻项和对应记分牌；长单元不要求全流水停钟|

记分牌跟踪两个寄存器域的 RAW/WAW；源在读取时捕获，未读取 rs3 不能被更年轻写
覆盖。组内不配 RAW/WAW；FP 与独立整数 ALU 可同组，FP 转整数结果相关指令等待。
FP 访存与任何另一个访存不能同拍发射。比较/转换写 x 时占用槽 0 的整数写口，
与整数完成冲突需要在整数写回域排队，不能偷增 RF 端口。

仅有记分牌而无提交缓冲不能实现精确异常：长 FP 前的年轻整数/访存可能已经完成。
建议共用 C2-I 的 16 项顺序完成/提交跟踪，FP 数据以 tag 保存在分布式 RAM，
数据完成可被消费者转发，架构 RF、CSR 和 store 副作用按序提交；年轻结果可丢弃。
若 C2-I 选择更小提交窗口，模型提供 4 项敏感度。模型不另假定无限 ROB。
FRF 写在提交时发生；FP 完成数据 RAM 另有一个仲裁写口，其 2 个源转发读副本加
1 个提交读副本共 3 份。旁路标签比较/选择必须切拍并由 C2-I 对齐整体源就绪定义。

长除法/开方自身不锁住整数发射；无关整数可填充提交窗口，窗口满后仍会等待队首。
“不阻塞整数流水”不能解释成无限量年轻指令绕过顺序提交。访存故障、分支冲刷和
中断边界由整数核负责；FP 不另加超时、重试、故障兜底或私有异常路径。

### 2. 结构资源估算

运行 `python3 tools/cpu/eval/fpu_resources.py` 可重算。输入 p=24/53，
`W=3p+5`，`k=ceil(log2(W))`，`h=ceil(log2(p))`；一个 barrel 的每个
可选移位级按每位一个 LUT 的保守逻辑计数，不是器件映射后的 LUT6 结果：

```
L(p) = 2Wk + 3ph + 6p + 3W + p + 600 + 6(p+4) + 6p
Q(p) = (ceil(W/36)+3)W + 5p + 256 + 3(p+4) + 128
```

L 的项分别为两个完整对齐/规格化移位器、三个输入归一化、前导零树、加减/符号、
舍入、控制/转发选择、SRT 迭代器、分类/转换/符号等简单操作。600 是控制和
转发 mux 的开发估算输入，256/128 是有效/tag、控制及接口寄存估算输入；
Q 的 `(ceil(W/36)+3)W` 是分片加法与三级规格化寄存，
5p 是输入、短路径和舍入寄存。
本模型只适合架构量级比较，尚未逐位网表计数；建议资源留出约 ±40% 估算区间，
不能用作确定面积或 CLM 装填承诺。APM 外部对齐 FF 另按上文准确求和加入。

无 FPU 为 0；F 为 L(24)、Q(24)+48；F+D 为 L(24)+L(53)、
Q(24)+Q(53)+48+2284；保守相加，未预扣共享控制逻辑。
以下不含 C2-I 基础核、cache 或共享整数提交队列。

|配置|逻辑 LUT 估算|CLM FF 估算|APM|分布式 RAM 物理/逻辑 bit|LUTRAM 单元估算|
|---|---:|---:|---:|---:|---:|
|无 FPU 增量|0|0|0|0/0|0|
|F|2749|1098|2|11200/3824|175|
|F+D|8450|5514|14|21440/7408|335|

FRF 存储位数（含复制）为 `2×32×FLEN`；16 项 FP 完成数据+flags 的三个读副本为
`3×16×(FLEN+5)`。按每个深度≤64、宽 1 的副本占一个 64×1 LUTRAM 单元保守
估算，单元数 `2×FLEN+3×(FLEN+5)`，物理 bit=单元数×64；保留深度不足造成的
打包浪费。真实 Pango 分布式 RAM 的形状/打包由 PDS 确认。逻辑 LUT 列不含 RAM
单元；若按总 LUT 位置粗加，F 为 2924、F+D 为 8785。3R FRF 再加 FLEN 个
LUTRAM 单元（S 32、D 64），无需复制写口。

现有 C2-I 基础核若为 `(L_I,Q_I,A_I,R_I)`，总资源就是基础核加上相应增量。
目前尚无 C2-I 定版资源，不能把上述表伪装为完整 CPU 的测量。D 的 2284 个
级联外部 FF 是主要代价，未来可以评估用分布式 RAM 实现固定延迟，但本表未
预扣未实现的节省。F-only 是 CLM 紧张时的推荐默认构建。

### 3. 软件负载与复现

```
. ~/.local/opt/edrv32/env.sh
python3 tools/cpu/eval/fpu_model.py
python3 tools/cpu/eval/fpu_resources.py
python3 tools/cpu/eval/fpu_eval.py run
# 已保留 ELF/Spike trace 时，只重跑周期估算：
python3 tools/cpu/eval/fpu_eval.py measure
```

脚本串行构建、串行 Spike、串行重放，不并行启动重进程。本次在本机完成，无需
sim-vm。原始 ELF、命令、反汇编、Spike log、size、JSON 与表格均放
`build/c2f/<负载>/<soft|F|FD>/`，汇总为 `build/c2f/results.json`、`table.md`，
生成物不入库。工具为 xPack GCC 15.2.0，Spike 的版本另记录在负载 README。

编译选项：`-O2 -std=c11 -Wall -Wextra -Werror -ffp-contract=fast
-fno-math-errno -ffreestanding -ffunction-sections -fdata-sections`，
`-nostdlib -Wl,--gc-sections -lm -lc -lgcc`。不启用 fast-math，不重排浮点加法；
允许 GCC 合成 FMA。ISA/ABI 为 `rv32im/ilp32`、`rv32imf/ilp32f`、
`rv32imfd/ilp32d`，三者都附加启动/控制所需的 Zicsr/Zifencei。链接使用对应
multilib。Spike 在 M 模式、从 0x80000000 启动，32 MiB RAM；启动设置 FS，
硬浮点版清 fcsr；计时区间为 start_time 入口（含返回）到 stop_time 入口，不含数据初始化。

|负载|规模与内容|
|---|---|
|matrix_s / matrix_d|16×16 矩阵乘，三重循环，分别 float/double；初始化在计时外，4096 次乘加|
|whetstone_s / whetstone_d|Netlib Rich Painter v1.2 Whetstone，LOOP=1、II=1；保留模块 2/3/4/6/7/8/9/11，原版本模块 1/10 的循环数就是 0；保留函数和数学库调用；sqrt 使用显式 GCC builtin|
|vertex_s|64 顶点，各一次 4×4 矩阵乘向量、法线长度/归一化、光照点积与钳零；包含 FSQRT/FDIV|
|physics_s|64 粒子×3 分量×16 时间步，弹簧力+阻尼的半隐式 Euler：先更新速度再更新位置|

Whetstone 源自 [Netlib 原程序](https://www.netlib.org/benchmark/whetstone.c)，
保留整个许可注释，移除命令行、打印与墙钟校准，改用固定次数与 volatile 输出
保留模块计算；float 版使用 float 字面量及 sinf/cosf/atanf/logf/expf；sqrt 用
`__builtin_sqrtf` / `__builtin_sqrt`，在硬浮点版直接生成 FSQRT，软浮点版调用库。
模块间输出参与 volatile sink，避免因为移除打印而把模块整体消掉。这里不发布
标准 MWIPS 分数，只比较相同改编源码的三版 trace。数学函数由 xPack newlib
提供，F 配置的库可能含软件 double，不能把它等同于全部都是单精度运算。

### 4. 周期模型口径

独立 `fpu_model.py` 不导入/修改 C2-I 的 `pipe_model.py`，借鉴其 Spike 实际指令
流、寄存器相关性和结构占用的重放思路。本模型：

- 顺序双发射，槽 1 仅 ALU；分支/跳转结束当前发射组；组内 RAW/WAW 不配。
- 两个寄存器域，ALU 1、load 2、D load/store 3 拍且 LSU 占两拍，整数乘法
  4、整数除法 34 拍且阻止整数继续发射；表内各 FPU 延迟照前文。
- 16 项顺序提交跟踪，每拍最多 2 条且最多 1 个 FP 目的写；FP 完成结果先写
  一端口结果 RAM，再按序提交 FRF；源可从完成结果转发；完成写口冲突延后可用时间；整数结果按发射槽预约原有写口，转换共用槽 0 写口。
- FMA 默认 2R 多 1 拍并占两拍 FP 读入口，第二拍仍允许整数；D 宽算术 II=4。
- 1024 项 PC 索引二位饱和预测器，初值弱不跳，预测错误增加两拍；JALR 固定两拍
  重定向，JAL 无额外跳转损失。不模拟 BTB/RAS、取指分组和真实预测器训练时序。
- L1 全命中，无 I$/D$ miss、总线争用、TLB、数据值相关的特殊值提前完成、
  wrong-path 执行；访存假定理想 store-to-load 转发、不加地址别名停顿；
  也无图形 API/驱动/完整 GLQuake 软件栈。

这不是 C2-I V5 的完整周期模型，绝对 IPC 不能与其结果直接对比；同一口径的
soft/F/FD 比值用于架构排序。通过 Spike trace 得到正确执行路径不意味着本模型
已经验证 IEEE 算术；数值正确性需要下述 SoftFloat/TestFloat 计划。
结果尾端预约和写回冲突均已计入，不能仅用动态 FP 指令数乘平均延迟替代。

### 验证方案草案
