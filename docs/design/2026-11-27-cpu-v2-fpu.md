# CPU v2 可配置浮点单元设计与周期模型（C2-F2）

## 背景和问题

第一版 `84c6bb7ff` 用每拍三层 LUT 加一段 36 位 carry，S ADD/MUL/FMA 为
8/10/14 拍，D FMA 30 拍。第二版按 C2-I `ba4afff65` 第 3 节的 PDS 样本重新
建模；工作起点为 `069f00855`，交付提交包含本记录与 `tools/cpu/eval/fpu_*.py`。
所有流水、周期、加速比、面积与频率均为**估算**；ELF 大小、Spike 路径和动态
指令数为软件测量。本记录不改 `cpu-spec.md`，不实现 RTL，不宣称已完成 IEEE
算术验证或 150 MHz 收敛。

## 约束

- 时序校准只读调用 `v2_estimates.py`：`q=0.742ns`、`Hff=1.191ns`、
  `ADD32=1.259ns`，每段另加 0.450ns。规划段上限 6.25ns，保留 C2-I 的
  5% 整片频率余量，拥塞压力情景仍可能只有 135MHz。
- 普通段 `T=Hff+n×q+carry(w)+0.450`；`carry(w)=ADD32+
  (ceil(w/4)−8)×0.090`。后式是把样本四位进位组外推到其他宽度的**假设**，
  不是实测宽链时序；77 位 carry+3 普通级为 6.206ns，84 位 carry+2 级
  为 5.554ns。不能把 LUT 级数减少直接解释为整个 FPU 延迟减半。
- APM→本地 FF 含余量为 5.323ns；APM 内部级联未被 CPU 样本校准。
  下表用 5.323ns 作 APM 寄存阶段的规划代理，必须另测 X/Y 输入 setup、
  MULT/P/CPO 和连续站点级联。不能从该代理推出内部时序已经通过。
- 槽 0、独立 FP RF、默认 2R1W/满配 3R1W、单 FP 写口、顺序提交、
  FLD/FSD 两 beat，采用 C2-I 已确认接口。整数-only 四项队列；含 FP 评估
  8/16 项共享完成队列，数据用 LUTRAM，控制用 FF。
- 表中本体延迟从已捕获最后一个源起到本地完成数据可转发；2R FMA 额外一拍
  捕获 rs3，按调度加一次。不是在指令总延迟之外重复加拍。

### ISA 范围与软件契约

采用 RISC-V F/D 2.2，RV32，不附加 Zfh、Zfa、Zfinx 或 RV64 指令。
参考 [F 官方定义](https://docs.riscv.org/reference/isa/v20260120/unpriv/f-st-ext.html)
及 [D 官方定义](https://docs.riscv.org/reference/isa/v20260120/unpriv/d-st-ext.html)。

|范围|设计中包含的行为|
|---|---|
|状态|f0–f31，F 为 FLEN=32，F+D 为 64；fcsr=frm[7:5]+fflags[4:0]；NV/DZ/OF/UF/NX 粘滞累计；CSR 读改写按指令顺序|
|舍入|RNE、RTZ、RDN、RUP、RMM；rm=111 采样已提交 frm；静态 rm 同样支持；精确操作不凭空置 NX|
|特殊值|硬件处理输入/输出 subnormal，渐进下溢，舍入后检测 tininess；±0、±∞；算术 NaN 结果规范化为 S 0x7fc00000 / D 0x7ff8000000000000；sNaN 的 NV 按指令定义|
|FMA|FMADD/FMSUB/FNMADD/FNMSUB 的 S/D，完整乘积与加数相加后只舍入一次；不能用 FMUL+FADD 替代；0×∞ 即使加数为 qNaN 仍置 NV|
|算术|FADD、FSUB、FMUL、FDIV、FSQRT，S 与启用 D 时的 D|
|最值/比较|FMIN/FMAX 按 2.2 的 minimumNumber/maximumNumber；单 NaN 返回数值、sNaN 置 NV；−0 小于 +0；FEQ 仅 sNaN 置 NV，FLT/FLE 遇任意 NaN 置 NV，结果写整数 RF|
|分类/符号|FCLASS 十类；FSGNJ/FSGNJN/FSGNJX，不做算术舍入、无浮点异常；保留转移/符号指令规定的 NaN payload|
|转换|FCVT.W[U].S、FCVT.S.W[U]；D 配置加 FCVT.W[U].D、FCVT.D.W[U]、FCVT.S.D、FCVT.D.S；越界/NaN 的整数结果和 NV/NX 按 ISA；不包含 RV64 的 L/LU 转换|
|位搬移|FMV.X.W / FMV.W.X 保留低 32 位编码；RV32 D 没有 FMV.X.D / FMV.D.X，不额外发明指令|
|访存|FLW/FSW；D 加 FLD/FSD；FLW/窄结果写入高 32 位全 1；FLD/FSD 原样搬移 64 位；32 位 LSU 拆成低地址字、再高地址字两个 beat|
|NaN-boxing|D 配置的窄非搬移运算（含比较、分类、符号注入）检查高 32 位全 1，否则视作 canonical NaN；窄结果上部填 1；FSW、FMV.X.W 的位搬移保留低位，不能误套算术 boxing 检查|
|配置与特权|无 FPU 时不暴露 F/D/浮点 CSR；F 配置不暴露 D；mstatus.FS=Off 的非法访问和 FS Dirty、上下文保存由整数核/特权集成负责；浮点数值异常只置 flags，不陷入|

rm/frm 保留编码的处理、复位 FS 状态以及 FLD/FSD 的自然对齐要求要由协调者写入
未来规格；建议保留舍入编码触发非法指令，访存沿用 CPU 的自然对齐异常。
这是待确认建议，不在此记录中新增架构规定。FLD 两字全部返回后才提交结果；
FSD 两 beat 是一条指令，不能在中途退休/响应中断。32 位总线不承诺 64 位
访存原子性；第二 beat 访问故障的可见副作用遵从总线/CPU 的访存异常契约。

计入外部 FF。表中 APM=1 表示该拍位于内部流水，非“一拍只用了一个 APM”；
完整 S/D 链仍为 2/12 颗，不能压缩专用链本身的 N+2 拍数。

并行支路也要切拍：S 加数 C 的指数比较在 E2 准备，7 层对齐在 E3/E4
按 3+4 级流水，等待完整乘积；D 在 E2 准备指数控制，8 层对齐在 E3/E4
按 4+4 级流水；每段≤6.093ns。S 的 77 位 LZA 树在 E6 并行分组、E7 最后
两级归约与四层移位；D 的 164 位 LZA 分组跨 E16/E17，E18 最后两级与
四层移位。LZA 不串到最终长 carry 之后；校正最多一位并入后级选择。
MUL 高位选择/下溢处理采用同一尾端。完整低积保留到舍入，远小加数才压为
sticky；精确消去和 subnormal 不陷入软件。

D ADD 的对齐最后两级与 57 位有效加减合并，LZA在同拍并行分组，
尾端第一拍最后两级LZA加四层移位，第二拍移位两层，第三拍舍入；
D MUL采用同一三拍尾端（移位4+2、最后舍入），所以是18拍，D FMA 的加减按低 84/高 80
切开，低位等待高位结果，carry 状态随 tag 传递。比较的 64 位大小关系由
高/低 32 位并行比较后归约，不能串成两条 carry32。
转换以最慢方向预算，S/D 分别 3/4 拍；窄整数→D 等可提前计算但本模型不计。
分类、min/max、比较两拍，符号注入和位搬移一拍；D boxing 与特殊值选择在
所列普通级预算内，必须在真实映射时核对。

|MUL 旁路|7|18|1；D 保守4|S 1 / D 4|

D 算术 II=4 仍为保守调度输入，APM 全寄存链理论 II=1，模型同时给出
`parallel_d` 的 II=1 敏感度，资源不假设因 II=4 自动减少。
ADD/MUL/FMA 共享各精度尾端入口，S 两拍、D 三拍，按入口周期预约，冲突反压；
流水尾端每拍接受一个结果，并不是整个尾端必须空两/三拍才能接收下一条。
短操作有独立组合流水，完成仍竞争一个 FP 写口。
统一 FMA 方案把 ADD/MUL 也走 8/20 拍（2 源指令不加 rs3 捕获周期）。
独立 ADD 方案只解除尾端冲突，不增加槽 0 发射宽度。

FADD 等效 a×1+b、FMUL 等效 a×b+0 仅描述数值结构；NaN、零符号和 flags
仍按原始 opcode 判定，不能把普通 FMA 的异常判定直接套给 ADD/MUL。

### 2. 24×24 与 53×53 的 APM 分块

正尾数在 X 端按 24 位切块，Y 端按 16 位切块，各块补零进入有符号端口。
`a=Σai·2^(24i)`，`b=Σbj·2^(16j)`，每项权位 `e=24i+16j`。
按 e 排序，链头 `C0=a0b0`，后继 `Ck=ai·bj+(C{k−1} >> Δe)`；
把前一 C 的低 Δe 位延迟后拼接到结果，不用 CLM 加法树。

|精度|X 块 / Y 块|项的权位次序|APM 数|输入到完整乘积|II|
|---|---|---|---:|---:|---:|
|S，p=24|24 / 16+8|0,16|2|4|1|
|D，p=53|24+24+5 / 16+16+16+5|0,16,24,32,40,48,48,56,64,72,80,96|12|14|1|

D 的 e=48 按 a2b0（5×16）、a0b3（24×5）排序，两项之间需要 **Δe=0**，不能误接 shift8。厂商模型 `MODEZ[2:0]=011`
直接选择 CPI，配置 MODEZ=3；后续需要新增固定直通级联包装，本次不写 RTL。
其他差值仅为 8/16，使用已有模式；头部 MODEZ=0。48 位后加器必须保存未舍入
部分积；单项小于 2^40，重复权位求和亦小于 2^47，不发生有符号溢出。
符号在外部单独处理。最终得到完整 48 / 106 位积。

N 项全寄存链延迟 N+2；第 k 项操作数错开 k 拍。保守保留全部 CLM 延迟寄存：
`FFalign=Σ k(wxk+wyk)+Σ Δek(N−1−k)`。
S 为 32+16=48 FF，D 为 1708+576=2284 FF。这里不把 APM 内部寄存误计为 CLM。
`fpu_resources.py` 用固定种子和极值验证 2006 个无符号完整乘积，包括 Δe=0；
这是整数分块模型验证，尚不是 CPU 浮点 RTL 与厂商原语逐拍等价验证。

### 3. 除法/开方与 D 复用

独立 radix-4 digit recurrence：`L=ceil((p+3)/2)×c+overhead`。
S：p=24,c=1,overhead=5，得到 14+5=19；D：p=53,c=1,overhead=7，
得到 28+7=35。准备 2 拍；最后余数修正、规格化、舍入 S3/D5 拍。
57 位余数进位链并不天然要求两拍，新预算容纳 carry57+3 级逻辑 5.756ns，
所以第二版允许 D 每拍一轮。前提是 digit selection、部分根选择和符号修正
总共不超过三层普通逻辑；这是最需验证的设计假设，超过后应重切并重跑模型，
不能保留 35 拍数字而偷偷增加组合深度。S recurrence 为 carry28+4 级，5.778ns。
该迭代结构仍用 `6(p+4)` LUT、`3(p+4)` FF 估算，不使用 APM。

Newton 为比较方案：8 位种子，S 两轮/D 三轮，内部至少 p+3 位且有精确
residual/末位校正。S 27×27 需四颗 APM；反馈内部 FMA 估算 11 拍，D 56×56
需十二颗 APM、内部 FMA 21 拍。DIV 为 `6×11+5=71` / `8×21+7=175`，
SQRT 为 `8×11+5=93` / `11×21+7=238`；种子两张256×12共6144bit（1 DRM）。
内部反馈不读 RF；不是反复执行标准舍入指令就能保证正确舍入。虽比初版缩短，
仍远慢于 19/35 拍，并占据对应 FMA，推荐独立 recurrence。

|FD 微架构|S ADD/MUL/FMA|D ADD/MUL/FMA|D II|逻辑LUT/FF/APM 增量（8项，含集成）|
|---|---|---|---:|---|
|统一 FMA|8/8/8|20/20/20|4|8882 / 4441 / 14|
|共享尾端旁路|5/7/8|6/18/20|4|9282 / 4633 / 14|
|额外独立 S ADD|5/7/8|6/18/20|4|10198 / 4906 / 14|
|只保留宽 D FMA，S 嵌入 D|20/20/20|20/20/20|1|6533 / 3766 / 12|
|D 串行复用 S 两颗 APM|5/7/8|45/45/45|36（乐观）|9282 / 2551 / 2|

上述都另有576个LUTRAM单元（结果多读复制口径）。统一省每精度200LUT/96FF；独立ADD加
`floor(L(24)/3)=916 LUT`、`floor(Q(24)/3)=273 FF`，是设计输入而非测量。
宽通路省2749LUT/867FF/2APM，但 S 被拉长到20拍。串行 D 估算12项×3拍，
连同前后处理和控制约45拍，II36是乐观可重叠尾端下界，阻占 S 核入口；
保留 D 的宽移位、累加和舍入，不能把 L(53) 直接删掉。外部级联对齐2284FF
替换为106位累加+96位残数寄存，故只省2082FF。推荐独立 S 快路径+D 扩展，
两者共享 RF、入口和提交，而不复用 S 的乘法资源。
串行D只是一个具体参考排程，不代表两颗APM复用的最优延迟；理论部分积
发射下界为6次，但并行部分积的宽累加、残数及S/D切换仍需另做结构设计，
不能把该下界直接记为6拍D FMA。

## 决策

设计推荐仍为 **NONE / F / FD 三种构建，F 默认面向图形，FD 可选一般计算**。
算术采用 FMA 核心加 ADD/MUL 旁路、共享尾端、独立 radix-4 DIV/SQRT；
默认 2R1W，满配 3R1W。以下负载数据决定队列推荐与旁路价值，均是待协调者
评审的设计建议，不新增规格或 RTL 配置参数。

### 1. 接口、完成队列和周期计数

槽 0 接 FP 算术/访存/转换；槽 1 只配独立整数 ALU。FMA 2R 先读 rs1/rs2，
次拍读 rs3，两个源在入口锁存，该拍可执行独立整数但不再读新的 FP；3R 无此
捕获相位。整数转换/比较共享槽 0 整数写口，槽 1 保留原写口；两个寄存器域
各自记分牌跟踪 RAW/WAW，同组相关指令不配。

完成队列是 **全核共享顺序队列**，8/16 项替换整数-only的4项FF记录；
NONE 的四个FF记录独立写入，不能给它施加迁移后LUTRAM两bank的伪争用。不是再增加一份
FP 专用队列。顺序 tag 的奇偶决定两个 bank，各 bank 单写；完成 bank 冲突时
保留较年轻源结果，本模型按年龄预约完成周期。PC与结果按完整队列记录在完成时写入，无rd的branch/store也预约bank写口，
不允许与较老结果同bank双写；定向回归覆盖branch PC与load结果的碰撞。
FP load 和算术同时还竞争单 FP
完成写口；每拍退休最多两条且最多一个 FP 目的写。结果本地捕获后可转发，
架构 RF、fflags、store 副作用按序提交，冲刷按 tag 取消年轻项。队列满反压最老
未发射指令；不允许年轻指令绕过，也不假定无限窗口。
数据 RAM 的写入/提交读/源转发采用 C2-I 的 mux/捕获预算并补足下文确认的结果读取副本，不能把深队列
异步读直接接 EX。此处假设读选择与捕获能含在所列末级/整数流水预算内，
没有额外增加消费者拍；若 PDS 需要额外读取拍，必须重跑 RAW/队列评估。

`C_total=C_integer+源捕获/结构等待+依赖等待+写回竞争+FD额外beat`。
脚本返回 `components`，五项按**实际日程互斥计数**：

- `integer`：实际发射组（FP 指令也占组）、重定向、普通整数相关/除法与最后
  drain 的基本周期；这是当前 trace 的整数流水部分，不是另跑软浮点的总周期。
- `structure`：零发射周期中队列满（含未提交 FP）、两读口捕获占用、单元或
  共享尾端预约、CSR 等待 FP 排空；有独立整数实际发射时不再收取同拍等待。
- `dependency`：零发射周期中未完成 FP 源/目的造成的 RAW/WAW，以及 FP
  队首最后 drain；2R 源捕获延迟也通过实际 ready 传播到后续依赖。
- `writeback`：数据已算出而所需结果尚因单写口/bank 冲突不可用的零发射周期。
  多个写口冲突但被其他执行覆盖时不重复加周期。
- `fd_beat`：第二 beat 占用 LSU 的零发射周期，或完整 FLD 最后一拍阻止使用。
  阻塞原因同时存在时按当前最老指令的队列/依赖/读口/单元检查顺序归属，
  所以分项取决于约定，但总和恒等于重放实际周期，不是独立最坏值之和。

FLD/FSD 在32位LSU占两拍，FLD结果3拍可用，S load2拍；只有两字齐全才能
使用。64位数据保持原样；两个 beat 精确异常及跨行提交需后续接口规格冻结。
分支1024项两位计数器初值弱不跳、错预测/JALR额外2拍，ALU1、整数乘4、
整数除34且暂停整数发射。L1全命中，无别名、I/D miss、wrong-path 执行、
BTB/RAS或真实取指分组，不能将 IPC 当 C2-I V5 完整核的 IPC。
本次补充含FP配置共享队列两个 bank 的完成冲突，NONE 基线用4项独立FF，
因此与第一版的
16项基线和没有bank冲突的绝对周期不能只按延迟变化作差。

### 2. 资源公式（全部为结构估算）

令 p=24/53，W=3p+5，k=ceil(log2 W)，h=ceil(log2 p)。
保持第一版组合结构计数；新切拍只减少外部流水寄存，不按逻辑深度减少 LUT：

```
L(p)=2Wk+3ph+6p+3W+p+600+6(p+4)+6p
Q(p)=(ceil(W/84)+2)W+5p+256+3(p+4)+128
```

L 各项为两宽移位器、三输入归一化、LZ树、加减/符号、舍入、控制/转发、
DIV/SQRT、短操作。Q 为分片加法与两级规格化载荷、输入 C/短路/舍入/源捕获
等5p寄存、tag/控制256、迭代3(p+4)、接口128；5p不是再复制 APM X/Y。
L(24)/Q(24)=2749/819；L(53)/Q(53)=5701/1476。
APM外部对齐寄存为48/2284；内部寄存计0个CLM FF。资源约±40%量级，
未逐位网表计数；5p与控制常数需要实际模块映射后替换。

FLEN=B，队列N，读口R（默认2）：

```
RF LUTRAM = R×B；逻辑位 = R×32×B
结果副本 M=R+1（R 个源读取 + 1 个提交读取）
共享队列 LUTRAM = 2×(M×B+32)；逻辑位 = N×(M×B+32)
队列选择/仲裁 LUT = 6×(B+32)
队列控制 FF 增量 = 18N+32−4×77
FP 记分牌 FF = 32×(1+ceil(log2 N))
FP 记分牌/标签选择 LUT = 32×(1+ceil(log2 N))+10N
浮点 CSR 增量 = 48 LUT + 10 FF（fcsr8 + FS2，SD组合生成）
```

18N=目的rd5+原控制8+fflags5；32为局部控制副本；原4×77FF包含旧数据和
控制，迁到RAM后整体扣除，不能再保留旧队列并重复扣。选择预算沿用 C2-I，
不扣旧四项选择逻辑；FP记分牌/tag比较为此任务另计。CSR不包含已在整数核的
异常控制、mstatus其余位或额外HPM；frm采样/flags提交选择包含48LUT预算。

两个bank每个深度N/2，每位保守占一个64×1 LUTRAM（即N=8与16的物理单元
数相同），RF每个读副本每位占一个单元。物理容量=64×单元数；真实CLMA打包
待PDS。共享队列已存FP结果/flags，不再另加第一版的三副本FP结果RAM。
3R比2R再加3B个LUTRAM：RF增加B、队列两bank各增加B；逻辑位再加
32B+NB，不增加写口。2R F/FD 比 C2-I 单结果副本上侧预算额外加128/256
LUTRAM；3R额外加192/384。PC每bank只一份，flags与控制保持FF。
这是协调者在C2-F2问答确认的保守多读复制口径；不能把C2-I的单副本预算
用于任意项转发而漏掉读取端口。输入转发mux与tag选择包含L(p)的600控制
预算及独立记分牌选择预算，仍待映射核对。

|配置/队列|增量总LUT/逻辑LUT|增量FF|增量APM|LUTRAM/逻辑bit|增量CLM|CPU LUT/FF/APM/CLM|
|---|---:|---:|---:|---:|---:|---|
|NONE/4|0/0|0|0|0/0|0|8789/5155/4/3139|
|F/8|3709/3389|873|2|320/3072|1325|12498/6028/6/4464|
|F/16|3821/3501|1049|2|320/4096|1365|12610/6204/6/4504|
|FD/8|9858/9282|4633|14|576/5888|3521|18647/9788/18/6660|
|FD/16|9970/9394|4809|14|576/7680|3561|18759/9964/18/6700|

增量总LUT含LUTRAM，逻辑LUT不含；总LUT=逻辑LUT+LUTRAM，一次计数。
`CLM=ceil(max(LUT/4,FF/8)/0.70)`。增量CLM是单独对增量套公式，CPU总CLM
是对整体重算，不能把局部取整简单累加。CPU列加只读调用
`v2_estimates.estimate('V5-default')` 的8789LUT/5155FF/4APM，DRM仍18。
NONE为基础核，不含FP状态；F/FD均包含RF、队列替换、记分牌与CSR。
N8→16增加112LUT和176FF：队列控制144、记分牌32，数据逻辑容量增加但上侧
物理LUTRAM不变。C2-I若调整基础核，脚本会重算CPU列，增量公式不变。

### 验证方案草案

参考 [Berkeley SoftFloat 3e](https://www.jhauser.us/arithmetic/SoftFloat.html) 与
[TestFloat](https://www.jhauser.us/arithmetic/TestFloat-3/doc/TestFloat-general.html)，
SoftFloat 设置 tininess-after-rounding；包装 RISC-V canonical NaN、FMIN/FMAX、
比较、位搬移/boxing 和 CSR 语义，不能直接把通用 IEEE 库行为当全部 ISA 行为。
Spike 做逐条架构参考，未来 DUT trace 同时比较指令、rd/domain、原始结果位、
本条 flags、累计 fcsr、异常、FS 状态及访存副作用。riscv-arch-test 运行仓库
`third_party/riscv-arch-test` 的 RV32 F/D 测试；实际目录/版本以开发时选定基线为准。
