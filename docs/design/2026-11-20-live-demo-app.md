## 1. 背景和问题

用户 2026-11-20 提出三点：

1. 决赛现场要在多个应用之间来回切换。希望做一个"现场演示"应用，把各场景串起来，放在首页最上方，替换原来的两张场景卡（"智能视觉 · 检测计数"和"体感积木"）。
2. 摄像头画面有时偏暗，识别不准。用户在图像处理里调高亮度和对比度后，画面变亮了。
3. 希望在 YOLO 识别前加少量固定的前处理选项（例如去噪、亮度），用来体现我们能对摄像头输入做前处理。不需要像图像处理应用那样任意编辑。

查到的现状：

- NPU 输入由 VIN CH2 从所选源的原始像素流取得，不经过 PIX（`vin-spec` 2.8）。所以图像处理应用里调亮度，只改变显示画面，不改变 NPU 输入。
- OV5640 自动曝光的稳定窗口是 `0x3a0f/0x3a10 = 0x30/0x28`（`sw/drivers/ov5640.c`），目标亮度偏低。
- VIN 每个通道可以独立选择输入源（`vin-spec` 2.4）。图片识别应用已经在板上用过"内存源 → CH2"这条通路。

## 2. 约束

- 不改 RTL，不重新生成 bitstream：沿用卡 75 的比特流。
- 前处理只能用现有硬件：PIX 的亮度/对比度、Gamma 和两级 3×3 滤波，再加 VIN 内存源。
- 现场必须有不依赖手机的切换方法：用 PC 调试工具操作。
- 演示控制只交给 PC 和手机。电脑屏幕要留出来放海报或 PPT，所以 PC 工具不能长期占着前台。

## 3. 可选方案

### 3.1 前处理接入 NPU 的方式

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| A 内存源回环 | 摄像头 → PIX → CH0 写入 Surface；该帧完成后，用 VIN 内存源读回这张 Surface，送 CH2 → NPU | 只改软件；屏幕显示的就是 NPU 看到的画面 | 识别延迟多约一帧；DDR 每帧多读 1.8 MB（30 fps 时约 55 MB/s，估算 = 1280 × 720 × 2 B × 30） |
| B 改 RTL，让 CH2 接在 PIX 之后 | VIN 增加 CH2 的选点 | 没有额外延迟 | 要改规格、仿真、PDS 和时序，风险大 |
| C 只调 OV5640 的 ISP | 改传感器的 AEC 目标、SDE 亮度/对比度和去噪 | 最简单 | 用的不是我们自己的硬件，体现不出自研 |

### 3.2 场景切换的控制方式

| 方案 | 优点 | 缺点 |
|---|---|---|
| 板上按键回目录 | 不依赖网络 | 板上只有 4 个键，各场景页面都在用；每次切换要按两下 |
| PC 调试工具 | 已经有网口通路 | 占用电脑屏幕 |
| 手机 → PC → 板 | 队友手里的手机本来就是遥控端；电脑屏幕可以留给 PPT | 需要 PC 和手机之间新建一条连接 |

### L2 现场演示应用

- 首页最上方原来的两张场景卡，换成一张"现场演示"卡，占满整行。
- 进入后是"演示目录"页：

  - 显示当前前处理档位和画面亮度（L4）。
- 在目录里选中一个场景，按确认进入，打开对应的现有页面。
- 演示模式下：
  - 场景页顶部有一条横幅，例如"现场演示 · 第 2 章 落地应用 · 安全帽检测 4/10"；
  - 在场景里按"返回"，回到演示目录（不是首页），目录自动选中下一个场景；
  - 在目录里按"返回"，回到首页，退出演示模式。

- 返回的细则（worker 提问，协调者 2026-11-20 确认）：各场景页，包括图形引擎和抓取实验等自定义按键页，先按现有规则关闭抽屉、退出控件编辑；之后按“返回”直接回演示目录，不先退出页面内部的页签。页面退出时 benchmark 自然停止。
- 场景页保持现有功能。演示应用只负责切换顺序、横幅和返回规则，不复制页面代码。

### L3 手机 → PC → 板的控制链路（用户确认：按钮放在手机遥控端；PC 必须能单独操作）

网络连接：

- 手机打开热点，平板和 PC 都连到这个热点。
- PC 另用有线网卡连开发板（`192.168.1.2` ↔ `192.168.1.10`，不变）。

**EDSC 新命令（PC → 板）**：

| type | payload（4 B） | 说明 |
|---|---|---|
| 0x09 DEMO | `action`(u8) + `arg`(u8) + 2 字节 0 | 见下面 action 表 |

| `action` | 含义 | `arg` |
|---|---|---|
| 0 | 跳到某个场景 | 场景序号 1–10 |
| 1 | 下一场景 | 0 |
| 2 | 上一场景 | 0 |
| 3 | 设置前处理档位 | 档位 0–3（L4） |
| 4 | 回到演示目录 | 0 |

应答规则：

- 先回复 ACK(1)。
- 场景动作（0、1、2、4）何时回复 ACK(2)：
  - 场景 1–5、7、8：页面一打开就有应用运行，应用到达 RUNNING 后回复；
  - 场景 6、9、10：进入页面后还要用户再操作才启动应用，所以到达页面就回复（worker 提问，协调者 2026-11-20 确认）；
  - 目标是演示目录时，到达目录就回复。
- 档位动作（3）在新档位第一次生效的帧完成后回复 ACK(2)。
- 不在演示模式时收到场景动作，先进入演示模式，再执行。
- 演示模式记录“当前场景 k”，即最近一次进入的场景（经目录确认、DEMO 跳转或上一/下一场景进入时都更新）。下一场景 = k+1，上一场景 = k−1，与目录当前聚焦哪一项无关。
- 尚未进入过任何场景时（k = 0，包括不在演示模式时），下一场景进入场景 1，上一场景进入场景 10。
- 下一场景在第 10 个场景时回到第 1 个；上一场景在第 1 个时转到第 10 个。
- 场景序号或档位超出范围时，回复 ACK(3, 2)，不做任何修改。
- 与 APP 命令的关系（worker 提问，协调者 2026-11-20 确认）：
  - APP 打开命令（action 0）会退出演示模式，并把 k 清零；
  - APP 暂停、继续、重试保留演示模式；
  - DEMO 跳到已打开但处于 PAUSED 的同一场景时，先恢复运行，到 RUNNING 后回复 ACK(2)。
- 同类命令仍按 8.2 规则：收到 ACK(2) 或 ACK(3) 之前，PC 不发下一条。

**STATE 和 HELLO**：

- STATE 原第 5–7 字节是保留的 0，现在定义为：

  | 偏移 | 字段 | 类型 | 含义 |
  |---|---|---|---|
  | 5 | `demo_scene` | u8 | 0 = 不在演示模式；255 = 在演示目录；1–10 = 当前场景 |
  | 6 | `preset` | u8 | 当前前处理档位 0–3 |
  | 7 | `luma` | u8 | 最近一次测得的画面平均亮度 0–255；没有摄像头画面时为 0 |

  STATE 长度不变（56 B）。
- HELLO 的 `proto` 从 3 改为 4。工具不接受 proto 3。

**PC 调试工具**：

- 新增"现场演示"面板，包含：
  - 10 个场景按钮，以及上一场景、下一场景、回到目录；
  - 4 个前处理档位；
  - 当前场景、档位和亮度（取自 STATE）。
- REST 新增 `POST /api/demo {action,arg}`；`GET /api/board` 返回值中增加上述三个字段。
- 新增"手机中继"：
  - 在面板里填写手机的热点地址（手机遥控界面顶部已经显示），然后点"连接手机"；
  - PC 主动连接手机的 TCP **47633** 端口，断线后每秒重连；
  - 连接成功后，可以把工具最小化，手机的命令在后台照常转发。
- 中继消息是按行分隔的 JSON：
  - 手机 → PC：`{"demo":{"action":n,"arg":m}}`；PC 收到后发 EDSC DEMO。
  - PC → 手机：`{"board":{"connected":bool,"scene":n,"preset":n,"luma":n}}`；STATE 变化时发送，此外每 1 s 发一次。
  - 格式错误时关闭连接，并在界面上显示原因（与 APK 的 RemoteTransport 一致）。
  - 忙状态（worker 提问，协调者 2026-11-20 确认）：
    - board 消息另带 `"busy":bool`，表示有 DEMO 命令在等待 ACK(2/3)；busy 变化时立即发送。
    - PC 在 busy 期间收到新的 DEMO（来自手机或面板），不排队、不发送，界面显示“同类命令正在等待设备完成”。
    - 手机在 busy 期间把场景和档位按钮显示为禁用，并显示“切换中”。
    - 手柄 pad 不受 busy 影响。

**手机遥控端 APK**：

- 遥控界面增加"现场演示"控制条，包含：
  - 上一场景、下一场景；
  - 场景列表（10 项，点一下直接跳转）；
  - 4 个前处理档位；
  - 板端当前场景、档位、亮度，以及 PC 连接状态。
- **游戏手柄**（用户 2026-11-20 追加，用于 NES）：板端当前场景为 10 时，遥控界面显示虚拟手柄，按键为方向键、A、B、Select、Start、确认、返回。确认和返回用于游戏列表和退出游戏。
  - 手机在按键状态变化时发 `{"pad":{"keys":n}}`，`n` 是 8.5 节虚拟输入的按键位图（bit0…11：上、下、左、右、A、B、Select、Start、Enter、Esc、Next、Prev）。
  - PC 收到后用现有虚拟输入通路发给板端：只填按键，坐标和鼠标为 0；照常按 100 ms 周期重发快照。
  - 手机断开时，PC 清空中继带来的按下状态。
  - 板端不改：虚拟输入已经可以操作 NES。
- 手机在 TCP 47633 上监听 PC，与现有的平板连接（47632）互不影响。
- 平板显示端不变。

### L4 前处理档位（用户确认：固定几档，不能任意编辑）

| 档位 | 名称 | PIX 设置 | CH2 输入源 |
|---|---|---|---|
| 0 | 原始 | 旁路 | cam0（与现在相同） |
| 1 | 自动亮度 | BC_EN，参数由自动增益决定 | 内存源，读回 CH0 当帧 |
| 2 | 降噪 | S1 = 高斯 | 内存源 |
| 3 | 自动亮度 + 降噪 | BC_EN + S1 = 高斯 | 内存源 |

**作用范围**：

- 档位是全局设置，作用于所有用摄像头做识别的应用：目标检测、安全帽、农场、手势、姿态、人脸贴纸，以及各体感游戏。
- 图像处理应用和图片识别应用不受档位影响。
- 档位可以在三个地方切换：演示目录、已有设置抽屉的识别页（在抽屉里新增一行"识别前处理"分段选择；方块工坊、抓取实验、体感游戏、空中画板没有抽屉，不新增）、EDSC DEMO action 3。

**没有 PIX 的 FPGA 版本**（例如 VRN；worker 提问，协调者 2026-11-20 确认）：

- 档位 1–3 不可用：界面上这三档显示为禁用，并标注“本 FPGA 版本无 PIX”。
- DEMO action 3 选 1–3 时，回复 ACK(3, 4)，不做修改。
- 默认档位取 0，界面照常显示当前档位，不停止应用。

**亮度测量**（CPU）：

- 每个 CH0 帧完成后，在这张 Surface 上按 80 × 45 的网格取 3600 个点，计算平均亮度 `Y = (77R + 150G + 29B) >> 8`（RGB565 展开到 8 位，展开方法与 `vin-spec` 2.8 相同）。
- 读取前按 SoC 7.4 和 BSP 接口失效对应的 cache 行。
- 档位 0 时也测量，只用于显示。

**自动增益**（档位 1、3）：

- 用纯增益 `g`：`CONTRAST = round(256·g)`，`BRIGHTNESS = round(128·(g − 1))`。代入 PIX 2.2 的公式，结果等于 `c' = clamp(g·c)`。
- `g` 的范围是 1.0 到 511/256（约 2.0），初值为 1.0。上限受 PIX `BC.CONTRAST` 只有 9 位的限制；原定的 2.5 会溢出，审查时修正。
- 每 4 帧调整一次：
  - 设测得的均值为 `M`，目标为 `T`；
  - `|M − T| ≤ 8` 时不调整；
  - 否则令 `g ← clamp(g · (1 + 0.5·(T/M − 1)), 1.0, 2.5)`，即每次只补偿误差的一半，避免振荡。
- `M = 0` 且需要调整时，`g` 直接取上限（等于 `T/M → ∞` 时 clamp 的极限；worker 提问，协调者 2026-11-20 确认）。
- 这里的 `M` 是增益之后的画面亮度，所以是闭环调节。
- 目标亮度 `T` 为 **[待定]**，初值 110；上板后按识别置信度定稿。

**内存源回环的规则**：

- 档位 1–3：
  - CH0 每完成一帧，若内存源和 CH2 空闲，就对这张 Surface 启动 `MSRC`，CH2 的 `SRC` 选内存源；
  - 若不空闲，跳过这一帧（不排队）；
  - 这张 Surface 在内存源发出 DONE 之前保留引用，不得回收。
- 档位 0 时 CH2 直接选 cam0，与现在相同。
- 切换档位后，从下一个 CH0 帧开始生效。

**界面**：

- 识别页左上角显示一个小标签，例如"前处理：自动亮度 ×1.8 · 亮度 62"。
- 屏幕上显示的是 PIX 处理后的画面，也就是 NPU 看到的画面。

### L5 默认档位（[待定]）

- 开发初值：档位 1（自动亮度）。
- 上板时在暗、亮两种环境下，分别用档位 0–3 跑目标检测和安全帽，比较平均置信度和 fps，然后定稿默认档位和 `T`。
- 降噪会不会降低置信度，以实测结果为准。

### L6 两项默认值（用户 2026-11-20 追加）

### L7 手机镜像板上界面（用户 2026-11-20 选“镜像按钮 + 导航键”）

**背景**：手机只能切场景还不够，例如进入图形引擎或芯片信息后，还得用电脑或板上按键才能开始跑分。用户要求 HDMI 上的全部界面和操作都能在手机上完成。

**要求**：板子把当前页面上能操作的控件列表发给 PC，PC 转发给手机；手机按列表画出对应的按钮、开关、滑块和分段选择，点哪个就操作板上哪个。此外，任何页面都可以用导航键操作。

**板端控件列表**：

- 范围：当前页面默认输入组（`lv_group_get_default()`）中，所有未禁用的对象，包括抽屉里的控件，抽屉收起时也包括。
- 每个控件的信息：

  | 字段 | 类型 | 说明 |
  |---|---|---|
  | `id` | u8 | 在组内的序号 |
  | `kind` | u8 | 0 按钮，1 开关或复选框，2 滑块，3 分段选择或下拉框 |
  | `value` | i16 | 开关取 0/1；滑块取当前值；分段取选中序号；按钮取 0 |
  | `min` / `max` | i16 | 只对滑块有意义，其余为 0 |
  | 名称 | UTF-8，最多 48 B | 取控件内第一个标签的文字；没有标签时，取同一行里控件前面的标签文字 |
  | 选项 | UTF-8，最多 96 B | 只用于分段和下拉框，各选项之间用 `\n` 分隔 |
  | 区域 | u8 | 0 = 页面，1 = 抽屉 |

**EDSC 新消息**：

| type | 方向 | payload | 说明 |
|---|---|---|---|
| 0x89 UI_ITEMS | 板 → PC | `revision`(u32) + `part`(u8) + `parts`(u8) + `page`(u8，`ui_page`) + 1 字节 0 + 标题（u8 长度 + UTF-8，最多 48 B）+ 若干控件 | 页面切换或控件值变化时发送，此外每 1 s 发一次。每条 payload 不超过 1024 B，放不下就按 `part/parts` 分几条发。`revision` 在页面或控件结构变化时加 1，只是值变化时不变 |
| 0x0A UI_ACT | PC → 板 | `revision`(u32) + `id`(u8) + `action`(u8) + `value`(i16) | `action`：0 点击（按钮发 CLICKED，开关切换）；1 设值（滑块、分段、下拉框设成 `value`，并发 VALUE_CHANGED）。`revision` 与当前不一致时回复 ACK(3, 5)。执行后回复 ACK(2)，之后板端发一次新的 UI_ITEMS |

- 执行效果与用板上按键聚焦后操作该控件完全相同，页面代码不需要为此改动。
- 游戏运行中由应用接管输入时（P5 8.5 输入所有权），UI_ACT 回复 ACK(3, 5)。这时手机用导航键或 NES 手柄操作。

**导航键**：

- 手机在所有场景都显示一组导航键：上、下、左、右、上一个、下一个、确认、返回。
- 走现有的手柄通路，即 `pad` 消息和虚拟输入位图（bit8 Enter、bit9 Esc、bit10 Next、bit11 Prev，方向键 bit0–3）。
- 场景 10 照常显示 NES 手柄。

**PC 中继**：

- PC 把 UI_ITEMS 合并成一条，用 `{"ui":{"revision":n,"page":n,"title":s,"items":[{"id","kind","value","min","max","label","options":[...],"area"}]}}` 发给手机。页面或控件有变化时发送，此外每 1 s 发一次。
- 手机发 `{"ui_act":{"revision":n,"id":n,"action":n,"value":n}}`，PC 收到后转成 UI_ACT。
- PC 调试工具的“演示”页也显示同一份控件列表，可以直接点击。

**手机界面**：

- 场景网格保留。
- 下方用两个标签页切换：“画面控件”是镜像列表，分“页面”和“抽屉”两组；“导航”是导航键。
- 场景 10 时，“导航”页换成 NES 手柄。
- 在 907×420 dp 的屏幕上，控件可以纵向滚动，文字不能截断。

### L9 前处理：快捷档 + 高级调节（用户 2026-11-20 选“全套，含传感器曝光”；本节取代 L4 的档位定义和自动增益）

**快捷档**：

| 档位 | 名称 | 内容 |
|---|---|---|
| 0 | 原始 | PIX 旁路，CH2 直接取 cam0；传感器曝光目标恢复默认值 |
| 1 | 暗光增强 | 自动色阶 + 自动 gamma |
| 2 | 降噪 | 滤波 = 高斯 |
| 3 | 暗光增强 + 降噪 | 档位 1 加上档位 2 |
| 255 | 自定义 | 在高级调节里改过任意一项后进入这个状态；选任意快捷档会覆盖全部高级参数 |

STATE 的 `preset` 字段取值 0–3 或 255。DEMO action 3 的 `arg` 只接受 0–3。

**高级参数**：放在识别页抽屉“识别前处理”下的“高级”区，通过 L7 自动出现在手机和 PC 上。

| 参数 | 范围 | 说明 |
|---|---|---|
| 自动色阶 | 开/关 | 打开时，亮度、对比度两个滑块变为禁用，显示自动算出的值 |
| 亮度 | −128…127 | PIX `BRIGHTNESS` |
| 对比度 | 0.50…1.99 | PIX `CONTRAST`，Q8，取值 128…511 |
| 自动 gamma | 开/关 | 打开时 gamma 滑块变为禁用 |
| gamma | 0.4…1.5 | 十分值 4…15，PIX Gamma 查表 |
| 滤波 | 无 / 均值 / 高斯 / 锐化 | PIX S1；S2 固定旁路 |
| 传感器曝光目标 | 24…120 | OV5640 AEC 目标亮度。默认 44，等于现有的 `0x3a0f/0x3a10 = 0x30/0x28` |

**自动色阶**（CPU，每 4 帧一次）：

1. 沿用 L4 的 80 × 45 网格，取 3600 个亮度样本。
2. 求第 2 和第 98 百分位 `lo`、`hi`。`hi − lo < 32` 时按 32 计，避免全黑画面被过度放大。
3. 目标是把 `[lo, hi]` 映射到 `[16, 240]`：`CONTRAST = round(256 · 224 / (hi − lo))`，上限 511；`BRIGHTNESS` 取能使 `lo → 16` 的值，限制在 −128…127。PIX 的对比度以 128 为中心，代入 PIX 2.2 的公式求解。
4. 与上一次的值做一半平滑：新值 = (旧值 + 计算值) / 2。

**自动 gamma**（在色阶之后，每 4 帧一次）：

- 设色阶后的平均亮度为 `m`（由测得均值经当前 BC 推算），目标 `T` = 110（沿用 L5 的 [待定] 初值）。
- `γ = ln(T/255) / ln(m/255)`，限制在 0.4–1.0，即只提亮、不压暗。
- `|γ − 当前值| < 0.05` 时不更新；更新时写入不用的 Gamma 组，再切换组，与图像处理页的做法相同。

**传感器曝光目标**：

- 按 Linux `ov5640` 驱动 `ov5640_set_ae_target` 的做法，由目标值 `t` 写入 6 个寄存器：

  | 量 | 计算 | 写入寄存器 |
  |---|---|---|
  | 稳定区上限 | `t·27/25` | `0x3a0f`、`0x3a1b` |
  | 稳定区下限 | `t·23/25` | `0x3a10`、`0x3a1e` |
  | 快速区上限 | 稳定区上限 × 2，最大 255 | `0x3a11` |
  | 快速区下限 | 稳定区下限 / 2 | `0x3a1f` |

- 只在值改变时，经 I2C 写入。
- 快捷档不改曝光目标，档位 0 除外（恢复默认 44）。

**L4 的“自动增益”删除**（它等价于只做增益，没有色阶和 gamma）。L4 的“没有 PIX 的 FPGA 版本”规则继续适用：没有 PIX 时，档位 1–3 和所有 PIX 参数都禁用；传感器曝光目标仍然可调。
