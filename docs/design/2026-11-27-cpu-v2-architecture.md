# CPU v2 整数核架构评估（C2-I）

## 背景和问题

评估输入仓库提交 `b2a273141a59515d20529d10cb1ca3c460113ce8`，CPU 冻结 RTL 为
`9fa3f649`（v0.21；现行 cpu-spec v0.23 撤回 v0.22）。本次只产生模型和设计建议。
**结论：支持“按 FPGA 的 RAM 和控制布线重构”，不支持“改成五级就能在三项上同时获胜”。**
V5 的普通 load 延迟 2（一个 load-use 气泡），会失去 B0 提前 load 延迟 1 的收益；
缩短误预测恢复不足以自动补偿这一损失。频率、资源数字均是带条件的工程估算，尚无候选的 PDS 结果。

基线口径有两个，不能把它们拼成一次实测：

| 基线 | 条件、结果 | 来源 |
|---|---|---|
| R-05 | GCC15.2 tuned，SRAM，10 次；2,479,576 指令 / 1,807,726 周期，5.531812 CM/MHz | `docs/reports/2026-11-06-cpu-n-t2.md`、`2026-11-07-cpu-n-t3.md`，集成 `04545f85`，后续冻结未改变周期 |
| SoC 集成 | 1,798,647 周期，5.559735 CM/MHz，125/125 MHz 功能仿真 | `docs/reports/2026-11-08-soc-int-v021.md`，输入 `5f2b9837`，CPU/cache 等价 `9fa3f649`；ELF 布局、环境不同 |
| 整片时序 | clk_sys 125 MHz WNS −0.546 ns / 479 终点；CPU I$ tag → IB，逻辑 3.046 / 布线 4.873 ns | 卡75 `42b3fa1615af0330b1a4aabcdbe06a0dbfee3fa5`，PDS2022.2-SP6.1 build138931，PG2L200H-6 FBB676，慢角 |

因此本评估用 **R-05 的 1.807726M** 校准，每 MHz 分数取 `10^7 / 周期`；5.56 只作为另一个实测条件。
CoreMark 的十次窗口不满足官方十秒规则。视觉是 75 候选/head 的合成后处理，LVGL 是
9.6.0、160×120 RGB565 的一次滚动刷新；不是整机摄像头或 1280×720 GUI。

## 约束

不改 RTL、规格、sw；保留 B0 周期模型。输入旧 trace 已丢失，经协调者批准，在
`build/c2i-source/` 从 `b1e9d08b` 重建原 ELF/Spike；CoreMark 依赖
`cfa9ab377835911f23d9b0831c7be302ed1f58de`，LVGL 依赖
`80ca777e37a2b176770726a02e07a6fb79ef0b39`。源和 flags 没有修改。
工具为 xPack GCC15.2.0、Spike1.1.1-dev（本机 edrv32 环境）、CPython3.12.3；周期回放用
PyPy3.10 v7.3.17 加速，顺序单模型进程。三窗口原始指令数应分别为
2,479,576 / 1,901,338 / 527,757；Zba/Zbb 是重新编译的新窗口。

模型限定：有真实退休 PC、访存地址、预测器状态和顺序配对；没有错路 cache 污染、
完整 AXI 竞争、写缓冲满等待、设备访问绝对等待和异常/中断负载。
I$ 探针只模拟 v0.19 **增量**重发一拍；D$ 探针只统计 miss，不凭空添加或拟合总线等待。
V5 复用已校准的取指队列和调度器，改变结果可用时间和恢复代价；不是一个经 RTL 验证的五级实现。
尤其 IF/ID 内部排队、同步 DRM 与 RF 读的边沿安排，必须在下一步实现中核实。

目标是整片所有域 setup/hold 干净后的 `P×F` 和 `P×F/R`。
本记录所有候选 F 是条件估算，**没有测得一个整片完全干净的候选 F**；
卡75 的 NPU、MEM setup 和 RGMII RX hold 也有违例，CPU 改造不能替它们关闭时序。
R 以核加 I$/D$ 控制总 LUT 为主，同时列 FF、CLM、DRM36K 等效和 APM；不把 DRM 位数算作 LUT。

这里按 **空发射槽 / (2×退休指令)** 分配 CPI，不相加重叠的 HPM9/12/16。
有效槽约为 0.5 CPI；组内相关、结构/类型/第二条不足各只占实际未使用的槽。
误预测包含错路槽及 D/E/M 恢复空槽；乘除/其他结果为 `slots_other_result`，CSR 串行单列。
三负载除法停顿以 HPM10 另报；CSR 和乘法结果等待同时出现时，现模型不进一步归因。
这是一种互斥吞吐损失账本，不是把某项删除就必然得到同样收益的反事实实验。

cache 一行只列可识别的 **I$ 增量重发净成本**：分别回放 recovery=1 和 0，
用 `ΔC/I`，从前端项扣除以保持总和。其余交互留在其他槽的归因中。
**I$原有填充与D$绝对miss CPI未完整建模，不可由提交trace单独测得，不能写成实测0。**
给出 `D_miss×L/I` 的无重叠敏感性；L=8/16/32 拍是输入场景，不是测得延迟。
I$填充可被IB存货及其他停顿遮蔽，固定请求序列的敏感性区间为0到`I_miss×L_I/I`，
LI同取8/16/32拍时只是场景上侧，不能与D$敏感性直接相加后当实测；请求轨迹也可能随等待变化。
CoreMark模型/RTL残差作为未知项列出，不能全部归给cache；低总周期误差不证明cache因果归因准确。

B0模型 **1,807,472周期**，R-05实测1,807,726，差 **-254周期（-0.014051%）**，退休指令完全相同。
对应CPI 0.728943981 vs 0.729046418，未知残差 0.000102437 CPI；没有乘系数拟合。
I$ recovery=0 对照为 1,807,389，重发净增83周期，非322次miss全部暴露；
视觉净增90，LVGL净增2343周期。B0提前load次数 CoreMark/视觉/LVGL为 291,130/580,684/81,409，
不能把这些load都按普通延迟2或3计算。


这推翻了“深流水必然让所有 load-use 都多两拍”的简化：B0 有严格资格的提前地址查询，
不少 load 实际延迟为 1。V5 不含该重复查询阵列，普通 EX 地址 → MEM 数据 → 后继 EX 是延迟 2。
V5 是减少复杂提前路径和控制的资源选择，不能先把 B0 的提前 load 收益删除再宣称同 IPC。

### 2. 候选及逐项选项

B0 用 `run_pipeline_cut_eval.BASE`（E/D 恢复 4/3、MUL4、注册控制、严格提前地址、
BTB128/gshare4096/RAS4、两级 tournament），不采用已撤回的 D1/D2 或 M2。
V5 用 IF/ID/EX/MEM/WB，2 发射，64 位取指、一个 LSU、两个 ALU/分支能力；
普通 load 延迟 2（MEM末捕获，下一拍WB→EX旁路，不串DRM→ALU）、MUL4 作为独立流水旁挂单元；EX 直接把预先计算的目标送下一 PC，
E/D 恢复 2/1。另给 3/2 的保守恢复点，避免把“EX 直接改 PC”当作无条件零路由代价。
分支目标加法在 ID 与 RF 读并行，EX 只做比较、年龄选择、PC 选择；JALR 仍有操作数依赖。

为单独看效果，V5 参照点用 gshare4096/BTB128/RAS4；default 再缩至 1024/64/4。
所有选项单独叠加 V5，而非互相累计。full 是全融合实验点，ip-full 是推荐的高端整数配置。
Zba、Zbb、二者组合都实际用 GCC15.2 重新编译并经 Spike 生成新 trace，不用静态模板计数冒充编译收益。

lui+addi及通用full融合2500 LUT的输入：RF额外两写口 `31×32×2=1984`，额外旁路约280，选择/译码/PC跟踪236；
688 FF沿用旧融合记录的四结果记录预算。auipc+jalr因每组至多一控制，
只需额外一写口：992RF+140旁路+128选择/跟踪+96译码=1356LUT，额外344FF；
compare+branch只产一个整数目的，与一个普通年轻ALU配对仍最多两写，128LUT/128FF预算仅覆盖译码、双退休边界及控制记录。它是**通用不丢第一目的**实现的上侧估算，
不声称每种特化融合都必需这么大。两个宏同拍完成最多代表4条架构指令，
通用融合若实施还要扩展退休trace、minstret/HPM增加量和每成员精确异常边界；默认V5仍最多两条架构退休。

### 4. 不用全局停顿的控制及探索轨

V5采用逐级valid、局部输入credit和按序提交：IF/ID队列、EX、MEM、WB/完成队列各自推进。
ID在上一拍已登记的MEM容量内发射，D$ tag只决定本地响应valid/miss状态，不组合反馈到ID发射、RF或IF。
miss时已进入的年轻EX结果进入4项完成记录，提交头等待较老请求完成；队列满后只阻止新发射，
已完成WB和前端独立推进。store和设备访问在确认最老、不可被较老异常取消后才能对外生效。
乘除、CSR和FP均用目的记分牌标记依赖，提交保持程序顺序；不因为长运算冻结整个核。
这不是允许任意越序发射：等待最老源操作数的ID仍阻止后续指令越过它。

payload寄存器不接统一stall/flush CE；流水数据可无条件传递，以valid决定消费。
必须保留的局部skid/完成数据按每16位或更小分区复制使能。
根redirect只到 IF PC、前端队列valid、EX年轻valid、完成队列取消记录四区；根直接负载估算≤8。
各区复制后的kill/hold最多16个LUT/valid/CE输入，数据CE以16位分组（例如128位保留数据需8个本地副本）；
四级入口valid、8个完成/缓存局部控制根共预算不超过16个根负载，约32–64个额外控制FF已计资源。
RAS数据不清零，恢复指针；长结果携带年龄/取消状态，不能在flush后写RF或fflags。
记分牌查询按读口分副本，目的更新注册后再查询，不能让一个全局busy/ready网穿透全部级。
这些上限是实现约束；没有网表就不能声称综合一定保留副本或实际fanout≤16。

探索一（已有回放）：按DRM边沿划分取指，增加一个物理IF子级，保留64位原指令，
后级再译码；以 `V5-drm-fetch` 的taken+1、恢复3/2给出保守吞吐场景。
它避免重演v0.22的加宽预译码RAM（卡66/67资源增加且频率反降），但模型结果表明反馈气泡很贵，
ID/RF若仍是最长段则加级没有频率回报，不能推荐只加IF级。

探索二（解析上界，不伪称周期回放）：D$ miss一旦确知，取消年轻EX/ID并在返回后从其PC重取，
让MEM/WB本地排空，省完成队列和长距离hold。最多取消2条EX+4条ID队列+2条IF在途，共8条，重启2拍，
固定重取成本场景 `ΔC≤D_miss×(ceil(8/2)+2)=6D_miss`，基于下述提交miss计数；
未计二次误预测、错路访问和连续miss，这不是完整程序周期上界；不能用于有设备副作用/已提交年轻store的路径。
它与有完成队列的默认方案二选一，不给默认方案叠加这个重取成本。

## 决策

**建议默认：V5-default，双发射、单LSU、gshare1024、BTB64、RAS4、2个HPM、RV32IM，
保留Zicsr/Zifencei，关闭级联、通用融合、Zba/Zbb。** 先以整片125MHz完全干净为验收目标，
以135MHz作为拥塞压力口径的规划目标：按1.182，125/135MHz分别需要独立至少147.8/159.6MHz。
150MHz只作探索目标，最低5%余量要求157.5MHz，但按最新整片压力需要177.3MHz，
高于当前预算的160.1MHz独立上界；不能以一次157.5MHz独立探针通过就宣布整片150达标。
性能优先配置为V5-ip-full（tournament4096/BTB128/RAS8、8HPM）；仍单LSU、不级联、不通用融合，
允许超过10k预算，若10k约束也适用于高端则裁为HPM0，减1166LUT为9923LUT中心估算（仍保留mcycle/minstret，三负载不读HPM，周期相同）。
小配置为V5-1，保留统一异常/缓存接口和RV32IM软件兼容。

默认模型 5.265 CM/MHz，8,789 LUT / 5,155 FF，F=150MHz预算时 789.8 CoreMark、89.9 CoreMark/kLUT；
拥塞压力F=135MHz时分别为 710.8、80.9。
推荐满配模型 5.483 CM/MHz，11,089 LUT / 5,921 FF，F=150MHz预算时 822.4 CoreMark、74.2 CoreMark/kLUT；
拥塞压力F=135MHz时分别为 740.2、66.8。
小配置模型 3.591 CM/MHz，6,951 LUT / 4,677 FF，F=150MHz预算时 538.6 CoreMark、77.5 CoreMark/kLUT；
拥塞压力F=135MHz时分别为 484.7、69.7。

频率必须补足每MHz吞吐的损失。以B0整片sys上界117.03MHz为参照，
下表为保持相同指令吞吐所需的V5频率 `117.03×C_candidate/C_B0`，仍是模型阈值：

### FPU接口（已与协调者确认）

协调者在本Dispatch的 `ask` 回复明确同意以下建模接口并负责转告C2-F，补充了FD、fflags和FMA两读口规则。
第二次队列口径确认：整数-only为4项，带FP的现有C2-F模型为共享16项；后续C2-F2评估8/16项，新增存储优先分布式RAM，仅控制放FF，新增资源由FP集成承担。
这里是架构契约假设，不创建未批准的RTL接口：

- **发射槽**：槽0接收FP算术/转换及FP load/store；槽1仍可配对独立整数ALU，单组至多一个FP操作、一次LSU访问。FPU busy只反压槽0的相关发射；最老等待指令仍阻止年轻指令越序。
- **RF**：独立FP RF，F为32×32，FD为32×64，默认2R1W，满配3R1W；整数RF不增端口。FMA默认先读rs1/rs2并锁存、次拍读rs3，因此每次FMA额外1个源捕获周期，连续FMA接受间隔至少2拍；不能把算术延迟额外再重复加这一拍。3R可按FPU本体II接受。FP→整数转换/比较共用槽0整数写回端口，整数→FP共用槽0整数读口。
- **写回**：整数与FP各有自己的写域；FP load返回与FPU完成竞争单FP写口，完成结果先入本地队列，再按年龄选最老可提交项；转换写整数RF时占槽0写口，与同拍槽0整数/LSU结果冲突则保留较年轻结果，槽1仍有原整数写口。FPU操作用发射tag/年龄和目的记分牌跟踪，提交队列满时反压，不能丢结果。
- **顺序与取消**：所有寄存器写和fflags均按程序顺序提交；RISC-V浮点算术本身不产生陷阱，只累计fflags。错路/较老异常时取消年轻操作及其fflags；FP load/store仍可产生普通访存异常。fcsr/frm/fflags及mstatus.FS的配置增量计入FP集成，不计入整数NONE资源；没有推测向设备发store或不可撤销FP flags写。
- **LSU**：FLW/FSW复用单32位LSU，FLD/FSD在FD配置中分两个32位beat，期间占槽0访存路径；地址、字节使能、异常、store提交由整数LSU负责。FP数据返回FP RF，FSW/FSD从FP RF取store数据，不为FP复制D$或增加整数RF端口。两个beat的精确异常与跨cache行行为需由C2-F/协调者在正式接口规格定稿。

完成队列扩容的集成增量估算（不含FPU/FP RF本体，不能漏算在C2-F报告之外）：

| 实现 | 输入公式（16项替换原4项） | LUT增量估算 | FF增量估算 |
|---|---|---:|---:|
| F，数据用LUTRAM | 数据=16×(结果32+PC32)=1024bit；控制=16×(rd5+原控制8+fflags5)=288bit，再加32控制副本；减原4×77=308FF | 512=128 LUTRAM上侧预算+384选择/仲裁 | +12=288+32−308 |
| FD，数据用LUTRAM | 数据=16×(结果64+PC32)=1536bit，控制同F | 768=192 LUTRAM上侧预算+576选择/仲裁 | +12 |
| F，全部FF对照 | 16×82+32−4×77 | 384选择/仲裁 | +1036 |
| FD，全部FF对照 | 16×114+32−4×77 | 576选择/仲裁 | +1548 |

LUTRAM数据按两写入槽分成两个8项bank，各bank单写并行读；同bank完成竞争要保留源结果并仲裁。
1024/1536bit按64bit/LUT的容量下限仅16/24 LUTRAM，但按每bank每数据bit一个LUT的未充分打包上侧取128/192，不能把容量下限当实际映射。
384/576的选择预算取数据宽度64/96×6，包含头两项读出和写入/提交年龄仲裁，不扣除旧四项的选择逻辑，因而偏保守。
该估算把原4项FF数据也迁入LUTRAM，才会出现队列增大而FF增量很小；若仅增加12项、保留原4项数据FF，则不能再扣原数据FF。
LUTRAM输出需本地结果捕获，不能把深队列异步读串入原EX旁路；其真实II、bank冲突和时序留给C2-F2联合评估。

整数三负载没有FPU指令，本表额外周期为0，主P/F/R表资源不含上述FP集成增量、FP RF/FPU本体。
给C2-F的组合模型公式是 `C_total=C_integer+源捕获/结构等待+依赖等待+写回竞争+FD额外beat`，
各项按实际调度互斥计数；不能把它们的独立最坏值直接相加成实测结果。

### B0-fix：先给修补路线同等机会

保留原提前读副本和短 load，不把V5的cache控制精简专属化：元数据DRM化、本地hit捕获、
refill/维护控制合并、取消宽valid/dirty选择，同样计入B0-fix。仅保留提前读需要的9个DRM及其局部路由。
对卡75 cache/APB 的 `6814 LUT/4570 FF`，用第一轮 `2554 LUT/1411 FF` 控制预算替换，
另加提前副本控制 `320 LUT/192 FF`、控制复制及新增捕获 `96 LUT/320 FF`。
因此 B0-fix 为 `19238−6814+2554+320+96=15394 LUT`、
`12109−4570+1411+192+320=9462 FF`、27 DRM、4 APM；没有按流水级数比例减面积。
这些精简仍有第一轮所述的维护/失效语义待规格化条件。

回放以下可审查的拆法，避免把“只修时序”默认当零周期：

- `B0-fix`：I$ tag输出寄存、后拍预译码；早期资格分D1/D2（复用 `decode_split`），接口E/D参数5/4；模型为额外D级再加1，因此实际恢复预算6/5，已预测taken增加1拍。
- `B0-fix-predecode`：静态预译码在IB写入时拆开，动态rs1资格按RF端口分本地比较，保留原D发射拍；仍计I$输出寄存引入的taken+1及恢复5/4。其更低周期依赖资格网络确实能收敛到下面预算，不是假称已经实现。
- 各拆法均将 e_redirect/m_redirect 按IF、IB、执行与提交区域复制，根只驱动局部控制；payload不挂全局CE，保留数据与valid分离。
- `B0-fix-best` 为第二种拆法再加本轮基4及提前结束除法器，用于与新默认的组合比较。
- `B0-fix-parallel` 给修补路线一个**不增加反馈拍**的方案：I$两路数据并行预译码，tag比较只选预译码后的结果；静态load/rs字段在IB入口捕获，动态资格按源端口本地计算。这样不用给每次taken额外一拍。两路预译码/选择另加128 LUT，得到15522 LUT/9462 FF；并行数据路径 `HDRM+4Q=5.542 ns`、tag路径 `HDRM+3Q=4.800 ns` 均短于保留旁路环，所以仍按140/125 MHz。
- `B0-fix-parallel-div` 再加352 LUT/64 FF的新除法器，是修补路线的最有利组合；与其余候选一样实际回放，而不是把有气泡版本当作修补路线的全部可能性。

保留B0旁路的最长段取 `HFF+ADD32+5Q=6.160 ns`，
拆后的资格 `HFF+6Q=5.643 ns`，I$输出后至IB捕获 `HDRM+3Q=4.800 ns`。
这是假定原长路径被局部拆开后的目标，而非仅删除报告中的最坏组；
仍保守给B0保留比V5多一级的旁路选择。加0.450 ns布线余量后最长6.610 ns，规划140 MHz、压力125 MHz。
控制复制不额外增加恢复周期，额外周期来自显式列出的寄存边界。

### V5+(a)：ID提前地址，仅RF或可用WB旁路

`V5-id-address` 不恢复旧双D$读副本。ID用RF读值或已完成WB值加立即数；
同组更老指令、EX、MEM任一记录写rs1则不用提前地址，WB中的MUL4未完成也排除。
未满足者仍走EX AGU、普通load延迟2。满足者在ID末形成请求地址，下一边沿由D$ DRM接收，
数据在load的EX周期返回并在消费者进入EX前捕获，结果延迟1。
只做提前地址计算；存储、副作用、异常与年龄控制仍由原单LSU/按序提交负责。
miss与设备访问没有被当成真实一拍命中；本轮仍沿用原命中模型及其局限。

关键区别是**数据先捕获再供消费者ALU**：
`DRM tco1.644+way选择Q+旁路2Q+setup0.406+skew0.200+uncertainty0.324=4.800 ns`。
随后独立一拍执行消费者，`HFF+ADD32+4Q=5.418 ns`；
不允许将消费者ALU直接接在4.800 ns之后形成 `6.059 ns`，再增加其他结果选择。
ID AGU必须包含RF读取，取 `HFF+3MUX+Q+ADD32=5.571 ns`；完整ID/RF段仍为第一轮 `HFF+3MUX+3Q=5.796 ns`。
加0.450 ns后独立周期6.246 ns，按5% reserve为150 MHz规划、按1.182拥塞系数为135 MHz压力。
因此本节只将“本地DRM返回→操作数捕获”的写法列为有效150 MHz规划候选；
如果实现重新把DRM、消费者ALU、完整结果选择串起来，必须降低F后重排推荐。

这里的Q是单层4:1选择（老/年轻指令各一份RF基址及两个WB值），数据4位加二进制选择2位可放入LUT6。
资格比较和选择编码并行计算，立即数选择走另一条较短输入路径；不允许在RF之后再串多层槽选择、WB选择与资格门控。
若综合映射需要RF后三层Q，则AGU为7.055 ns、规划降至125 MHz，不属于本轮有效150 MHz候选。

资源增量 `ID=(128 AGU+96资格+64选择, 32地址+32操作数+32控制)=(288 LUT,96 FF)`；
保留单份D$，18 DRM。EX store地址和提前load的请求由原LSU本地请求/写缓冲安排，
不能为支持这一结构偷偷增加第二LSU或第二D$副本。

### V5+(b)：load依赖的后段ALU/分支

`V5-late-alu` 仅将等待一个load结果的add/sub、逻辑和简单比较移至后段，两个槽均可；
移位、乘除、CSR、地址和store不覆盖，也不引入同组RAW级联。
`V5-late-branch` 再允许条件分支后移，使用已有MEM重定向路径；
消费者后面的依赖继续按后段结果延迟2检查，不能只删load-use而忽略新依赖。
分支预测错误在MEM处理并清除年轻指令，模型保留这个额外恢复成本。

借鉴的是[EH1的主/次执行流水和后段依赖控制](https://github.com/chipsalliance/Cores-VeeR-EH1/blob/main/design/dec/dec_decode_ctl.sv)，
并没有把EH1的频率、乱序能力或非阻塞load性能当本IP的证据。
本轮复用late字段，但用显式 `late_execute` 保留V3s的交换/配对规则，
且只隐藏实际load等待，不给所有ALU/MUL依赖免费后移。

结构预算：每个简单ALU `32加减+32逻辑+32比较+64操作选择+32控制=192 LUT`，两个共384；
不复制完整396 LUT ALU中的移位网络。局部32位双路数据/结果选择及年龄控制320 LUT，
两槽操作数/结果捕获192 FF加32位操作/目的/late控制，合计704 LUT/224 FF；
条件分支再65 LUT/128 FF（含一个预测更新暂存条目的索引、PC、目标、历史及控制预算）。
load→后段ALU用专门捕获寄存器，不经普通全结果选择器，最长 `HDRM+2Q+ADD32=5.317 ns`；
若映射需要额外一级选择，则变6.059 ns，加0.450余量后规划降至145 MHz。
ALU单独候选采用专用捕获结构；分支仍需条件/类型选择，最长保守取 `HDRM+3Q+ADD32=6.059 ns`，
因此包含后段分支的候选按145 MHz规划、125 MHz压力，不能把它也按150 MHz计分。
表中同时给出 `full2-no-late`，避免满配把无效或低效旁路强行全部打开；其可实现性仍待PDS。

### V5+(c)：GCC 15.2编译调度，硬件与软件收益分列

原调优为 `-O3 -funroll-all-loops -finline-limit=600 -falign-functions=4 -falign-jumps=4 -falign-loops=4`，
本轮全部保留，没有退回-O2，也没有修改工作负载C源码。
比较追加 `-mtune=rocket` 或 `-mtune=sifive-7-series`，两者再加 `-fsched-pressure -frename-registers`。
[GCC15.2 generic描述](https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-15.2.0/gcc/config/riscv/generic.md)
和[sifive7描述](https://raw.githubusercontent.com/gcc-mirror/gcc/releases/gcc-15.2.0/gcc/config/riscv/sifive-7.md)
的整数load都是3周期，所以不能把任意一个 `-mtune` 冒称精准的load延迟2。

另交付 `gcc_load2.cc`：GCC15.2调度插件只把整数load的真依赖cost改为2，
保留原target hook处理其他依赖，结合sifive7双发射调度和上述选项形成 `load2` 实验。
使用[GCC TARGET_SCHED_ADJUST_COST契约](https://gcc.gnu.org/onlinedocs/gccint/Scheduling.html)，
没有改ISA、插入手工nop或修改编译器安装。
探针 `int f(int*p,int a){return *p+a;}` 的sched2 dump确认load在t=0、消费者在t=2发射；
原始reservation列仍显示3，但依赖队列实际cost=2，不能只看reservation列判断插件无效。
这是IP软件交付的调度实验，不是声称整个sifive7机器描述等同本核。
所有软件回放均固定裸V5/gshare4096、load延迟2，避免把ID提前地址或新除法器的收益记到编译器头上。

### 预测器与除法器

推荐默认 **gshare4096、LUTRAM**，不再以节约约96 LUTRAM换掉CoreMark收益。
第一轮固定BTB128/RAS4的隔离比较中，1024→4096将CoreMark周期1,895,827→1,854,797（吞吐+2.21%）、视觉1,827,042→1,825,278（+0.10%）、LVGL488,932→479,507（+1.97%）；与BTB容量变化分开。
PHT容量下限 `4096×2/64=128 LUTRAM`，1024项为32；第一轮预算的100 LUT增量包含4 LUT控制余量。
异步PHT输出经本地预测捕获，沿用第一轮IF段预算，不再增加预测反馈拍。
DRM版需要8192 bit，本器件按半个36K宏记0.5 DRM，PHT节约128 LUTRAM而请求/更新另加32 LUT/32 FF，净−96 LUT。
同步读取带来一拍方向反馈，回放 `V5-pht-drm` 采用taken+1、E/D恢复3/2的保守反馈包络；
这不是宣称已实现DRM端口/RMW冲突的周期精确预测器。
DRM返回最长 `HDRM+2Q=4.058 ns`，整体仍受ID/RF限制，不能拿PHT单段变短冒称整核频率提高。
因此只有LUTRAM极紧且能接受表中吞吐损失时才选DRM，默认无此动机。

除法三方案均在B0和裸V5上逐项回放，未用HPM10百分比直接从总周期减去：

- 原基2：每条EX额外停顿33拍，沿用校准模型。
- 基4 SRT规划：每拍产生2个商位，EX额外停顿 `1+ceil(32/2)=17`；增量192 LUT/32 FF，表示候选减法/商选择与局部记录的电路预算。
- 基2提前结束：从Spike提交日志恢复源操作数，符号数先取幅值，`k=max(0,bitlen(|a|)−bitlen(|b|)+1)`，EX停顿 `1+k`；除零k=0。余数为0不再另假设逐步早停，a<b但位数相等仍保守做一步。增量160 LUT/32 FF：两棵32 LUT位数编码树，加32位三级4:1/4:1/2:1对齐网络96 LUT及局部捕获。
- 基4+提前结束：停顿 `1+ceil(k/2)`，资源相加352 LUT/64 FF；预处理分两拍：幅值处理加四层编码 `HFF+ADD32+4Q=5.418 ns`，再对齐 `HFF+3MUX=3.570 ns`；迭代最长 `HFF+ADD32+3Q=4.676 ns`，不降低表中F。

上述停顿是模型的额外EX hold；若把除法指令自身执行拍也计入，端到端需再加1，不能把17称作含全部阶段的固定总延迟。
上述1+k/1+ceil(k/2)对应EX自身一拍加额外hold，共两拍固定预处理；假设商符号按生成过程维护、最终修正选择并入最后迭代。基4增量的32 FF预算包含额外商候选。
若只能在循环结束后另做完整符号/余数修正，必须增加延迟并重新回放；不能把四层编码、三级对齐及修正串成同一拍。
真实SRT的规格还需明确signed digit选择、最后余数修正及符号恢复能否并入预算的固定拍；
本轮只评估这些明确的规划延迟，没有实现算法或验证SRT正确性。
正路除法的每次延迟由实际操作数决定；错路指令没有对应的架构提交操作数，仍按原33拍模型直到较老重定向取消，不记作免费的早停收益。
B0仅更换除法器不能修好其原关键环，所以B0三行仍按117.03 MHz；B0-fix-best才使用修补后的F。

### 结果解释与更新推荐

**推荐默认改为 `default2-early-div`：V5双发射、ID RF/WB提前地址、gshare4096 LUTRAM、BTB128/RAS4、2 HPM、基2位数提前结束除法器。**
保留RV32IM/Zicsr/Zifencei、单LSU、MUL4、4项整数完成记录；关闭后段执行、级联、融合与Zba/Zbb。
中心预算 **9457 LUT/5347 FF、18 DRM、4 APM、3378 CLM**，规划150 MHz，压力135 MHz。
三负载每MHz相对B0为 **+1.74% / +12.46% / +11.94%**；
按135 MHz为 **+17.36% / +29.73% / +29.13%**，按150 MHz为 **+30.41% / +44.14% / +43.48%**。
默认模型5.629 CM/MHz，150 MHz场景844.3 CoreMark、89.3 CoreMark/kLUT；135 MHz场景759.9、80.4。

ID方案保留了视觉91.32%的load短延迟（B0为93.62%），没有恢复9个提前读DRM。
裸V5三负载load-use空槽 `324944/868684/49398` 降为 `187264/82754/13154`，
已接近B0的 `185808/61694/11370`。这才是本轮每MHz性能恢复的主要原因。
提前结束再把视觉除法停顿154638降到27338，减少127300周期；CoreMark没有除法，收益为0，不能把视觉比例套过去。
基4+提前结束相对单独提前结束，视觉仅再省11092周期，默认配置却再多192 LUT，
所以默认选较小的基2提前结束；`default2` 组合点留在总表供性能优先者复核。

单独late ALU在视觉只覆盖7066条消费指令，净省224周期，不能默认增加两套后段运算与旁路。
加入late branch能后移449005条视觉分支、去掉99.09%的裸V5 load-use空槽；
但分支段的F降至145/125 MHz，且ID提前地址已经消除了多数同类等待。
组合 `full2` 虽每MHz最好，按其F换算后，三个负载均落后于 `full2-no-late`；
后段分支不是免费增强，满配也不应为了“开全开关”保留它。
实际回放的late branch训练暂存峰值均为1，资源已预算一个条目；未将冲突当成双写免费更新。

**推荐满配 `full2-no-late`**：在新默认基础上用tournament4096/BTB128/RAS8、8 HPM、基4+提前结束。
中心预算 **11729 LUT/6081 FF、18 DRM/4 APM、4189 CLM**，规划150 MHz、压力135 MHz，允许超过10k。
每MHz相对B0 **+3.40% / +16.45% / +13.44%**；
按135 MHz **+19.28% / +34.34% / +30.86%**，按150 MHz **+32.53% / +49.26% / +45.40%**。
它比默认在同F下提高约1.6%/3.6%/1.3%的吞吐，付出约24%的LUT增量；
这是峰值性能档，面积效率仍以默认更好，不能把更多HPM当成运行收益。

**推荐小配置 `small2-early-div`**：单发射、ID提前地址、gshare4096 LUTRAM、BTB64/RAS4、HPM0、基2提前结束。
中心预算 **7371 LUT/4677 FF、18 DRM/4 APM、2633 CLM**，规划150 MHz、压力135 MHz。
每MHz相对B0 **−33.02% / −29.97% / −15.72%**；
按135 MHz **−22.73% / −19.21% / −2.78%**，按150 MHz **−14.14% / −10.23% / +8.02%**。
小配置保留短load的结构收益，但单发射损失不能被频率全部补足；它适用于面积优先场合，
不宣称三负载都胜过B0，也不是本轮最佳CoreMark/kLUT点。

本轮也给B0最有利的无反馈气泡修补：`B0-fix-parallel` 周期与B0相同，
不是把增加taken气泡的版本作为唯一对照。加新除法的 `B0-fix-parallel-div` 为15874 LUT/9526 FF/27 DRM、140/125 MHz。
新默认的每MHz三负载性能、F预算和面积均优于这个修补点；**在本轮模型与预算内，结论不是“B0-fix更好”**。
相对原B0，新默认中心LUT减少50.84%、FF减少55.84%、DRM减少33.33%。
这仍是结构预算：继承第一轮约1747 LUT不确定度，再给新增220+288+160 LUT按±25%，
得到 `1747+0.25×668=1914 LUT`，默认约7.54–11.37k；距10k中心余量只有543 LUT，不能宣称已证明≤10k。

软件三组配方均未超过原调优：即使精确load2配方把视觉load-use从868684降至58280空槽，
指令数也从1.90M变为3.83M，总周期反而增加40.72%。CPI改善不能替代同工作量周期比较。
这些结果是编译配方整体效果，sifive7的其他机器成本也会改变优化选择，不能据此断言所有编译调度都无益。
固定裸V5的F/R后，rocket/sifive7/load2分别为5.387/5.227/5.319 CM/MHz，
150 MHz场景为89.7/87.0/88.6 CoreMark/kLUT（裸V5为89.8）；**本轮三档均保留原调优配方，不叠加虚构的软件收益。**

### 背景、口径与约束

输入为 `b75d169871f8a90fe6f9d5ba974b1155f03ef967`，沿用第二轮

六项理想化的精确定义：完美预测仍保留真实取指宽度；零 load-use 用 load 结果延迟 1、
不删除组内 RAW；无同组 RAW 允许同组直接使用老指令结果，是不能作为时序推荐的 oracle；
无配对类型/资源限制移除槽类型和功能单元冲突，**仍保留组外未就绪操作数**；

### 电路方案：每槽 EX 早 ALU、MEM 晚 ALU

本轮让年轻相关指令在 **下一拍 MEM** 使用 EX 末已经捕获的老指令结果，
没有在 EX 或 MEM 内串两个加法器。不是第一轮 V5-cascade，也不是第二轮仅覆盖前组 load 的 late ALU。
两个槽各有一套早 ALU 和一套简单晚 ALU；只在需要等待一个周期且操作受支持时选择晚执行，
独立 ALU 继续在 EX 执行。模型保留严格按序发射、按序架构结果以及组内年龄选择。

| 消费关系 | 能否同组发射 | 数据边界与结果延迟 |
|---|---|---|
| EX ALU → 年轻简单 ALU | 可以 | EX 结果寄存 → 下一拍 MEM 晚 ALU；年轻结果延迟 2 |
| ID 短 load → 年轻简单 ALU | 可以，基址须满足原 RF/WB 资格 | 提前返回捕获 → 下一拍 MEM；年轻结果延迟 2 |
| 普通延迟 2 load → 同组消费者 | 不可以 | 数据要到 MEM 末才捕获，不能在同一个 MEM 段继续串 ALU |
| 前组普通 load → 简单 ALU | 可以隐藏剩余一拍 | load MEM 末捕获 → 消费者下一拍 MEM |
| 前组晚 ALU → 后继 ALU | 按延迟 2 检查 | 可再后移到后继自己的 MEM；禁止同一 MEM 内级联 |
| 晚 ALU → load/store 地址、MUL、JALR | 不因晚 ALU 获得特殊豁免 | 按真实结果可用时间等待 |
| 老 ALU/短 load → 条件分支 | 仅 late-branch 档可以 | MEM 比较/重定向；错误恢复多经过一级，已计入周期 |

晚 ALU 覆盖 `ADD/ADDI/SUB`、`AND/ANDI/OR/ORI/XOR/XORI`、
`SLT/SLTU/SLTI/SLTIU`。移位、MUL/DIV、CSR、访存地址和 JALR 不进入晚 ALU。
晚分支仅条件分支，不把间接跳转也当成已覆盖。MUL 结果等待不能冒充 load 等待被隐藏。
ID 提前地址资格与第二轮一致，组内老 load 是否短延迟在配对前用同一资格函数判断，
发射后的 load 记录仍由实际资格赋延迟；没有把所有 load 当成提前返回。

MEM 分支恢复由原模型的 M 重定向路径处理，不能沿用 EX 的恢复计数。
EX 与 MEM 训练同拍到达时通过按年龄排队的单写口训练机制处理；后表报告训练暂存峰值。
两个控制指令/组的实验还显式限制训练为每拍一个、暂存一个，队列不足时停住 E，
不是在 Python 中免费同拍写两次 PHT。

### 上限和后段执行的解释

单项上界不能相加：消除一种阻塞会改变随后分组和预测器训练时刻，也可能暴露另一种等待。
尤其 `ideal-pair` 没有删除所有 `pair_structural`，因为该原始计数器把“第二条等前组结果”也归在结构项。
分解表中 `operand` 是该等待，`unit` 是槽类型/单元/串行约束；RAW 优先归因，二者均按实际未用槽除以 `2N`。
没有把所有 load+load 都说成可消除：相邻相关地址先归 RAW，独立双访存才是双 LSU 的覆盖目标。

以默认基点为例，晚 ALU 覆盖93,565条（3.77%退休指令），同组RAW CPI从0.051595降到0.031680，
但长结果等待从0.019159升到0.032976，第二条结构等待从0.020925升到0.025314。
结果只净省10,134周期（0.57%），不是“删掉0.019915 CPI就得到全部收益”。
年轻晚 ALU 的结果延迟2，地址/MUL/JALR等后继无法一律晚执行，部分相关链只是把等待挪到了下一组。

加入晚分支后，默认覆盖93,676条ALU和78,339条条件分支（合计6.94%退休指令），
周期1,730,068，比默认净省46,495（2.62%）。load-use CPI降为0.023287，
同组RAW为0.030207，但长结果仍为0.031426；总误预测CPI由0.040541升为0.041164，
其中MEM恢复单列为0.003049。晚分支收益已经扣除了延迟恢复，不能再使用EX误预测罚拍重算。
普通load同组消费、移位消费者、访存地址、乘除、CSR、JALR以及两个晚结果同组依赖仍不能全部覆盖。
因此“把同组RAW损失直接相减约6.07”不是晚ALU可兑现的净收益；反事实重放以上限表为准。

### 配对放宽和取指的解释

`branch-one` 是已有两槽条件分支/JAL能力、每组最多一个控制的复核对照；不重复计收益或面积。
`control-one` 才额外把JALR操作数/目标输入放到第二槽，仍限制每组一个控制。
`branch-two` 再允许两个控制，单写口训练使用一个暂存项并在不足时反压，表中周期包含训练结构停顿。
不能把两个控制的组合全称为“预测器也能同拍预测两个目标”：本轮前端每组仍只有一个预测入口。

`lsu-slots` 和 `mul-slots` 分别允许同一单元从两槽按年龄选输入，
例如load+MUL与MUL+load两个方向都可安排到一个LSU和一个MUL上；不是复制单元。
单LSU仍禁止load+load、load+store、store+load、store+store；单MUL仍禁止MUL+MUL。
两槽都有普通ALU/条件分支能力已由基点拥有，但这不等于所有两条“通用槽”指令都能配对。
CSR/serial仍遵循原串行语义，不用扩槽去消除其架构要求。
双MUL独立列出了额外4 APM及增加到8项完成记录的预算，不把它当作只加一个输入选择器。

`pair_one` 不等于I$ miss或取指位宽不足。64位组容纳两条32位指令，但taken目标落在组末字时，
该次返回只有一条有效指令；真实目标对齐表给出这种入口的动态占比。
“目标后/其余”列只按上一条控制与当前头PC是否非顺序分类，不能把其余全部归咎于队列深度。
即使队列更深，连续taken、误预测清空、注册返回的到达相位和每组单预测入口仍会限制第二条。
取指表同时列了pair_one、前端和误预测CPI，避免把因训练时刻变化而增加/减少的预测损失都算成带宽收益。
128位实验与8条队列一起评估；64位8/16条实验分别隔离深度影响，128位16条再观察宽度与深度交互。

默认CM最主要的类型组合是load+load（0.008942 CPI）、branch+branch（0.006492），
以及MUL+load和load+MUL（合计0.006315）；结构项前几位则是MUL+ALU等前组乘法结果、
load+load等前组基址/结果、ALU+ALU等前组结果，均不是“再加一个执行单元就能消除”的冲突。
CM配对项中与CSR有关的四个空槽合计约0.000000807 CPI；视觉/LVGL该窗口没有CSR配对损失。
这组负载不能用于证明CSR密集软件的扩槽收益。

单LSU双槽年龄选择在默认省15118/4785/2404周期（CM/视觉/LVGL），
单MUL双槽选择省15117/2171/129周期；两者均增96 LUT/32 FF且保留150/135预算。
它们的收益来自混合类型配对，不会消除单LSU的独立双访存。
原视觉窗口确有2011个MUL+MUL类型空槽（0.000529 CPI），LVGL有19个，CM为0；
但单MUL扩槽后的重新分组已吸收这些机会，双MUL相对单MUL扩槽三窗口净周期收益均为0。
因此不为双MUL再付257 LUT、505 FF及4 APM。

双槽JALR在默认CM只省1周期，在视觉/LVGL省2653/2277周期；
两个控制/组在默认CM省11395周期，却需要140/125 MHz预算，规划P×F由844.3降到793.1，
不作为保持频率的增强。双LSU在ID提前地址下省33590/57468/41180周期，
命中模型对LVGL最有效，但规划/压力预算降为135/120 MHz，故不进本轮CM吞吐推荐。

64位增深到8/16条IB在默认CM反而增加2043/3718周期；满配8条则省5510周期，16条只省2634。
更深队列改变预测查询、训练和F2修正相位，pair_one变少并不保证总周期下降。
128位取指把默认CM的pair_one从0.020068降到0.003220 CPI（削减约84%），
但误预测从0.040541增到0.046602，净省17179周期仅0.97%，还付出135/120 MHz预算。
因此单独加宽和无条件增深均不推荐默认；8条IB仅在满配组合中根据实际重放保留。

## 第四轮：可移植的预测、双 load、非对齐取指与 RAM 寄存器堆（C2-I4）

### 背景、边界和统计口径

本轮最终模型/预算源码提交：`1a26a7924`（含`e9ea34c05`的全部重放功能）；
基点来自第三轮`fd91a07b1`。前三轮记录保持原文。

本轮以第三轮的 `default2-early-div/base`（下称 default）和
`full2-no-late/combo-control`（下称 full）分别为起点；full 已包含早/晚简单 ALU、
晚条件分支、单 MUL 双槽输入、JALR 双槽输入和 8 条 IB，绝不把它换成未组合的 full2。
五个方向各自重放 CoreMark、视觉、LVGL 三个原工作窗口，再对选定结构组合重放。
小配置另以 `small2-early-div` 单发射点比较 FF/RAM RF。

**以下周期、误预测和覆盖率均为 trace 驱动的模型估算；资源、关键段及频率均为估算，
不是 RTL 仿真、综合或 PDS 测量。** 保持第三轮的命中流水、I$ miss 增量恢复、真实分组、
预测查询/训练相位、晚结果依赖及退休窗口；不加入未建模的 DDR/refill 总延迟。
原 ISA 三窗口退休指令数为 2,479,576 / 1,901,338 / 527,757；
Zba为2,456,216 / 1,829,215 / 525,403。
表中 ΔCPI 是新配置 `cycles/N` 减对应起点 `cycles/N`，负数表示减少；Zba 使用新 N，
因此另用同工作量总周期判断收益，不能把 ISA 间 IPC/ΔCPI 当作加速比。
CM/MHz 为 `10,000,000 / CM_cycles`。失槽 CPI 仍按 `slots/(2N)` 统计，
同步 RF 和双 load 补读的所有净停顿都进入总周期，不直接相减旧 CPI 损失项。

用户排除的 FPGA LUT/进位链运算级联没有评估；本轮只使用常规加法、常数连线、
分 bank、复制 RAM、LVT 和注册流水。RAM 以后均须通过 `rtl/tech/` 包装；
本轮不修改 RTL、冻结规格、软件或 FPGA IP 配置。

### 实现模型：预测器

新 `RamTage` 为 TAGE 类候选，不声称复刻某个标准 TAGE 实现：

- 原 gshare4096 快速方向表与 BTB/RAS 继续供给 F1；同步 RAM 基表（4096×2，PC 索引）和
  3/4/5 个标签表并行读，F2 比较标签、选择最长历史的 provider，不同则真实纠正一拍。
  **没有在搬走 F1 表的同时仍免费使用它的预测**；存储位数和面积保留 F1 表，再增加 RAM 基表。
- 几何历史长度分别为 `(4,16,64)`、`(4,12,32,96)`、`(4,10,24,60,144)`；
  每表比较 128/256/512/1024 项中的所列表项，标签 10 bit、方向计数 3 bit、usefulness 2 bit、
  valid 1 bit，每项共 16 bit。索引是 PC 与完整历史的分段 XOR 折叠，标签使用另一组折叠。
- F2 返回时保存索引、标签、provider、预测及 alternate，在存活的 EX/MEM 条件分支解析时训练。
  provider 是最长匹配，alternate 是次长匹配（无匹配用基表）；误预测在更长表中按顺序最多分配一项，
  占用候选的 usefulness 在分配压力下递减。没有假设 RAM 全表能一拍并行老化。
  与既有Direction接口一致，只有持有F1方向查询token的存活分支训练局部/TAGE状态；
  BTB冷miss不训练RAM基表或推进TAGE长历史，fast gshare仍按全部解析条件分支更新。
  因此本轮长历史是“被BTB识别的条件分支历史”，不是完整解析分支历史；
  结果限定于这一明确的TAGE类变体。没有用未来trace方向提前训练，也未加入可选loop/统计校正器。
- 预测读与训练的当前行读不能共用一个免费端口。每个同步基表/标签表另外保留一份
  1R1W训练RAM副本：D预读当前行，EX/MEM按年龄计算更新，再镜像写预测副本。
  原方向查询token不保存过期计数器来冒充当前状态。
- full可能同拍解析老MEM和年轻EX分支。每拍最多发射一个控制、E/M解析相差一拍，
  因此任意窗口的更新数至多比单写口服务数多一条，一个待写项可吸收这种峰值。
  F1/D查询旁路该待写项，保持逻辑模型的即时按年龄更新语义，不另加训练停顿。
  这一队列/旁路是本轮RAM电路预算的假设，尚没有RTL验证。
- F1提前计算待写项的index/tag命中并注册，F2将旁路命中并入末级标签比较；
  不把完整RAM字先mux再串比较。额外路径为`HFF+6Q=5.643 ns`，没有增加F2纠正拍数。
  训练副本、读/待写寄存、双查询旁路的增量均计入后述预算。

方向状态位数 `8192(F1)+12(GHR)+8192(base)+T×E×16+max(history)`，不含 BTB/RAS；
查询侧表另为 `16×[T×(log2(E)+10)+5]` bit；
新增训练副本另占 `8192+T×E×16` bit。表中这三项分别报告，DRM同时计入各副本和分bank碎片。表中的“控制误预测”包括方向和目标错误，
括号内仅条件分支方向错误；同时列 F2 纠正，F2 纠正不是退休分支误预测。
保留 tournament4096（21004 方向状态 bit）对照，full 的该行与基点完全相同。

### 实现模型：一个 LSU 的双 load

注册版本 `load64/128/256` 的 D 只按类型、RAW 和已存在的操作数就绪条件接纳两个独立 load；**D 不读取未来有效地址来决定配对**。
两个 AGU 均在 EX，两个 load 都按普通延迟 2 返回，取消这组的 ID 提前返回。
EX 形成并注册两地址，在 MEM 并行比较地址/资格和读数据：必须同落在一个对齐的 8/16/32 byte RAM 读块，
每个完整访问均不能跨该读块，而且都是普通可缓存地址，才一次读出并分别提取/扩展两个结果。
64/128/256 位分别覆盖同 64 位字、同 128 位块、同一 32 byte cache 行。

另外重放 `load64/128/256-early`：保留老 load 的已有 ID 提前地址，在其 EX 宽读同时由
年轻 EX AGU 比较地址，匹配时同时返回两结果，不匹配则计补读 hold。这样可隔离普通返回延迟的代价；
但年轻基址旁路、加法、比较/资格串到同一个 EX 终点，预算
`HFF+2MUX+ADD32+3Q=6.262 ns`，加0.450后为6.712 ns，仅规划140/压力125 MHz，
不能用它的较短周期回答保持150/135的目标。`combo4-load-early`另与TAGE4/双bank组合重放。

若地址不同块，单 LSU 第二次读增加一个注册全流水 hold，按真实年龄顺序完成；
这不是第二 LSU，也不是用“同一行但分两次读”冒充一次返回。
该保守补读模型使后继不能偷偷占用补读周期；两个目的沿用 2W 写回和年轻 WAW 优先。
覆盖率分母是实际接纳的 EX 候选组，覆盖分子分别检查 8/16/32 byte，而非所有相邻 load 的静态计数。
注册版本采用全流水补读冻结，三个读宽在同一候选分组上比较；early版本会因结果提前而改变后续分组，
组合也另行重放。各覆盖率按本行实际EX候选统计，不能代替普通返回延迟、补读和降频之后的净收益。
这仍继承第三轮命中后端的局限，未声称精确覆盖 refill、store-buffer 或维护操作的所有争用。

store+load 与 load+store **不能直接套用两读合并**：store 是有字节掩码且有提交/异常顺序的写事务。
同字 store+load 需要年轻 load 看到老 store 的逐字节合并/转发，异字还需要一读一写端口与脏位仲裁；
load+store 必须返回写前值，并把年轻 store 保留至允许提交。
采用真双口 RAM 加 store buffer 可另做一读一写，但须定义 RAM read-during-write 和年龄/异常协议，
不是“一次读同时返回两个 load”的同一功能。本轮仍单 LSU，不给混合读写组合计收益或加入实现。

### 实现模型：双 bank 取指、Zba、RF

I$ 数据按 32 位字奇偶分两个 bank，对任何 4 byte 对齐 PC 读 `PC` 和 `PC+4`，
在 IF/F2 内按奇偶交换到固定双槽；遇行尾同时探测两行，miss 增量停顿也计入。
BTB 从 8 byte 组索引改为 4 byte 字索引，仍总计 128 项、按奇偶各 64 项；
两个字各查一次方向和目标，选择最老的 taken，仍只投递一个目标和每组一个控制。
因此没有悄悄把 BTB 容量翻倍，也不能预设误预测数与基点相等。
F2 同时保存和纠正两个查询；第一条纠正可暴露/丢弃第二条 call/return，RAS 动作按原快照修正。
TAGE 的 PC-XOR-history 索引奇偶在相邻字之间相反，基表/标签表可奇偶分 bank，各增加半个 DRM 的碎片成本；
tournament 的局部计数索引不保证不同 bank，另计读副本及选择资源。
与第三轮 128 位对齐取指的重放并列，64 位方案不引入四字对齐器或加大 ID/RF 选择。

Zba 只重放既有 `build/cpu-v2/isa/zba/` 的 GCC15.2 / Spike 输入，不重编译或修改软件。
`sh1add/sh2add/sh3add` 的 1/2/3 位移位是固定连线，不经 barrel shifter，
在已有 ALU 输入选择内编码，关键段恢复为普通加法路径；保留 +128 LUT 的双槽译码/输入预算。
模型也把这三种操作明确识别为固定移位加法，允许使用相同晚简单 ALU（延迟 2）的依赖规则；
晚ALU识别将它们按常数移位加法处理，不使用普通动态移位的时序预算。
没有涉及 RV64 的 add.uw，也没有评估 LUT/进位链部分级联。

RAM RF 的 4R2W 方案是两个写 owner bank × 四个读副本，每份 32×32，合计 8192 数据 bit；
31 bit FF LVT 保存 x1..x31 的最新写 owner，x0 硬连零，同址双写选年轻写。
每读口由 LVT 选两个 owner 的返回，再做 WB 转发，WB 不依赖 RAM 同址读写模式。
异步读和同步读保持同样的架构寄存器与端口语义：

| RF 结构（估算，不含其余核） | LUT | FF | RAM | 对流水的影响 |
|---|---:|---:|---:|---|
| 原 FF 4R2W | 2235 | 992 | 0 | 原 D/RF |
| 异步 RAM + LVT 4R2W | 652 | 127 | 8×32×32，256 LUTRAM 已含在 LUT | 无新增流水级 |
| 同步 RAM + LVT 4R2W | 396 | 335 | 8 个 RAM18K，即 4 DRM36K | D1 发读，D2 选 owner/转发/AGU；解析、记分牌和恢复均多一级 |
| 小配置异步 RAM 2R1W | 160 | 64 | 2×32×32，64 LUTRAM 已含在 LUT | 不需要 LVT 或双 owner 选择 |

652 LUT = 256 数据 RAM + 128 owner 选择 + 128 WB 转发 + 64 写译码 + 32 LVT 控制
+ 44（四个32选1 owner读树）；
127 FF = 31 LVT + 64 写回控制/数据捕获 + 32 本地控制。
同步 RF 移除 256 LUTRAM，加 128 读数据捕获和 80 新流水负载 FF；
八个浅 RAM18K 实际占 147456 宏容量 bit，只利用 8192 bit，不能只报逻辑容量而忽略碎片。
小配置沿第一轮拆分，把 FF RF 的 LUT 份额记为 `2235−1110=1125`，替换为
`64 RAM + 64 WB + 32 decode=160 LUT`，FF 从 992 到 64；此拆分同样是预算而非综合证据。

异步 RAM 是技术包装所需的读延迟契约；不支持异步 RAM 的目标不能无代价地套用异步性能表。
同步方案实际启用已有 `decode_split` 模型，包含新增 D1/D2 的就绪/分支/训练与恢复相位；
没有额外再加一次已由该模型计入的误预测罚拍。
ASIC 上可包装同样的复制 1R1W 宏，或用原生 4R2W RF 宏折叠副本；需要维持相同读延迟、
同址双写优先和 WB 转发契约。同步/异步宏对应各自的流水配置，ASIC 不必沿用 FPGA 的 RAM 碎片，
但不能把 ASIC 宏接口改变后仍引用另一配置的周期。因此 IP 的微结构/语义可移植，资源数字仍针对本轮 FPGA 预算。


#### 异步 RF 的 F2 owner 预解码方案

普通异步 LVT 的瓶颈是 D 中 32 选 1 owner 查询，不是 RAM 数据读。
另估算一个仍为 4R2W、无新增流水级的放置方案：F2 根据两条指令的 rs 字段并行读取 LVT，
将 owner 随 IB 保存；每个存活 IB 操作数在任一 WB 写中同寄存器时更新 owner，双写同址按年轻写优先。
D 只使用注册 owner，当前 WB 数据照常旁路。`QueuedOwners` 功能模型覆盖队头等待期间 owner
反复切换、当前 WB 旁路、双写同址、同拍写后新入队及 x0；这不是预测 owner，也没有用未来值。

双 bank 取指不能先对齐指令再串上 LVT 查询，否则额外 MUX 会破坏频率。
本方案在两个物理数据 bank 后分别查询 LVT；每个逻辑 IB 项保留两份候选 owner（每源2 bit）及一个
物理 bank 选择位，共5 bit/指令。D 的一位 owner 选择与数据 RAM 读并行；指令本身仍送固定逻辑头寄存器。
WB 命中时两份候选都更新为同一个新 owner，未选候选的旧值不影响语义。
这样无需把 F2 末尾对齐再串成一级，也无需把 RF 地址选择加到 D 的 RAM 读之前。

估算额外资源：令 `K=IB_depth+2`（含两个输入项），LUT 增
`4K×3(5-bit compare)+2K(owner使能)+32(WB局部分发)+4(D头owner选择)`，
即 default 的120、full 的176 LUT；四个LVT查询共44 LUT从D移到F2，已在652 LUT基数中。
FF 加 `5K+14`，即44/64 FF。
本地 WB tag 控制在相同 W 边沿复制为两个区域，每区比较扇出不超过16；14 FF 是新增副本，
不是晚一拍才修正 owner。队列和输入按注册边界同拍更新，吞吐/停顿语义与原异步 RF 相同。

| 新方案关键段（估算） | 公式 | ns（未含0.450） |
|---|---|---:|
| F2 物理 bank 到 LVT 到 WB 优先 | HDRM+3MUX+MUX；WB五位比较与LVT查询并行 | 5.746 |
| D 注册 owner 到数据/WB/AGU | HFF+1.700+2MUX+ADD32 | 5.736 |

两段都小于保留的5.796 ns核预算，因此仍估算150/135 MHz；F2余量仅0.050 ns，
**必须以该物理 bank 前置查询和候选 owner 寄存结构为条件**，不能把此频率套回普通 D 内 LVT。
所有操作是普通比较、寄存和 mux，ASIC/其他 FPGA 也能实现，不依赖 LUT/进位链运算级联。
最终需综合和 STA 确认这些输入假设；当前不能将0.050 ns称为已验证裕量。

这使 RF 模块预算从原2235 LUT/992 FF降为：default 的772 LUT/171 FF，full 的828 LUT/191 FF，
仍是8192数据bit、256 LUTRAM已含在LUT，新增 owner 元数据为44/64 FF的一部分，不加DRM。
`rf-head` 与各 `-head` 行使用其异步读配置的**同一次独立周期重放**，仅另外计算上述放置/资源；
`HEAD_ALIASES` 显式列出对应关系，不把它们冒充新的吞吐测量。
普通异步LVT、同步LVT和F2预解码LVT分别给出F/R，因此不会把普通异步方案的低资源和不同结构的频率混用。

### 关键段和资源估算公式

继续调用 `v2_estimates.py` 的输入：`Q=0.742 ns`、`HFF=1.191 ns`、`HDRM=2.574 ns`、
`ADD32=1.259 ns`、`MUX=0.793 ns`，未建模布线/时钟余量 `0.450 ns`。
`T=max(各关键段)+0.450`；规划 `F=5×floor(1000/T/1.05/5)`，
压力 `F=5×floor(1000/T/1.182/5)`；`CLM=ceil(max(LUT/4,FF/8)/0.70)`。
保留原核最坏段 `HFF+3MUX+3Q=5.796 ns`，不因局部变短就宣称整核升频。

| 候选新增关键段（估算） | 公式 | ns（不含 0.450） | 总周期/规划/压力 |
|---|---|---:|---|
| TAGE F2 / 双 bank IF | HDRM+4Q：标签比较两级，屏蔽/优先与结果归并两级；长历史用注册折叠 | 5.542 | 6.246 ns / 150 / 135 MHz |

这些是功能路径预算，不使用特定 FPGA 的算术级联映射。标签比较/优先网络、RF 宏读延迟、
每 bank 的真实宽度/深度和 SoC 额外拥塞仍需 STA/综合验证。异步数据 RAM 的读假设为1.2+局部路由0.5 ns，
但 LVT 是四个32选1的 FF 读口，三层 MUX 必须计入；它成为临界路径，把4R2W异步方案降至135/120，
因此不进入保持150/135的推荐。同步方案在D1/D2边界捕获LVT owner，避免把该选择串到D2数据路径；
小配置2R1W无需LVT，仍为150/135。不能把异步RAM“功能上无新增流水级”理解为频率必然不变。
150/135 是相同假设下的规划/压力场景，CM/MHz 本身与 F 无关。

资源以两个起点中心预算 9457/5347、12898/6897 LUT/FF 为基础，所有增量在
`v2_round4_estimates.py` 可执行：
TAGE 每表 `32(hash)+6(tag compare)+16(counter/usefulness)+16(update)=70 LUT`，
共享选择64、基本更新转发96 LUT，查询侧表 `2×key_width LUT`，
再加每表64 LUT用于训练行与待写旁路。FF总增量为 `max(history)+64T+128`；
预测表和独立训练副本各需 `(T+1)` 个RAM18K，即各`0.5(T+1) DRM36K`。
替换 full 的 tournament 专属预算减1010 LUT/186 FF，保留 RAS8、全 HPM 和原快速 gshare；
default 的 tournament 对照则加相同专属增量。
双 bank 加 `64(lane)+32(predecode)+64(addr)+64(BTB)=224 LUT/96 FF`，
TAGE 双查再加 `38T+64 LUT/16T FF` 和每表第二个 RAM18K bank；
tournament 局部读副本另加112 LUT/64 FF。
双 load 加 `128(第二AGU)+32(compare)+32(qualify)+64(replay)+64×log2(read_bytes)` LUT、160 FF；
D$ 容量不变，读宽用同容量 RAM 的并联/分段实现，故仍沿用 cache 的18 DRM总预算，未凭空复制 D$。
128 位取指在 default 增至8条IB，单列 +336 LUT/+448 FF；full 原本已有8条，只加256 LUT/128 FF，
不重复增加四条IB。Zba +128 LUT；RF 直接替换上表模块预算。
逻辑 RAM bit、按宏取整的 DRM 与 LUTRAM 分开报告；LUT 中已经包含分布式 RAM，不能再加一次。

### 五个方向的结果解读

TAGE并不是表越多就按比例省周期。以4×512为例，default相对tournament4096的CM周期
从1,748,024降至1,723,528，full从1,682,765降至1,654,948；两基点的CM方向误预测
分别从27,568/28,473降至15,708/16,214。F2纠正已经进入周期。
但full视觉由1,206,476增至1,210,446，说明更低CM误预测不能直接代表所有负载收益。
从4×512扩大到5×1024，CM单项只再省1168/1542周期，方向状态却从49260增至98460 bit，
加训练副本后的存储成本也上升；选择四表是资源与三负载的折中，五表峰值单列。
这些结论只针对本节定义的查询过滤历史/分配策略，尚未评估完整解析历史、loop或SC。

同字/同行双load在CM的覆盖率不足以抵消补读及取消提前返回的代价。
default三读宽覆盖11.57%/13.44%/15.13%，full为13.11%/14.71%/15.87%。
256位注册方案在两个CM基点分别多17656/19729周期；在LVGL则省4570/4565周期，约1%。
视觉的覆盖率较CM高，default/full同一行约46.76%/42.89%，但净周期仍分别多778/5766。
保留老ID宽读的early方案只小幅改善这些周期，又落到140/125预算，因此不进入150/135推荐。
组合中256位读也使CM回退，例如full `combo4-load` 比 `combo4` 多19289周期，
虽然LVGL另省3791周期。这是一个可按访存负载取舍的选项，本轮CM档关闭。
全流水补读是本轮的保守实现；若改为只占LSU队列、允许无关ALU继续执行，需另建明确的预约/返回模型，
不能把这里的负收益泛化为所有双load实现都无效。

双bank取指在default/full分别省25490/25833个CM周期，规划P×F为856.62/905.29，
优于128位对齐取指的767.31/816.12。full的pair_one CPI由0.018734降至0.008613，
控制误预测数也随BTB字索引与训练相位变化，故不能把净周期全部归到pair_one。
128位取指在full虽少2770周期，但135/120预算抵消了收益；它与任意4字节起点的双bank不是同一个结构。

Zba取消多余选择级后，单项恢复150/135预算，CM在default/full分别省19327/21373周期，
但视觉单项周期却增至1,621,270/1,551,453，LVGL为458497/434946，也并非必然加速。
视觉pair_one CPI从0.007316/0.007405跃升至0.216433/0.226739，
同期误预测CPI反而下降；回退主要落在重编译后前端供给/分组相位。
在双bank+TAGE4组合上，Zba视觉pair_one回到0.001967/0.003128，
周期为1,223,020/1,169,941，显示ISA与取指布局必须组合评估。
“目标后”和“顺序”两类不足都显著变化，未把它们全部解释为尾字目标。
固定连线的时序修正是必要的；实际速度还取决于新trace的相关链、布局和预测。

普通异步LVT虽少用逻辑，但D内owner树把预算降到135/120；同步LVT保持150/135，
却增加D1/D2、就绪和恢复成本。default同步RF三个周期相对基点增加约3.60%/3.29%/4.98%，
full增加约3.25%/2.65%/4.81%，并加4 DRM。
这些数字使用正确的D2提前地址资格：当前D2/E在下一拍是EX/MEM，不能作为RF/WB提前基址；
当前MEM在下一拍是WB，可按原WB条件使用。新增用例同时检查这两个方向。
F2预解码LVT保留原异步周期，并显式计入查询、候选owner寄存和WB更新，作为主推荐的资源压缩手段。

### 结论和三档建议（设计提案）

**在相同150 MHz规划 / 135 MHz压力预算下，本轮模型可以超过6 CM/MHz。**
原RV32IM满配的 `combo4-head` 为6.1285，`combo5-head` 为6.1426；
Zba峰值 `combo5-zba-head` 为6.2651。三者都没有使用运算级联技巧或更低频率。
这里的“可以”以所列电路路径/宏读延迟/布线预算成立为条件，不代表已有RTL实现或板上成绩。

默认基点单独加入本轮方向的集合，最高为 `combo5-zba`（及其head RF等周期版本）的
5.9931，仍不足6；不能把满配已经拥有的早/晚ALU收益暗中算到default上。
小配置单发射3.7059也不达6。达标结论来自满配，不能声称三档都超过6。

建议三个主档保持原RV32IM软件口径：默认、小配置优先减少资源并保持三负载原周期，
满配用TAGE4×512/双bank/预解码LVT，在压缩逻辑资源的同时超过6。
Zba作为明确增加ISA的可选吞吐点，另列四/五表候选；不因CoreMark峰值最高就默认保证所有软件都更快。

默认建议 `default/rf-head`：保持原gshare4096、64位对齐取指、4条IB、基2提前结束除法器、2HPM和原三负载周期。
LUT/FF降15.47%/15.35%，DRM仍18，CM面积效率由89.28提高到105.62（规划P×F/kLUT）。
同步RF的CM面积效率中心值106.98略高，但需要22 DRM，并有前述三负载周期代价。
推荐head的依据是保留三负载周期和RAM宏预算；若优先接近6，可按表选择TAGE5/Zba增强点，
其5.9931仍需至少再省1922周期才到6，且DRM为27。

满配建议 `full/combo4-head`：保留第三轮早/晚ALU与条件分支、单MUL双槽、JALR双槽、8条IB、
基4提前结束及8HPM，加入TAGE4×512、双bank取指和F2预解码LVT。
CM/视觉/LVGL相对第三轮满配的同工作量速度分别提高约3.13%/0.58%/2.61%；

规划P×F从891.39增至919.27，规划P×F/kLUT从69.11增至78.04。
四表选择避免为五表约0.23%的CM增益再付一个表和训练副本。
若启用Zba，四表组合为6.2536、11907 LUT；五表模型峰值为6.2651、12127 LUT，

Zba四表与五表CM仅差2925周期（约0.18%），因此同时报告，不把极小差异称为硬件定论。

小配置建议 `small/rf-async`：保持单发射、gshare4096/BTB64/RAS4、0HPM、基2提前结束，
仅将RF改2R1W异步RAM；没有LVT owner树，150/135预算和三负载周期均保留。
