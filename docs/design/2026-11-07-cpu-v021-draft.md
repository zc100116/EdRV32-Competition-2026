# CPU v0.21 / cache v0.12 / testplan v0.8 审阅草稿

## 背景和问题

输入 `23fcd74c`；卡62 150 MHz WNS −0.752 ns，目标150 MHz。本文是协调者审阅材料，不是规格，状态：用户撤回，改为 e + d0；流水结构保持 v0.20，等价修复与独立路预测试验并行。
D$ tag DRM→m_result_r 仍为−0.394 ns/5级，因此只寄存选出的load结果不够。

## 约束

Verilog-2001；FF/LUTRAM≤6级、DRM≤3级；≥4级路径的负载>16必须复制。
不修改乘法/除法结果延迟，不引入配置参数；规格审定前不修改流水级、延迟或接口。

## 可选方案与推荐决策

推荐F1/F2/IB/D1/D2/E/M/M2/W/W2；IB是队列，不计执行级。
M2在D$内捕获每路原始tag/data，比较、选路放在捕获之后，core同步保存对应指令记录。
仅寄存命中路或扩展后的数据仍保留DRM→tag比较→mux→FF路径，不选。
预译码移到D1：IB只存指令和预测元数据，D1译码、配对和预约后寄存完整控制字段。
这样I$ tag/F2 payload→IB写端不再串联译码，D1→D2的新边界承担译码延迟。
D2不得重新配对；下游停顿时保持整组，冲刷按程序顺序取消预约。

### 旁路结构和工具实测

D1提前比较rd/rs并寄存候选；D2按实际保持/推进位置确定独热源；RF和M/M2/W寄存结果先与或树合并，E ALU/提前load数据在末级合并。
ALU反馈不能经过M/M2/W优先编码链；W valid/rd/dest匹配在D1前移。
CSR/HPM在M2读出，W捕获；M2本拍CSR读取按结果延迟3提供旁路，计数器选择从D2预先寄存到E/M/M2。
新增来源的最终工具级数/扇出在RTL后填写，当前尚未测量；不以结构估计冒充实测。
