# 决赛场景 2：正式版手部交互应用

## 1. 背景和问题

- 决赛演示分两个场景（用户 2026-11-15）：
  1. 普通目标检测，例如监控计数；
  2. 手部 21 关键点模型与渲染交互。基本操作是用手抓起、拖动、放下物体，以此驱动一个自研的弹弓类游戏：同类玩法，美术和关卡都自己做。
- 用户 2026-11-16 要求开始做场景 2 的正式版应用。
- 已取代 `2026-11-14-finals-demo-pose-game.md` 第 4 节中"人体关键点 + 上半身手势"的建议。

## 2. 约束

- **比特流**：以卡 75 为演示版本，开启硬件后处理，clk_sys 125 MHz、clk_npu 180 MHz；卡 89 是 NPU 150 MHz 的备份。
- **识别**：
  - 实时识别 27 fps（中位数），每帧周期 35 ms，受 NPU 限制；
  - 摄像头到结果的端到端延迟约 78 ms（卡 75，中位数）；
  - CPU 解码约 0 ms，CPU 余量主要留给界面和游戏。
- **手部输入**（卡 85、88 和手部 v2 模型待定）：
  - 光标：手的位置，取关键点或检测框中心，做一阶平滑；
  - 抓取状态：
    - 模式 C 按模型类别判断：握拳或抓紧算抓，张开或四指算放，其他手势保持当前状态；
    - 或模式 A 两指捏合。
  - 卡 85 中抓住状态的保持时间偏短；R2 加了滞回和防抖，卡 88 正在复测。
- **显示**：
  - DISP 两层：L0 是 RGB565 摄像头画面，L1 是 ARGB8888 界面层，按像素 alpha 叠加；
  - 界面由 LVGL 绘制，RND 加速：填充、拷贝、缩放、翻转、半透明、调色板，**不支持旋转**；
  - LVGL 整屏重绘较慢（benchmark 平均每帧 43 ms），游戏只能局部刷新：运动物体的数量和面积都要控制。
- **CPU**：rv32im 没有 FPU，物理计算用定点数。
