## 2. 约束

**待用户确认的口径**：协调者在本任务 ask 答复中允许按 LUT/FF ≤80%、DRM/APM ≤90% 起草；这尚未变更规格或原始任务的 80% 要求。

## 3. 可选方案

**A：按整时钟区分大块。** CPU = 左 Y3–Y4，NPU = 右 Y0–Y3，mem+DDR = 右 Y4，其余左 Y0–Y2。
优点是 CLM 容量直接取整区、不依赖面积插值；缺点是 mem+DDR `17336/12800=135.44%` LUT、`28/30=93.33%` DRM，剩余左区 `40446/49800=81.22%` LUT（按 1.1 表逐项相加），不能满足调整后的口径；32 KiB 亦不成立。

**B：细分左侧，mem 的监视器/rbuf 外移，DDR 与 NPU 共用右下大区。** 推荐作下一次 PCE 试验草稿；不改 RTL，不绑定父子嵌套区域。
拆分依据 F10：`u_mem/u_perf_mon` = 3833/2552/0/9，`u_mem/u_xbar/u_rbuf` = 1802/1214/4/0；mem 剩余 = 6998/5907/24/0。
优点是每份硬块只计一次、CPU 独立，并能容纳暂估 +8 DRM；代价是 CPU、RND 的 LUT 接近上限，mem 内部和 DDR 口增加长线，ETH 到 L3 的距离也较长。

## 4. 决策

推荐 **B（条件草案）**，不宣称已满足布局/时序验收。下表与草稿 FDC 同名；资源列顺序均为 LUT / FF / DRM / APM。
部分时钟区的 CLM **容量也是估算**：整区容量乘矩形交集面积比例，再相加；FF = 2×LUT。无完整 CLMA/CLMS site 表，不能把面积当实际可放容量。
例如 CPU LUT = `15600×25/50×77/122 + 13800×77/92 ≈16473`；DISP 为同一上部左区 21600 减 CPU。其余左区按各行占比；右区为整时钟区相加。

|---|---|---|---|---|

| fp_disp | (77,121,175,249) | ≈5127 / 10254 / 10 / 20 | 2917 / 3886 / 8 / 7 | 56.89 / 37.90 / 80 / 35 |

各区域矩形不重叠；硬块容量和为 DRM 415、APM 740，没有重复借用。fp_sysio = sys+ETH/RGMII+rbuf；fp_media = VIN/PIX/GEO+perf_mon；fp_npu_ddr = NPU+DDR。
32 KiB 使用**相同矩形**，仅 fp_cpu 变成 `13150+ΔL / 7353+ΔF / 14 / 4`；DRM 35%，LUT/FF 为 `(13150+ΔL)/16473`、`(7353+ΔF)/32946`，其他区不变。CPU LUT 仅约 `0.8×16473−13150=28` 余量，T-IC1 若增加更多 LUT 就要移动边界重算，不能保证此分配成立。
NPU 级联：32 条×8 APM =256 子单元=128 站点；每链同列连续 4 站点。右区三根全列各 40 槽、两根内列各 30 槽，共 180 站点。
即使不跨时钟行，每列每行 `floor(10/4)=2` 链，提供 `3×4×2+2×3×2=36` 个链位置 ≥32；其余 NPU APM `290−256=34` 子单元另需至少 17 站点。此为容量推导，U/D 顺序、链合法性和实际打包仍由 PDS 验证；不按插值锁死 PAP_LOC。

### 4.1 约束草稿与验证边界

草稿：`fpga/constraints/edrv32_fpga_board_b2_top_regions.fdc`。依据 UCE V1.7 PDF 89–90、95–96 页、指南 2.1；卡 11 `b3v-placement.fdc` 确认 `define_attribute {i:...}` 与点分层次，未包含已验证的全局区域实例。
只写一条全局 PAP_REGION，分号分隔矩形，类型 `[CLMA,CLMS,APM,DRM]`；单对象逐行关联，不复制导出文件的忽略缺失实例选项。
mem 为避免父子属性冲突，只约束 gw、P6 仲裁、perf_mon、xbar 的 regs/sched/rbuf 和六个 W RAM；mem/xbar 的直属胶合逻辑未被这些子模块属性覆盖，预算计入 fp_mem，具体位置仍未约束。草稿不承诺完整封闭 mem 区域。
静态复核：`git diff --check` 通过；`tclsh build/floorplan-input/check-regions.tcl` 的 stub 读取通过（7 区、24 个关联，不等于 PDS 语义验证）；按指南公式清点 M11 全部硬块，无重复/遗漏，合计 415 DRM/740 APM；关联实例名与 RTL 核对通过。用 `git show <上述提交>:<文件>` 可复取输入。未运行 PDS、未取得部分区域 PCE Statistics；不需要 RTL 仿真或 lint。

## 5. 影响

以下仅列出**需要评估打拍**的接口；没有 STA 证据前不把候选写成确定必须增加寄存器。AXI 必须同时处理 payload、valid/ready、五通道顺序及 outstanding，不能只寄存数据。

| 接口 / 区域边界 | 候选寄存位置 | 规格 / RTL / 测试影响（后续决定，本任务不改） |
|---|---|---|
| P0 DISP、P1 VIN、P4 GEO、P5 RND、P6 ETH → mem AXI256 | 左区出口及右上 mem 入口，双向响应同侧处理；P2/P3 分别见下 | SoC 4.2、mem-xbar 吞吐/仲裁；各主口及 xbar 加流水须验证突发、响应顺序、背压和持续吞吐 |
| CPU/sys → DDR 网关 AXI64（P2） | CPU/sys 出口、网关 sys 侧入口 | 保留 X2 异步桥；SoC 5.2、cache miss/维护与 CPU 性能重测 |
| NPU AXI256（P3）、APB 槽 6 | X9/X10 已有桥的 mem 侧，靠 fp_mem；NPU 内桥仍在 NPU 边界 | 不替代 CDC；桥后弹性流水影响 outstanding/延迟，NPU DMA/APB 回归 |
| mem → DDR adapter/UI AXI256 | fp_mem 南侧出口及 fp_npu_ddr 的 DDR UI 入口 | SoC 4.2、DDR 网关；检查 AXI ID/突发写数据与应答顺序，带宽、STA 重测 |
| xbar ↔ rbuf；xbar → perf_mon | fp_mem 出口与 fp_sysio/fp_media 接收侧 | rbuf 读延迟、满/空信用和调度依赖可能变化；perf 事件与标签须对齐，涉及 mem-xbar/perf 规格及验证 |
| sys 媒体 APB、IRQ、复位/ready 到各区 | APB 目的区入口；IRQ/ready 按现有同步器接收侧；复位不随意加拍 | X1/X3/X8；APB wait-state、中断延迟/PLIC 行为、复位释放次序需逐项确认 |

FDC 草稿未接入现有 `.fdc` 或 `fpga/scripts/import_board_b2_top.tcl`；规格、RTL、测试均无修改。

## 7. 协调者审核意见（2026-10-31）

1. **方案 B 拆开了 mem_xbar**：rbuf 放进 fp_sysio，perf_mon 放进 fp_media，xbar 本体放在右上角 fp_mem，DDR 控制器又在 fp_npu_ddr。clk_mem 在 B3R 中只有 +0.072 ns 余量，xbar↔rbuf 的读返回路径属于关键路径，拆到不同区域风险最大。mem_subsys 应当整体放在 DDR PHY 附近（右侧 y≈100..178）。
2. **补充方案 C**：mem_subsys、DDR 控制器、NPU 合成右半区一个区域（x124..238，全高）。按 1.1 表逐项相加估算：
   - LUT 19700 + 17336 = 37036 / 80800 = 45.8%；
   - DRM 156 + 28 = 184 / 210 = 87.6%；
   - APM 290 + 9 = 299 / 420 = 71.2%。
