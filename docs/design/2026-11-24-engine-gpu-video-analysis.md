## 2. 他们做得好的地方

1. **演示结构清楚**：同一款游戏先展示正常玩法，再进入压测模式，最后现场切换 CPU/FPGA 对比；屏幕上始终显示精灵数和帧率。
2. **游戏完成度高**：武器商店和升级、伤害数字、Boss 血条、多种弹幕图案，看起来像真游戏，而不只是技术测试。
3. **原创 3D 游戏有统一的美术风格**：低多边形加平涂和冷色调，三角形不多但画面好看；HUD 和任务提示用中文。
4. **微基准逐项量化**：每项都给出渲染 µs 和 CPU 对照。

## 3. 局限（他们画面上的数字）

- 第一人称 3D 只有 8–14 FPS，敌人是 2D 公告板，不是 3D 模型。
- 3D 测试场景只有 92 个三角形。
- 2D 压测在 3680 个精灵时约 59 FPS，与千影（2300 个目标，60 FPS）同一量级。

## 4. 对我们的启示

| 借鉴 | 我们的做法 |
|---|---|
| 每个游戏都有正常模式和压测模式，HUD 显示对象数、三角形数、帧率、GPU 时间 | 写进各游戏的公共要求；GPU 时间读 PERF 计数 |
| 现场 CPU/GPU 对比 | 测试与展示第 13 项；能对比的游戏都提供切换 |
| 游戏性元素（升级、Boss、飘字、音效） | 玩法确认时逐项定 |
| 原创 3D 游戏用统一的低多边形美术风格 | 3D 游戏采用同类思路，题材另定，不做深海潜航 |
| 超过他们 | 3D 用真正的三角形模型，在 60 FPS 下达到数万个三角形；2D 用对象单元做万级弹幕 |

不复刻他们的具体游戏（群怪生存武器表、深海潜航）和素材。
