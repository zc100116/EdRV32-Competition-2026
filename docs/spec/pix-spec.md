## 1. 概述

PIX 接在 VIN 的选路和 CH0 写 FIFO 之间（`vin-spec.md` 1、3）。它从 VIN 接收一帧像素流（SoC 4.5，`pix_in_*`），按固定顺序做四级处理，把同样尺寸的一帧送回 VIN（`pix_out_*`）：

```
pix_in ─ 展开 RGB888 ─ 点运算 1 ─ 3×3 第一级 ─ 3×3 第二级 ─ 点运算 2 ─ 截断 RGB565 ─ pix_out
                       亮度/对比度    S1_OP          S2_OP        灰度/二值化/反色
                       Gamma 查表
```

- 时钟域：全部在 clk_mem；复位 `rst_mem_n`（系统子系统规格 2.10，媒体软复位）。
- 没有 DDR 端口；寄存器在媒体 APB 槽 2；中断为 PLIC 源 9。
- PIX 是独立模块，在媒体子系统顶层与 VIN 连接（`vin-spec.md` 3）。

## 2. 功能描述

### 2.1 像素表示

- 输入、输出都是 RGB565，每拍 2 像素，低 16 位是左边的像素（SoC 4.5）。
- 入口把每个像素按位复制展开为 RGB888：`R8 = {R5, R5[4:2]}`，`G8 = {G6, G6[5:4]}`，`B8 = {B5, B5[4:2]}`。四级之间一律传 RGB888。
- 出口截断回 RGB565：`R5 = R8[7:3]`，`G6 = G8[7:2]`，`B5 = B8[7:3]`，不舍入。
- 灰度：`Y = (77·R8 + 150·G8 + 29·B8 + 128) >> 8`，结果 0–255。需要灰度的运算都按此式从 RGB888 计算。
- 输出灰度结果时 `R8 = G8 = B8 = 结果`。

### 2.2 点运算 1

对每个像素的 R8、G8、B8 分别依次执行：

1. 亮度/对比度（`CFG.BC_EN = 1` 时）：`c' = clamp(((c − 128) · CONTRAST) >>> 8 + 128 + BRIGHTNESS, 0, 255)`。`CONTRAST` 为无符号 9 位 Q8（0x100 = 1.0），`BRIGHTNESS` 为有符号 9 位；`>>>` 是算术右移（向负无穷取整）。
2. Gamma 查表（`CFG.GAMMA_EN = 1` 时）：`c'' = GAMMA[GAMMA_BANK][c']`。三个通道共用一张表。

### 2.3 Gamma 表

- 两组表（bank 0、1），每组 256 项 × 8 位。
- `CFG.GAMMA_BANK` 选择本帧使用的组，与其他配置一样在帧开始时生效（2.6）。
- 软件经 `GAMMA_WR`（4.2）逐项写入任一组，写入立即生效。软件应写当前不使用的组，写完后改 `GAMMA_BANK`；写正在使用的组时，当帧的结果未定义。
- 表内容不复位，复位后未定义；使用前软件必须写入。

### 2.4 3×3 级（两级结构相同）

每级由 `CFG.S1_OP` / `CFG.S2_OP` 选择运算。窗口中心为当前像素 `p11`，`p00`…`p22` 按行列排列。图像以外的邻点取 0（R8 = G8 = B8 = 0，Y = 0）。

| OP | 运算 | 计算对象 | 定义 |
|---|---|---|---|
| 0、7 | 旁路 | — | 输出等于输入，不经过行缓存 |
| 1 | 均值 | R8、G8、B8 分别 | `floor((Σ p + 4) / 9)` |
| 2 | 高斯 | R8、G8、B8 分别 | 核 `[[1,2,1],[2,4,2],[1,2,1]]`，`(Σ w·p + 8) >> 4` |
| 3 | 锐化 | R8、G8、B8 分别 | `clamp(5·p11 − p01 − p10 − p12 − p21, 0, 255)` |
| 4 | Sobel | Y | `Gx = −p00 + p02 − 2·p10 + 2·p12 − p20 + p22`，`Gy = −p00 − 2·p01 − p02 + p20 + 2·p21 + p22`，结果 `min(|Gx| + |Gy|, 255)`，输出灰度 |
| 5 | 腐蚀 | Y | 窗口内 9 个 Y 的最小值，输出灰度 |
| 6 | 膨胀 | Y | 窗口内 9 个 Y 的最大值，输出灰度 |

### 2.5 点运算 2

对每个像素依次执行：

1. 灰度（`CFG.GRAY_EN = 1` 时）：`R8 = G8 = B8 = Y`。
2. 二值化（`CFG.BIN_EN = 1` 时）：`Y ≥ THRESH` 时 `R8 = G8 = B8 = 255`，否则为 0。`Y` 由本步骤的输入计算。
3. 反色（`CFG.INV_EN = 1` 时）：每个通道 `c = 255 − c`。

### 2.6 帧边界和配置生效

- `CTRL.ENABLE`、`CFG`、`BC`、`THRESH` 是影子寄存器：PIX 在接收输入 `sof` 的那一拍，把它们的当前值锁存为本帧配置，整帧使用不变。
- 本帧 `ENABLE = 0` 时，四级全部旁路，输出等于输入（展开后再截断，等于原值）。
- 上一帧的最后一拍从 `pix_out` 送出（`eof` 握手）之前，PIX 不接收下一帧的 `sof`（`pix_in_ready = 0`）。因此同一时刻 PIX 内只有一帧。
- 一帧的行宽由该帧第一行（到第一个 `eol`）的拍数确定，行数由 `eof` 确定。行宽为偶数、不超过 1280 像素、各行等长，由 VIN 的帧整形保证（`vin-spec.md` 2.2），PIX 不检查。

### 2.7 帧末冲刷

- 每个启用的 3×3 级比输入晚 1 行输出。输入 `eof` 被接收后，PIX 用补零行把最后一行冲刷出来，输出像素数与输入相同。
- 输出始终被接收时，从接收输入 `eof` 到送出输出 `eof` 不超过 `2 × W/2 + 32` 个 clk_mem 周期（W 为行宽像素数；1280 宽时约 10.5 µs），远短于摄像头的场消隐（`vin-spec.md` 2.5）。

### 2.8 不完整的输入帧

VIN 中止一帧时（`vin-spec.md` 5.3 ABORT、SOFT_RST），送入 PIX 的帧可能在 `eof` 之前停止。PIX 在收到下一个 `sof` 时，如果上一帧还没有收到输入 `eof`，就丢弃上一帧留在 PIX 内、尚未输出的数据（不补齐，不输出该帧的 `eof`），计入 PERF3，然后从新帧开始。已经送出的部分由 VIN CH0 按中止处理。

### 2.9 流控

- 输出不被接收（`pix_out_ready = 0`）时 PIX 暂停，并经 `pix_in_ready` 反压输入。
- 除 2.6 第 3 条、2.7 冲刷外，输出始终被接收时 PIX 每拍接收 2 像素，不插入空拍。

## 4. 寄存器

媒体 APB 槽 2。公共寄存器按 SoC 7.1；寄存器块忽略 `pstrb`，按整字写（SoC 4.3）。未列出的偏移读为 0、写忽略。

### 4.1 公共寄存器

| 偏移 | 名称 | 规定 |
|---|---|---|
| 0x000 | ID | 0x0002_0001 |
| 0x004 | CTRL | bit0 ENABLE（影子，2.6），复位 0；bit1 START、bit2 ABORT 无作用；bit3 SOFT_RST（5.2） |
| 0x008 | STATUS | BUSY = PIX 内有帧（已接收 `sof`，尚未送出 `eof` 或被 2.8 丢弃）；IDLE = 非 BUSY；ERROR 恒为 0 |
| 0x00C | IRQ_EN | 复位 0 |
| 0x010 | IRQ_STAT | bit2 FRAME：送出一帧的输出 `eof`。bit0、bit1 恒为 0 |
| 0x014 | ERR_CODE | 恒为 0（第 6 节） |
| 0x020–0x028 | DESC_BASE、DESC_COUNT、DOORBELL | 不使用：读为 0，写忽略 |
| 0x02C | DONE_COUNT | 送出的完整帧数（自增，回绕） |
| 0x040–0x07C | PERF | 4.3 |

### 4.2 私有寄存器

| 偏移 | 名称 | 访问 | 复位值 | 说明 |
|---|---|---|---|---|
| 0x100 | CFG | RW | 0 | 影子（2.6）。[0] BC_EN；[1] GAMMA_EN；[2] GAMMA_BANK；[6:4] S1_OP；[10:8] S2_OP；[16] GRAY_EN；[17] BIN_EN；[18] INV_EN；其余位读为 0 |
| 0x104 | BC | RW | 0x0000_0100 | 影子。[8:0] CONTRAST（无符号 Q8）；[24:16] BRIGHTNESS（有符号）；其余位读为 0 |
| 0x108 | THRESH | RW | 0x0000_0080 | 影子。[7:0] 二值化阈值 |
| 0x10C | GAMMA_WR | WO | — | 写：把 [23:16] VALUE 写入 [8] BANK 组的第 [7:0] INDEX 项（2.3）。读为 0 |

### 4.3 性能计数器

32 位，回绕；复位和 SOFT_RST 清零。

| 编号 | 内容 |
|---|---|
| PERF0 | 送出的完整帧数 |
| PERF1 | 输入停顿周期：`pix_in_valid = 1` 且 `pix_in_ready = 0` |
| PERF2 | 输出停顿周期：`pix_out_valid = 1` 且 `pix_out_ready = 0` |
| PERF3 | 按 2.8 丢弃的不完整帧数 |
| PERF4–15 | 读为 0 |

## 5. 行为与时序

### 5.1 一帧的边界

- 一帧在 PIX 中的开始 = 输入 `sof` 被接收；结束 = 输出 `eof` 被接收，或按 2.8 被丢弃。
- 输出 `eof` 握手的同一拍：IRQ_STAT.FRAME 置位，DONE_COUNT、PERF0 加 1。

### 5.2 SOFT_RST

`CTRL.SOFT_RST` 写 1 后，PIX 在 STATUS.IDLE = 1 时（当前帧送出 `eof`，或按 2.8 被丢弃，之后尚未接收新的 `sof`）把全部寄存器（含影子寄存器和本帧配置）和内部状态恢复到复位值；在此之前照常处理当前帧，不接收新帧。Gamma 表内容不清除。

## 6. 错误处理

无。所有寄存器编码都有定义；帧尺寸和行长由 VIN 保证（2.6），PIX 不检查。

## 7. 性能与资源指标

| 项 | 指标 |
|---|---|
| 吞吐 | 2 像素/拍 @ clk_mem 125 MHz（250 Mpixel/s），除 2.6、2.7 的帧间间隙外不插空拍 |
| 延迟 | 每个启用的 3×3 级 1 行加不超过 16 拍；点运算各不超过 8 拍 |
| 帧末冲刷 | ≤ `2 × W/2 + 32` 拍（2.7） |
| 片上存储 | 每个 3×3 级 2 行 × 640 项 × 48 位（两像素 RGB888），共 4 行；用 DRM，经 `rtl/tech/` 包装（**[待定]** IP 规格，估算 6 个 DRM36K 当量）；Gamma 表用分布式 RAM |
| LUT | **[待定]** ≤ 3K（估算）。SoC 9.3 中 VIN + PIX + DISP 合计 10K |

测量条件：吞吐、延迟和冲刷时间由模块级仿真测得；资源由 Windows PDS 布局布线报告测得。

## 8. 验证要点

1. 每种运算的结果与 Python 参考模型逐位一致（2.1–2.5），覆盖边界：亮度/对比度的饱和两端、`CONTRAST` 0 与 511、Sobel 饱和、图像四边和四角的补零。
2. 两级 3×3 的全部 7 × 7 组合中至少包括：高斯 + Sobel、腐蚀 + 膨胀、膨胀 + 腐蚀、均值 + 锐化，以及与点运算 1、2 同时启用。
3. 行宽 2 到 1280（偶数）、行数 1 到 720；1 行和 1 列（2 像素宽）的帧。
4. 影子寄存器只在 `sof` 生效：帧中修改 CFG、BC、THRESH、ENABLE、GAMMA_BANK。Gamma 两组切换。
5. 随机输入间隙和输出反压下结果不变；输出始终被接收时满足 2 像素/拍和 2.7 的冲刷上限。
6. 不完整输入帧（2.8）后下一帧完全正确；PERF3。
7. SOFT_RST 在帧中写入时等到帧结束才生效（5.2）。
8. 寄存器复位值、只读位、IRQ_STAT.FRAME、DONE_COUNT、PERF。
