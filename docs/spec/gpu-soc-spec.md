## 1. 系统概述

### 1.1 系统功能

| 功能 | 说明 |
|---|---|
| 通用计算 | EdRV32 CPU（与视觉项目相同）运行游戏逻辑、系统软件和 CoreMark |
| 图形渲染 | GPU：硬件几何、三角形与屏幕空间四边形、透视校正纹理、模板/深度/混合、对象运动与碰撞、片上渲染目标、写出（`gpu-spec.md`） |
| 显示输出 | HDMI 720p60；GPU 的 640 × 360 画面由 DISP 放大 2 倍显示，也可以按 1280 × 720 条带渲染后原尺寸显示 |
| 声音 | 放音：I2S 输出到 PMOD 放音模块（ES8156），混音由 CPU 软件完成（`aud-spec.md`） |
| 网络 | 千兆以太网（ETH，与视觉项目相同）：加载程序和素材；手机或 PC 作为手柄 |
| 系统外设 | UART、GPIO（按键/LED）、I2C（配置音频芯片）、CLINT、PLIC |

### 1.2 演示内容

三部分（设计记录 R6）：原创 2D 弹幕挑战；原创低多边形 3D 小场景；GPU 扩展功能的逐项开关演示页。具体玩法另行确认。

### 1.3 硬件平台

与视觉规格 1.3 相同，但不接摄像头。J25 扩展口经 PMOD-X4 转接板，在 PMOD-D 接 MES-Speaker 放音模块（引脚见设计记录 `2026-11-23-audio-pmod-pins.md`）。

## 3. 顶层端口契约

`edrv32_gpu_soc_top` 的端口与视觉规格第 3 节相同，以下几处除外：

| 改动 | 内容 |
|---|---|
| 删除 | `clk_npu_i`；`camN_pclk_i`、`camN_vsync_i`、`camN_href_i`、`camN_data_i`、`camN_pwdn_o`、`camN_rst_n_o` |
| 新增 | `clk_gpu_i`：GPU 时钟，频率由 GPU 规格确定 |
| 新增 | `clk_aud_i`：12.288 MHz 音频主时钟（256 × 48 kHz）；FPGA 层同时把它从 MCLK 引脚输出给音频芯片 |
| 新增 | `aud_bclk_o`、`aud_lrck_o`、`aud_sdata_o`（clk_aud 域，各 1 位）：I2S 位时钟、声道时钟、放音数据，FPGA 是 I2S 主机 |
| 改变用途 | `i2c0_*` 的下标 0 接 ES8156 的配置口，下标 1 不使用（8.1） |
| 改变用途 | GPIO0 bit12–15 不使用（视觉项目中驱动摄像头） |

## 5. 时钟与复位

### 5.1 时钟域

| 时钟 | 频率 | 包含的逻辑 |
|---|---|---|
| clk_sys | 与视觉项目相同 | 同视觉规格 5.1 |
| clk_mem | 125 MHz | mem_xbar、DDR 网关 256 位侧、媒体 APB、DISP 读侧、AUD 的寄存器块和 DMA、ETH 引擎 |
| clk_pix | 74.25 MHz | 同视觉规格 5.1 |
| clk_gpu | [GPU 规格]，开发初值 150 MHz | GPU 全部逻辑和寄存器块；AXI256 主口和 APB 从口异步桥的 GPU 侧 |
| clk_aud | 12.288 MHz | AUD 的 I2S 发送和样本 FIFO 读侧 |
| eth_rx_clk / eth_tx_clk | 125 MHz | 同视觉规格 5.1 |

### 5.2 跨时钟域清单

视觉规格 5.2 中，X1、X2、X5、X6、X7、X8 不变；X4 不使用；以下几项按本文执行：

| # | 起点 → 终点 | 内容 | 方式 |
|---|---|---|---|
| X3 | clk_mem、clk_gpu → clk_sys | 媒体、ETH 中断（clk_mem），GPU 中断（clk_gpu） | 电平同步 |
| X9 | clk_gpu ↔ clk_mem | GPU DDR 主口（AXI256，mem_xbar P3） | `axi256_async_bridge`，放在 GPU 边界 |
| X10 | clk_mem → clk_gpu | GPU 寄存器（媒体 APB 槽 6） | `apb_async_bridge`，放在 GPU 边界 |
| X11 | clk_mem → clk_aud | 音频样本；放音使能 | `async_fifo`；`cdc_sync_bit` |
| X11 | clk_aud → clk_mem | 欠载事件 | `cdc_pulse` |

### 5.3 复位

同视觉规格 5.3，其中“NPU”换成“GPU”。reset_ctrl 增加 clk_aud 域复位 `rst_aud_n`；原 NPU 域复位在本项目中改名为 `rst_gpu_n`，行为不变（8.1）。

## 6. 地址映射与互连

### 6.1 地址映射

地址区间、系统 APB 槽位与视觉规格 6.1 相同。媒体 APB 槽位和 PLIC 中断源按下表：

| 媒体 APB 槽 | 模块 | PLIC 源 | 来源 |
|---|---|---|---|
| 1 | AUD | 8 | AUD |
| 5 | DISP | 12 | DISP |
| 6 | GPU | 13 | GPU |
| 7 | ETH | 14 | ETH |
| 8 | MEM_XBAR | 15 | MEM_XBAR |
| 0、2–4、9–15 | 预留，访问回 SLVERR | 3、4、7、9–11 | 预留，接 0 |

PLIC 源 1、2、5、6 与视觉规格相同（UART0、GPIO0、I2C0、CACHE_CTRL）。地址映射文件为 `rtl/include/gpu_soc_address_map.json`，本项目的 RTL 和软件头文件由它生成；视觉项目的 `soc_address_map.json` 不修改。

### 6.2 mem_xbar 端口

mem_xbar 减为 5 个端口（8.3），调度规则同视觉规格 6.4.2–6.4.4：

| 端口 | 主设备 | 服务等级 | 方向 | 紧急信号 |
|---|---|---|---|---|
| P0 | DISP | RT | 读 | 有 |
| P1 | AUD | RT | 读 | 有（样本 FIFO 低水位，`aud-spec.md` 2.4） |
| P2 | DDR 网关（CPU） | LAT | 读写 | — |
| P3 | GPU | SRT | 读写 | — |
| P4 | ETH | BEL（限速） | 读写 | — |

参数复位值：

| 参数 | P0 | P1 | P2 | P3 | P4 |
|---|---|---|---|---|---|
| `OUTST_RD` | 4 | 1 | 1 | 4 | 2 |
| `OUTST_WR` | 0 | 0 | 1 | 2 | 2 |
| `WEIGHT` | 4 | 1 | — | 3 | 1 |
| `RATE` | — | — | 10% | — | 5% |

P0、P2、P4 的值与视觉项目中 DISP、CPU、ETH 端口相同；P3 沿用视觉项目 NPU 端口的值，P1 按 AUD 的流量取值，两者都为 **[待定]**（GS-4），按联调测量修订。全局参数复位值同视觉规格 6.4.5。

### 6.3 DDR 访问规则

视觉规格 6.5 的第 1–3 条适用（其中“NPU 缓冲区”一词不适用）。第 4 条改为：DISP、ETH 通过公共 2D DMA 单元访问 DDR；GPU、AUD 的访问方式由各自的模块规格规定，必须满足视觉规格 4.2。

## 7. 模块间交互

视觉规格 7.1–7.4 适用于本项目的全部引擎（DISP、AUD、GPU、ETH、MEM_XBAR），其中只针对 VIN、NPU 的条款不适用。GPU 为命令式引擎，AUD 为流式引擎。视觉规格 7.5 的启动流程、BIOS、监控程序适用；“S1–S3”各帧流程由下面的游戏流程代替。

**游戏每帧流程**
1. CPU 根据输入（按键、ETH 虚拟手柄）和上一帧 GPU 的命中列表、释放列表更新游戏状态，写对象表、四边形表、顶点缓冲和命令列表（按视觉规格 7.4 第 1 条保证一致性）。
2. CPU 写 GPU 的 DOORBELL。GPU 执行命令列表，最后 RESOLVE 到一块 FILLING 状态的显示 Surface（条带渲染时每条重复一遍，`gpu-spec.md` 2.1）。
3. GPU 报告 DONE 后，该 Surface 变为 READY；CPU 把它设为 DISP L0 的下一帧，DISP 在 VBlank 切换，并报告释放上一块 Surface。
4. AUD 持续从 DDR 环形缓冲读取 CPU 混好的样本播放；CPU 按 AUD 的水位中断补充样本。

## 8. 沿用模块的改动

以下改动只在本项目的 RTL 中实现，视觉项目的文件不变。

### 8.1 系统子系统

| 项 | 改动 |
|---|---|
| I2C0 | 协议引擎和两对引脚不变；端口 0 接 ES8156，端口 1 不接器件 |
| GPIO0 | 不变；bit12–15 不使用 |
| reset_ctrl | 原 NPU 域复位改名为 GPU 域复位 `rst_gpu_n`（输入时钟为 clk_gpu），行为不变；新增 clk_aud 域复位 `rst_aud_n`，与媒体引擎同批释放（视觉规格 5.3 第 2 步） |
| SYSCTRL | CHIP_ID 改为 **[待定]** 0xED32_0002，用于区分 GPU 项目的 bitstream |

### 8.2 DISP：L0 2 倍放大

在 `disp-spec.md` v0.4 的基础上增加：

| 项 | 规定 |
|---|---|
| 寄存器 | LAYER_CTRL（0x118）bit2 `L0_X2`，复位值 0，帧锁存 |
| `L0_X2` = 0 | 行为与 v0.4 完全相同 |
| `L0_X2` = 1，读取 | 屏幕第 y 行读 L0 Surface 的第 `SCROLL_Y + ⌊y / 2⌋` 行，每行读 640 个像素：`base = CUR_BASE + (SCROLL_Y + ⌊y/2⌋) × CUR_STRIDE + 2 × SCROLL_X`，`width_bytes` = 1280（40 beat）；要求 `SCROLL_X` 为 16 的倍数。每个屏幕行都重新读取，不使用行缓冲 |
| `L0_X2` = 1，扫描 | 源像素 k 输出到屏幕 x = 2k 和 2k + 1；读空和欠账规则按 beat 计，同 v0.4 |
| `L0_X2` = 1，紧急信号 | L0 FIFO 水位低于 40 beat 时，`urgent_o` 有效（替代 v0.4 的 81 beat） |
| 软件保证 | L0 Surface 每行至少 SCROLL_X + 640 个像素，至少 SCROLL_Y + 360 行 |
| 验证 | 增加 `L0_X2` = 1 的扫描逐像素比对、帧间切换 `L0_X2`、与 L1 叠加的测试 |

---

### 8.3 存储子系统：mem_xbar 减为 5 个端口

在 `mem-subsys-spec.md` 的基础上：

| 项 | 规定 |
|---|---|
| 端口 | 5 个主端口 P0–P4（6.2）；原 P4、P5 的逻辑删除，原 P6（ETH）改为 P4 |
| ID | 下游 ID 仍为 4 位：主设备本地 ID 1 位 + 端口号 3 位（端口号 0–4） |
| 限速 | 令牌桶用于 P2、P4（原 P2、P6） |
| 寄存器 | 按端口编址的寄存器（`0x200 + 0x20·p` 起的参数，`0x400 + 0x20·p` 起的统计）只有 p = 0–4；p = 5、6 的地址读为 0、写忽略。`RATE[p]` 复位值：P2 为 26，P4 为 13，其余为 0。`ERR_PORT` 报告 0–4 |
| 其他 | 调度、流量控制、读返回缓冲、错误处理与 `mem-subsys-spec.md` 相同 |
| 验证 | mem_xbar 的单元测试和模块级测试按 5 个端口改写后全部通过；端口号映射、ETH 限速、5 个端口同时满负荷的回归 |

## 9. 性能与资源指标

### 9.1 DDR 带宽（估算，60 fps）

| 流量 | 640 × 360 放大显示 | 1280 × 720 条带渲染 |
|---|---:|---:|
| DISP L0 扫描 | 55 MB/s | 111 MB/s |
| GPU 写出 | 28 MB/s | 111 MB/s |
| GPU 对象表读写（3 万个 × 32 B × 2） | 115 MB/s | 115 MB/s |
| GPU 命令、四边形、顶点 | ≤ 50 MB/s | ≤ 100 MB/s |
| AUD（48 kHz × 4 B） | 0.2 MB/s | 0.2 MB/s |
| **合计** | **约 0.25 GB/s** | **约 0.44 GB/s** |

均远低于 0.75 × B_eff（视觉规格 9.1）。纹理装入为偶发流量，不计入。

### 9.2 实时性

任何负载下，DISP 不得读空，AUD 不得欠载。

### 9.3 资源预算

| 模块 | LUT 上限 |
|---|---:|
| CPU 核 + cache 控制、系统总线 + 外设、DDR 网关 + mem_xbar、ETH | 与视觉规格 9.3 相同（合计 28K） |
| DISP | 6K **[待定]** |
| AUD | 1K **[待定]** |
| GPU | 60K **[待定]** |
| **合计** | **95K** |

DRM（估算）：GPU 约 320 块，保留模块约 62 块，合计约 382 / 415（设计记录 `2026-11-23-gpu-architecture.md` 第 6 节）；最终以 PDS 为准。
