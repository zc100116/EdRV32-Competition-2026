## 1. 概述

EdRV32 是顺序双发射的 RV32 处理器核，是 SoC 的控制核心，也承担比赛的 CoreMark 测评。它位于 clk_sys 域，通过内部接口连接 I$ 和 D$（第 3.2、3.3 节），再由 cache 的 AXI64 主口接入 sys_xbar。

| 指标 | 目标 |
|---|---|
| CoreMark/MHz | ≥ 3.6 |
| 资源（核 + cache 控制，不含 RAM） | ≤ 10K LUT |
| 最高频率 | **[待定]** 开发初值 150 MHz（CPU 最小顶层单独综合） |

## 2. 功能描述

### 2.1 指令集

| 项 | 规定 |
|---|---|
| 基础 | RV32I |
| 扩展 | M、Zicsr、Zicntr、Zifencei |
| C 扩展 | **[待定]** 开发初值：实现。评估期间用参数 `RVC_EN` 开关，评估结束后删除该参数 |
| Zba、Zbb | **[待定]** 开发初值：不实现。先用指令级模拟器评估收益 |
| 特权模式 | 只有 M 模式 |
| 不实现 | F/D、A、PMP、S/U 模式、调试模式和触发器、NMI |
| 非对齐访存 | 不支持，产生地址不对齐异常（mcause 4/6） |

### 2.2 发射结构

- 顺序发射，每周期最多 2 条，顺序退休。
- 同一周期发射的两条指令称为一"组"。组内较老的在**槽 0**，进入管线 0；较年轻的在**槽 1**，进入管线 1。

| 管线 | 能力 |
|---|---|
| 管线 0 | ALU、分支/跳转、load/store、乘除法、CSR、系统指令（ECALL、EBREAK、MRET、WFI、FENCE、FENCE.I） |
| 管线 1 | ALU（含 LUI、AUIPC）。是否支持分支：**[待定]** 开发初值：不支持 |

### 2.3 结果延迟

"结果延迟 N"表示：相关的消费者最早可以在生产者进入 E 级之后第 N 个周期进入 E 级。延迟大于 1 时，消费者在 D 级停顿。

| 生产者 | 结果延迟 | 紧跟其后的相关指令停顿 |
|---|---|---|
| ALU（两条管线）、JAL/JALR 的链接地址 | 1 | 0 拍 |
| load | 2 **[待定]** | 1 拍 |
| 乘法 | 3 **[待定]** | 2 拍 |
| CSR 读 | 2 | 1 拍 |
| 除法 | 除法期间整条流水线停顿，完成时写回 | — |

## 3. 接口

### 3.1 外部端口

| 信号 | 方向 | 位宽 | 时钟域 | 说明 |
|---|---|---|---|---|
| `clk_i` | in | 1 | clk_sys | |
| `rst_n_i` | in | 1 | clk_sys | 低有效，本域同步释放 |
| `irq_meip_i` | in | 1 | clk_sys | PLIC 外部中断，已同步 |
| `irq_msip_i` | in | 1 | clk_sys | CLINT 软件中断 |
| `irq_mtip_i` | in | 1 | clk_sys | CLINT 定时器中断 |
| `mtime_i` | in | 64 | clk_sys | CLINT 的 mtime |
| `debug_o` | out | 64 | clk_sys | 见 7.2 |
| I$ 接口 | — | — | clk_sys | 见 3.2 |
| D$ 接口 | — | — | clk_sys | 见 3.3 |

### 3.2 core ↔ I$ 接口

I$ 的 tag 和数据 RAM 都是同步读：F1 级给出地址，F2 级得到结果。

| 信号 | 方向（以 core 为准） | 位宽 | 说明 |
|---|---|---|---|
| `ic_req_valid_o` | out | 1 | F1 发出取指请求 |
| `ic_req_addr_o` | out | 32 | 取指地址，8 字节对齐（`[2:0]` 为 0） |
| `ic_req_ready_i` | in | 1 | I$ 可以接收请求；缺失处理期间为 0 |
| `ic_resp_valid_i` | in | 1 | 请求被接收后的下一个周期，命中时为 1；缺失时为 0，直到填充完成后给出该请求的数据 |
| `ic_resp_data_i` | in | 64 | 对齐的 8 字节指令数据 |
| `ic_resp_err_i` | in | 1 | 取指访问错误（PMA 违例或总线错误），与 `ic_resp_valid_i` 同拍 |
| `ic_kill_o` | out | 1 | 取消已发出、尚未返回的请求（重定向时）。I$ 丢弃该请求的响应；正在进行的填充继续完成并写入 I$，但不返回给 core |
| `ic_inv_o` | out | 1 | 使整个 I$ 无效（FENCE.I） |
| `ic_inv_done_i` | in | 1 | 无效完成 |

### 3.3 core ↔ D$ 接口

E 级末尾给出地址，M 级得到结果。

| 信号 | 方向（以 core 为准） | 位宽 | 说明 |
|---|---|---|---|
| `dc_req_valid_o` | out | 1 | E 级的 load/store 发出请求。只在该指令本周期确定进入 M 时为 1（D$ 接受请求即视为该指令进入 M；M 级停顿时不发出新请求） |
| `dc_req_addr_o` | out | 32 | 字节地址 |
| `dc_req_store_o` | out | 1 | 1 表示 store |
| `dc_req_size_o` | out | 2 | 0 字节，1 半字，2 字 |
| `dc_req_ready_i` | in | 1 | D$ 可以接收请求 |
| `dc_resp_valid_i` | in | 1 | M 级结果有效：可缓存 load 命中时为请求后的下一个周期；store 命中时表示 tag 检查通过；缺失时为 0，直到填充完成；设备访问在提交并完成后有效 |
| `dc_resp_data_i` | in | 32 | load 数据，已按地址移到低位，未做符号扩展 |
| `dc_resp_err_i` | in | 1 | 访问错误，与 `dc_resp_valid_i` 同拍 |
| `dc_resp_device_i` | in | 1 | 该访问属于设备或非缓存区域，需要等提交后才能执行 |
| `dc_kill_o` | out | 1 | 取消 M 级尚未提交的请求（该指令被冲刷） |
| `dc_commit_o` | out | 1 | M 级的 load/store 已经可以提交。可缓存 store 此时写入写缓冲；设备访问此时发出 |
| `dc_store_data_o` | out | 32 | store 数据（未移位），与 `dc_commit_o` 同拍有效 |
| `dc_fence_o` | out | 1 | FENCE：等待写缓冲排空 |
| `dc_clean_all_o` | out | 1 | FENCE.I 的第一步：写回全部脏行 |
| `dc_fence_done_i` | in | 1 | `dc_fence_o` 或 `dc_clean_all_o` 的操作完成 |

可缓存访问和设备访问的区分以及 PMA 检查，由 D$ 依据 SoC 地址映射完成（见 `cache-spec.md`）。

### 3.4 退休追踪信号约定（验证用）

`edrv32_cpu_core` 顶层模块内必须有以下名称的内部信号，供验证环境通过层次化引用读取。它们不是端口，不得因此增加端口或条件编译。

| 信号 | 位宽 | 说明 |
|---|---|---|
| `trace_valid_w` | 2 | [0] 管线 0、[1] 管线 1 本周期有指令退休（进入 W 后完成写回的那个周期） |
| `trace_pc_w` | 2×32 | 退休指令的 PC，[31:0] 对应管线 0 |
| `trace_instr_w` | 2×32 | 退休指令的编码（压缩指令给出原始 16 位编码，高 16 位为 0） |
| `trace_rd_w` | 2×5 | 写回的寄存器号，不写回时为 0 |
| `trace_rd_data_w` | 2×32 | 写回的值 |
| `trace_trap_w` | 1 | 本周期进入异常或中断处理 |
| `trace_cause_w` | 32 | 进入时的 mcause 值 |

同一周期两条都有效时，管线 0 的指令较老。

## 4. 行为与时序

### 4.1 流水级

**[待定]** 开发初值：6 级。

| 级 | 名称 | 工作 |
|---|---|---|
| F1 | 取指 1 | 选择取指 PC；查询 BTB、gshare、RAS；向 I$ 发出请求 |
| F2 | 取指 2 | 接收 I$ 数据；（`RVC_EN` 时）拼接和展开压缩指令；把规范的 32 位指令连同 PC、预测信息、取指异常写入指令缓冲 |
| — | 指令缓冲 IB | F2 与 D 之间的队列，容量 4 条 **[待定]** |
| D | 译码 | 从 IB 取出最老的 1–2 条；译码；配对检查（4.2）；读寄存器堆；冒险检查（4.3）；发射到 E |
| E | 执行 | ALU；分支判定和目标计算（管线 0）；访存地址计算并向 D$ 发出请求；乘法第 1 级 |
| M | 访存 | 接收 D$ 结果；load 数据符号扩展；乘法第 2 级；CSR 读写；收集异常，决定是否提交（4.5） |
| W | 写回 | 乘法第 3 级；写寄存器堆；退休计数 |

**提交点**：指令从 M 进入 W 时变为不可撤销，进入 W 的指令一定会退休。

### 4.2 配对规则

D 级在满足以下全部条件时，把两条指令作为一组发射；否则只发射较老的一条（槽 0）。

1. 槽 1 指令是管线 1 支持的类型。
2. 槽 1 的源寄存器不等于槽 0 的目的寄存器（x0 除外）。
3. 槽 0 不是 CSR、系统指令或 FENCE/FENCE.I。
4. 槽 1 没有取指异常，也不是非法指令。
5. 两条指令在 IB 中按程序顺序相邻。由前端保证：槽 0 被预测为跳转时，IB 中不会有它的顺序后继。

两条指令的目的寄存器相同时允许配对；同时写同一个寄存器时，槽 1 的结果生效。

### 4.3 冒险与停顿

| 情况 | 处理 |
|---|---|
| 源寄存器依赖一条结果延迟尚未满足的生产者（2.3） | 该指令在 D 级停顿，直到延迟满足 |
| 旁路 | 两条管线的 E、M、W 级结果都可以旁路给进入 E 的操作数 **[待定]**；寄存器堆同周期写读同一寄存器时，读出新值 |
| CSR 指令 | 单独发射，并在 D 级等到 E、M 中没有更老的指令后才发射 |
| 除法 | 在 E 级启动迭代，整条流水线停顿到除法完成 |
| I$ 缺失 | 停顿 F1/F2，后端继续执行 IB 中已有的指令 |
| D$ 缺失、设备访问 | 停顿 M 及其之前的各级 |

### 4.4 分支预测与重定向

| 项 | 规定 |
|---|---|
| BTB | 32 项 **[待定]**，直接映射，索引 `PC[7:3]`，tag `PC[31:8]`；每项记录组内分支所在位置（`PC[2:1]`）、目标地址、类型（条件分支、JAL、JALR、调用、返回） |
| 方向预测 | gshare，512 项 2 位饱和计数器 **[待定]**，索引 `PC[9:1] ^ GHR[8:0]`；计数器复位为 01（弱不跳转）；9 位全局历史 GHR 在条件分支于 E 级判定时按实际方向更新（非推测） |
| RAS | 4 项 **[待定]**；调用压栈，返回出栈；满时覆盖最老项。在 F1 预测时推测更新，同时保存检查点（栈指针 + 栈顶项）随指令传递；重定向时用被冲刷的最老指令的检查点恢复 |
| 预测更新 | 分支在 E 级判定后更新；被冲刷的指令不更新 |
| E 级重定向 | 条件分支方向或目标预测错误、JALR 目标预测错误：冲刷 F1、F2、IB、D，以及同组槽 1 中较年轻的指令；下一周期 F1 从正确地址取指。误预测代价 3 个周期 |
| D 级重定向 | JAL 在 BTB 中未命中时，D 级计算目标并重定向，冲刷 F1、F2 和 IB 中较年轻的指令；代价 2 个周期 |
| F2 误取恢复（仅 `RVC_EN`=1） | F2 到达 BTB 预测的分支位置时，核对该位置是否为一条指令的起始半字、指令长度是否与 BTB 记录一致；任一项不符（代码经 FENCE.I 修改，或从半字入口形成重叠指令流）：取消在途的目标取指请求，清除该 BTB 项，恢复预测前的 RAS，从该位置所在的实际指令 PC 重新取指。`RVC_EN`=0 时指令 4 字节对齐、长度固定，不实现此逻辑；评估后删除 C 扩展时一并删除 |
| 优先级 | 同一周期有多个重定向时，较老的指令优先：M 级异常和中断 > E 级重定向 > D 级重定向 > F2 误取恢复 |

### 4.5 异常和中断的处理时机

- 各级发现的异常（取指错误、非法指令、地址不对齐、访存错误、ECALL、EBREAK）随指令传到 M 级。
- 在 M 级，如果槽 0 有异常：槽 0 及所有较年轻的指令都不提交；冲刷 M 及之前的各级；更新 mepc、mcause、mtval、mstatus；下一个周期从 mtvec 取指。
- 如果槽 0 正常而槽 1 有异常：槽 0 提交，槽 1 及更年轻的指令被冲刷，按槽 1 的异常处理。
- 中断在 M 级判定：有被使能的中断等待，并且 M 级槽 0 是一条可以接受中断的指令（不是正在进行的设备访问或除法）时，该指令不提交，mepc 指向它，进入中断处理。
- MRET 在 M 级提交时更新 mstatus，并从 mepc 重定向。
- WFI 在 M 级提交后停止取指，直到有被使能的中断等待（不论 mstatus.MIE）才继续。

### 4.6 CSR

CSR 指令在 M 级读出旧值、写入新值，提交时生效。由于按 4.3 单独发射，CSR 指令之间不存在冒险。

### 4.7 访存语义

| 项 | 规定 |
|---|---|
| 访问顺序 | 所有访存按程序顺序完成；cache 为阻塞式，同一时刻至多一个缺失在处理 |
| 可缓存 store | M 级查 tag，缺失时停顿并完成写分配填充；命中后在提交时（`dc_commit_o`）写入 **1 项写缓冲**，D$ 在下一个周期通过数据 RAM 的写口写入；写缓冲的写出和接收可以在同一周期完成，连续的 store 不停顿 |
| 写缓冲旁路 | load 访问的字与写缓冲中的地址相同时，按字节使能合并返回数据（由 D$ 实现） |
| 设备和非缓存访问 | 提交时发出，单拍访问。**store 为非推送**：收到写响应后指令才进入 W；load 收到数据后进入 W |
| FENCE | 等写缓冲排空后提交 |
| FENCE.I | 在 M 级依次：写回 D$ 全部脏行（`dc_clean_all_o`）→ 使整个 I$ 无效（`ic_inv_o`）→ 提交，并从下一条指令重新取指 |

### 4.8 乘除法

| 项 | 规定 |
|---|---|
| 位置 | 只在管线 0 |
| 乘法 | 使用 APM 乘法器（`rtl/tech/` 包装），33×33 有符号乘法覆盖 MUL/MULH/MULHSU/MULHU；全流水，每周期可以接受一条；结果延迟见 2.3 |
| 除法 | 基 2 迭代，约 33 个周期；除法期间整条流水线停顿，不设解耦执行和记分牌 |
| 特殊情况 | 除以 0、有符号溢出（-2³¹ ÷ -1）按 RISC-V 规范直接给出结果，不进入迭代 |

## 5. 寄存器（CSR）

| CSR | 地址 | 说明 |
|---|---|---|
| mstatus | 0x300 | MIE、MPIE；MPP 固定为 3 |
| misa | 0x301 | 只读，反映实际实现的扩展 |
| mie | 0x304 | MEIE、MTIE、MSIE |
| mtvec | 0x305 | BASE + MODE（0 direct，1 vectored） |
| mcountinhibit | 0x320 | CY、IR、HPM3–10 可写，其余只读为 0 |
| mhpmevent3–10 | 0x323–0x32A | 5 位事件编码（7.1），高位只读为 0 |
| mscratch | 0x340 | |
| mepc | 0x341 | 最低位固定为 0；`RVC_EN = 0` 时低 2 位固定为 0 |
| mcause | 0x342 | |
| mtval | 0x343 | 地址类异常写入出错地址；非法指令写入指令编码；其他写 0 |
| mip | 0x344 | MEIP、MTIP、MSIP，只读 |
| mcycle / mcycleh | 0xB00 / 0xB80 | 64 位 |
| minstret / minstreth | 0xB02 / 0xB82 | 64 位，每周期可增加 0、1 或 2 |
| mhpmcounter3–10 / 高半部 | 0xB03–0xB0A / 0xB83–0xB8A | 64 位 |
| cycle、instret、hpmcounter3–10 及高半部 | 0xC00、0xC02–0xC0A / 0xC80、0xC82–0xC8A | 只读别名 |
| time / timeh | 0xC01 / 0xC81 | 只读，返回 `mtime_i` |
| mvendorid、marchid、mimpid、mhartid | 0xF11–0xF14 | 只读；mhartid = 0 |

访问未实现的 CSR、写只读 CSR，都产生非法指令异常。

补充约定：

- 复位值：除 mstatus.MPP 固定为 3 外，全部 CSR 复位为 0；mvendorid、marchid、mimpid 为 0。
- misa 为 WARL：读出实际实现的扩展，写入被忽略，不产生异常（属于上一句"写只读 CSR"的例外）。
- mtvec.MODE 为 WARL：写入 2、3 时 MODE 变为 0。
- 同一周期 CSR 指令写计数器（mcycle、minstret、mhpmcounter）与该计数器的自动加一冲突时，CSR 写入生效。
- 同一周期 M 级异常/中断进入与 CSR 写入或 MRET 冲突时，异常/中断进入优先，该 CSR 指令或 MRET 不提交。

## 6. 错误处理

| 错误 | 检测位置 | 上报 |
|---|---|---|
| 取指访问错误 | I$ 返回 `ic_resp_err_i` | 随指令到 M 级，mcause 1，mtval 为取指地址 |
| 非法指令（含未实现 CSR） | D 级译码 | mcause 2，mtval 为指令编码 |
| 地址不对齐 | E 级地址计算 | mcause 4/6；`RVC_EN = 0` 时跳转目标不对齐为 mcause 0 |
| load/store 访问错误 | D$ 返回 `dc_resp_err_i` | mcause 5/7，mtval 为访问地址 |
| 脏行写回错误 | D$ | 不经过 core，见 `cache-spec.md` |

## 7. 性能观测

### 7.1 HPM 事件（mhpmevent 编码，5 位）

| 编码 | 事件 | 编码 | 事件 |
|---|---|---|---|
| 0 | 不计数 | 9 | load-use 停顿周期 |
| 1 | 双退休周期 | 10 | 除法停顿周期 |
| 2 | 单退休周期 | 11 | 设备/非缓存访问等待周期 |
| 3 | 零退休周期 | 12 | 前端断流周期（D 级可以发射但 IB 为空） |
| 4 | 已退休的分支和跳转数 | 13 | I$ 缺失次数 |
| 5 | 配对失败：组内 RAW | 14 | D$ 缺失次数 |
| 6 | 配对失败：结构冲突 | 15 | D$ 脏行写回次数 |
| 7 | 配对失败：槽 1 类型不被管线 1 支持 | 16 | 分支和跳转误预测次数（E 级和 D 级重定向） |
| 8 | 配对失败：第二条未取到（IB 中只有 1 条） | 17–31 | 保留，不计数 |

配对失败类事件在"D 级发射了槽 0 而没有发射槽 1"的周期计数，每个周期只计一个原因，优先级为 5 > 6 > 7 > 8。
