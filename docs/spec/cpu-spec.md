## 1. 概述

EdRV32 是顺序双发射的 RV32 处理器核，是 SoC 的控制核心，也承担比赛的 CoreMark 测评。它位于 clk_sys 域，通过内部接口连接 I$ 和 D$（第 3.2、3.3 节），再由 cache 的 AXI64 主口接入 sys_xbar。

| 指标 | 目标 |
|---|---|
| CoreMark/MHz | ≥ 3.6；v0.17 开发目标 **[待定]**：不低于周期模型对 v0.17 的预测值的 95%（R-05） |
| 资源（核 + cache 控制，不含 RAM） | ≤ 10K LUT |
| 最高频率 | 125 MHz：完整 SoC 在 PG2L200H-6 上布局布线后 clk_sys 慢角 setup WNS +0.087 ns（卡 48 F125 r2），并已上板运行（卡 51–54） |
| CPU+L1 独立频率（v0.17） | **[待定]** 开发目标 150 MHz：`edrv32_cpu_subsys` 单独布局布线（卡 56 的探针顶层与约束）clk_sys 慢角 setup WNS ≥ 0。完整 SoC 中 CPU 所在时钟域的频率另行确定 |

## 2. 功能描述

### 2.1 指令集

| 项 | 规定 |
|---|---|
| 基础 | RV32I |
| 扩展 | M、Zicsr、Zicntr、Zifencei |
| C 扩展 | 不实现（用户 2026-10-28 确认，设计记录 `2026-10-28-cpu-timing-closure.md`）。指令 4 字节对齐 |
| Zba、Zbb | **[待定]** 开发初值：不实现。先用指令级模拟器评估收益 |
| 特权模式 | 只有 M 模式 |
| 不实现 | F/D、A、PMP、S/U 模式、调试模式和触发器、NMI |
| 非对齐访存 | 不支持，产生地址不对齐异常（mcause 4/6） |

### 2.2 发射结构

- 顺序发射，每周期最多 2 条，顺序退休。
- 同一周期发射的两条指令称为一"组"。组内较老的在**槽 0**，较年轻的在**槽 1**。槽表示程序顺序，管线表示执行位置；槽到管线的分配见 4.2。

| 管线 | 能力 |
|---|---|
| 管线 0 | ALU、条件分支、JAL、JALR、load/store、乘除法、CSR、系统指令（ECALL、EBREAK、MRET、WFI、FENCE、FENCE.I） |
| 管线 1 | ALU（含 LUI、AUIPC）、条件分支、JAL |

### 2.3 结果延迟

"结果延迟 N"表示：相关的消费者最早可以在生产者进入 E 级之后第 N 个周期进入 E 级。延迟大于 1 时，消费者在 D 级停顿。

| 生产者 | 结果延迟 | 紧跟其后的相关指令停顿 |
|---|---|---|
| ALU（两条管线）、JAL/JALR 的链接地址 | 1 | 0 拍 |
| load | 2；满足 4.10 条件的 load 为 1 | 1 拍；满足 4.10 时 0 拍 |
| 乘法 | 4 | 3 拍 |
| CSR 读 | 2 | 1 拍 |
| 除法 | 除法期间整条流水线停顿，完成时写回 | — |

|---|---|---|---|---|
| `clk_i` | in | 1 | clk_sys | |

| I$ 接口 | — | — | clk_sys | 见 3.2 |

### 3.2 core ↔ I$ 接口

I$ 的 tag 和数据 RAM 都是同步读：F1 级给出地址，F2 级得到结果。

| 信号 | 方向（以 core 为准） | 位宽 | 说明 |
|---|---|---|---|
| `ic_req_valid_o` | out | 1 | F1 发出取指请求 |
| `ic_req_addr_o` | out | 32 | 取指地址，8 字节对齐（`[2:0]` 为 0） |
| `ic_req_ready_i` | in | 1 | I$ 可以接收请求；缺失处理期间为 0 |
| `ic_resp_valid_i` | in | 1 | 请求被接收后的下一个周期，命中时为 1；缺失时为 0，直到填充完成后给出该请求的数据 |
| `ic_resp_data_i` | in | 64 | 对齐的 8 字节指令数据 |
| `ic_resp_err_i` | in | 1 | 取指访问错误（PMA 违例或总线错误），与 `ic_resp_valid_i` 同拍 |
| `ic_kill_o` | out | 1 | 取消已发出、尚未返回的请求（重定向时）。I$ 丢弃该请求的响应；正在进行的填充继续完成并写入 I$，但不返回给 core。与 kill 同一周期给出的响应不受影响，由 core 忽略；kill 不得组合地屏蔽同一周期的响应（避免组合环）。 |
| `ic_inv_o` | out | 1 | 使整个 I$ 无效（FENCE.I） |
| `ic_inv_done_i` | in | 1 | 无效完成 |

### 3.3 core ↔ D$ 接口

E 级末尾给出地址，M 级得到结果。

| 信号 | 方向（以 core 为准） | 位宽 | 说明 |
|---|---|---|---|
| `dc_req_valid_o` | out | 1 | E 级的 load/store 发出请求。只在该指令本周期确定进入 M 时为 1（D$ 接受请求即视为该指令进入 M；M 级停顿时不发出新请求）。`dc_req_ready_i` 为 0 时请求保持不变（valid 和负载不变），只有一种例外：该指令被冲刷（寄存的重定向或 M 级陷阱，4.4）时，未被接受的请求撤销 |
| `dc_req_addr_o` | out | 32 | 字节地址 |
| `dc_req_store_o` | out | 1 | 1 表示 store |
| `dc_req_size_o` | out | 2 | 0 字节，1 半字，2 字 |
| `dc_req_ready_i` | in | 1 | D$ 可以接收请求；只取决于 D$ 的内部状态，不取决于本周期请求的地址、读写类型和大小 |
| `dc_resp_valid_i` | in | 1 | M 级结果有效：可缓存 load 命中时为请求后的下一个周期；store 命中时表示 tag 检查通过；缺失时为 0，直到填充完成；设备访问在提交并完成后有效 |
| `dc_resp_data_i` | in | 32 | load 数据，已按地址移到低位，未做符号扩展 |
| `dc_resp_err_i` | in | 1 | 访问错误，与 `dc_resp_valid_i` 同拍。`dc_resp_err_i` 为 1 时 `dc_resp_valid_i` 必为 1；`dc_resp_valid_i` 为 0 时 `dc_resp_err_i` 必为 0。core 可以单独用 `dc_resp_err_i` 判定访存错误 |
| `dc_resp_device_i` | in | 1 | 该访问属于设备或非缓存区域，需要等提交后才能执行 |
| `dc_kill_o` | out | 1 | 取消 M 级尚未提交的请求（该指令被冲刷）。与 kill 同一周期给出的响应不受影响，由 core 忽略；kill 不得组合地屏蔽同一周期的响应（避免组合环）。core 保证 `dc_kill_o` 与 `dc_commit_o` 不在同一周期有效 |
| `dc_commit_o` | out | 1 | M 级的 load/store 已经可以提交。可缓存 store 此时写入写缓冲；设备访问此时发出 |
| `dc_store_data_o` | out | 32 | store 数据（未移位），与 `dc_commit_o` 同拍有效 |
| `dc_fence_o` | out | 1 | FENCE：等待写缓冲排空 |
| `dc_clean_all_o` | out | 1 | FENCE.I 的第一步：写回全部脏行 |
| `dc_fence_done_i` | in | 1 | `dc_fence_o` 或 `dc_clean_all_o` 的操作完成 |
| `dc_wb_event_i` | in | 1 | D$ 每发起一次脏行写回突发给出一个单周期脉冲（含维护操作和 FENCE.I 引起的写回），只用于 HPM 事件 15 |
| `dc_early_valid_o` | out | 1 | 4.10：D 级本周期发射一条满足条件的 load，请 D$ 提前查询。推测性的，没有握手 |
| `dc_early_addr_o` | out | 32 | 提前查询的字节地址，与 `dc_early_valid_o` 同拍 |
| `dc_early_hit_i` | in | 1 | 查询的下一个周期（该 load 在 E 级）给出：1 表示提前查询成功，`dc_early_data_i` 有效；0 表示失败（读口被普通请求占用、缺失、设备或非缓存、写缓冲或 M 级已被接受的 store 中有同一个字）。D$ 不检查对齐：未对齐的 load 在 M 级照常产生异常，用了提前结果的年轻指令随之被冲刷 |
| `dc_early_data_i` | in | 32 | 提前查询的 load 数据，已移到低位，未做符号扩展 |

可缓存访问和设备访问的区分以及 PMA 检查，由 D$ 依据 SoC 地址映射完成（见 `cache-spec.md`）。

### 3.4 退休追踪信号约定（验证用）

`edrv32_cpu_core` 顶层模块内必须有以下名称的内部信号，供验证环境通过层次化引用读取。它们不是端口，不得因此增加端口或条件编译。

| 信号 | 位宽 | 说明 |
|---|---|---|
| `trace_valid_w` | 2 | 本周期有指令退休（进入 W 后完成写回的那个周期）。按程序顺序排列，与所在管线无关：[0] 为较老的一条，[1] 为较年轻的一条；只退休一条时它在 [0] |
| `trace_pc_w` | 2×32 | 退休指令的 PC，[31:0] 对应 `trace_valid_w[0]` |
| `trace_instr_w` | 2×32 | 退休指令的编码 |
| `trace_rd_w` | 2×5 | 写回的寄存器号，不写回时为 0 |
| `trace_rd_data_w` | 2×32 | 写回的值 |
| `trace_trap_w` | 1 | 本周期进入异常或中断处理 |
| `trace_cause_w` | 32 | 进入时的 mcause 值 |
| `trace_bypass_w` | 12 | 本周期从 D 发射到 E 的指令的操作数来源，4 个 3 位字段：[2:0] 槽 0 rs1、[5:3] 槽 0 rs2、[8:6] 槽 1 rs1、[11:9] 槽 1 rs2。编码：0 寄存器堆（或未发射、不使用该操作数），1 E 管线 0，2 E 管线 1，3 M 管线 0，4 M 管线 1，5 W 管线 0，6 W 管线 1。v0.17 中 W2 级经寄存器堆同周期写读得到的值编码为 0 |
| `trace_redirect_cause_w` | 2 | 本周期由寄存器发出的 E 级或 M 级重定向（4.4）的原因：0 无，1 条件分支方向错误，2 目标错误（分支目标或 JALR 目标、RAS 返回地址），3 非控制转移指令被预测为跳转 |
| `trace_stall_cause_w` | 3 | 本周期 D 级停顿的原因（多个原因同时成立时取编码最小者）：0 无，1 等待 load 结果，2 等待乘法结果，3 等待 CSR 读结果，4 CSR 指令等待 E、M 中更老的指令排空，5 除法进行中。M 级引起的停顿（D$ 缺失、设备访问）见 debug_o |
| `trace_redirect_stage_w` | 2 | 本周期由寄存器发出的重定向（4.4）的判定级：0 无，1 D 级，2 E 级，3 M 级（4.11 的分支，以及 MRET、FENCE.I 重新取指、WFI 恢复）。异常和中断不在此列，由 `trace_trap_w` 表示 |
| `trace_redirect_pc_w` | 32 | 发出该重定向的指令的 PC，`trace_redirect_stage_w` 非 0 时有效 |

`trace_*` 的 [0]/[1] 都按程序顺序（较老在 [0]）；`trace_bypass_w` 的消费者按槽（程序顺序），旁路源按管线。

## 4. 行为与时序

### 4.1 流水级

**[待定]** 开发初值：6 级。

| 级 | 名称 | 工作 |
|---|---|---|
| F1 | 取指 1 | 选择取指 PC；查询 BTB、gshare、RAS；向 I$ 发出请求 |
| F2 | 取指 2 | 接收 I$ 数据；把 32 位指令连同 PC、预测信息、取指异常写入指令缓冲 |
| — | 指令缓冲 IB | F2 与 D 之间的队列，容量 4 条 **[待定]**。F2 只能写入本周期开始时已有的空位；D 级在同一周期取走的条目，下一周期才能写入（前端是否推进不取决于 D 级本周期的发射结果） |
| D | 译码 | 从 IB 取出最老的 1–2 条；译码（类型、源/目的寄存器等字段可以在写入 IB 时预译码，D 级只做配对、冒险和旁路选择）；配对检查（4.2）；读寄存器堆；冒险检查（4.3）；满足 4.10 的 load 计算访存地址并提前访问 D$；发射到 E |
| E | 执行 | ALU；分支判定和目标计算（两条管线，每组至多一条），判定结果寄存（4.4）；访存地址计算并向 D$ 发出请求（4.10 的 load 在 E 级得到数据）；乘法进入 APM |
| M | 访存 | 接收 D$ 结果；load 数据符号扩展；4.11 的分支用 load 数据判定；CSR 读写；收集异常，决定是否提交（4.5） |
| W | 写回 | 退休前的结果流水级。v0.17 在 W 之后增加 W2：寄存器堆在 W2 写入（同周期写读读出新值），退休追踪（3.4）在 W2 给出；E、M、W 级结果寄存器旁路给进入 E 的操作数。乘法的 APM 输出在 W 级进入本地寄存器（4.9），在 W2 写入。乘法每周期仍可接受一条 |

**提交点**：指令从 M 进入 W 时变为不可撤销，进入 W 的指令一定会退休。

### 4.2 配对规则

D 级在满足以下全部条件时，把两条指令作为一组发射；否则只发射较老的一条（槽 0，进入管线 0）。

1. 两条指令能分到不同管线：至多一条只能由管线 0 执行（load/store、乘除法、JALR）。
2. 组内至多一条控制转移指令（条件分支、JAL、JALR）。
3. 槽 1 的源寄存器不等于槽 0 的目的寄存器（x0 除外）。
4. 两条都不是 CSR、系统指令或 FENCE/FENCE.I。
5. 槽 1 没有取指异常，也不是非法指令。
6. 两条指令在 IB 中按程序顺序相邻。由前端保证：槽 0 被预测为跳转时，IB 中不会有它的顺序后继。

管线分配：槽 1 能由管线 1 执行时，槽 0 进入管线 0、槽 1 进入管线 1；否则（槽 1 只能由管线 0 执行，按条件 1 槽 0 一定能由管线 1 执行）槽 0 进入管线 1、槽 1 进入管线 0。指令在后续各级保持程序顺序：退休、异常、中断、冲刷和 WAW 都按槽判定，与所在管线无关。

两条指令的目的寄存器相同时允许配对；同时写同一个寄存器时，槽 1（较年轻）的结果生效。

### 4.3 冒险与停顿

| 情况 | 处理 |
|---|---|
| 源寄存器依赖一条结果延迟尚未满足的生产者（2.3） | 该指令在 D 级停顿，直到延迟满足 |
| 旁路 | 两条管线的 E、M、W 级结果都可以旁路给进入 E 的操作数 **[待定]**；寄存器堆同周期写读同一寄存器时，读出新值 |
| CSR 指令 | 单独发射，并在 D 级等到 E、M 中没有更老的指令后才发射 |
| 除法 | 在 E 级启动迭代，整条流水线停顿到除法完成 |
| I$ 缺失 | 停顿 F1/F2，后端继续执行 IB 中已有的指令 |
| D$ 缺失、设备访问 | 停顿 M 及其之前的各级 |

### 4.4 分支预测与重定向

| 项 | 规定 |
|---|---|
| BTB | 128 项，直接映射，索引 `PC[9:3]`，tag `PC[31:10]`；每项记录组内分支所在位置（`PC[2]`）、目标地址、类型（条件分支、JAL、JALR、调用、返回）。有效位复位清 0；其余字段上电和复位都不清除 |
| 方向预测 | gshare，4096 项 2 位饱和计数器，索引 `PC[13:2] ^ GHR[11:0]`；计数器上电初值 01（弱不跳转），复位不清除；12 位全局历史 GHR 在条件分支于 E 级判定时按实际方向更新（非推测） |
| RAS | 4 项；调用压栈，返回出栈；满时覆盖最老项。在 F1 预测时推测更新，同时保存检查点（栈指针 + 栈顶项）随指令传递；重定向时用被冲刷的最老指令的检查点恢复 |
| 预测更新 | 分支在 E 级判定，判定结果寄存后在下一个周期写入 BTB、gshare 和 GHR（任一管线；每组至多一条，所以每周期至多一次更新）；被冲刷的指令不更新；4.11 的分支在 M 级判定，同样寄存后写入 |
| E 级重定向 | 条件分支方向或目标预测错误、JALR 目标预测错误（条件分支可在任一管线）：判定结果在 E 级末尾寄存，**下一个周期**由该寄存器发出重定向：冲刷 F1、F2、IB、D、E，以及同组中比它年轻、此时已在 M 的指令（它在槽 0 时；该指令尚未提交，不得提交：它的 D$ 请求在进入 M 时已被接受，此时必须用 `dc_kill_o` 取消，不得发出 `dc_commit_o`；本周期在 E 级的错路 load/store 不得发出 `dc_req_valid_o`）；再下一个周期 F1 从正确地址取指。误预测代价 4 个周期。E 级误预测重定向不等待任何后级接收条件（M 级停顿或 D$ 不能接收请求）即可发出，每条指令只发出一次；该指令仍在后级可以接收后进入 M。M 级的指令随后陷阱时，E 级已做的预测器更新（BTB、GHR、RAS 推测更新）不撤销 |
| D 级重定向 | JAL（槽 0 或槽 1）在 BTB 中未命中时，D 级计算目标并寄存，下一个周期由该寄存器重定向，冲刷 F1、F2、IB 中以及已经进入 D、E 的较年轻指令；代价 3 个周期。后级停顿（D 级不能发射）期间，D 级重定向不等停顿解除即可发出，每条指令只发出一次；该指令仍在停顿解除后进入 E |
| M 级重定向 | 4.11 的分支在 M 级判定方向错误或目标错误时，判定结果寄存，下一个周期由该寄存器重定向，冲刷 M 及之前各级中比它年轻的指令；代价 5 个周期 |
| 优先级 | 所有送往前端的重定向（M 级异常、中断、MRET、FENCE.I、WFI 恢复，以及 4.11 的 M 级、E 级、D 级判定）都先寄存，下一个周期发出，不组合地依赖本周期的停顿、发射或 cache 握手。core 内部的冲刷按程序顺序当周期生效，较老者优先：M 级异常和中断 > M 级判定 > E 级判定 > D 级判定。同一周期前端只接收一个寄存的重定向；较老的重定向在下一周期发出时覆盖较年轻的（较年轻者已做的预测器更新不撤销） |

### 4.5 异常和中断的处理时机

- 各级发现的异常（取指错误、非法指令、地址不对齐、访存错误、ECALL、EBREAK）随指令传到 M 级。
- 在 M 级按程序顺序检查本组：槽 0 有异常时，槽 0 及所有较年轻的指令都不提交；槽 0 没有异常而槽 1 有异常时（槽 1 在管线 0 执行 load/store，或在管线 1 执行目标不对齐的条件分支/JAL），槽 0 正常提交，槽 1 及所有较年轻的指令不提交。两种情况都冲刷 M 及之前的各级，按发生异常的那条指令更新 mepc、mcause、mtval、mstatus。M 级的冲刷在 core 内部当周期生效；送往前端的重定向先寄存，下一个周期发出，再下一个周期从 mtvec 取指（4.4 优先级）。
- 中断在 M 级判定：有被使能的中断等待，并且 M 级槽 0（本组较老的指令）是一条可以接受中断的指令（不是正在进行的设备访问、除法或 FENCE.I）时，该指令不提交，mepc 指向它，进入中断处理。
- MRET 在 M 级提交时更新 mstatus，并从 mepc 重定向（同样先寄存，下一周期发出）。FENCE.I 重新取指、WFI 恢复取指同样经过寄存。这三种情况下，较年轻指令的冲刷与 E 级寄存重定向相同：在寄存器发出重定向的那个周期生效（此时在 M 级的年轻指令不提交，E 级未被接受的 D$ 请求撤销）。异常和中断的冲刷在进入陷阱的周期生效
- WFI 在 M 级提交后停止取指，直到有被使能的中断等待（不论 mstatus.MIE）才继续。

### 4.6 CSR

CSR 指令在 M 级读出旧值、写入新值，提交时生效。由于按 4.3 单独发射，CSR 指令之间不存在冒险。

### 4.7 访存语义

| 项 | 规定 |
|---|---|
| 访问顺序 | 所有访存按程序顺序完成；cache 为阻塞式，同一时刻至多一个缺失在处理 |
| 可缓存 store | M 级查 tag，缺失时停顿并完成写分配填充；命中后在提交时（`dc_commit_o`）写入 **1 项写缓冲**，D$ 在下一个周期通过数据 RAM 的写口写入；写缓冲的写出和接收可以在同一周期完成，连续的 store 不停顿 |
| 写缓冲旁路 | load 访问的字与写缓冲中的地址相同时，按字节使能合并返回数据（由 D$ 实现） |
| 设备和非缓存访问 | 提交时发出，单拍访问。**store 为非推送**：收到写响应后指令才进入 W；load 收到数据后进入 W |
| FENCE | 等写缓冲排空后提交 |
| FENCE.I | 在 M 级依次：写回 D$ 全部脏行（`dc_clean_all_o`）→ 使整个 I$ 无效（`ic_inv_o`）→ 提交，并从下一条指令重新取指 |

### 4.8 乘除法

| 项 | 规定 |
|---|---|
| 位置 | 只在管线 0 |
| 乘法 | 使用 APM 乘法器（`rtl/tech/` 包装），33×33 有符号乘法覆盖 MUL/MULH/MULHSU/MULHU；全流水，每周期可以接受一条；结果延迟 4（2.3）；APM 输出先进入乘法器本地寄存器，再进入结果选择、旁路和寄存器堆（4.9） |
| 除法 | 基 2 迭代，约 33 个周期；除法期间整条流水线停顿，不设解耦执行和记分牌 |
| 特殊情况 | 除以 0、有符号溢出（-2³¹ ÷ -1）按 RISC-V 规范直接给出结果，不进入迭代 |

### 4.9 时序预算

适用于 `edrv32_cpu_subsys` 内全部寄存器到寄存器的路径（core、I$、D$、预测器 RAM）。级数按 LUT 级计：32 位加法或比较的进位链计 2 级，muxf7/muxf8 各计 1 级。**[待定]** 预算值在卡 59 的 PDS 结果出来后校准。

| 起点 | 到下一个寄存器的级数上限 |
|---|---|
| 触发器、分布式 RAM（LUTRAM）输出 | 7（卡 56 实测 LUTRAM 输出弧 0.08–0.24 ns，按触发器计） |
| DRM 输出 | 4 |
| APM 输出 | 0：直接进入寄存器 |

| 规则 | 内容 |
|---|---|
| 单周期环 | ALU 加旁路的环（E 结果 → 旁路选择 → ALU → E 结果）、F1 下一 PC 的环都必须满足上表；卡 56 R1 中前者为 9–10 级，必须改结构，不能靠布局布线参数 |
| 前端控制 | 重定向、冲刷和预测器训练进入 F1、F2、IB、I$ 时只来自寄存器（4.4），不组合地经过 E/M 级的判定、停顿或 D$ 握手 |
| 扇出 | 级数 ≥ 5 的路径上，驱动超过 16 个负载的网络用寄存器复制，每个副本 ≤ 16 个负载 |
| 判定 | 以 PDS 结果为准（第 1 节 CPU+L1 独立频率）；Linux 端的综合级数只作参考 |

### 4.10 提前地址生成

| 项 | 规定 |
|---|---|
| 条件 | D 级的 load，其 rs1 的最新值在本周期开始时已经在寄存器堆或 M/W 级的结果寄存器中。等价地，rs1 不是以下指令的目的寄存器：同组较老的槽、正在 E 级的任何指令、正在 M 级的 load 或 CSR 读、结果尚未产生的乘法 |
| 行为 | D 级用 rs1 与立即数计算地址，在发射到 E 的同时提前访问 D$ 的 tag 和数据 RAM；命中时 load 数据在 E 级末尾可用，结果延迟为 1（2.3） |
| 推测 | 提前查询只读 RAM，不改变 D$ 状态（LRU、填充、写缓冲、缺失状态机）；被冲刷的 load 的提前查询没有任何效果。接口见 3.3 的 `dc_early_*` |
| 请求 | 该 load 在 E 级照常发出普通请求，在 M 级按普通接口完成和提交，异常和状态更新与普通 load 相同。提前查询成功、并且该 load 在查询的下一个周期离开 E 时，D$ 用已寄存的提前结果作为 M 级响应，不再读 RAM，读口留给下一条提前查询 |
| 失败 | `dc_early_hit_i` 为 0（或该 load 没有在下一个周期离开 E）时，已经按延迟 1 发射的相关指令在 E 级冻结，用 M 级的普通结果修复操作数后再执行。冻结只由寄存的失败标志驱动，不组合地依赖 `dc_early_hit_i` |
| 时序 | `dc_early_data_i` 到消费者操作数寄存器的路径从 DRM 出发，按 4.9 不超过 4 级 |
| store | 不提前 |

### 4.11 load 后的比较分支

| 项 | 规定 |
|---|---|
| 条件 | D 级的条件分支，它的一个或两个源寄存器只依赖正在 E 级、结果延迟为 2 的 load；该分支是本组最年轻的指令（槽 1，或单独发射） |
| 行为 | 分支不在 D 级停顿，照常发射；在 M 级用该 load 已寄存的结果（W 级结果寄存器）完成比较和判定 |
| 重定向 | 见 4.4 M 级重定向，代价 5 个周期；预测正确时没有额外周期 |
| 发射限制 | 4.11 的分支在 E 级的周期，D 级不发射任何控制转移指令（条件分支、JAL、JALR），保证它在 M 级判定时没有同时在 E 级判定的分支，每周期至多一次预测器更新（4.4）。该限制只依赖 E 级的寄存状态 |
| 其他 | 不满足条件的分支（包括槽 0 的分支后面配有年轻指令的情况）按 2.3 的 load 结果延迟停顿，组照常配对 |

## 5. 寄存器（CSR）

| CSR | 地址 | 说明 |
|---|---|---|
| mstatus | 0x300 | MIE、MPIE；MPP 固定为 3 |
| misa | 0x301 | 只读，反映实际实现的扩展 |
| mie | 0x304 | MEIE、MTIE、MSIE |
| mtvec | 0x305 | BASE + MODE（0 direct，1 vectored） |
| mcountinhibit | 0x320 | CY、IR、HPM3–10 可写，其余只读为 0 |
| mhpmevent3–10 | 0x323–0x32A | 5 位事件编码（7.1），高位只读为 0 |
| mscratch | 0x340 | |
| mepc | 0x341 | 低 2 位固定为 0 |
| mcause | 0x342 | |
| mtval | 0x343 | 地址类异常写入出错地址；非法指令写入指令编码；EBREAK 写入该指令的 PC；其他写 0 |
| mip | 0x344 | MEIP、MTIP、MSIP，只读 |
| mcycle / mcycleh | 0xB00 / 0xB80 | 64 位 |
| minstret / minstreth | 0xB02 / 0xB82 | 64 位，每周期可增加 0、1 或 2 |
| mhpmcounter3–10 / 高半部 | 0xB03–0xB0A / 0xB83–0xB8A | 64 位 |
| cycle、instret、hpmcounter3–10 及高半部 | 0xC00、0xC02–0xC0A / 0xC80、0xC82–0xC8A | 只读别名 |
| time / timeh | 0xC01 / 0xC81 | 只读，返回 `mtime_i` |
| mvendorid、marchid、mimpid、mhartid | 0xF11–0xF14 | 只读；mhartid = 0 |

访问未实现的 CSR、写只读 CSR，都产生非法指令异常。

补充约定：

- 复位值：除 mstatus.MPP 固定为 3 外，全部 CSR 复位为 0；mvendorid、marchid、mimpid 为 0。
- misa 为 WARL：读出实际实现的扩展，写入被忽略，不产生异常（属于上一句"写只读 CSR"的例外）。
- mtvec.MODE 为 WARL：写入 2、3 时 MODE 变为 0。
- 同一周期 CSR 指令写计数器（mcycle、minstret、mhpmcounter）与该计数器的自动加一冲突时，CSR 写入生效。
- 同一周期 M 级异常/中断进入与 CSR 写入或 MRET 冲突时，异常/中断进入优先，该 CSR 指令或 MRET 不提交。

### 7.1 HPM 事件（mhpmevent 编码，5 位）

|---|---|---|---|
| 0 | 不计数 | 9 | load-use 停顿周期 |
