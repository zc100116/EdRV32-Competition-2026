## 1. 概述

DISP 每帧从 DDR 读两层 Surface：底图层 L0（RGB565，不透明）和 UI 层 L1（ARGB8888，非预乘 alpha）。两层各经一个扫描 FIFO 送到 clk_pix 域，逐像素混合后按 CEA-861 720p60 时序输出 TMDS 符号（SoC 3.3 `tmds_sym_o`）。两层各自交接 Surface（设计记录 image-path Q6、rnd-disp 3.3），新参数在帧边界生效。

```
clk_mem:  寄存器块 ─ 读控制 ─ dma2d_rd ─ mem_xbar P0
                       │          ├─ async_fifo L0（X5）─┐
                       │          └─ async_fifo L1（X5）─┤
                       └─ 本帧扫描参数（X5 握手）───────┤
clk_pix:  帧请求(X6) ── 显示时序 ─ 扫描 + 混合 ─ TMDS 编码 ─ tmds_sym_o
```

时钟域：寄存器块、读控制、`dma2d_rd` 在 clk_mem；显示时序、扫描、混合、TMDS 编码在 clk_pix（SoC 5.1）。复位：`rst_mem_n`、`rst_pix_n`（系统子系统规格 2.10）。

## 2. 功能描述

### 2.1 显示时序（按旧工程移植）

与旧工程 `edrv32_hdmi_timing.v` 相同（盘点 1.2、2），参数固定，不提供寄存器：

| 项 | 水平（像素） | 垂直（行） |
|---|---:|---:|
| 有效 | 1280 | 720 |
| 前沿 | 110 | 5 |
| 同步 | 40 | 5 |
| 后沿 | 220 | 20 |
| 总计 | 1650 | 750 |

像素时钟 74.25 MHz，帧率 60 Hz；HS、VS 高有效。VS 的跳变与 HS 前沿对齐（CEA-861 逐行扫描）：以有效区第 0 行第 0 列为原点，VS 在第 725 行 x = 1390 处变高，持续 5 行。行、场计数从 `rst_pix_n` 释放后立即开始，与 `CTRL.ENABLE` 无关，始终输出完整时序（显示器不失锁）；未扫描的帧输出黑色。

### 2.2 TMDS 编码（按旧工程移植）

- 三个通道 B、G、R 各一个 8b/10b TMDS 编码器，算法与旧工程 `edrv32_tmds_encoder.v` 相同（最小化跳变 + 直流平衡，运行差异计数）。
- 有效区编码像素；消隐区输出控制符号：B 通道的 `{c1, c0}` = `{VS, HS}`，G、R 通道为 `{0, 0}`。
- DVI 编码方式：不发送数据岛（无 InfoFrame、无音频）。
- `tmds_sym_o[9:0]` = B，`[19:10]` = G，`[29:20]` = R（SoC 3.3）。时钟通道符号（`10'b1111100000`）、10:1 串化、`GTP_OSERDES_E2`、`GTP_OUTBUFDS` 在 FPGA 层（盘点 8 移植清单）。

### 2.3 像素格式

RGB565 展开为每通道 8 位：R、B `{v[4:0], v[4:2]}`，G `{v[5:0], v[5:4]}`（与 PIX 相同）。

### 2.4 帧请求与参数生效

1. 每帧最后一个有效行结束时（进入场消隐，第 720 行开始），显示时序在 clk_pix 采样同步后的 `CTRL.ENABLE`：为 1 则本帧之后的下一帧**扫描**，并向 clk_mem 发一个帧请求（X6 握手，clk_mem 侧记下请求后才应答）；为 0 则下一帧输出黑色，不发请求。
2. 读控制收到帧请求后：若上一帧已经全部读完，立即开始读新的一帧；否则记下这个请求，在上一帧读完后立即开始。
3. 开始读一帧时，把 4.2 中标为"帧锁存"的寄存器一次锁存为本帧参数（SoC 7.1"下一帧生效"、8.8"新 Surface 只在 VBlank 生效"：锁存发生在场消隐开始之后，新内容从下一帧第一个像素起显示）。
4. 锁存的同一拍置 `IRQ_STAT.FRAME`、`FRAME_CNT` 加 1。对每一层分别判断释放：若上一帧读取了该层（该层使能），而本帧不读该层（该层关闭）或该层基址与上一帧不同，则置该层的 SWITCH（L0 为 `IRQ_STAT.SWITCH`，L1 为 `IRQ_STAT.SWITCH1`），该层的 REL_BASE = 上一帧该层的 CUR_BASE。此时上一帧的全部读事务已经完成，旧 Surface 已释放（SoC 7.3 R3、R4），软件可以把它交给生产者。只改 `L0_SCROLL` 或 L1 的位置、大小、透明度，不构成释放。
5. 软件不改参数时，每帧重复显示同一组 Surface（SoC 8.8"无新帧"），不置 SWITCH。
6. 锁存的同时，读控制经握手（X5，`cdc_handshake`）把扫描侧需要的本帧参数送到 clk_pix：`L0_EN`、L0 拍内偏移 `SCROLL_X[3:0]`、`L1_EN`、L1 的 `X`、`Y`、`W`、`H`、`OPA`。扫描侧在该帧第 0 行开始时取用最近收到的一组参数。由于每帧的读事务在该帧最后一行扫描前完成（否则已经读空），第 2 条中的"上一帧尚未读完"只在读空时发生；其余情况下参数在场消隐内（30 行，约 0.67 ms）到达。
7. 场消隐 30 行是新帧的预取时间。

### 2.5 读取

- 一个 `dma2d_rd`，`OUTSTANDING` = 4。每帧按行号 y = 0…719 依次处理；每一行先发 L0 的行描述符（`L0_EN` = 1 时），再发 L1 的行描述符（`L1_EN` = 1 且 `Y` ≤ y < `Y + H` 时）。两层都关闭时不发描述符。
- L0 行描述符：`base = CUR_BASE + (SCROLL_Y + y) × CUR_STRIDE + 32 × ⌊SCROLL_X / 16⌋`，`stride = CUR_STRIDE`，`height = 1`；`width_bytes` = 2560（`SCROLL_X` mod 16 = 0，80 beat）或 2592（否则，81 beat）。
- L1 行描述符：`base = L1_CUR_BASE + (y − Y) × L1_CUR_STRIDE`，`stride = L1_CUR_STRIDE`，`width_bytes = 4 × W`，`height = 1`；`W / 8` beat。L1 Surface 的第 0 行第 0 列对应屏幕上的 (`X`, `Y`)。
- 描述符严格按上述顺序发出；每个描述符只在对应层扫描 FIFO 的空位（容量减去水位，再减去已发出、尚未写入 FIFO 的 beat 数）不少于该行 beat 数时发出，前一个描述符未发出时后面的不发。因此 `dma2d_rd` 的输出始终被接收，P0 的读数据通道不反压（不占住 mem_xbar 读返回缓冲，SoC 6.4.4）。
- 读控制按发出顺序记录每个描述符所属的层，把 `dma2d_rd` 输出的每一行写入该层的扫描 FIFO。
- 每个扫描 FIFO 的水位在 clk_mem 侧由写入计数减去同步过来的读出计数得到（读出计数经 `cdc_gray_cnt`，X6）；同步延迟只会使水位偏高、空位偏少，不会溢出。

### 2.6 扫描 FIFO

- 每层一个 `rtl/common/edrv32_async_fifo.v`，宽 256 位：L0 FIFO 每 beat 16 个 RGB565 像素，深度 512 **[待定]**；L1 FIFO 每 beat 8 个 ARGB8888 像素，深度 512 **[待定]**。两者都至少容纳 2 行（L0 162 beat，L1 320 beat；SoC 8.8）。beat 内低地址像素在前（SoC 4.5）。
- `urgent_o`：读控制正在读一帧，且满足下列任一条件时为 1（SoC 8.8）：
  - `L0_EN` = 1 且 L0 FIFO 水位低于 81 beat；
  - `L1_EN` = 1，读控制下一个要处理的行号 y 满足 `Y` ≤ y < `Y + H`，且 L1 FIFO 水位低于 `W / 8` beat。

### 2.7 扫描与混合

本节的 L0、L1 参数均为扫描侧取用的本帧参数（2.4 第 6 条）。

**L0**（`L0_EN` = 1）：
- 令 p = `SCROLL_X` mod 16。每个有效行开始时取一个 beat，从其第 p 个像素起依次作为屏幕 x = 0, 1, … 的底图像素；一个 beat 用完后取下一个。每行取 80（p = 0）或 81（p ≠ 0）个 beat，最后一个 beat 中用不到的像素丢弃。
- 需要取 beat 时 L0 FIFO 为空：本应来自这个 beat 的像素的底图输出黑色，L0 **欠账**加 1，本帧记为 L0 读空（第 6 节 ERR_CODE 1）。
- `L0_EN` = 0：底图为黑色，不从 L0 FIFO 取数。

**L1**（`L1_EN` = 1）：
- 在 `Y` ≤ y < `Y + H` 的行中，从 x = `X` 起每 8 个像素取一个 beat，到 x = `X + W − 1` 为止，每行 `W / 8` 个 beat。
- 需要取 beat 时 L1 FIFO 为空：这 8 个像素的 L1 视为全透明，L1 **欠账**加 1，本帧记为 L1 读空（ERR_CODE 3）。
- 矩形之外的像素，以及 `L1_EN` = 0 时的全部像素，L1 视为全透明，不从 L1 FIFO 取数。

**欠账**（每层一个计数）：欠账不为 0 时，该层 FIFO 中到达的 beat 先丢弃（每丢一个欠账减 1），再用于显示。欠账跨帧保留。由于各帧按请求顺序完整读出（2.4 第 2 条），丢弃的正好是迟到的、已经错过显示位置的 beat，后续像素位置保持对齐。欠账偿还在消隐和未扫描帧中照常进行。

**混合**（逐位规定，参考模型与之一致）：

- 记 d(x) = (t + (t >> 8)) >> 8，其中 t = x + 128。对 0 ≤ x ≤ 65025，d(x) 等于 x / 255 四舍五入（0.5 进位）。
- 底图颜色 B_c（c ∈ R、G、B）由 L0 像素按 2.3 展开到 8 位；底图为黑色时 B_c = 0。
- L1 像素 {α, R, G, B}（ARGB8888，`[31:24]` = α）：a = d(α × OPA)；L1 视为全透明时 a = 0。
- 输出 out_c = d(a × F_c + (255 − a) × B_c)，F_c 为 L1 像素的 8 位颜色。a = 0 时 out_c = B_c，a = 255 时 out_c = F_c。

**未扫描的帧**（2.4 第 1 条为 0）输出黑色，不为显示从 FIFO 取数，也不计读空。

### 2.8 停止确认（clk_mem ↔ clk_pix）

保证 clk_mem 侧在判定"已停稳"时，没有仍在跨域途中的帧请求（SoC 5.2 X5、X6）：

- clk_pix 侧电平 `scan_live` = 同步后的 `ENABLE` 为 1，或帧请求握手尚未完成；经电平同步送到 clk_mem。
- clk_mem 侧每次 `ENABLE`（含 ABORT、SOFT_RST 引起的清零）由 1 变 0，向 clk_pix 发一次停止确认握手；clk_pix 侧只有在同步后的 `ENABLE` 为 0 且帧请求握手已完成时才应答。握手完成前 clk_mem 侧视为扫描侧仍在运行。
- STATUS.BUSY 包含：同步后的 `scan_live`，或停止确认未完成，或本帧参数握手（2.4 第 6 条）未完成。

## 4. 寄存器

媒体 APB 槽 5。公共寄存器按 SoC 7.1；寄存器块忽略 `pstrb`，按整字写。未列出的偏移读为 0、写忽略。

### 4.1 公共寄存器

| 偏移 | 名称 | 规定 |
|---|---|---|
| 0x000 | ID | 0x0005_0002 |
| 0x004 | CTRL | bit0 ENABLE（2.4 第 1 条，下一帧生效）；bit1 START 无作用；bit2 ABORT（5.2）；bit3 SOFT_RST：先按 5.2 停止接受帧请求，等到 STATUS.IDLE（已请求的帧读完、两层欠账归零），再把 clk_mem 侧寄存器和控制状态回到复位值；扫描 FIFO 和跨域计数器不复位，PERF0–2、5–6 以 SOFT_RST 时的值为基线清零；clk_pix 侧由媒体软复位复位（系统子系统规格 2.10） |

|---|---|

| 1 | L0 读空的帧数（clk_pix） |
| 2 | L0 读空的 beat 数（clk_pix） |
| 3 | `p0_urgent_o` 为 1 的 clk_mem 周期数 |
| 4 | 帧请求到达时上一帧尚未读完的次数（2.4 第 2 条） |
| 5 | L1 读空的帧数（clk_pix） |
| 6 | L1 读空的 beat 数（clk_pix） |

## 5. 行为与时序

### 5.1 使能

- `CTRL.ENABLE` 置 1：下一个场消隐开始时发出第一个帧请求，再下一帧开始显示。
- 清零：已请求的帧照常读完并扫描完，之后输出黑色。
- `LAYER_CTRL` 的两层开关按帧锁存，与 `CTRL.ENABLE` 相互独立；`CTRL.ENABLE` = 1 而两层都关闭时，帧照常请求、锁存和报告 FRAME，输出黑色。

### 5.2 ABORT

DISP 没有可中止的命令。`CTRL.ABORT` 写 1 等同于把 `CTRL.ENABLE` 清零：不再接受新的帧请求，已请求的帧照常读完（保证扫描侧两层欠账能够归零，2.7），并完成 2.8 的停止确认，之后 STATUS.IDLE = 1，不留下未完成的总线事务（SoC 7.1）。

### 5.3 软件交接（设计记录 image-path Q6、rnd-disp 3.3）

1. 生产者（VIN CH0、GEO、RND 或 CPU）报告某 Surface 完成；
2. 软件写该层的基址寄存器（以及需要改变的其他帧锁存寄存器）。同一帧要一起生效的一组参数，应在 FRAME 中断之后一次写完：FRAME 发生在锁存时刻，距下一次锁存约 16.7 ms；
3. 下一次 FRAME 中断时，若某层的 SWITCH 为 1，该层 REL_BASE 指向的 Surface 交还生产者（清除其 SLOT_BUSY 标记或放回空闲环）；
4. 显示中的 Surface（两层的 CUR_BASE）由软件在生产者侧标为占用（VIN `CHn_SLOT_BUSY`），满足 SoC 7.3 R3。

各场景的图层用法见设计记录 `2026-10-29-rnd-disp.md` 3.5。

## 6. 错误处理

| ERR_CODE | 错误 | 检测 | 上报 | 恢复 |
|---|---|---|---|---|
| 1 | L0 读空 | 扫描侧（2.7），每个 L0 读空的帧上报一次（X6 脉冲） | IRQ_STAT.ERROR、PERF 1–2 | 欠账机制自动恢复对齐 |
| 2 | 读响应非 OKAY | `dma2d_rd` `err_o` | IRQ_STAT.ERROR | 数据照常显示 |
| 3 | L1 读空 | 扫描侧（2.7），每个 L1 读空的帧上报一次（X6 脉冲） | IRQ_STAT.ERROR、PERF 5–6 | 同 1 |

寄存器的对齐由位宽保证；4.2 中由软件保证的范围不检查。

## 8. 验证要点

1. 时序：HS/VS/DE 的位置和宽度与 2.1 逐项一致；TMDS 符号与参考编码器（Python 模型）逐符号一致，运行差异在消隐后正确复位。
2. 扫描：DDR 中的测试图（含每行不同内容、stride > 2560）逐像素与输出一致；L0 卷轴覆盖 p = 0…15 和非零 SCROLL_Y。
3. 混合：L1 的 α 和 OPA 取 0、255 和中间值，输出与 2.7 公式逐位一致；L1 矩形边界（X = 0、X + W = 1280、W = 8、H = 1）。
4. 交接：帧中写帧锁存寄存器只在下一帧生效；每层 SWITCH、REL_BASE 的时刻与值，含该层开、关切换；只改卷轴或位置不置 SWITCH；不改参数时重复显示。
5. 读空：P0 长时间不响应造成两层读空，L0 输出黑色、L1 透明，计数正确，DDR 恢复后两层像素位置各自对齐（欠账）；帧请求到达时上一帧未读完。
6. 读取不反压：两层同时打开时任何情况下 `p0_rready` 为 1；描述符顺序与 2.5 一致。
7. 使能、关闭、ABORT、SOFT_RST 后无未完成事务；clk_pix 与 clk_mem 频率比变化。
