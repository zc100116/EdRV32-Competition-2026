## 1. 概述

I$ 和 D$ 位于 CPU 核与 sys_xbar 之间，属于 clk_sys 域：
- 朝 core 一侧使用 cpu-spec 3.2、3.3 节定义的接口；
- 朝总线一侧各有一个 AXI64 主口（SoC 规格 4.1 节），I$ 只读，D$ 读写；
- 两者都负责本侧访问的 PMA 检查（SoC 规格 6.1 节）。

`edrv32_cache_ctrl` 是系统 APB 槽 5 上的寄存器块，用来向 D$ 发起维护操作，并上报写回错误（PLIC 源号 6）。

## 2. 功能描述

### 2.1 组织

| 项 | I$ | D$ |
|---|---|---|
| 容量 | 32 KiB | 32 KiB |
| 相联度 | 2 路 | 2 路 |
| 行大小 | 32 B | 32 B |
| 组数 | 512 | 512 |
| 地址划分 | tag = `addr[31:14]`，组索引 = `addr[13:5]`，行内偏移 = `addr[4:0]` | 同左 |
| 替换 | 每组 1 位 LRU；命中和填充时更新 | 命中比较结果先寄存，下拍更新 LRU；填充时更新。同组背靠背访问后立即缺失允许使用尚未更新的 LRU，替换选择可与立即更新不同 |
| 写策略 | — | 写回、写分配 |
| 缺失处理 | 阻塞式，同一时刻至多一个缺失 | 阻塞式，同一时刻至多一个缺失 |

### 2.2 存储结构

| 存储 | 实现 | 说明 |
|---|---|---|
| I$ 有效位、I$/D$ LRU 位 | 寄存器 | 复位清零；I$ 整体失效（`ic_inv_o`）在一个周期内完成 |
| D$ 有效位、脏位 | 与 tag 同存于每路 tag RAM，每项 {valid, dirty, tag} | 不靠复位清零；复位后由维护扫描逐组清零（5.5） |
| D$ 组段脏标志 | 寄存器，每个组段 1 位（512 / 组段大小） | 复位清零；该组段任一行变脏时置 1，整体 clean 扫完该组段后清零；只用于整体 clean 跳过干净组段（5.4） |
| tag | 每路一个同步读 RAM，`rtl/tech/` 包装：I$ 512 × 18 位；D$ 512 × 20 位（{valid, dirty, tag[17:0]}） | 不复位 |
| 数据 | 每路一个同步读 RAM，2048 × 64 位（每行 4 个 64 位字），`rtl/tech/` 包装；D$ 的数据 RAM 带 8 位字节写使能 | 不复位 |

| D$ 提前查询副本 | 每路 tag RAM 和数据 RAM 各一份副本，与主 RAM 使用同一包装和 IP | 写口与主 RAM 同时写入同一地址、同一数据和字节使能；读口只服务 cpu-spec 4.10 的提前查询，因此提前查询不与普通请求争用读口（用户 2026-11-05 决定） |

数据 RAM 宽度与 AXI64 一致，一次突发的每一拍写入一个 64 位字；core 读取时由行内偏移选出 64 位（I$）或其中的 32 位（D$）。

### 2.3 PMA 检查

两个 cache 各自用 `rtl/include/edrv32_soc_map.vh` 中生成的常量做地址译码。所有区域的大小都是 2 的幂次且自然对齐，译码只比较地址高位。

| 区域 | I$（取指） | D$（load / store） |
|---|---|---|
| Boot ROM | 不可缓存，单拍读 | load：不可缓存；store：访问错误 |
| SRAM | 可缓存 | 可缓存 |
| CLINT、PLIC、系统 APB、媒体 APB | 访问错误 | 设备访问 |
| DDR（0x8000_0000 起） | 可缓存 | 可缓存 |
| DDR 非缓存别名（0xC000_0000 起） | 访问错误 | 不可缓存访问 |
| 其他地址 | 访问错误 | 访问错误 |

"设备访问"和"不可缓存访问"在 D$ 中的处理相同：置 `dc_resp_device_i`，提交后单拍执行（4.3 节）。PMA 违例不向总线发出请求，直接以 `ic_resp_err_i` / `dc_resp_err_i` 返回。

## 4. 寄存器（edrv32_cache_ctrl，系统 APB 槽 5）

| 偏移 | 名称 | 访问 | 复位值 | 说明 |
|---|---|---|---|---|
| 0x000 | ID | RO | 0x0005_0001 | [31:16] 模块类型码 5，[15:0] 版本 1 |
| 0x008 | STATUS | RO | 0 | bit0 BUSY：维护操作进行中 |
| 0x00C | IRQ_EN | RW | 0 | bit1：写回错误中断使能 |
| 0x010 | IRQ_STAT | RW1C | 0 | bit1：写回错误。软件写 1 清除与新的写回错误同一周期发生时，新错误优先：该位保持为 1，ERR_ADDR 记录新错误的地址 |
| 0x014 | ERR_ADDR | RO | 0 | 最近一次写回出错的行地址 |
| 0x020 | OP_ADDR | RW | 0 | 维护范围起始字节地址 |
| 0x024 | OP_SIZE | RW | 0 | 维护范围长度（字节） |
| 0x028 | OP_CMD | WO | — | 写入 1–4 启动对应操作（3.2 节编码）；写入其他值无效果；BUSY 为 1 时写入无效果 |

未列出的偏移读出 0，写入无效果。

## 5. 行为与时序

### 5.1 I$

| 情况 | 时序 |
|---|---|
| 命中 | 请求被接受的下一个周期 `ic_resp_valid_i = 1`；每周期可以接受一个新请求 |
| 缺失（可缓存） | `ic_req_ready_i` 从发现缺失的下一个周期起拉低（只由寄存状态给出，不取决于本周期的 tag 比较）；发现缺失的那个周期被接受的下一条请求丢弃，不返回响应（cpu-spec 3.2、4.3）；选 LRU 路作为替换路；发出 AR（行对齐地址，LEN = 3，SIZE = 3，INCR）；4 拍数据依次写入数据 RAM；写 tag、置有效位、更新 LRU；然后返回该请求的 64 位数据，`ic_req_ready_i` 恢复 |
| ROM 取指 | 发出单拍 AR（SIZE = 3），数据直接返回，不装入 cache；`ic_req_ready_i` 和下一条请求的丢弃与缺失相同 |
| `ic_kill_o` | 丢弃尚未返回的响应；正在进行的填充继续完成并装入 cache，但不返回给 core。与 kill 同一周期给出的响应不受影响，由 core 忽略；kill 不得组合地屏蔽同一周期的响应（避免组合环）。 |
| `ic_inv_o` | 清除全部有效位，下一个周期给出 `ic_inv_done_i`。与在途填充重叠时 invalidate 优先：填充照常接收完 4 拍并把该请求的数据返回给 core（未被 `ic_kill_o` 取消时），但该行不置有效 |

### 5.2 D$：可缓存访问

| 情况 | 时序 |
|---|---|
| load 命中 | 请求被接受后的第二个周期（M2） `dc_resp_valid_i = 1`，`dc_resp_way_data_i` 为两路各自按地址移到低位并合并写缓冲的数据；每周期可以接受一个新请求 |
| 提前查询（cpu-spec 4.10） | `dc_early_valid_i` 有效的周期用 `dc_early_addr_i` 读 tag 和数据 RAM，下一周期给出 `dc_early_way_hit_o` / `dc_early_way_data_o`（格式同普通响应）；从提前查询副本读取（2.2），不与普通请求、缺失处理和维护操作争用读口。查询拍或响应拍有维护操作进行或开始时 hit 为 0，普通请求按 5.4 延后处理。不改变 LRU、填充、写缓冲、缺失状态机。写缓冲或 M/M2 级已接受的 store 中有同一个字、缺失、设备或非缓存时 hit 为 0；不检查对齐（未对齐 load 由 core 在 M2 级报异常）。成功、并且下一周期被接受的普通请求带 `dc_req_early_i = 1`（cpu-spec 3.3，表示它就是该查询对应的 load）时，请求接受后的第二周期 M2 级响应使用寄存的提前结果，不再读 RAM；`dc_req_early_i = 0` 时走普通路径。没有握手，`dc_kill_o` 不影响提前结果，由 core 丢弃 |
| store 命中 | 请求被接受后的第二个周期（M2） `dc_resp_valid_i = 1`，表示 tag 检查通过；数据在 `dc_commit_o` 时进入写缓冲 |
| 写缓冲 | 1 项，保存地址、32 位数据、4 位字节使能；进入后的下一个周期通过数据 RAM 的写口写入并置脏位。写入与接收新一项可以在同一周期完成，因此连续提交的 store 不停顿 |
| 写缓冲旁路 | load 的字地址与写缓冲中的地址相同时，返回数据按字节使能合并写缓冲中的字节 |
| 缺失 | `dc_req_ready_i` 拉低；选 LRU 路作为替换路；替换行为脏时，先发出写回突发（AW 握手成功的那个周期给 `dc_wb_event_i` 一个单周期脉冲，维护操作的写回同样如此；设备 store 不产生脉冲）（AW 行地址，LEN = 3，SIZE = 3，4 拍 W，等待 B），再发出填充突发；填充完成后写 tag、置有效位、清脏位、更新 LRU，然后完成该请求 |
| `dc_kill_o` | 取消 M、M2 级尚未提交的请求：load 不返回数据；store 不进入写缓冲。已经开始的填充继续完成并装入 cache。与 kill 同一周期给出的响应不受影响，由 core 忽略；kill 不得组合地屏蔽同一周期的响应（避免组合环）。 |

### 5.3 D$：设备和不可缓存访问

1. 请求在 M2 级经 PMA 判为设备/不可缓存时，D$ 给出 `dc_resp_device_i = 1`，不访问 cache 阵列，等待 `dc_commit_o`。
2. 收到 `dc_commit_o` 后发出单拍 AXI 事务：地址为原地址，SIZE 为访问大小，`WSTRB` 按 `addr[2:0]` 落在 64 位总线的对应字节。
3. load 收到 R 后，`dc_resp_valid_i = 1`；store 收到 B 后，`dc_resp_valid_i = 1`（非推送）。
4. 被 `dc_kill_o` 取消的设备请求不发出总线事务。

### 5.4 维护操作

| 操作 | 行为 |
|---|---|
| 范围 clean | 对 `[OP_ADDR, OP_ADDR + OP_SIZE)` 覆盖到的每一行：查 tag，命中且脏则写回并清脏位 |
| 范围 invalidate | 对覆盖到的每一行：命中则清有效位（不写回，脏数据丢弃） |
| 范围 clean+invalidate | 对覆盖到的每一行：命中且脏则写回，然后清有效位 |
| 整个 D$ clean | 对全部 512 组 × 2 路中的脏行：写回并清脏位 |
| FENCE.I（`dc_clean_all_o`） | 与"整个 D$ clean"相同；完成时给出 `dc_fence_done_i` |
| FENCE（`dc_fence_o`） | 写缓冲为空时给出 `dc_fence_done_i` |

- 普通请求在 M 末直接寄存每路原始 tag 和数据，M2 比较、选路；写缓冲捕获与 LRU 更新使用寄存后的命中状态。连续命中每周期可接受一请求，M2 停顿时保留 M 中已接受请求。
- 维护操作开始前先等写缓冲排空，并等待 M/M2 查询不再占用阵列；已接受请求保留至维护完成后继续。
- 维护操作进行期间（`maint_busy_o = 1`）：D$ 照常接受请求，`dc_req_ready_i` 不取决于请求地址（cpu-spec 3.3）；已接受的可缓存请求等维护操作完成后才访问阵列，在此之前不返回响应（CPU 停在 M2 级）；设备和不可缓存请求照常执行，因此 CPU 可以轮询 STATUS；PMA 违例请求按 2.3 在 M2 级直接返回错误，不等待维护完成。
- 命令 1–3 的 OP_SIZE 为 0 时，操作立即完成。命令 4 和 FENCE.I 的整体 clean 不使用 OP_ADDR、OP_SIZE。
- 范围操作只访问范围覆盖到的组：覆盖行数 N = ⌈(OP_ADDR + OP_SIZE) / 32⌉ − ⌊OP_ADDR / 32⌋；N 小于组数时按行地址依次访问这 N 个组，N 不小于组数时每组访问一次。每次访问同时检查两路的 tag，两路都按上表处理。
- 整体 clean 只访问含脏行的组：按组段脏标志检查，标志为 0 的组段直接跳过。组段大小由实现决定 **[待定]**（开发初值 16 组）。

### 5.5 复位

复位清除 I$ 有效位、LRU 位、D$ 组段脏标志、写缓冲有效标志和状态机；tag 和数据 RAM 不复位。复位释放后，D$ 用维护扫描逐组把两路 tag RAM 项写为 {valid = 0, dirty = 0}，共 512 个周期；扫描期间 `dc_req_ready_i` 为 0，不接受维护请求。扫描完成后两个 cache 均为空。

## 6. 错误处理

| 错误 | 检测 | 上报 | 状态 |
|---|---|---|---|
| PMA 违例 | 地址译码 | `ic_resp_err_i` / `dc_resp_err_i` | 不发出总线事务 |
| 填充读到错误响应（SLVERR/DECERR） | R 通道 | 该请求返回错误 | 该行不装入（有效位保持 0）；本次突发的剩余拍照常接收 |
| 设备/不可缓存访问返回错误 | R/B 通道 | `dc_resp_err_i` | — |

`dc_resp_err_i` 只在 `dc_resp_valid_i` 为 1 的周期为 1（cpu-spec 3.3）；D$ 必须用自身的寄存器状态产生 err，不得让 err 依赖本拍的 tag 比较结果。
| 脏行写回返回错误 | B 通道 | `wb_err_o` 脉冲；`edrv32_cache_ctrl` 置 IRQ_STAT.bit1、记录 ERR_ADDR | 被替换行的数据丢失；后续填充照常进行 |

## 7. 性能与资源指标

| 指标 | 要求 |
|---|---|
| 命中延迟 | I$ 在请求被接受后的下一周期返回；D$ 在第二周期 M2 返回；提前查询仍下一周期 E 返回 |
| 命中吞吐 | 每周期一个请求 |
| 缺失代价（SRAM，无竞争，干净替换） | 从缺失确定到返回数据不超过 4 + AXI 往返延迟 + 4 拍数据 个周期 |
| 范围维护 | 无写回时，从 OP_CMD 被接受到 BUSY 清零不超过 min(N, 512) + 8 个周期 **[待定]**；每个脏行另加该行引起的扫描停顿（含 tag 捕获、等总线、行写回 AW→B、恢复扫描），每行额外停顿为固定周期数 **[待定]** |
| 整体 clean | 无脏行时不超过 512 / 组段大小 + 8 个周期 **[待定]**；每个脏行的附加时间同上 |
| 时序 | clk_sys 时序路径不由 cache 限制：cache 内部及 cache 与 CPU 之间的路径级数不超过 CPU 核内最长路径，目标频率以 PDS 实测为准 **[待定]** |
| 存储资源 | I$、D$ 各为数据 RAM 2 × 2048 × 64 位；tag RAM：I$ 2 × 512 × 18 位，D$ 2 × 512 × 20 位；D$ 另有提前查询副本：数据 2 × 2048 × 64 位、tag 2 × 512 × 20 位 |
| 复位初始化 | D$ 复位释放后 512 个周期内完成清零（5.5） |
| 逻辑资源 | 计入 CPU"核 + cache 控制 ≤ 10K LUT"的预算 |
