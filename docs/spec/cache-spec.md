## 1. 概述

I$ 和 D$ 位于 CPU 核与 sys_xbar 之间，属于 clk_sys 域：
- 朝 core 一侧使用 cpu-spec 3.2、3.3 节定义的接口；
- 朝总线一侧各有一个 AXI64 主口（SoC 规格 4.1 节），I$ 只读，D$ 读写；
- 两者都负责本侧访问的 PMA 检查（SoC 规格 6.1 节）。

`edrv32_cache_ctrl` 是系统 APB 槽 5 上的寄存器块，用来向 D$ 发起维护操作，并上报写回错误（PLIC 源号 6）。

## 2. 功能描述

### 2.1 组织

| 项 | I$ | D$ |
|---|---|---|
| 容量 | 8 KiB **[待定]** | 8 KiB **[待定]** |
| 相联度 | 2 路 | 2 路 |
| 行大小 | 32 B | 32 B |
| 组数 | 128 | 128 |
| 地址划分 | tag = `addr[31:12]`，组索引 = `addr[11:5]`，行内偏移 = `addr[4:0]` | 同左 |
| 替换 | 每组 1 位 LRU（2 路时即精确 LRU）；命中和填充时更新 | 同左 |
| 写策略 | — | 写回、写分配 |
| 缺失处理 | 阻塞式，同一时刻至多一个缺失 | 阻塞式，同一时刻至多一个缺失 |

### 2.2 存储结构

| 存储 | 实现 | 说明 |
|---|---|---|
| 有效位、脏位（D$）、LRU 位 | 寄存器 | 复位清零；整体失效可以在一个周期内完成 |
| tag | 每路一个同步读 RAM，128 × 20 位，`rtl/tech/` 包装 | 不复位 |
| 数据 | 每路一个同步读 RAM，512 × 64 位（每行 4 个 64 位字），`rtl/tech/` 包装；D$ 的数据 RAM 带 8 位字节写使能 | 不复位 |

数据 RAM 宽度与 AXI64 一致，一次突发的每一拍写入一个 64 位字；core 读取时由行内偏移选出 64 位（I$）或其中的 32 位（D$）。

### 2.3 PMA 检查

两个 cache 各自用 `rtl/include/edrv32_soc_map.vh` 中生成的常量做地址译码。所有区域的大小都是 2 的幂次且自然对齐，译码只比较地址高位。

| 区域 | I$（取指） | D$（load / store） |
|---|---|---|
| Boot ROM | 不可缓存，单拍读 | load：不可缓存；store：访问错误 |
| SRAM | 可缓存 | 可缓存 |
| CLINT、PLIC、系统 APB、媒体 APB | 访问错误 | 设备访问 |
| DDR（0x8000_0000 起） | 可缓存 | 可缓存 |
| DDR 非缓存别名（0xC000_0000 起） | 访问错误 | 不可缓存访问 |
| 其他地址 | 访问错误 | 访问错误 |

"设备访问"和"不可缓存访问"在 D$ 中的处理相同：置 `dc_resp_device_i`，提交后单拍执行（4.3 节）。PMA 违例不向总线发出请求，直接以 `ic_resp_err_i` / `dc_resp_err_i` 返回。

## 3. 接口

### 3.1 I$

| 信号组 | 说明 |
|---|---|
| `clk_i`、`rst_n_i` | clk_sys 域 |
| core 接口 | cpu-spec 3.2 节全部信号（方向相反） |
| AXI64 读主口 | 前缀 `axi_`，只有 AR、R 通道，ID 固定为 0 |

### 3.2 D$

| 信号组 | 说明 |
|---|---|
| `clk_i`、`rst_n_i` | clk_sys 域 |
| core 接口 | cpu-spec 3.3 节全部信号（方向相反） |
| AXI64 读写主口 | 前缀 `axi_`，五个通道，ID 固定为 0 |
| 维护接口 | 与 `edrv32_cache_ctrl` 之间，见下表 |

**D$ 与 `edrv32_cache_ctrl` 之间的维护接口**

| 信号 | 方向（以 D$ 为准） | 位宽 | 说明 |
|---|---|---|---|
| `maint_req_valid_i` | in | 1 | 发起一次维护操作，保持到 `maint_req_ready_o` |
| `maint_req_ready_o` | out | 1 | 接受操作 |
| `maint_cmd_i` | in | 3 | 1 范围 clean，2 范围 invalidate，3 范围 clean+invalidate，4 整个 D$ clean |
| `maint_addr_i` | in | 32 | 范围起始字节地址 |
| `maint_size_i` | in | 32 | 范围长度（字节） |
| `maint_busy_o` | out | 1 | 操作进行中（包括 FENCE.I 引起的整体 clean） |
| `wb_err_o` | out | 1 | 一次脏行写回收到错误响应，单周期脉冲 |
| `wb_err_addr_o` | out | 32 | 出错行的地址，与 `wb_err_o` 同拍有效 |

### 3.3 edrv32_cache_ctrl

| 信号组 | 说明 |
|---|---|
| `clk_i`、`rst_n_i` | clk_sys 域 |
| APB 从口 | SoC 规格 4.3 节，前缀 `apb_` |
| 维护接口 | 3.2 节表格（方向相反） |
| `irq_o` | 电平中断，`|(IRQ_STAT & IRQ_EN)`，接 PLIC 源号 6 |

## 4. 寄存器（edrv32_cache_ctrl，系统 APB 槽 5）

| 偏移 | 名称 | 访问 | 复位值 | 说明 |
|---|---|---|---|---|
| 0x000 | ID | RO | 0x0005_0001 | [31:16] 模块类型码 5，[15:0] 版本 1 |
| 0x008 | STATUS | RO | 0 | bit0 BUSY：维护操作进行中 |
| 0x00C | IRQ_EN | RW | 0 | bit1：写回错误中断使能 |
| 0x010 | IRQ_STAT | RW1C | 0 | bit1：写回错误。软件写 1 清除与新的写回错误同一周期发生时，新错误优先：该位保持为 1，ERR_ADDR 记录新错误的地址 |
| 0x014 | ERR_ADDR | RO | 0 | 最近一次写回出错的行地址 |
| 0x020 | OP_ADDR | RW | 0 | 维护范围起始字节地址 |
| 0x024 | OP_SIZE | RW | 0 | 维护范围长度（字节） |
| 0x028 | OP_CMD | WO | — | 写入 1–4 启动对应操作（3.2 节编码）；写入其他值无效果；BUSY 为 1 时写入无效果 |

未列出的偏移读出 0，写入无效果。

## 5. 行为与时序

### 5.1 I$

| 情况 | 时序 |
|---|---|
| 命中 | 请求被接受的下一个周期 `ic_resp_valid_i = 1`；每周期可以接受一个新请求 |
| 缺失（可缓存） | `ic_req_ready_i` 拉低；选 LRU 路作为替换路；发出 AR（行对齐地址，LEN = 3，SIZE = 3，INCR）；4 拍数据依次写入数据 RAM；写 tag、置有效位、更新 LRU；然后返回该请求的 64 位数据，`ic_req_ready_i` 恢复 |
| ROM 取指 | 发出单拍 AR（SIZE = 3），数据直接返回，不装入 cache |
| `ic_kill_o` | 丢弃尚未返回的响应；正在进行的填充继续完成并装入 cache，但不返回给 core |
| `ic_inv_o` | 清除全部有效位，下一个周期给出 `ic_inv_done_i`。与在途填充重叠时 invalidate 优先：填充照常接收完 4 拍并把该请求的数据返回给 core（未被 `ic_kill_o` 取消时），但该行不置有效 |

### 5.2 D$：可缓存访问

| 情况 | 时序 |
|---|---|
| load 命中 | 请求被接受的下一个周期 `dc_resp_valid_i = 1`，`dc_resp_data_i` 为按地址移到低位的数据；每周期可以接受一个新请求 |
| store 命中 | 下一个周期 `dc_resp_valid_i = 1`，表示 tag 检查通过；数据在 `dc_commit_o` 时进入写缓冲 |
| 写缓冲 | 1 项，保存地址、32 位数据、4 位字节使能；进入后的下一个周期通过数据 RAM 的写口写入并置脏位。写入与接收新一项可以在同一周期完成，因此连续提交的 store 不停顿 |
| 写缓冲旁路 | load 的字地址与写缓冲中的地址相同时，返回数据按字节使能合并写缓冲中的字节 |
| 缺失 | `dc_req_ready_i` 拉低；选 LRU 路作为替换路；替换行为脏时，先发出写回突发（AW 行地址，LEN = 3，SIZE = 3，4 拍 W，等待 B），再发出填充突发；填充完成后写 tag、置有效位、清脏位、更新 LRU，然后完成该请求 |
| `dc_kill_o` | 取消 M 级尚未提交的请求：load 不返回数据；store 不进入写缓冲。已经开始的填充继续完成并装入 cache |

### 5.3 D$：设备和不可缓存访问

1. 请求在 M 级经 PMA 判为设备/不可缓存时，D$ 给出 `dc_resp_device_i = 1`，不访问 cache 阵列，等待 `dc_commit_o`。
2. 收到 `dc_commit_o` 后发出单拍 AXI 事务：地址为原地址，SIZE 为访问大小，`WSTRB` 按 `addr[2:0]` 落在 64 位总线的对应字节。
3. load 收到 R 后，`dc_resp_valid_i = 1`；store 收到 B 后，`dc_resp_valid_i = 1`（非推送）。
4. 被 `dc_kill_o` 取消的设备请求不发出总线事务。

### 5.4 维护操作

| 操作 | 行为 |
|---|---|
| 范围 clean | 对 `[OP_ADDR, OP_ADDR + OP_SIZE)` 覆盖到的每一行：查 tag，命中且脏则写回并清脏位 |
| 范围 invalidate | 对覆盖到的每一行：命中则清有效位（不写回，脏数据丢弃） |
| 范围 clean+invalidate | 对覆盖到的每一行：命中且脏则写回，然后清有效位 |
| 整个 D$ clean | 遍历全部 128 组 × 2 路，脏行写回并清脏位 |
| FENCE.I（`dc_clean_all_o`） | 与"整个 D$ clean"相同；完成时给出 `dc_fence_done_i` |
| FENCE（`dc_fence_o`） | 写缓冲为空时给出 `dc_fence_done_i` |

- 维护操作开始前先等写缓冲排空。
- 维护操作进行期间（`maint_busy_o = 1`）：可缓存请求不被接受（`dc_req_ready_i = 0`）；设备和不可缓存请求照常接受，因此 CPU 可以轮询 STATUS。
- 命令 1–3 的 OP_SIZE 为 0 时，操作立即完成。命令 4 和 FENCE.I 的整体 clean 不使用 OP_ADDR、OP_SIZE，总是遍历全部行。

### 5.5 复位

复位清除有效位、脏位、LRU 位、写缓冲有效标志和状态机；tag 和数据 RAM 不复位。复位后两个 cache 均为空。

## 6. 错误处理

| 错误 | 检测 | 上报 | 状态 |
|---|---|---|---|
| PMA 违例 | 地址译码 | `ic_resp_err_i` / `dc_resp_err_i` | 不发出总线事务 |
| 填充读到错误响应（SLVERR/DECERR） | R 通道 | 该请求返回错误 | 该行不装入（有效位保持 0）；本次突发的剩余拍照常接收 |
| 设备/不可缓存访问返回错误 | R/B 通道 | `dc_resp_err_i` | — |
| 脏行写回返回错误 | B 通道 | `wb_err_o` 脉冲；`edrv32_cache_ctrl` 置 IRQ_STAT.bit1、记录 ERR_ADDR | 被替换行的数据丢失；后续填充照常进行 |

## 7. 性能与资源指标

| 指标 | 要求 |
|---|---|
| 命中延迟 | 请求被接受的下一个周期返回 |
| 命中吞吐 | 每周期一个请求 |
| 缺失代价（SRAM，无竞争，干净替换） | 从缺失确定到返回数据不超过 4 + AXI 往返延迟 + 4 拍数据 个周期 |
| 存储资源（每个 cache） | 数据 RAM 2 × 512 × 64 位，tag RAM 2 × 128 × 20 位 |
| 逻辑资源 | 计入 CPU"核 + cache 控制 ≤ 10K LUT"的预算 |
