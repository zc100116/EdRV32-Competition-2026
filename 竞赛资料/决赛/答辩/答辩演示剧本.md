## 逐段剧本

> 每段先列 B 的动作（【B】），再列 A 的台词。动作写在台词前面的，B 要在 A 开口前做完。

### ① 开场（大屏：PPT 封面）

【B】开场前：大屏显示 PPT 封面；开发板、平板上电待命；平板放在胶带标记处。

A：各位评委老师好，我们的作品是 EdRV32 边缘视觉 SoC。我们在一片紫光同创 PG2L200H 上，自己设计了 RISC-V 处理器、神经网络加速器 NPU 和一整条多媒体通路，组成一颗完整的边缘视觉芯片。

A：今天演示里，大屏幕上的每一帧画面，都是这颗芯片实时生成的，中间没有电脑参与。

### ② 系统框图与数据流（大屏：PPT 第 2、3 页）

【A】翻到第 2 页「系统框图」。

A：先看系统框图。左边是我们自研的 RISC-V 处理器，通过 64 位系统总线连接启动 ROM、片上 SRAM 和外设。

A：中间一排是六个专用引擎：视频采集和像素处理、几何变换、2D 渲染、显示、千兆网络和 NPU。它们和 CPU 一起，通过 256 位的 DDR 交叉开关共享 1 GB DDR3。

【A】翻到第 3 页「数据流」。

A：一帧画面这样走：摄像头画面一路存成显示底图，一路缩小成 640 乘 384 交给 NPU；NPU 识别，并在硬件里完成框的解码；CPU 做去重和应用逻辑；渲染引擎画界面和检测框；显示引擎把两层叠加，从 HDMI 输出。

A：现场每秒 27 帧，从拍摄到显示 78 毫秒。

### ③ 分模块介绍（大屏：PPT 第 4–8 页）

【A】翻到第 4 页「CPU」。

A：下面分模块介绍。首先是 CPU。它实现 RV32IM 指令集，七级流水线，每拍最多发射两条指令，有分支预测和各 32 KB 的指令、数据缓存。

A：我们从设计开始就把频率和每拍效率一起考虑，按 FPGA 的逻辑级数切分流水线。现在 CPU 跑在 125 MHz，板上实测 CoreMark 每兆赫 5.57 分。

【A】翻到第 5 页「NPU」。

A：第二是 NPU。核心是 512 个 8 位乘加单元，每拍同时算 32 个输出通道、8 个输入通道和 2 个像素。每层参数是一条 64 字节的描述符，CPU 把整张网络一次交给 NPU。

A：调度上，外层按行推进，整层权重常驻片上，输入提前预取，写回和计算重叠，乘加阵列 86% 的时间都在计算。NPU 跑在 180 MHz，一帧 YOLOv8n 34.4 毫秒。

【A】翻到第 6 页「多媒体引擎」。

A：第三是多媒体引擎。像素处理在采集通路上做 3 乘 3 滤波和边缘检测；几何引擎做任意角度的旋转和缩放；2D 渲染引擎是 LVGL 的硬件绘制后端；显示引擎把视频层和界面层按透明度混合，输出 720p60。

【A】翻到第 7 页「DDR 带宽调度」。

A：七个主设备共享一块 DDR3，而显示和摄像头的每一行都必须准时。所以 DDR 交叉开关按五条规则调度：

A：显示或摄像头缓冲告急时发紧急请求，最先服务；CPU 缓存缺失走低延迟通道，用令牌桶限流；等太久的请求提升优先级，防止饿死；其余按权重轮询分配带宽；读写成组发出，减少换向损失。这样显示最坏只等约 2 微秒。

【A】翻到第 8 页「软件」。

A：最后是软件。板上是裸机 C 程序：驱动、LVGL 图形库加我们的硬件绘制后端、NPU 运行时和各个应用。

A：我们还写了量化部署工具链，把训练好的模型量化成 INT8、编译成描述符，并用参考模型逐位验证。板上部署了 5 个模型，手势和安全帽模型是我们自己训练的。

### ④ 进入演示（大屏：开发板 HDMI）

【A】按 Esc 退出 PPT 放映。【B】把大屏信号切到开发板 HDMI，停在主界面。

A：下面进入功能演示，我的队友负责操作。大屏现在是开发板的 HDMI 输出，这是芯片的主界面，由 LVGL 和我们的 2D 引擎绘制。

【B】按键选中「智慧农场」→ 确认；平板打开 APK「智慧农场」，放到胶带标记处。

A：第一个场景：智慧农场。

### ⑤ 智慧农场（大屏：板上「智慧农场」；平板：APK 智慧农场）

A：比赛现场带不了牛羊，所以我们做了一个平板 App，模拟牧场高处的监控画面。开发板的摄像头对着平板，就相当于对着真实的牧场。

A：芯片已经数出来：牛 2 头、马 1 匹、羊 3 只、鸡 3 只，每只都有检测框。顶栏是实时性能：识别帧率、NPU 每帧耗时和端到端延迟。

【B】板上按「盘点」。

A：队友先按盘点，把现在的数量记为基准，再在平板上开始演示剧本。

【B】平板点「演示」（剧本约 30 秒：羊走出 → 走回 → 人进入 → 离开）。

A：一只羊走出了围栏。数量少了一只，持续两秒以后，系统报警：羊少一只。

（等告警出现再说下一句；走失要持续 2 秒才报警，这是为了避免误报。）

A：羊回来了，告警自动解除。

A：接着有人翻进牧场。芯片检测到人，半秒内报警有人闯入，人的框变成红色。人离开后，告警解除。

【B】板上打开「看板」。

A：看板上记录了走失和闯入的次数和时间。检测、计数和告警判断，全部在芯片上完成。

### ⑥ 工地安全帽（大屏：板上「安全帽检测」；平板：APK 互动工地）

【B】板上返回 → 进入「安全帽检测」；平板返回首页 →「工地」→ 第一项「互动工地」。

A：换一个场景：工地安全。这里用的是我们自己训练的安全帽检测模型。

A：画面里有 6 名工人，芯片识别出 4 人戴了安全帽、2 人没戴：绿框是戴帽，红框是没戴，屏幕给出警示。

【B】平板上依次点两名未戴帽的工人。

A：队友点一下没戴帽的工人，让他戴上，红框变绿。两个人都戴好以后，警示消失。

### ⑦ 抓取实验（大屏：板上「抓取实验」）

【B】收起平板；板上进入「抓取实验」，选好提前测过最稳的抓取方式；站到摄像头前 0.5–1 米，手掌正对镜头。

A：最后是人机交互。这里没有手柄，也没有任何传感器，只有一个摄像头。手部模型一次推理，同时给出 14 种手势和 21 个手部关键点。

【B】伸手抓起一个方块，移动，张手放下。

A：屏幕是镜像画面。队友伸手就能把方块抓起来，带着它移动，张开手就放下。

【B】把两三块叠起来，再推倒。

A：方块和球都有体积，会旋转、碰撞、倒塌。刚体物理全部在 CPU 上用定点数计算，因为我们的处理器没有浮点单元；旋转的方块贴图由几何引擎预先生成。

【B】抓起一块，朝一侧用力一甩再张手。

A：抓起来用力一甩，它会顺着手的方向飞出去。

### ⑧ 总结（大屏：开发板主界面，不切回 PPT）

【B】抓取实验结束后退回板上主界面，大屏保持开发板画面。

A：总结一下。我们在一片 PG2L200H 上实现了一颗完整的边缘视觉 SoC：自研双发射 RISC-V 处理器，125 MHz，CoreMark 每兆赫 5.57 分；自研 NPU，每拍 512 次乘加，一帧 34.4 毫秒；从摄像头到显示的完整多媒体通路和 2D 图形引擎；以及量化部署工具链和全部应用。

A：整颗芯片用了约 8.9 万个查找表。谢谢各位老师，请批评指正。

## 为什么只演这三个场景

| 场景 | 选它的原因 |
|---|---|
| 智慧农场 | 通用检测 + 计数 + 告警，故事完整，平板可控，效果稳定 |
| 工地安全帽 | 自训练模型，评委能看到"我们自己训练"的成果；可交互 |
| 抓取实验 | 自训练手势模型 + 定点数物理 + 几何引擎，体现软硬件协同，观感最强 |

不演：人体姿态、空中画板、人脸贴纸、方块工坊、各类小游戏、经典游戏、图像处理、跑分。评委提问时可以作为补充演示（人脸贴纸、人体姿态最稳）。

## 现场准备

- 提前 30 分钟上电，把三个场景各进一遍；平板亮度调到最高，关闭自动锁屏、自动旋转和通知。
- 平板用支架固定在胶带标记处，距摄像头约 30–50 cm，占画面宽度约 65%，稍微倾斜避开顶灯反光。
- B 背熟从首页进入各页的按键顺序：智慧农场 → 安全帽检测 → 抓取实验。
- 抓取实验时 B 身后最好是素净背景，画面里不要有其他人。
- 按本剧本计时完整彩排至少 3 遍；彩排时录下每段，作为现场失败时的备份视频。

## 风险与应对

| 情况 | 应对 |
|---|---|
| 平板反光或计数不准 | 调整平板角度和距离；仍不行就说明现场光线影响，播放备份视频 |
| 农场告警慢半拍 | 说明"走失要持续 2 秒才报警，避免误报"，等它出现 |
| 抓不起来或抓取不稳 | 手离摄像头近一些（约 0.5 米），手掌正对摄像头；换备用抓取方式 |
| 板子死机 | 不现场重新加载，切到备份视频继续讲 |
| 超时 | 先压缩第 ③ 段，再删工地中"两个人都戴好"之后的等待 |

## 可能的提问

| 问题 | 回答要点 |
|---|---|
| 哪些是自研的？ | CPU、NPU、多媒体通路（采集、像素处理、几何、2D 渲染、显示）、片上互连、量化部署工具链和全部应用软件。DDR3 控制器、PLL、存储块用紫光同创 IP。模型结构用开源 YOLOv8n，手势和安全帽模型自己训练 |
| CoreMark 怎么测的？ | 板测 5.57 / MHz（125 MHz 下 696 分）：GCC 15.2 -O3 调优编译，代码和数据在片上 SRAM；RTL 仿真 5.56 / MHz，两者一致 |
| 帧率受什么限制？ | NPU：一帧 34.4 ms（约 29 帧/秒），摄像头本身 30 帧/秒；现场显示 25–28 帧/秒 |
| 量化掉多少精度？ | 以手部模型为例，INT8 比浮点 mAP50-95 低 3.6 个点；平板素材都先在电脑上用同一 INT8 参考模型验证过 |
| 时序收敛了吗？ | 如实回答：125 MHz 下 CPU 指令缓存到预译码的路径在慢速工艺角有 0.546 ns 违例，快速工艺角有余量；全部演示都在这个版本上完成上板测试 |
| 为什么用平板？ | 现场没法带牛羊和工地；摄像头拍的是真实光学画面，识别过程与真实场景相同 |
