# 独立双 ALU 双发射阶段，2026-10-07

## 实现范围

`edrv32_core`、`edrv32_cached_core` 新增默认关闭的 `DUAL_ISSUE` 参数，SoC 对应 `CPU_DUAL_ISSUE`。打开时自动启用双窗口前端。原 `FRONTEND_DUAL_WINDOW=1, DUAL_ISSUE=0` 仍能独立验证双窗口前端与标量后端。

A 是较老指令，B 是紧接其后的年轻指令。两条均为合法、无取指异常、未预测跳转的 ALU 指令，且 PC 连续、epoch 相同时才能配对。同组 A→B RAW 和非 x0 的 WAW 拆开；WAR 允许，因为两条操作数均在 DECODE 捕获。译码的 `uses_rs1/rs2` 判断排除立即数字段造成的假冲突；x0 不制造依赖。LUI、AUIPC 和压缩后解码为 ALU 的指令也可配对。

访存、分支/跳转、MDU、CSR、FENCE、MRET、WFI 暂时单独发射。共享 LSU/MDU 的所有权、token 和原来的 A 槽晚 Load/MDU 消费者流程保留。B 操作数必须已经准备好；如果 B 暂时不能配对，A 可以先走，B 随后成为 A。

## 结果、旁路与提交

寄存器堆为可选 4R2W，保留 `u_regfile.regs_r` 的调试层级。四个读口都显式写透；同地址双写时年轻 B 优先，x0 始终为零。正常配对阶段禁止同组 WAW，这一优先级也通过单元用例单独验证。

B 的 DECODE payload 为 `{valid, pc, instr, compressed, epoch, rd, write, alu_op, lhs, rhs}`，EX 后为 `{valid, pc, instr, compressed, epoch, rd, write, result}`，宽度定义在 `rtl/include/edrv32_pair.vh`。B 与 A 使用相同的 capture/transfer/kill，通过 EX 输出寄存器、MEM1 两项 FIFO、MEM2 所有者和 MEM2→COMMIT 寄存器。pipe 仅保存寄存器，不新增 ready/FSM/冒险逻辑。B 内嵌 valid 只有在父包有效时才可观察，故无须复位无效 payload。

跨组旁路按 EX→MEM1→MEM2→COMMIT 的年轻到年老顺序匹配；同一包内 B 比 A 年轻。MDU 在这个顺序中的位置继续由 `passed_mem1/passed_mem2/authorized` 所有权年龄标志判断。最新匹配者未准备好时阻塞，不能绕过它选旧值。DECODE 内尚未执行的 B RAW 保守等待到 EX 结果边界，不能误用只适用于 A 的 resident bypass 标记。

COMMIT 仍是唯一不可撤销副作用所有者。A/B 成对退休，输出 `second_retire_*` 和 `retire_count_o[1:0]`。中断在 A 之前生效时两条都不写回，mepc 指向 A；MRET 后重放整组。已授权而未完成的较老 MDU 通过原 COMMIT 规则阻止年轻组写回。

`minstret` 正确增加 0/1/2；HPM 同一个事件可收到两次 occurrence，+2 的 32 位低字进位条件包含 `fffffffe`。事件、选择器、inhibit 仍按原边界采样，CSR 写入优先级保留。第二事件向量仅增加 B 的 ALU/压缩退休及 IF2 第二指令的半字消费事件；周期归因事件不重复增加。`FE_CONSUME_HW1 + 2*FE_CONSUME_HW2` 现在可统计双窗口捕获的总半字，而 `EMPTY_RETIRE_SLOT` 仍表示整周期零退休，不等同于双槽未用容量。

## 验收与复现

完整验收包含所有 CPU 模块/定向用例、八种 LSU throughput 场景、三种固定随机种子、4R2W、旁路年龄、计数进位、成对 IRQ 重放，以及冻结 ISA/ACT 与固定 CoreMark 镜像。

`sim/script/run_dual_isa.py` 对每个配置运行 62 项 riscv-tests（I 39、M 8、C 1、M-mode 14），82 项 ACT（I 39、M 8、Zca 26、Zicsr 6、Zicntr 2、Zifencei 1）。scalar/dual × direct/cached 合计 576 次。Debug trigger 与 PMP 两项沿用仓库既有 profile 排除规则；本核没有 F/D，本回归不运行 F/D。输入 ELF/归档和转换脚本一起纳入版本，运行从 ELF 符号提取 tohost，每个 ELF/HEX 都记录 SHA256。Zca 使用冻结的 Sail 参考 signature 自检 ELF；未增加现场生成 Sail signature 或新的完整合规认证流程。

运行器检查实际仿真退出码和 PASS/FAIL，而非仅看脚本执行完。架构 testbench 对 B 退休和父包背压下的 B payload 保持增加检查，并将 B 加入退休统计。每个输出目录保留命令、工具版本、输入哈希、日志和 manifest；失败和超时也落盘。

```sh
python3 sim/script/run_dual_issue.py --suite all
python3 sim/script/run_dual_isa.py --mode both --memory both --jobs 8
python3 sim/script/run_dual_coremark.py --mode all --opt both
```

`dual-alu` 用例含 974 条指令，在退休边界按 A 后 B 的顺序执行独立指令语义参考模型，核对每个写回值和最终寄存器。128 条独立压缩 ALU 的连续段要求不超过 68 周期且至少 60 对实际双退休，不能以偶然的双 valid 代替吞吐量验证。默认种子 1、7、20261006；通过 `--seed` 和 `--wave` 保存复盘波形。

## 架构回归发现并修复的边界

完整回归发现 dual/cached 下 `Zca-c.sw`、`Zca-c.swsp`、`rv32um-p-div/rem/remu` 五项停顿。逐周期追踪确认是 IF2 控制被 X 污染：FIFO 只有一条完整 32 位指令时，第二指令长度读取了占用范围外的未初始化 payload，导致双捕获条件不再是确定的 false。

修复先根据寄存占用数判断 B 首半字存在，再检查其长度和完整性，不复位或初始化无效 payload。永久用例 `if2-dual-missing` 在原谓词上失败、修复后通过；修复后 cached/dual ACT 82 项及三个 M 测试均已定向确认。最终全部测试结果另见本阶段结果记录，失败版本日志也保留在审计目录。

## 性能与下一步

固定 GCC 15.2 O2/O3、10 次迭代镜像保持不变；三轮 CRC 和退休指令数必须与标量基线一致。周期对照来自软件读取 mcycle/minstret 的区域，不使用 testbench 外侧观察区间替代。压缩 ALU 极限段的 2 IPC 是供给足够且无依赖的受控结果，不能直接外推为 CoreMark 的 2 IPC。

下一步先根据 SIM_PROFILE 的互斥配对拒绝原因选择扩展方向：共享 LSU 与 ALU 配对、B 槽分支、resident B 依赖处理和更宽取指分别评估。扩展前须维持本阶段全部测试。资源、最高频率和板上 CoreMark 仍需后续综合布线/上板结果确认，本阶段不修改默认板级配置。
