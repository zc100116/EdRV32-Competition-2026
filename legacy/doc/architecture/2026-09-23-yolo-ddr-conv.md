# YOLOv8n 卷积层的 DDR 数据通路

本轮实现的是一个 **32 输出通道块**的 DDR→卷积→INT8→DDR 执行单元。它复用已经上板验证的 512 MAC 阵列和量化器，用来验证特征图布局、突发传输、行复用和激活双缓冲。量化参数需要在启动该通道块前写入。后续扩展的 C2f、SPPF、上采样与共享执行器记录在[YOLOv8n 共享执行器与上板节点](2026-09-23-yolo-v8n-exec.md)；固定整网层序、检测头和摄像头入口仍待开发。

## 固定 YOLOv8n 的几何约束

按 [Ultralytics 的 YOLOv8 检测模型定义](https://github.com/ultralytics/ultralytics/blob/main/ultralytics/cfg/models/v8/yolov8.yaml) 中 `n` 的宽度系数 0.25 和本项目的 640×384 输入，主干五级分辨率为 320×192/C16、160×96/C32、80×48/C64、40×24/C128、20×12/C256。SPPF 内部四路拼接会形成 20×12/C512 的 1×1 输入；检测颈部的两处上采样拼接会形成 40×24/C384 与 80×48/C192 的 1×1 输入。因此输入通道块计数须容纳 32 个 C16 块，1×1 行缓存须能处理一行超过 204 个 bank 地址的情况。当前 RTL 已覆盖这些地址／计数边界；C2f 和 SPPF 的层序验证见后续文档。

## 多输出块与跨层复用

`edrv32_yolo_conv_group` 在一个物理卷积单元上顺序运行同一层的多个 C32 输出块。每块装入 32 通道量化参数，按 `weight_block_stride` 移动权重地址，按两个 `output_plane_stride` 移动输出地址；上一层的输出 Surface 可直接作为下一层的输入 Surface。模块锁存启动时的层描述符，完成信号在最后一个输出块的写响应返回后产生。不增加 MAC 阵列或 DDR Master。

`tb_yolo_conv_group.sv` 已在 AXI 存储模型上连续验证 C16→C32、C32→C64、C64→C32 三层，第二层两个输出块使用不同权重和量化系数，量化配置含等待，逐 beat 检查各层写回及下一层读取。它继续测试按相邻 C16 平面表达的三路拼接，无需额外 DDR 拷贝，以及宽 40、C384 输入和宽 20、C512 输入的 1×1 卷积。输入通道块计数已从 5 bit 扩为 6 bit，容纳 32 个 C16 块。最后一次命令只启用一个 C16 输出面，模拟 YOLOv8n 首层 C16 输出，未启用的第二面保持原值。七次卷积命令总计 256 次通道配置、8416 个 MAC 输入 beat、5312 个 DDR 读 beat、476 个写 beat。当前调度按完整输出块运行，因此第二个输出块会重新从 DDR 读取输入特征；跨输出块的行缓存复用与固定 YOLOv8n 整网层序仍待实现。此模块尚未并入板测顶层，也没有新的 PNR 结果。

`edrv32_yolo_c16_residual_add` 是 C2f shortcut 所需的逐元素 INT8 加法级，每周期可处理一个 256 bit C16 beat，包含输出寄存与背压。它要求两路输入和输出使用同一量化尺度、零点；此约束必须在模型量化时满足。100-beat 连续传输、输出反压、正负饱和仿真通过。`edrv32_yolo_c16_residual_dma` 已连接两路 DDR 读取和一路写回：每次最多缓存 16 beat 的 A 与结果，按 A、B、输出三处 4 KiB 边界拆块。37-beat 跨边界、全部 AXI 通道插入等待、原地址覆盖写和逐 byte 结果比较均通过。该 DMA 目前顺序处理块，没有下一块的预取；它已接入下述 C2f 控制器，但尚未接入板测顶层。

`edrv32_yolo_c2f` 已把卷积块与残差 DMA 接成首个 C2f 的顺序：C32 输入经 1×1 生成两个 C16 分支，第二分支依次经过两次 3×3 C16 卷积并与原第二分支相加，三个连续 C16 平面直接供最后 1×1 C48→C32 融合读取。测试中两次 3×3 只写一个 C16 输出面；逐 beat 检查了最终两个输出面和未启用面的哨兵值。小尺寸 DDR 模型仿真为 128 次量化通道配置、四次各 256 byte 激活表配置、736 个 MAC 输入 beat、512 个读 beat、112 个写 beat，全部通过。此测试使用恒等激活表来隔离 C2f 数据流；独立量化器测试以 `q ^ 0x5a` 覆盖了全部 256 个表地址。模块现已扩到双 bottleneck 和可选 shortcut，见后续文档。当前尚无真实模型权重和经校准的 SiLU 表，因此不能证明预训练模型的数值精度。

卷积结果先进行带每通道 bias／乘数／移位的 INT8 量化，再经过一张可选的 256×8 激活表。16 个并行输出字节各有一份相同的表，增加一个流水级，仍每周期接收 16 个量化值。各通道的预激活量化输出必须共用尺度 `S_pre` 和零点 `Z_pre`，才能共用这张表。每个输出块开跑前，控制器先写 32 个量化通道，再顺序写 256 个表项。主机生成 SiLU 表时，地址是卷积预激活量化字节 `q_pre` 的二进制编码，表值应按 `sat8(round(SiLU((signed(q_pre)-Z_pre)×S_pre)/S_post)+Z_post)` 计算。残差与后续拼接须使用表输出的尺度和零点；残差两路与结果必须具有同一尺度和零点。当前表由外部逐项提供，尚未完成权重转换和量化标定。16 份表共 4 KiB，最终映射资源、时序和功耗须看新的综合与布局布线报告。

## 特征图布局

中间特征图采用 `[C16 通道块][行][水平像素对]`。一个 256 bit DDR beat 包含相邻两个像素，每个像素 16 个 INT8 通道：

```text
bits 127:0   = pixel(2*x),   channel 0..15
bits 255:128 = pixel(2*x+1), channel 0..15
```

32 输出通道块的量化结果每对像素为 512 bit，写入器拆成两个 C16 平面的各一个 256 bit beat；输出只有 16 通道时只写第一个 C16 平面。输入宽度必须是 4 的倍数；输入通道不足 16 的首层需要补零到 C16。DDR 特征图按通道块连续，每个通道块占 `input_height × input_width/2 × 32` 字节。摄像头缩放流到首层的入口尚未接入本执行单元。

## 片上缓存与调度

| 存储 | 容量 | 作用 |
| --- | ---: | --- |
| 权重 tile | 128 KiB | `512 K 行 × 8 bank × 256 bit`，一次读入并复用整个输出面 |
| 特征行缓存 | 64 KiB | 两个读 bank，各 `1024 × 256 bit`，最多保留 5 条完整输入行 |
| 激活 tile | 32 KiB | 两个 16 KiB 半区，交替生成 patch 和执行卷积 |
| 写缓冲 | 2 KiB | 两组各 16 对像素，可同时填充与向 DDR 写出 |

行缓存按 DDR 像素对的奇偶分 bank，因此相邻两个输出像素在 3×3、stride=2 下可同时读两个 beat。3×3 使用 5 个带标签行槽复用相邻输出行；1×1 每行复用槽 0，避免宽通道输入超出行缓存。激活生成器按 `pair → ky → kx → C16 block → 8 通道半块` 的顺序生成 128 bit 行。软件选择 `tile_pairs`，须满足 `tile_pairs × K ≤ 1024`，其中 `K = 2 × CinBlocks × (kernel3 ? 9 : 1)`。3×3 须满足 `5 × cache_row_stride ≤ 1024`；1×1 只须满足 `cache_row_stride ≤ 1024`。两者均有 `cache_row_stride = CinBlocks × input_width/4`。

DDR 读器最多允许 4 个未完成请求，每个请求最多 16 beat，并在 4 KiB 边界拆分。它轮流装载权重和缺失的特征行。DDR 写器有两组 16 对像素缓冲；每组分别向两个 C16 输出平面发突发，填充下一组时可排出上一组，未返回的写响应最多 4 个。输出行完成以写响应返回为准。读、写走独立 AXI master 接口；进入整机 DDR 仲裁器时，显示和摄像头仍需有界服务时间，YOLO 请求的 16 beat 上限用于限制一次授权占用时间。

## 已验证范围

`tb_yolo_axi_stream.sv` 用带等待的 AXI 模型检查 4 KiB 拆分、突发长度、写数据重排和写响应。`tb_yolo_conv_layer.sv` 用随行列及通道块变化的数据，逐 beat 比较 DDR 输出，覆盖 1×1、3×3 stride=1、3×3 stride=2、双 C16 输入块；并检查行复用和激活生成与卷积重叠。3×3 stride=1 的 8×3 小例子只读取 3 条输入行，共 12 个特征 beat，权重 144 beat，执行 216 个 MAC 阵列 beat，写出 24 beat。

## DDR 板级自检顶层

`edrv32_pango_200h_yolo_ddr_top` 已连接完整路径：YOLO 150 MHz → 现有 AXI 异步桥 → DDR 用户接口 125 MHz → 现有 256 bit AXI interconnect → 现有 DDR AXI adapter → DDR3 IP。IP 的 `core_clk` 是 125 MHz；DDR3 配置的物理数据速率为 1000 MT/s。原先见到的 200 MHz 属于未使用的 LPDDR 配置项。

当前顶层默认运行 64×32、3×3、C16→C32 的吞吐用例；`BENCHMARK_MODE=0` 保留原来的 8×3 短自检。KEY0 复位后，用例先向 DDR 写入权重和输入特征，再执行卷积并从两个输出平面逐 beat 读回校验。大尺寸用例使用全 1 输入/权重，按边界位置期望输出 4、6 或 9；这是用于连续传输和边界校验的合成负载，不代表真实 YOLOv8n 层的数值分布。interconnect 的第二个 master 在卷积期间持续读取独立区域，检验竞争时的服务。串口输出 `YDDR PASS/FAIL MAC=... RD=... WR=... CYC=...`。当前只有测试 master 和背景读 master；摄像头、显示与 CPU 尚未接到新顶层。

自检完成后只输出一次结果。紧随其后的 `YDBG ERR=... LOC=... GOT=... EXP=... PHY=...` 用于定位原因。`ERR` 的 bit 0～4 依次表示初始化写响应、卷积层错误、读回响应、读回 `RLAST`、读回数据不符；bit 5～8 依次表示 DDR 初始化稳定后的 PHY 告警、DDR adapter、interconnect、背景读取错误。`PHY` 的 bit 0/1 分别记录初始化或稳定等待期间出现过的 `ddr_phy_init_fail` / `align_error`，bit 2/3 记录稳定后出现过的两种告警，bit 4/5 是发送报文时的实时电平。训练期的瞬态保留在 `PHY` 中，但不再单独判为自检失败。短自检的 `LOC` 仍为请求与像素对位置；吞吐用例的 `LOC[10:4]` 是 0～127 号读回 burst，`LOC[3:0]` 是 burst 内的 0～15 号 beat。`GOT/EXP` 显示首个错误 beat 中像素 0 前四个通道的实测/期望值。此前用于临时板级 `fail_r` 的 setup false path 已移除，读回数据先寄存，再进行比较并锁存错误原因。

第三行 `YPRF WGT=... FET=... RUN=... ARW=... WWR=... BGR=... GAP=...` 是性能计数：前三项分别为权重装载、特征装载、行执行阶段的 150 MHz 周期数；`ARW/WWR` 是 YOLO AXI 地址/写数据通道的 ready 等待周期；`BGR` 是背景 master 收到的 256 bit beat 数；`GAP` 是背景 master 活跃期间连续没有收到 beat 的最长 125 MHz 周期数。背景流停止并排空后才采样 `BGR/GAP`。串口助手只保留 `CYC/ERR/PHY/WGT/FET/RUN/BGR/GAP` 八条核心观测规则，其他字段仍可在原始串口行中查看。`MAC/CYC` 给出该用例的 MAC 输入占空比，`(RD+WR)×32×150 MHz/CYC` 给出 YOLO 端平均有效载荷速率；这些量不是 DDR 物理总线利用率。

仿真使用 DDR UI 行为模型，通过完整的跨时钟路径和竞争场景。缓存读请求增加寄存描述符后，无竞争时卷积阶段为 906 个 YOLO 时钟周期；加入 528 beat 背景读取后为 1046 周期。两个场景都读入 156 beat、执行 216 个 MAC 阵列 beat、写出并读回校验 24 beat，且串口报文通过解码检查。该小规模自检不能外推为 YOLOv8n 整网帧率。新增流水和 DDR 时钟组约束仍需以新的布局布线时序报告确认。

64×32 吞吐用例已在行为 DDR 模型中完整读回校验。`tile_pairs` 取 2、4、8、16 时，无背景流量的执行周期分别为 31079、29648、30747、34680，因此板测默认取 4。取 4 时，无背景流量为 29648 周期，持续背景读取为 30326 周期，MAC 输入均为 18432 周期，读 1168 beat、写 2048 beat；竞争使执行时间增加约 2.3%。背景 master 收到 16144 beat，最长服务间隔 31 个 DDR 周期。故意改坏首个输出 beat 的仿真会报 `ERR=00000010 LOC=00000000 GOT=04040405 EXP=04040404`。这组数据来自行为 DDR 模型，板级持续吞吐和时序需要新一轮布局布线及上板确认。

2026-09-23 板级测试完成：`YDDR PASS MAC=00004800 RD=00000490 WR=00000800 CYC=00008477`，`YDBG ERR=00000000 PHY=02`；`YPRF` 计得 `WGT=560 FET=4067 RUN=29155 ARW=0 WWR=78 BGR=9024 GAP=337`。`PHY=02` 只表示初始化等待期间曾出现 `align_error`，稳定后无告警。150 MHz 下执行约 226.1 μs，MAC 输入占空比约 54.4%，以每 beat 512 个逻辑 MAC 计约 41.7 GMAC/s。背景读取 282 KiB，最长无 beat 间隔为 337 个 125 MHz 周期（约 2.70 μs）；该间隔包括突发之间及 DDR 服务等待，不能直接解释为仲裁器独占时间。板上背景服务量小于行为模型，真实 DDR 和后续显示流量仍需单独评估。此次 PNR 用时 34 分 7 秒，所有已约束时序通过；YOLO 150 MHz 建立裕量 +0.105 ns，DDR 125 MHz 建立裕量 +0.568 ns。YOLO 最紧路径从写缓冲的 `drain_index_r[0]` 到 AXI 异步桥写 FIFO，扇出 519，路径延迟约 85% 来自布线，是后续扩展时的时序风险点。

随后将写缓冲按 8 个 64 bit lane 分组，分别寄存并保留读索引驱动，以降低上述单根索引的扇出。AXI 读写测试、单层卷积、五命令 DDR 链及完整板顶仿真均通过；该 RTL 改动尚未重新综合和布局布线，不能沿用上一版的 +0.105 ns 裕量作为新实现结果。

PDS 导入时先设置 `EDRV32_TOP` 为 `edrv32_pango_200h_yolo_ddr_top`，再执行 `import_sources.tcl`；Device Map 前还须在 GUI 中确认并保存同名 Top Module。新顶层只使用已有的 `yolo_pll`、`yolo_weight_ram`、`yolo_activation_ram` 和 `ddr` IP，无需创建新 IP。`io.fdc` 仅激活了已有 DDR/ref 引脚语句，未改引脚位置；`clock.fdc` 激活 DDR 时钟并声明 150/125 MHz 时钟域异步。
