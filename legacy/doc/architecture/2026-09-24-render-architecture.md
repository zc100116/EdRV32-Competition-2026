# 2D 图形加速器设计计划

2026-09-24。面向 LVGL 界面、视频叠加和自制横版游戏。本文记录已讨论确定的硬件架构；资源和帧率须以 RTL 仿真、综合及混合 DDR 负载测量验证。

## 目标与数据流

EdRV32 生成绘制命令列表并放入 DDR，通过 APB 提交列表地址和数量。渲染器取命令，维护一块覆盖显示区域的 **ARGB8888 预乘 Alpha 前景 Surface**。底图为不透明 RGB565 Surface，可以由 Camera/Pixel/Geometry 提供，也可以由绘制命令生成。合成器读取底图与前景，写入已有 HDMI 显示缓冲；若底图刚写入该缓冲，可原地合成，否则可从独立底图 Surface 读取。底图与前景都没有变化时 HDMI 继续显示当前完整帧。

**只有一块物理前景 Surface**。绘制、前景写回和合成按序执行，不做双前景同步。HDMI 继续使用现有显示缓冲池和 VBlank 切换。前景未启用时，格式兼容的 READY 底图直接交给 HDMI；没有圆角、阴影等命令时，对应发生器不参加数据通路。

```text
CPU → DDR 命令列表 → 命令/帧控制 → 二维地址生成 ─┬→ 256-bit 清除/填充/不透明搬运
                                                   └→ 素材/形状覆盖率 → 2 像素 Alpha 流水线
                                                                           ↓
                                                                前景读写缓存 → DDR
READY 底图 + 稳定前景 → 合成读/混合/写回 → 完整显示 Surface → HDMI pageflip
```

## 硬件功能

| 命令 | 工作 |
|---|---|
| CLEAR | 指定前景区域清为完全透明 |
| FILL / GRADIENT | 不透明底图填充、前景透明填充；水平/竖直渐变 |
| BLIT | RGB565、ARGB8888、A8 素材绘制；裁剪、全局透明度、颜色键、最近邻缩放、翻转 |
| COPY | 同格式矩形搬运，处理同一 Surface 内的重叠区域 |
| ROUND_RECT | 硬件产生 8-bit 圆角和边框覆盖率并着色 |
| BOX_SHADOW | 按圆角、模糊宽度、扩展及偏移生成控件阴影；复用角部数据 |
| A8_BLUR | 用 DDR 临时区对任意 A8 掩码进行二维模糊，再着色混合 |

所有命令受目标矩形和裁剪矩形约束。命令按列表顺序改变 Surface；阴影与控件本体的前后关系由命令顺序决定。文字排版、图像解码、UI 与游戏逻辑由软件完成；字形 A8 着色、圆角、阴影及大量像素搬运由硬件执行。目标只能选择当前受帧控制器保护的前景或可写底图，命令不能任意改写 HDMI 正在扫描的缓冲。

## 命令、流水与 DDR

每条命令固定 64 byte，按 64-byte 对齐存放；命令 DMA 每次取两个 256-bit beat。公共字段包括操作码/格式/标志、目标与裁剪矩形、素材地址/stride/矩形、颜色、透明度及操作参数。命令解释器检查尺寸、stride、地址计算溢出和支持的格式。CPU 必须在 APB 启动前使 DDR 命令和素材写入对 DMA 可见。异常批次不发布显示 READY。

渲染器主时钟按 DDR UI 的 125 MHz 规划。Alpha 数据通路目标为 **2 像素/周期**，各流水级用 valid/ready 与本地容量承受 AXI 停顿；ARGB8888 源支持普通与预乘输入，前景统一保存预乘数据。清除、纯色填充和同格式不透明搬运走 256-bit beat 快速通路，不受 2 像素/周期乘法通路限制。

渲染器以一个 256-bit AXI Master 接入现有 DDR Fabric。命令、素材、底图、前景和临时区由内部调度器访问；读 FIFO 对齐来源与目标像素，前景的小型写合并缓存减少小图元反复读写。写通路先积攒完整计划 Burst，再发 AW 并连续发送 W。Burst 最长 16 beat、32-byte 对齐且不跨 4 KiB；矩形首尾通过字节写使能处理。大型阴影和 A8 模糊的中间结果放 DDR 临时区，片上只保留必要的行/角部缓存。

帧控制器收到上游完整底图、前景绘制完成且缓存写回后启动合成。仅在最后一个 AXI 写响应返回后，才把结果提交给 HDMI。若前景没有变化，摄像头新底图可复用现有前景自动合成，CPU 无需逐帧提交相同命令。渲染器落后时不显示半帧；HDMI 重复上张完整画面，旧的待处理视频帧可在所有权允许时跳过。HDMI 读 FIFO 的紧急服务仍由现有 DDR Fabric 优先处理，渲染器的 Outstanding 与连续 Burst 数必须有上限。

## 性能依据与验证

1280×720 RGB565 一帧 1.843 MB，ARGB8888 前景 3.686 MB。一次全屏合成需要读取两者并写 RGB565，载荷约 7.373 MB；若每秒合成 60 帧，约 442 MB/s，另有 HDMI 60 Hz 扫描约 111 MB/s。两像素流水线在 125 MHz 下处理一帧的理想计算时间约 3.69 ms；真实速度取决于 DDR 读写、图元重叠和短 Burst。前景全屏清除走 256-bit 快速通路，理想发数时间约 0.92 ms。这些数值均非板级吞吐保证。

先在 `rtl/vision/render/` 实现可综合 Verilog-2001；测试放在 `sim/cases/vision/` 的独立 case，使用 `files.f` 和 `make case-sim`。优先在 `edward` Linux VM 上编译及运行，对每次同步确认当前 RTL 版本。测试覆盖像素精确度、任意 AXI 背压、Burst/4 KiB/边界写使能、命令顺序、前景缓存回写、Fence、旁路、帧所有权及出错时不发布。画面级 case 将仿真 DDR 中的显示 Surface 导出为可查看的图片。当前不改 `fpga/pango_200h/edrv32_soc_render` 工程、源文件导入 Tcl 或约束。

### RTL 进度（2026-09-24）

已完成并通过 VM 仿真的部分：两像素预乘 Alpha 弹性流水线、RGB565 合成格式转换、64-byte 命令 DMA、RGB565/ARGB8888 256-bit 填充 DMA、RGB565 底图与 ARGB8888 前景的流式合成 DMA、圆角/边框行覆盖率发生器及最多 16 beat 的前景 tile 读改写 DMA、A8 字形蒙版着色 DMA、RGB565/ARGB8888 位图叠加和最近邻缩放 DMA、同格式重叠矩形 COPY，以及命令列表执行器。圆角、A8、位图及合成共用一条两像素 Alpha 流水线。A8 命令每行读取一个对齐的 256-bit 蒙版 beat，支持宽 1–32 像素；目标前景以不跨 4 KiB 的行 tile 读写 Burst。位图的 1:1 路径维持最多 8 beat 的 tile 写 Burst；缩放路径使用 Q16 步长和源 beat 缓存逐像素最近邻采样，写回沿用相同 tile。COPY 在同 Surface 重叠时要求相同 stride，不相交 Surface 可用不同 stride；先读完 tile 再以 AXI 字节写使能保护目标边界。合成 DMA 支持源/目的同址与异址；当前完整行宽需为 16 像素的整数倍。跨命令前景写合并缓存仍未实现。

帧控制器通过 APB 提交命令列表并保留最新待处理底图。绘制成功后置前景有效；有有效前景时自动合成，无前景时直接发布底图。三个目标缓冲按轮转选择，显示端退役 token 后才可复用；全部占用时等待，不覆盖显示画面。`edrv32_render_hdmi_system` 已将渲染写端、HDMI AXI 读端、异步 FIFO、scanout 和 TMDS 接在现有双 Master 256-bit AXI Fabric 上。HDMI FIFO 低水位经过跨时钟同步后提高读端优先级。`render-hdmi-system` 在缩小几何的共享 DDR 仿真中验证两次合成与扫描并行、目标像素、完整 HDMI 活动帧、源底图释放及目标 token 退役；仍需实际 720p 板级带宽与时序验证。

帧控制器的 `CONTROL` bit 1 可启用底图保留：成功合成后继续持有该底图；CPU 只更新前景时，绘制完成会自动用保留底图重新合成，无需新摄像头帧。新底图成功合成才替换并释放旧底图；关闭保留、关闭前景或改变画面尺寸会释放它。无前景直接旁路的底图仍在 HDMI 退役后释放。新帧到达与合成并行时，活动底图地址独立锁存，待处理底图不会覆盖它。该模式可按场景启用；视频场景不需要保留时维持原有释放策略。写通路保护器检查完整 AXI Burst：命令列表不得写三个 HDMI 目标地址槽，直接合成只能写它获分配的目标槽；越界 Burst 在本地丢弃并返回 DECERR，出错批次不发布。默认每槽 2 MiB，参数 `TARGET_SLOT_BYTES` 须与实际内存布局一致。当前保护器没有对前景、临时区及软件底图实行可写区白名单，也没有跟踪旁路摄像头底图的地址；这部分所有权仍由软件与上游帧协议保证。验证记录与图像见 [Render RTL 仿真](../validation/2026-09-24-render-rtl.md)。

位图命令支持颜色键、双轴翻转及最近邻缩放。缩放模式的源首地址与源 X 指向首个采样像素，Q16 步长给出每个目标像素/行的源坐标推进量；翻转标志使推进方向反转。1:1 命令继续走原有较快路径。渐变命令支持 RGB565 底图和预乘 ARGB8888 前景的水平或垂直线性颜色推进；CPU 为四个通道计算一次 Q16 步长，硬件逐像素累加并截断到 8-bit。

`A8_BLUR` 现用 DDR 临时区完成水平、垂直两遍零填充盒式模糊，支持半径 0–15 和任意行宽（stride 对齐 32 byte）。`BOX_SHADOW` 是一条宏命令：硬件先生成留有模糊边距的圆角 A8 蒙版，复用两遍模糊，再按最多 32 像素宽的片段调用现有 A8 着色 DMA 绘制到前景。软件计算阴影偏移及扩展后的外框坐标，硬件处理逐像素几何、模糊和混合。当前渐变、蒙版和模糊写回分别按单 beat 发 AXI 事务；是否合并 Burst 留待板级吞吐测量后决定。

前景写合并缓存属于性能优化，按板级测量结果决定实现方式。独立 720p 画面 case 已从 RTL DDR 输出验证元素缩放、渐变和三种半径的圆角阴影；仍不能推断板级帧率已达标。

### 执行与总线重构（2026-09-25）

render 板级顶层选用 `edrv32_render_system_parallel`：APB 帧控制、绘制执行器和独立合成器在渲染器内汇入一个 256-bit AXI Master。绘制与合成各有一条两像素 Alpha 流水线；内部双客户端 AXI 调度器用寄存请求入口切断下游 `ready` 的组合反馈。HDMI 扫描读取作为系统级另一 AXI Master 接入板级 DDR Fabric，FIFO 低水位参与读仲裁。板级演示命令写入器与色条写入器是另外两个 Master。保留的旧 `edrv32_render_system` 与 HDMI 内部互连模式只供现有回归使用。

三块合成 FIFO 的逻辑容量分别为 32、64、32 个 256-bit beat。FPGA 模式使用同一种 64×256 简单双口 RAM IP `render_fifo_ram`，外部以计数器限制逻辑容量，并以两字寄存预取维持首字可用接口；仿真模式使用同周期延迟的 RTL RAM。较小的图元 tile 缓存仍在本地，避免同步 RAM 读端改变随机像素访问时序。

已确认继续使用单前景 Surface，因此绘制与合成按帧互斥，避免合成读取时绘制改写同一区域。两条独立计算通路便于分别优化和复用，但不意味着同一前景上的跨帧同时执行。绘制命令执行器内部仍按列表顺序逐条执行。最新改动已通过 RTL 功能和板级顶层 FPGA_MODE 端口检查，尚无新一轮 PDS 时序与资源报告。
